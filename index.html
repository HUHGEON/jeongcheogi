기본 SQL 명령어

상황쿼리
데이터 추가 ❗INSERT INTO 테이블(컬럼1, 컬럼2... 생략가능) VALUES (값1, 값2 ...);
데이터 복제 ❗INSERT INTO 테이블1(컬럼1, 컬럼2... 생략가능) SELECT 컬럼3, 컬럼4... FROM 테이블2;
데이터 삭제 ❗DELETE FROM 테이블 WHERE 조건;
데이터 수정 ❗UPDATE 테이블 SET 컬럼1 = 값1, 컬럼2 = 값2 WHERE 조건;
테이블 제거 ❗DROP TABLE 테이블 RESTRICT; (다른 테이블이 참조하면 삭제 불가)DROP TABLE 테이블 CASCADE; (참조하는 테이블까지 삭제)
권한 부여 ❗GRANT 권한 ON 테이블 TO 사용자; (권한 = SELECT, INSERT...)
권한 회수REVOKE 권한 ON 테이블 FROM 사용자;
뷰 생성CREATE VIEW 뷰이름 AS SELECT 컬럼1, 컬럼2 ... FROM 테이블 WHERE 조건;
뷰 제거 ❗DROP VIEW 뷰이름 RESTRICT; (다른 테이블이 뷰 참조하면 삭제 불가)DROP VIEW 뷰이름 CASCADE; (뷰를 참조하는 테이블까지 삭제)
컬럼 기준 정렬 ❗SELECT 컬럼1, 컬럼2 FROM 테이블 ORDER BY 컬럼1 ASC; (오름차순, 생략가능)SELECT 컬럼1, 컬럼2 FROM 테이블 ORDER BY 컬럼1 DESC; (내림차순)
두 개 컬럼 정렬 ❗SELECT 컬럼1, 컬럼2 FROM 테이블 ORDER BY 컬럼1 DESC, 컬럼2 DESC; (컬럼1 먼저 정렬)SELECT 컬럼1, 컬럼2 FROM 테이블 ORDER BY 컬럼2 DESC, 컬럼1 DESC; (컬럼2 먼저 정렬)
범위 조회 ❗SELECT 컬럼1, 컬럼2 ... FROM 테이블 WHERE 컬럼1 BETWEEN 1 AND 3; (1~3 사이)SELECT 컬럼1 컬럼2 ... FROM 테이블 WHERE 컬럼1 IN (1,2,3); (1,2,3 중 하나)
특정 문자로 시작하는 데이터 조회 ❗SELECT 컬럼1 컬럼2 ... FROM 테이블 WHERE 컬럼1 LIKE ‘특정문자%’;
특정 문자가 포함된 데이터 조회 ❗SELECT 컬럼1 컬럼2 ... FROM 테이블 WHERE 컬럼1 LIKE ‘%특정문자%’;
특정 문자 앞에 딱 한글자만 있는 데이터 조회 ❗SELECT 컬럼1 컬럼2 ... FROM 테이블 WHERE 컬럼1 LIKE ‘_특정문자’;
합계에 조건을 걸고 조회할 때 ❗SELECT 컬럼2, SUM(컬럼1) AS 합계 FROM 테이블 WHERE 조건 GROUP BY 컬럼2 HAVING SUM(컬럼1) 조건;

테이블 정의 (CREATE TABLE) · 제약조건 ❗

상황쿼리
테이블 생성CREATE TABLE 테이블 ( 컬럼1 INT PRIMARY KEY, 컬럼2 VARCHAR(20) NOT NULL, 컬럼3 INT DEFAULT 0 CHECK(컬럼3 >= 0), 컬럼4 INT, FOREIGN KEY(컬럼4) REFERENCES 다른테이블(기본키) );
제약조건의미
PRIMARY KEY ❗기본키 (NOT NULL + UNIQUE)
FOREIGN KEY ❗외래키, 다른 테이블의 기본키 참조
NOT NULLNULL 값 입력 불가
UNIQUE중복 값 입력 불가 (NULL은 허용)
CHECK지정한 조건을 만족하는 값만 허용
DEFAULT값 미입력 시 기본값 지정
⚖️ DELETE vs TRUNCATE vs DROP
  • DELETE (DML) : 행을 조건부 삭제(WHERE 가능). 로그 남음, ROLLBACK 가능. 테이블 구조 유지.
  • TRUNCATE (DDL) : 전체 행을 한 번에 삭제(빠름, 되돌리기 어려움). 테이블 구조는 유지.
  • DROP (DDL) : 테이블 구조 자체를 삭제 (데이터 + 정의 모두 제거).

상황쿼리

서브쿼리 (IN · ALL ❗ · ANY=SOME · EXISTS)

종류쿼리 / 반환 조건
INSELECT 컬럼1, 컬럼2 ... FROM 테이블 WHERE 컬럼1 IN (SELECT 컬럼명 FROM 다른테이블 WHERE 조건); (서브쿼리 값 중 컬럼1이 어느 하나라도 일치하면 반환)
ALL ❗SELECT 컬럼1, 컬럼2 ... FROM 테이블 WHERE 컬럼1 > ALL (SELECT 컬럼명 FROM 다른테이블 WHERE 조건); (모든 서브쿼리 값 보다 컬럼1이 크면 반환)
ANY = SOMESELECT 컬럼1, 컬럼2 ... FROM 테이블 WHERE 컬럼1 > ANY (SELECT 컬럼명 FROM 다른테이블 WHERE 조건); (서브쿼리 값 중 컬럼1이 어느 하나보다 크면 반환)(ANY = SOME)
EXISTSSELECT 컬럼1, 컬럼2 ... FROM 테이블 WHERE EXISTS (SELECT 컬럼명 FROM 다른테이블 WHERE 조건); (서브쿼리 값 중 어느 하나라도 일치하는 튜플 반환)
🔍 배경설명 — ALL / ANY / EXISTS 동작 원리
  • > ALL : 서브쿼리 결과의 최댓값보다 커야 참 (모든 값보다 커야 하므로). ↔ < ALL = 최솟값보다 작아야.
  • > ANY(=SOME) : 서브쿼리 결과의 최솟값보다 크면 참 (하나라도 만족하면 됨). ↔ < ANY = 최댓값보다 작으면.
  • IN = = ANY 와 동일  /  NOT IN = <> ALL 과 동일.
  • EXISTS : 값 비교가 아니라 서브쿼리가 행을 1개라도 반환하는지(존재 여부)만 판단 (주로 상관 서브쿼리와 사용).
  • 시험 함정 : "> ALL = 가장 큰 값보다 크다", "> ANY = 가장 작은 값보다 크다" 로 바꿔 생각하면 계산이 쉬움.

세타 조인

(내부 조인 · INNER는 생략가능)

(ON 사용X)

외부 조인
(LEFT/RIGHT/FULL OUTER JOIN) 조건에 일치하지 않는 튜플도 반환, 일치하지 않는 부분은 NULL로 채움
SELECT 테이블1.컬럼1, 테이블2.컬럼2 FROM 테이블1 LEFT/RIGHT/FULL OUTER JOIN 테이블2 ON 테이블1.컬럼1 = 테이블2.컬럼1;

(ON 사용X)
(CROSS JOIN) 모든 튜플 조합 반환
SELECT 테이블1.컬럼1, 테이블2.컬럼2 FROM 테이블1 CROSS JOIN 테이블2; SELECT 테이블1.컬럼1, 테이블2.컬럼2 FROM 테이블1, 테이블2;
🔍 배경설명 — JOIN 종류 한눈에 구별
  • 세타 조인 : 비교 연산자(=, >, <, ≥ 등) 아무거나로 결합하는 가장 일반적인 조인.
  • 동등 조인 : 세타 조인 중 = (등호)로만 결합 → 공통 속성이 양쪽에 중복되어 남음.
  • 자연 조인 : 동등 조인에서 중복 속성 하나를 자동 제거 (ON 없이 같은 이름 속성 기준).
  • 외부 조인 : 조건에 안 맞는 튜플도 살림(LEFT/RIGHT/FULL). 빈 쪽은 NULL로 채움.
  • 교차 조인 : 조건 없이 모든 조합(카티션 곱). 결과 행 수 = 두 테이블 행 수의 곱.

2) 트랜잭션 ⭐

(1) ACID ❗

트랜잭션 특성키워드
원자성 (Atomicity) ❗All or Nothing, 모두 실행되거나 하나도 실행되지 않음

트랜잭션 상태 전이 ❗

활동(Active) → 부분완료(Partially Committed) → 완료(Committed) │ └→ 실패(Failed) → 철회(Aborted)
상태키워드
활동 (Active)트랜잭션이 실행 중인 상태
부분 완료 (Partially Committed)마지막 연산까지 실행했으나 COMMIT 전 상태
완료 (Committed)COMMIT 후 결과가 DB에 영구 반영된 상태
실패 (Failed)오류로 실행이 중단된 상태
철회 (Aborted)ROLLBACK으로 실행 이전으로 되돌아간 상태

(2) 회복 기법 핵심요소 ❗

핵심요소키워드
Redo (재실행) ❗장애 발생 전 DB로 복구, 시작(Start)/완료(Commit) 기록 필요
UNDO (취소) ❗작업 모두 취소, 시작(Start)있지만 완료(Commit) 기록 없는 경우
🔍 배경설명 — Redo vs Undo 판단 기준 (로그)
  • 로그에 Start + Commit 둘 다 있으면 → 완료됐으나 DB에 미반영일 수 있음 → Redo(재실행).
  • 로그에 Start만 있고 Commit 없음 → 중간에 실패한 트랜잭션 → Undo(취소).
  • "커밋 기록이 있냐/없냐"로 Redo·Undo가 갈림. 지연 갱신 = Redo만, 즉각 갱신 = Redo+Undo 모두 필요.

6) 정규화 🔥

정규형조건
제1정규형 ❗모든 속성 값 = 원자값 (Atomic value)
제2정규형 ❗부분 함수 종속 제거 (완전 함수 종속 성립)

🔍 배경설명 — 각 정규형이 제거하는 것 (두문자: 원부이결다조)
  • 1NF : 반복·다치 속성을 없애 모든 값을 원자값으로. (원)
  • 2NF : 기본키 일부에만 종속되는 부분 함수 종속 제거. (부)
  • 3NF : 키가 아닌 속성끼리의 종속인 이행 함수 종속 제거. (이)
  • BCNF : 모든 결정자가 후보키가 되도록. (결)
  • 4NF : 다치 종속 제거 (다)  /  5NF : 조인 종속 제거 (조)
  • 순서 암기 = 원·부·이·결·다·조. 정규화 목적은 삽입·삭제·갱신 이상현상(Anomaly) 제거. 과도하면 조인 증가로 성능↓ → 반정규화로 절충.

RAID = 여러 개의 값싼 디스크를 묶어 하나처럼 쓰는 기술. 목적은 두 가지 — 속도(병렬 입출력)와 안정성(고장나도 데이터 보존). 세 가지 기법의 조합으로 레벨이 갈립니다.

  • 스트라이핑(Striping) : 데이터를 조각내 여러 디스크에 나눠 저장 → 동시에 읽어 속도↑. 대신 한 개만 고장나도 전체가 깨짐(안정성 최악). = RAID 0.
  • 미러링(Mirroring) : 같은 데이터를 두 디스크에 똑같이 복제 → 하나 죽어도 나머지로 복구(안정성↑). 대신 용량이 절반. = RAID 1.
  • 패리티(Parity) : 원본은 나눠 저장하되, 오류 검출·복구용 계산값(패리티)을 함께 저장 → 디스크 1개 고장나면 패리티로 역산 복구. 미러링보다 용량 효율이 좋음. = RAID 5(패리티 1개)/RAID 6(패리티 2개, 2개까지 고장 허용).
  • 암기 포인트: 최소 디스크 수 → RAID 0·1 = 2개 / RAID 5 = 3개 / RAID 6·10 = 4개. "패리티 = 복구 가능한 검사값"이 핵심(단순 백업 아님).

DAS·NAS·SAN(스토리지 연결 방식)도 함께 출제 — DAS: 서버에 직접 케이블 연결(전용·빠름) / NAS: LAN(네트워크)에 연결된 파일 저장장치(공유 쉬움) / SAN: 스토리지 전용 고속 네트워크(파이버채널, 대규모).

그 외 페이지 교체 알고리즘 ❗

알고리즘교체 기준
OPT (최적, Optimal) ❗앞으로 가장 오랫동안 사용되지 않을 페이지 교체 → 이론상 결함 최소지만 미래를 알아야 해 실현 불가 (다른 알고리즘의 성능 평가 기준, Belady 제안)

(Not Used Recently)		최근에 사용되지 않은 페이지 교체. 참조 비트(R)·변형 비트(M) 2개로 판단 → (R,M)=(0,0)부터 교체. LRU의 오버헤드를 줄인 근사 기법

🔍 배경설명 — NUR 비트 우선순위 & Belady의 이상현상

  • Belady의 이상현상(Anomaly) ❗ : FIFO에서 프레임 수를 늘렸는데 오히려 Page Fault가 증가하는 모순. (LRU·OPT는 발생 안 함 → 스택 알고리즘)
  • OPT·LRU·NUR·LFU는 최근/미래 참조를 근거로 하지만, FIFO는 도착 순서만 봐서 이상현상이 생김.

🔍 배경설명 — 데이터그램 vs 가상회선
  • 데이터그램(비연결형) : 경로 설정 없이 각 패킷이 독립적으로 서로 다른 경로 이동 가능 → 순서 뒤바뀔 수 있음. 각 패킷이 목적지 주소(헤더)를 가짐. (예: IP)
  • 가상회선(연결형) : 전송 전 논리적 경로를 미리 설정 → 모든 패킷이 같은 경로로 순서대로 도착. (예: ATM, 프레임 릴레이)
  • "미리 연결 O = 가상회선", "각자 알아서 = 데이터그램". 순서보장·신뢰성은 가상회선, 유연성·장애우회는 데이터그램.

🔍 배경설명 — 거리 벡터 vs 링크 상태
  • 거리 벡터 (RIP) : 인접 라우터끼리 전체 라우팅 테이블을 주기적으로 교환. 벨만-포드 알고리즘, 경로 기준 = 홉 수(최대 15홉 제한). 규모 작을 때 적합, 수렴 느림.
  • 링크 상태 (OSPF) : 각 라우터가 링크 상태 정보만 전파해 스스로 전체 지도를 그림. 다익스트라 알고리즘, 경로 기준 = 비용(대역폭). 큰 네트워크를 지역(Area)으로 분할.
  • 경로 벡터 (BGP) : 서로 다른 AS 간(외부, EGP) 경로 교환. 처음엔 전체, 이후 변경분만.
  • IGP(내부)=RIP·OSPF, EGP(외부)=BGP. RIP은 홉 수, OSPF는 비용으로 최단경로 판단.

🔍 배경설명 — ARP/RARP 방향 & 헷갈림 방지
  • ARP : IP(논리) → MAC(물리). "이 IP를 쓰는 장치의 MAC이 뭐야?" 통신 직전 상대 MAC을 알아낼 때.

  • ICMP : 오류·상태 메시지 전달(ping). Ping of Death가 이를 악용.
  • A로 시작(ARP)하면 IP→MAC 순방향, R이 붙으면(RARP) 반대. "ARP = IP로 MAC 찾기".

(2) 사용가능한 IP 주소 갯수 구하기 ❗

예 — 만약 서브넷마스크가 255.255.255.192 라면...

10진수 : 255.255.255.192 2진수 : 11111111.11111111.11111111.11000000

뒤의 0의 갯수 = IP주소 결정에 사용 가능한 비트 = 6개 → 2⁶ = 64개

⚖️ "전체 개수" vs "실제 할당 가능한 호스트 수" 구별 (함정!)
  • 블록 전체 IP 개수 = 2⁶ = 64개 (네트워크 주소·브로드캐스트 주소 포함)
  • 실제 호스트에 할당 가능한 수 = 64 − 2 = 62개 (맨 앞 네트워크 주소 + 맨 뒤 브로드캐스트 주소 제외)
  • → 문제가 "호스트 수 / 할당 가능한 IP 수"를 물으면 −2, "전체 개수"를 물으면 그대로. 문구를 꼭 확인!

🔍 배경설명 — 커버리지 강도가 커지는 이유 (구문<결정<조건<조건/결정<MC/DC)
  • 구문(Statement) : 모든 문장을 최소 1번 실행 (가장 약함).
  • 결정(Decision/Branch) : 각 분기의 참/거짓 결과를 모두 실행.
  • 조건(Condition) : 결정문 내부의 개별 조건식 각각을 T·F 되도록 (결정 결과는 무관).
  • 조건/결정 : 조건 + 결정을 둘 다 만족.
  • MC/DC : 각 조건이 독립적으로 결정 결과에 영향을 주는 경우까지 (가장 강력, 항공 등).
  • 뒤로 갈수록 요구 테스트 케이스↑ · 강력함↑. 화이트박스 = 내부 로직(코드)을 보고 설계.

  • 옵저버 : 상태 변화를 구독자에게 자동 통지(발행/구독, 예: 이벤트 리스너).
  • 전략 : 알고리즘을 캡슐화해 런타임 교체 ↔ 템플릿 메서드 : 골격은 상위, 세부는 하위에서 구현.
  • 분류 = 생성(객체 생성 방식) / 구조(클래스·객체 조합) / 행위(객체 간 상호작용·책임 분배).

2) 응집도, 결합도 🔥

응집도 - 모듈 내부의 요소들이 얼마나 밀접하게 관련되어 있는지
결합도 - 모듈과 모듈 간의 상호 의존 정도

암기법 · 응집도 : “우리 논산 시절 통통한 순대 기억나?” (우논시절통순기) · 결합도 : “내공 외제차 안맞게 스있자” (내공외제스자)

응집도 (cohesion) — 표 순서: 응집도 강할수록 위쪽 ❗

응집도키워드
기능적 (Functional cohesion) ❗모든 기능 단일 목적 위해 수행
순차적 (Sequential cohesion) ❗이전 출력을 다음 입력으로 사용
통신적(교환적) (Communicational cohesion) ❗동일한 입력 출력 사용
절차적 (Procedural cohesion) ❗입출력간 연관성 X, but 순서에 따라 수행
시간적 (Temporal cohesion)특정 시간에 처리
논리적 (Logical cohesion)논리적 유사하지만 실제로는 다른 기능
우연적 (Accidental cohesion)모듈 내부 요소 연관 없음

결합도 (coupling) — 표 순서: 결합도 강할수록 위쪽 ❗

결합도키워드
내용 (Content coupling) ❗모듈 내부 변수
공통 (Common coupling) ❗전역 변수 참조 갱신
외부 (External coupling)외부 데이터 사용
제어 (Control coupling) ❗제어 신호(요소)를 이용하여 통신
스탬프 (Stamp coupling) ❗자료구조(배열, 객체, 구조 등) 전달
자료 (Data coupling)파라미터 통해서 전달
🔍 배경설명 — 좋은 설계 = 응집도 高 · 결합도 低 (순서 이유)
  • 응집도(강→약) : 기능적 > 순차적 > 통신적 > 절차적 > 시간적 > 논리적 > 우연적. 위로 갈수록 한 가지 일에 집중 → 좋음.
  • 결합도(강→약) : 내용 > 공통 > 외부 > 제어 > 스탬프 > 자료. 아래로 갈수록 의존이 느슨 → 좋음.
  • 제어 결합도(제어 신호로 상대 내부 흐름 좌우) ↔ 스탬프(자료구조 전체 전달) ↔ 자료(필요한 값만 파라미터로).
  • 목표는 응집도 ↑ + 결합도 ↓. 두 표 모두 "강한 것이 위" → 응집도는 위가 좋고, 결합도는 아래가 좋다.

접근 통제 방식키워드
DAC (임의적) ❗신분/식별자 기반, 사용자가 다른 사용자를 자신의 판단따라 권한 허용

⚖️ DAC vs MAC vs RBAC

  • MAC(강제적) : 중앙이 규칙(보안 등급)으로 강제. 소유자도 임의 변경 불가. 군사·강력 보안.

트리 순회 (Traversal) ❗

A / \ B C / \ D E 전위 (Preorder, root→L→R) : A B D E C 중위 (Inorder, L→root→R) : D B E A C 후위 (Postorder, L→R→root) : D E B C A

🗄️ DB·SQL 보강 ❗

(1) SQL 내장(단일행) 함수 ❗🔥

단일행(Single-row) 함수는 행(row) 하나마다 계산해 행 하나를 돌려주는 함수다. 입력 행 수 = 출력 행 수. 반대로 집계(다중행) 함수는 여러 행을 묶어 하나의 값으로 요약한다. 이 "행 수가 그대로냐(단일행) / 줄어드냐(집계)" 가 둘을 가르는 핵심 구별점

분류대표 함수 · 기능
문자UPPER/LOWER(대·소문자) · SUBSTR(s,시작,길이)(부분추출) · LENGTH(길이) · CONCAT(a,b)(연결) · TRIM(양끝 공백제거) · REPLACE(s,a,b)(치환)
숫자ROUND(n,자리)(반올림) · TRUNC(n,자리)(버림·절사) · MOD(a,b)(나머지) · ABS(절댓값) · CEIL(올림·천장) · FLOOR(내림·바닥)
날짜SYSDATE(현재 날짜·시각) · ADD_MONTHS(d,n)(n개월 가감)
변환TO_CHAR(숫자·날짜→문자) · TO_DATE(문자→날짜) · TO_NUMBER(문자→숫자)
NULL 처리NVL(a,b)(a가 NULL이면 b) · NVL2(a,b,c)(NULL 아니면 b, NULL이면 c) · COALESCE(a,b,c…)(첫 번째 NOT NULL) · NULLIF(a,b)(a=b면 NULL, 아니면 a)
-- 이름 첫 3글자 대문자 + 부서 NULL은 '미배정' SELECT UPPER(SUBSTR(NAME,1,3)) AS ABBR, NVL(DEPT,'미배정') AS DEPT FROM EMP; -- ROUND vs TRUNC (소수 첫째자리) SELECT ROUND(3.146,1), -- 3.1(반올림) TRUNC(3.146,1); -- 3.1(버림) ※ROUND(3.156,1)=3.2, TRUNC=3.1
🔍 배경설명 — 단일행 vs 집계, ROUND/TRUNC/MOD, NVL 계열

단일행 함수는 SELECT·WHERE 절 어디서든 쓸 수 있고 결과 행 수를 바꾸지 않는다. 집계 함수(SUM/AVG/COUNT/MAX/MIN)는 GROUP BY와 짝을 이뤄 그룹당 한 값을 낸다.

  • ROUND / TRUNC : 둘 다 자릿수를 받지만 ROUND는 반올림, TRUNC는 무조건 버림. 음수 자릿수를 주면 정수부를 처리 ROUND(1278,-2)=1300
  • MOD(a,b) : a를 b로 나눈 나머지. 홀·짝 판별(MOD(n,2))에 단골 출제
  • NVL2 : NVL이 인수 2개인 데 반해 NVL2는 3개 — "값이 있을 때/없을 때"를 각각 지정
  • NULLIF(a,b) : 두 값이 같으면 NULL을 반환(0으로 나누기 방지 등에 활용)
  • 암기 : 올림=CEIL(천장), 내림=FLOOR(바닥), 버림=TRUNC / 문자→날짜는 TO_DATE, 날짜→문자는 TO_CHAR (방향 헷갈리기 쉬움)

(2) 뷰(VIEW)의 장단점 ⭐

뷰는 하나 이상의 기본 테이블로부터 유도된 이름을 가진 가상 테이블(Virtual Table)이다. 실제 데이터를 저장하지 않고 SELECT 정의문만 저장하며, 질의 시점에 그 정의가 실행된다. 그래서 물리적 저장이 없어 인덱스를 못 만든다

구분내용
장점① 논리적 데이터 독립성 — 기본 테이블 구조가 바뀌어도 뷰로 접근하면 영향 최소화
② 보안(접근 제어) — 사용자에게 필요한 열·행만 노출
③ 질의 단순화 — 복잡한 조인·조건을 뷰로 감싸 간단히 조회
단점① 독립적 인덱스 생성 불가
② 정의(ALTER) 변경 불가 — 수정하려면 DROP 후 재생성
③ 삽입·갱신·삭제 제약 — 그룹함수·DISTINCT·조인 등으로 만든 뷰는 갱신 불가

WITH CHECK OPTION ❗ : 뷰를 정의한 조건을 위반하는 INSERT·UPDATE를 거부하는 옵션. 예) 부서=10만 보이는 뷰에 부서=20 행을 넣으려 하면 차단

🔍 배경설명 — 뷰가 "가상"이라는 의미

뷰는 CREATE 시점에 데이터를 복사하지 않는다. 조회할 때마다 원본 테이블에서 다시 계산되므로 원본이 바뀌면 뷰 결과도 즉시 반영된다.

  • 기본 테이블 삭제 : 뷰가 참조하던 원본 테이블이 DROP되면 그 뷰는 자동으로 사용 불가
  • 구별 : "인덱스 못 만든다 / ALTER 못 한다 / 갱신 제약" 이 셋이 뷰 단점 3종 세트

(3) 커서(CURSOR) · 사용자정의함수(UDF) ⭐

커서는 SQL 실행 결과 집합을 한 행씩 가리키며 처리하기 위한 포인터다. SELECT가 반환하는 여러 행을 절차적으로 순회할 때 쓴다.

종류설명
묵시적 커서
(Implicit)		DBMS가 자동 생성·관리. 일반 SQL(INSERT/UPDATE/단일행 SELECT) 실행 시 내부적으로 열림. 개발자가 선언하지 않음
명시적 커서
(Explicit)		개발자가 직접 선언·제어. 여러 행을 반복 처리할 때 사용. DECLARE → OPEN → FETCH → CLOSE 4단계
DECLARE CURSOR c1 IS SELECT NAME FROM EMP; -- ①선언 v_name EMP.NAME%TYPE; BEGIN OPEN c1; -- ②결과집합 열기 LOOP FETCH c1 INTO v_name; -- ③한 행씩 가져오기 EXIT WHEN c1%NOTFOUND; -- 더 없으면 탈출 DBMS_OUTPUT.PUT_LINE(v_name); END LOOP; CLOSE c1; -- ④닫기(자원 해제) END;

사용자정의함수(UDF, User-Defined Function) : 사용자가 만들어 반드시 값을 하나 RETURN하는 프로시저성 객체. 프로시저와 달리 SELECT 문 안에서 호출해 쓸 수 있다. 저장 프로시저는 RETURN 없이 OUT 매개변수로 결과를 넘김 — 이게 UDF와의 차이

(4) 병행제어를 안 하면 생기는 문제 🔥

병행제어(Concurrency Control)는 여러 트랜잭션이 동시에 실행돼도 결과가 순차 실행과 같도록 보장하는 기법이다. 이를 안 하면 아래 4가지 이상 현상이 발생한다.

문제설명
갱신 손실
(Lost Update)		두 트랜잭션이 같은 데이터를 동시에 갱신할 때 한쪽의 변경이 다른 쪽에 덮여 사라지는 현상
현황 파악 오류
(Dirty Read)		한 트랜잭션이 아직 COMMIT되지 않은(중간) 값을 다른 트랜잭션이 읽어 잘못 처리 뒤에 롤백되면 읽은 값은 무효
모순성
(Inconsistency)		두 트랜잭션이 동시에 갱신하며 서로의 연산에 간섭해 데이터가 일관성을 잃는 현상
연쇄 복귀
(Cascading Rollback)		한 트랜잭션이 롤백될 때, 그 미완료 값을 참조했던 다른 트랜잭션들까지 연쇄적으로 롤백되는 현상
🔍 배경설명 — Dirty Read와 Cascading Rollback의 연결

Dirty Read(미완료 값 읽기)가 허용되면, 원 트랜잭션이 실패해 롤백될 때 그 값을 이미 읽은 트랜잭션도 무효가 되어 함께 롤백해야 한다 — 이것이 연쇄 복귀다. 즉 둘은 원인·결과 관계.

  • 암기 4문제 : 갱손 · 현황(Dirty) · 모순 · 연쇄 — "갱현모연"

(5) 윈도우(순위) 함수 ❗⭐

윈도우 함수는 행을 그룹으로 줄이지 않고(집계와 달리 행이 유지됨), 각 행 옆에 그룹 내 순위·누계 등을 붙여 주는 분석 함수다. OVER(PARTITION BY 그룹 ORDER BY 정렬)로 창(window)을 지정한다.

함수동순위 처리 방식
RANK()공동 순위 부여 후 그 수만큼 건너뜀. 예) 1,1,3
DENSE_RANK()공동 순위 부여하되 건너뛰지 않음. 예) 1,1,2
ROW_NUMBER()동순위여도 무조건 유일한 연번. 예) 1,2,3
-- 부서(DEPT)별 급여 순위 + 부서별 급여 누계 SELECT NAME, DEPT, SAL, RANK() OVER(PARTITION BY DEPT ORDER BY SAL DESC) AS RNK, DENSE_RANK() OVER(PARTITION BY DEPT ORDER BY SAL DESC) AS DRNK, ROW_NUMBER() OVER(PARTITION BY DEPT ORDER BY SAL DESC) AS RN, SUM(SAL) OVER(PARTITION BY DEPT) AS DEPT_TOTAL -- 집계 윈도우 FROM EMP;
집계 함수 vs 윈도우 함수

집계는 GROUP BY로 행을 묶어 한 행으로 요약(원본 행 소멸). 윈도우는 SUM(SAL) OVER(PARTITION BY DEPT)처럼 원본 행을 그대로 두고 옆에 그룹 합계를 붙인다 — 상세와 요약을 한 번에 볼 수 있는 게 핵심.

(6) 반정규화(역정규화) 유형 🔥

반정규화(Denormalization)는 정규화된 테이블을 의도적으로 통합·중복·분리해 조회 성능을 높이는 기법이다. 조인·연산을 줄여 속도를 얻는 대신 데이터 중복으로 무결성 관리 부담이 커진다(성능↔무결성 트레이드오프). 정규화를 충분히 한 뒤, 성능 문제가 확인될 때 선택적으로 적용

유형설명
테이블 통합자주 함께 조회되는 두 테이블을 하나로 합쳐 조인 제거
테이블 분할수평 분할(행 기준, 예: 연도별 분리) / 수직 분할(열 기준, 자주 쓰는 컬럼만 분리)로 접근 부하 분산
중복 테이블 추가집계·이력 등을 담은 별도 테이블을 추가해 통계 조회를 빠르게(집계 테이블·이력 테이블)
중복 컬럼 추가조인으로 얻던 값을 같은 테이블에 복사해 조인 회피(예: 주문에 고객명 복제)
파생 컬럼 추가계산으로 얻는 값을 미리 저장(예: 총액 = 단가×수량을 컬럼으로)
🔍 배경설명 — 언제 반정규화하나

반정규화는 무조건 하는 게 아니라 정규화 → 성능 검토 → 필요 시 부분 적용의 순서다. 중복이 생기므로 원본과 복사본을 동시에 갱신해야 하는 갱신 이상 위험을 감수한다.

  • 수평 분할 : 행이 매우 많아 특정 범위만 자주 쓸 때(파티셔닝)
  • 수직 분할 : 컬럼이 많고 일부만 자주 접근할 때
  • 구별 : 컬럼(속성) 관련=중복컬럼·파생컬럼, 테이블 관련=통합·분할·중복테이블

(7) OLAP 연산 · OLTP 비교 ⭐

OLAP(OnLine Analytical Processing)은 다차원 데이터를 다양한 각도에서 분석하기 위한 처리다. 아래 연산으로 데이터를 요약·상세화·회전한다.

연산설명
롤업(Roll-up)상세 → 요약(상위 레벨로 집계). 예) 일별 → 월별 → 연별
드릴다운(Drill-down)롤업의 반대. 요약 → 더 상세한 하위 레벨로 파고듦
슬라이스(Slice)다차원 큐브를 한 차원 기준으로 잘라 2차원 단면 추출
다이스(Dice)여러 차원에 조건을 걸어 작은 부분 큐브를 뽑음(슬라이스를 여러 번)
피벗(Pivot)데이터의 축(행↔열)을 회전시켜 보는 관점을 바꿈
OLTP vs OLAP
구분OLTP / OLAP
목적OLTP : 실시간 트랜잭션 처리(주문·이체 등 삽입·갱신) / OLAP : 분석·의사결정 지원(조회 위주)
데이터OLTP : 현재·상세·정규화 / OLAP : 대량·요약·이력, 다차원
연산OLTP : 짧은 INSERT/UPDATE/DELETE 다수 / OLAP : 복잡한 SELECT 집계

(8) 해싱 오버플로우 해결 ❗🔥

해싱은 키 값을 해시 함수에 넣어 저장 주소(버킷)를 직접 계산하는 방식이다. 서로 다른 키가 같은 주소로 계산되면 충돌(Collision)이고, 그 키들을 동의어(Synonym)라 한다. 버킷이 꽉 차 더 못 넣는 상태가 오버플로우(Overflow)다.

용어의미
버킷(Bucket)해시 주소 하나가 가리키는 저장 공간 단위(여러 슬롯 포함 가능)
슬롯(Slot)버킷 안에서 레코드 하나가 들어가는 칸
충돌(Collision)서로 다른 키가 같은 버킷 주소로 계산됨
동의어(Synonym)같은 주소로 충돌한 키들의 집합
해결법세부 방식
개방 주소법
(Open Addressing)		충돌 시 비어 있는 다른 버킷을 찾아 저장.
· 선형 탐사 : 다음 칸(+1, +2 …) 순차 탐색
· 이차 탐사 : +1², +2² … 제곱 간격으로 탐색(집중 완화)
· 이중 해싱 : 두 번째 해시 함수로 탐사 간격 결정
폐쇄 주소법
(Closed Addressing)		체이닝(Chaining) — 같은 주소의 동의어들을 연결 리스트로 매달아 저장. 오버플로우를 버킷 밖 연결로 해결
🔍 배경설명 — 개방 vs 폐쇄, 헷갈리는 이름

이름이 반대라 자주 틀린다. 개방 주소법은 "저장할 주소를 개방(다른 빈 칸으로 열어둠)"이라 테이블 내부의 다른 버킷을 쓴다. 폐쇄 주소법(체이닝)은 "주소는 고정(폐쇄)"하고 외부 연결 리스트로 확장한다.

  • 선형 탐사 단점 : 데이터가 특정 구간에 뭉치는 1차 군집(clustering) 발생 → 이차 탐사·이중 해싱으로 완화
  • 암기 : 개방=빈칸 찾기(선형/이차/이중해싱), 폐쇄=체이닝(연결리스트). "충돌한 동의어를 테이블 안에서(개방) vs 밖에 매달아서(폐쇄)"

🌐 네트워크·OS 보강 ❗

(1) 프로세스 vs 스레드 ❗

프로세스는 실행 중인 프로그램으로 운영체제로부터 자원을 할당받는 단위(독립된 메모리 공간 보유)이고, 스레드는 프로세스 내에서 실제로 실행되는 흐름(실행) 단위다. 한 프로세스 안의 스레드들은 코드(Code)·데이터(Data)·힙(Heap)을 공유하고 스택(Stack)만 각자 갖는다.

구분내용
프로세스(Process)자원 할당 단위. 독립된 메모리(Code·Data·Heap·Stack) 보유. 프로세스 간 통신은 IPC 필요, 문맥 교환 비용 큼
스레드(Thread)실행(CPU 스케줄링) 단위. Code·Data·Heap 공유, Stack·레지스터(PC)만 별도. 생성·전환 비용 작음
멀티스레드 장점자원 공유로 메모리 절약, 응답성·처리량 향상, 문맥 교환 오버헤드 감소, 병렬성
멀티스레드 단점공유 자원 동기화 문제(임계구역·교착), 한 스레드 오류가 전체 프로세스에 영향, 디버깅 어려움
사용자 레벨 스레드사용자 라이브러리가 관리. 전환 빠르나 커널이 인식 못해 한 스레드 블로킹 시 전체 블로킹
커널 레벨 스레드커널이 직접 관리·스케줄링. 개별 블로킹에 강하나 전환 오버헤드 큼
프로세스 vs 스레드

프로세스 = "무엇을 실행하려고 자원을 통째로 받은 것"(무거움, 독립).
스레드 = "그 안에서 실제로 도는 여러 갈래의 실행 흐름"(가벼움, 공유).

🔍 배경설명 — 왜 스택만 별도인가

스택에는 함수 호출·지역변수·복귀 주소가 쌓인다. 실행 흐름마다 호출 경로가 다르므로 스택은 반드시 스레드별로 분리해야 한다. 반면 코드·전역데이터·힙은 같은 프로세스라면 공유해도 무방하다.

  • PC/레지스터 : 각 스레드가 어디까지 실행했는지 기억해야 하므로 스레드마다 별도
  • 구별 포인트 — 공유(Code·Data·Heap) vs 개별(Stack·레지스터·PC)

(2) 흐름 제어(Flow Control) ❗

송신 측이 수신 측의 처리 능력보다 빠르게 보내 수신 버퍼가 넘치는(오버플로) 것을 막기 위해 전송량·속도를 조절하는 기법. 데이터 링크·전송 계층에서 수행된다.

기법설명
정지-대기
(Stop-and-Wait)		프레임 1개를 보내고 ACK를 받아야 다음 프레임 전송. 구현 단순하나 대기 시간 때문에 회선 이용률(효율) 낮음
슬라이딩 윈도우
(Sliding Window)		ACK 없이 윈도우 크기만큼 연속 전송 후, ACK를 받은 만큼 윈도우를 밀며 계속 전송. 회선 이용률 높음(TCP가 사용)
흐름 제어 vs 오류 제어

흐름 제어 = 속도(양) 조절 — 빠른 송신자로부터 느린 수신자 보호(오버플로 방지).
오류 제어 = 손상·유실 복구 — 검출(패리티·CRC) 후 재전송(ARQ)으로 프레임 손상/분실 처리.

(3) TCP/IP 4계층 + OSI 7계층 대응 ❗

인터넷 표준 통신 규약. 4개 계층으로 구성되며 OSI 7계층과 아래와 같이 매핑된다.

TCP/IP 계층주요 프로토콜 / OSI 대응
응용 계층HTTP, FTP, SMTP, POP3, DNS, Telnet, SNMP · OSI 5~7(세션·표현·응용)
전송 계층TCP(신뢰·연결형), UDP(비신뢰·비연결형) · OSI 4(전송)
인터넷 계층IP, ICMP, IGMP, ARP, RARP · OSI 3(네트워크)
네트워크 액세스 계층Ethernet, PPP, 토큰링, 802.11(물리 매체 접근) · OSI 1~2(물리·데이터링크)
[ OSI 7 ] [ TCP/IP 4 ] 7 응용 ┐ 6 표현 ├─────────────→ 응용 계층 5 세션 ┘ 4 전송 ───────────────→ 전송 계층 3 네트워크 ───────────→ 인터넷 계층 2 데이터링크 ┐ 1 물리 ┴────────→ 네트워크 액세스 계층
TCP=신뢰성 있는 연결형(3-way handshake), UDP=속도 우선 비연결형(스트리밍·DNS)

(4) PCB(프로세스 제어 블록) ❗

Process Control Block — 운영체제가 각 프로세스를 관리하기 위해 프로세스에 관한 모든 정보를 저장하는 자료구조. 프로세스 생성 시 만들어지고 종료 시 제거되며, 문맥 교환 시 상태 저장·복원의 대상이 된다.

구성요소설명
PID프로세스 고유 식별 번호
프로세스 상태생성·준비·실행·대기·종료 등 현재 상태
프로그램 카운터(PC)다음에 실행할 명령어의 주소
레지스터·문맥 정보CPU 레지스터 값 등 실행 문맥(Context)
스케줄링 정보우선순위, 스케줄링 큐 포인터
메모리 관리 정보베이스·한계 레지스터, 페이지·세그먼트 테이블
계정·입출력 정보CPU 사용 시간, 할당된 I/O 장치·열린 파일 목록

(5) TCP 4-way handshake(연결 해제) ❗

TCP는 양방향 연결이므로 양쪽이 각각 FIN을 보내 종료해야 하며, 이 때문에 4단계가 필요하다. 연결 설정은 3-way(SYN → SYN+ACK → ACK)다.

클라이언트 서버 | ── FIN ──────────────────→ | ① 종료 요청 | ←──────────────── ACK ── | ② 수신 확인 | (서버 잔여 전송) | | ←──────────────── FIN ── | ③ 서버도 종료 요청 | ── ACK ──────────────────→ | ④ 확인 | (TIME_WAIT 후 CLOSED) |

TIME_WAIT : 마지막 ACK를 보낸 클라이언트가 일정 시간 대기하는 상태. 뒤늦게 도착하는 패킷 처리 및 상대의 FIN 재전송에 대비해 연결을 즉시 닫지 않는다.

3-way(연결) vs 4-way(해제)

3-way = SYN → SYN+ACK → ACK (서버의 ACK·SYN을 한 번에 합침).
4-way = FIN → ACK → FIN → ACK (수신 측이 남은 데이터 전송을 마쳐야 하므로 ACK와 FIN을 분리).

(6) 혼잡 제어(Congestion Control) ❗

네트워크 내부(라우터)에 패킷이 몰려 혼잡(폭주)이 발생하는 것을 막기 위해 송신 측이 전송량을 조절하는 기법. 혼잡 윈도우(cwnd)를 조정한다.

기법설명
느린 시작
(Slow Start)		cwnd를 1부터 시작해 ACK마다 지수적으로 2배씩 증가. 임계치(ssthresh) 도달 시 혼잡 회피로 전환
혼잡 회피
(Congestion Avoidance)		임계치 이후에는 1씩 선형 증가시켜 완만하게 대역폭 탐색
AIMD합 증가·곱 감소. 평상시엔 선형 증가(Additive Increase), 혼잡 감지 시 윈도우를 절반으로 감소(Multiplicative Decrease)
흐름 제어 vs 혼잡 제어

흐름 제어 = 수신자 보호 — 수신 버퍼 오버플로 방지(수신 윈도우 rwnd).
혼잡 제어 = 네트워크 보호 — 라우터·회선 혼잡 방지(혼잡 윈도우 cwnd).

TCP 실제 전송량 = min(rwnd, cwnd) — 흐름·혼잡 제어 중 더 작은 쪽을 따른다.

(7) 문맥 교환(Context Switching) ❗

CPU가 실행하던 프로세스(또는 스레드)를 잠시 멈추고 다른 프로세스로 전환할 때, 현재 프로세스의 상태(문맥)를 PCB에 저장하고 다음 실행할 프로세스의 상태를 PCB에서 복원하는 과정이다.

구분내용
저장(Save)실행 중이던 프로세스의 PC·레지스터·상태를 해당 PCB에 저장
복원(Restore)다음 프로세스의 PCB에서 문맥을 읽어 CPU 레지스터에 복원 후 실행 재개
발생 시점인터럽트, 타임 슬라이스 만료, I/O 요청, 우선순위 선점 등
오버헤드저장·복원 동안 CPU는 유용한 작업을 못 함 → 잦은 전환은 성능 저하. 스레드 전환이 프로세스 전환보다 오버헤드 작음
🔍 배경설명 — 오버헤드가 왜 생기나

문맥 교환 자체는 사용자 작업을 진행시키지 않는 순수 관리 비용이다. 프로세스 전환 시엔 메모리 맵(주소 공간)까지 바꿔 캐시·TLB가 무효화되어 비용이 더 크다.

  • 스레드 전환 : 같은 주소 공간을 공유해 메모리 맵 교체가 없어 상대적으로 가볍다
  • 구별 포인트 — 문맥 교환은 멀티태스킹을 가능케 하지만, 지나치면 오버헤드로 처리량이 떨어진다

🧪 SW개발·테스트 보강 ❗

(1) 결함·오류·장애 용어 구분 ❗🔥

테스트에서 가장 헷갈리는 4대 용어. 사람의 실수에서 시작해 시스템 장애까지 이어지는 인과 체인으로 외우면 정확하다.

Mistake(에러·사람 실수) ─▶ Fault/Defect/Bug(결함, 코드에 심김) ─▶ Error(오류, 실행 중 잘못된 상태) ─▶ Failure(장애, 요구와 다른 동작)
용어의미
에러(Mistake)사람(개발자)의 실수. 잘못 생각하거나 잘못 입력한 인간의 행위. 결함의 원인.
결함·버그(Fault·Defect·Bug)실수의 결과로 코드·산출물 안에 심긴 잘못. 정적으로 존재. 결함(Defect)=버그(Bug)=Fault 동의어.
오류(Error)결함이 실행되어 프로그램이 잘못된 내부 상태에 빠진 것. 아직 겉으로 안 드러날 수 있음.
장애·실패(Failure)오류가 드러나 시스템이 요구사항과 다르게 동작하는 것. 사용자가 체감하는 고장.
🔍 배경설명 — 인과 체인

정처기 실기 단골. "사람의 실수 → 코드의 결함 → 실행 중 오류 → 겉으로 드러난 장애" 순서를 정확히 답해야 한다.

  • Mistake : 사람이 저지름(원인)
  • Fault/Defect/Bug : 코드에 남음(정적)
  • Error : 실행 중 잘못된 상태(동적, 내부)
  • Failure : 요구와 다른 동작(외부로 표출)
  • 구별: Error는 아직 안 드러난 잘못된 상태, Failure는 실제로 표출된 고장이다. Fault는 정적, Error/Failure는 동적.

(2) 정적 테스트 vs 동적 테스트 + 리뷰 기법 ❗

정적 테스트는 코드를 실행하지 않고 산출물을 검토, 동적 테스트는 프로그램을 실행하며 검사한다.

정적 테스트 vs 동적 테스트
정적 : 실행 X · 명세/코드 자체 검토 · 인스펙션·워크스루·동료검토·코드 인스펙션
동적 : 실행 O · 결과 관찰 · 화이트박스·블랙박스 테스트
리뷰 기법설명
동료검토(Peer Review)2~3명 동료가 작성자 설명을 들으며 결함을 찾는 가장 비공식적 형태.
워크스루(Walkthrough)비공식·작성자 주도. 회의 전 산출물 배포, 짧은 회의로 오류 조기 검출. 준비 부담 적음.
인스펙션(Inspection)공식·체크리스트 기반. 진행자(중재자)가 주도, 역할 분담·기록·후속조치까지 하는 가장 엄격한 정적 검토.
🔍 배경설명 — 인스펙션 vs 워크스루

둘 다 정적 검토지만 공식성이 핵심 구별점.

  • 워크스루 : 비공식, 작성자(개발자)가 주도, 체크리스트 없어도 됨
  • 인스펙션 : 공식, 중재자(제3자)가 주도, 체크리스트로 결함 유형별 점검
  • 구별: "누가 주도하나?"로 답 — 작성자면 워크스루, 중재자·체크리스트면 인스펙션이다.

(3) 테스트 자동화 도구 ❗

도구용도
xUnit단위(Unit) 테스트 프레임워크 계열. JUnit(자바)·NUnit(.NET)·CppUnit(C++).
Selenium웹 애플리케이션 UI 자동화 테스트(브라우저 조작).
STAF서비스 호출·컴포넌트 재사용 지원 테스트 자동화 프레임워크.
FitNesse위키 기반 웹 인수 테스트 프레임워크(테이블로 입력·기대값 작성).

(4) 소프트웨어 테스트 기본 원리 7가지 ❗🔥

원리설명
결함 존재 밝힘테스트는 결함이 있음을 보일 뿐, 없음(완벽)은 증명 못 한다.
완벽한 테스팅 불가능모든 입력·경로를 다 테스트할 수 없다(무한 조합). 리스크 기반으로 선택.
초기 집중(Early Testing)개발 초기 단계부터 테스트 시작 — 결함을 일찍 잡을수록 비용 절감.
결함 집중(파레토 법칙)결함의 대부분(80%)이 소수 모듈(20%)에 몰려 있다.
살충제 역설같은 테스트 케이스를 반복하면 더는 새 결함이 안 나온다 → 케이스를 주기적으로 개선.
정황(맥락) 의존테스트는 소프트웨어 종류·상황에 따라 다르게 수행(안전필수 SW는 더 엄격).
오류 부재의 궤변결함을 다 없애도 사용자 요구에 안 맞으면 좋은 SW가 아니다.
🔍 배경설명 — 살충제 역설 vs 오류 부재의 궤변

두 원리를 자주 혼동한다.

  • 살충제 역설 : 같은 케이스 반복 → 효과 소멸 → 케이스 갱신 필요
  • 오류 부재의 궤변 : 버그 0이어도 요구 불충족이면 무의미
  • 구별: 살충제는 테스트 케이스 얘기, 궤변은 사용자 요구 충족 얘기다.

(5) V&V — 검증(Verification) vs 확인(Validation) ❗

Verification vs Validation
Verification(검증) : "제대로(올바르게) 만들고 있나?" · 명세·중간 산출물 기준 · 개발자 관점 · 정적
Validation(확인) : "올바른 것을 만들었나?" · 사용자 요구 기준 · 사용자 관점 · 최종 제품
구분핵심
VerificationAre we building the product right? — 명세대로 만들고 있는지(리뷰·인스펙션).
ValidationAre we building the right product? — 사용자가 원하는 것을 만들었는지(실사용 테스트).

(6) 결함 관리 ❗

결함 관리 프로세스: 등록 → 검토 → 할당 → 수정 → 재확인(재테스트) → 종료(모니터링)

결함 등록 ─▶ 결함 검토 ─▶ 결함 할당 ─▶ 결함 수정 ─▶ 결함 재확인 ─▶ 결함 종료
구분설명
심각도(Severity)결함이 시스템에 미치는 영향도의 크기(치명적·주요·보통·경미).
우선순위(Priority)결함을 처리(수정)할 순서(즉시·높음·보통·낮음).
결함 추이 분석시간·모듈별 결함 발생 추세를 분석해 품질 예측·개선점 도출.
🔍 배경설명 — 심각도 vs 우선순위

둘은 별개다. 영향 큰 결함이라도 급하지 않을 수 있다.

  • Severity : 영향의 크기(객관적)
  • Priority : 고칠 순서(비즈니스 판단)
  • 구별: 예) 잘 안 쓰는 화면의 다운(심각도 高)보다, 자주 보는 로고 오타(심각도 低)를 먼저 고칠 수 있음 → 우선순위는 심각도와 무관할 수 있다.

(7) 회귀 테스트(Regression Test) ❗

코드를 수정한 뒤, 그 변경이 기존 정상 기능에 영향(부작용)을 주지 않았는지 다시 확인하는 테스트.

항목설명
목적수정·기능 추가로 인한 기존 기능의 결함(부작용) 방지.
테스트 케이스 선정모든 변경에 영향받는 모듈 케이스 + 자주 실패하는 케이스 + 핵심 기능 케이스 선별.

전체 재수행은 비용이 크므로, 변경 영향 범위 중심으로 케이스를 선정해 수행한다.

(8) DRM 구성요소 ❗

DRM(Digital Rights Management): 디지털 콘텐츠의 불법 복제 방지·저작권 보호 기술.

구성요소설명
암호화(Encryption)콘텐츠·라이선스를 암호화해 보호.
키 관리(Key Management)콘텐츠 암·복호화에 쓰는 키의 저장·분배 관리.
식별 기술(DOI)DOI(Digital Object Identifier) 등 콘텐츠에 고유 식별자 부여.
저작권 표현라이선스·이용 조건을 메타데이터로 표현.
정책 관리(Policy)이용 규칙(재생·복사·기간 등) 설정·관리.
크랙 방지불법 해제·변조를 막는 탬퍼 방지(Tamper Resistance).
인증(Authentication)사용자·기기의 정당한 이용 권한 확인.
워터마킹(Watermarking)콘텐츠에 비가시 저작권 정보를 삽입해 출처 추적.

(9) 빌드 자동화·CI 도구 ❗

소스 컴파일·테스트·패키징을 자동화하는 빌드 도구와, 변경을 자주 통합·검증하는 CI(지속적 통합) 개념.

도구/개념설명
AntXML 기반 자바 빌드 도구(초기, 절차 기술).
MavenXML(pom.xml) 기반, 의존성 관리와 표준 빌드 라이프사이클 제공.
GradleGroovy/Kotlin DSL 기반, 유연·고성능 빌드(안드로이드 공식).
Jenkins대표적 CI 서버 — 빌드·테스트·배포 파이프라인 자동화.
🔍 배경설명 — CI vs CD

빌드 자동화 위에 통합·배포 자동화가 얹힌다.

  • 빌드 자동화 : 소스 → 컴파일·테스트·패키징(Ant·Maven·Gradle)
  • CI(지속적 통합) : 변경을 자주 병합·자동 빌드/테스트해 충돌 조기 발견(Jenkins)
  • CD(지속적 배포/전달) : 통합 산출물을 자동으로 배포까지 이어감
  • 구별: CI는 통합·검증 단계, CD는 그 뒤의 배포 단계다.

🔐 보안·신기술 보강 ❗

(1) 보안 솔루션 통합표 🔥

경계(방화벽)→탐지(IDS)→차단(IPS)→통합관리(ESM/SIEM/SOAR) 순으로 어디서 무엇을 하는지 위치를 잡고 외우면 헷갈리지 않는다.

솔루션한 줄 정의
방화벽 (Firewall)사전 정의된 정책(IP/Port)으로 내·외부 트래픽을 허용/차단하는 접근통제 1차 방어선
IDS침입 탐지 시스템 — 공격 패턴을 감지해 경고(알림)만 함. 직접 차단 X (수동적)
IPS침입 방지 시스템 — 탐지 + 실시간 자동 차단까지 수행 (능동적)
WAF (웹방화벽)웹 애플리케이션 계층 전용 방화벽 — SQL Injection·XSS 등 웹 공격 차단
UTM방화벽·IPS·백신·VPN 등 여러 보안기능을 하나의 장비로 통합한 통합위협관리
NAC네트워크 접근제어 — 접속 단말의 인증·보안상태를 검사해 접속 허용/격리
DLP데이터 유출 방지 — 내부 기밀 데이터가 외부로 새는 것을 감시·차단
ESM기업 보안관리 — 방화벽·IDS 등 이기종 보안장비의 이벤트를 중앙에서 통합 관제
SIEM 🔥보안 정보·이벤트 관리 — 전사의 로그·이벤트를 통합 수집·상관분석해 위협 탐지 (ESM의 진화형)
SOAR 🔥보안 오케스트레이션·자동화·대응 — SIEM이 탐지한 사고를 플레이북 기반으로 자동 대응
허니팟 (Honeypot)공격자를 유인하는 미끼(가짜) 시스템 — 공격 기법 수집·분석
VPN가상 사설망 — 공용망 위에 암호화 터널을 만들어 안전한 원격 통신 제공
🔍 배경설명 — WAF / SIEM / SOAR

세 개는 계층이 다르다. WAF는 방어 장비, SIEM은 분석·탐지, SOAR는 대응 자동화다.

  • WAF : 일반 방화벽은 IP/Port(3·4계층)만 보지만, WAF는 HTTP 요청 내용(7계층)까지 검사해 웹 전용 공격을 막는다. (예: OWASP Top10)
  • SIEM : 흩어진 로그를 한곳에 모아 상관분석(correlation)으로 개별 로그만으로는 안 보이는 공격 징후를 찾아낸다. 사람이 판단.
  • SOAR : SIEM이 "무엇이 일어났나"까지라면 SOAR는 "그래서 자동으로 무엇을 할까"를 담당. 플레이북으로 IP 차단·계정 잠금 등을 자동 실행해 대응 속도를 높인다.
  • 구별: IDS=탐지·경고 / IPS=탐지+차단 / ESM→SIEM(로그 상관분석 강화)→SOAR(대응 자동화) 순으로 발전.

(2) 사회공학 공격 ❗🔥

기술이 아니라 사람의 심리·신뢰를 노려 정보를 탈취하는 공격. 공격 매체(경로)로 구분하는 게 핵심 — 매우 빈출.

공격설명 (매체/특징)
피싱 (Phishing)정상 기관을 사칭한 가짜 이메일·웹사이트로 개인정보·금융정보 탈취
스미싱 (Smishing)SMS + Phishing — 문자메시지의 악성 링크로 앱 설치·정보 탈취 유도
파밍 (Pharming)DNS 변조(hosts 파일 조작 등)로 정상 주소 입력해도 가짜 사이트로 자동 접속
큐싱 (Qshing)QR코드 + Phishing — 악성 QR코드를 스캔하게 해 악성 앱 설치·피싱 유도
스피어피싱 (Spear Phishing)불특정 다수가 아닌 특정 개인·조직을 표적으로 맞춤 제작한 정밀 피싱
보이스피싱 (Vishing)Voice + Phishing — 전화 통화로 기관을 사칭해 금융정보·이체 유도
🔍 배경설명 — 피싱 vs 파밍

둘 다 가짜 사이트로 유도하지만 방법이 다르다.

  • 피싱 : 사용자가 가짜 링크를 직접 클릭하도록 유인 (미끼 낚시).
  • 파밍 : 사용자가 정확한 주소를 입력해도 DNS/hosts 변조로 가짜 사이트에 도달 → 사용자가 알아채기 더 어렵다.
  • 구별 포인트: "매체"로 이름이 갈린다 — SMS=스미싱, QR=큐싱, 전화=보이스피싱, 표적=스피어피싱.

(3) 인공지능 / 머신러닝 / 딥러닝 (신기술)

포함관계가 시험 포인트 → AI ⊃ ML ⊃ DL (AI가 가장 넓고 딥러닝이 가장 좁다).

구분설명
AI (인공지능)인간의 학습·추론·지각 능력을 컴퓨터로 구현하는 가장 넓은 개념
ML (머신러닝)데이터로부터 규칙(패턴)을 스스로 학습하는 AI의 한 분야
DL (딥러닝)다층 심층 신경망(Deep Neural Network) 기반의 ML 세부 기법
학습 방식설명
지도학습정답(라벨)이 있는 데이터로 학습 → 분류·회귀 (예: 스팸 분류)
비지도학습정답 없는 데이터의 숨은 구조 학습 → 군집화(Clustering)
강화학습행동에 대한 보상(reward)을 통해 최적 정책 학습 (예: 알파고)

신경망 종류 : CNN=이미지·영상 처리(합성곱), RNN=시계열·자연어 등 순차(시퀀스) 데이터 처리.

(4) 국산 대칭키 + 스트림 암호 ❗

국내 개발 대칭키(블록) 암호는 이름·특징으로 묶어 외운다. 모두 암·복호화에 같은 키를 쓰는 대칭키다.

암호특징
SEEDKISA 개발 128비트 블록 암호 (국내 표준, 전자상거래용)
ARIA학계·연구소·정부 공동 개발 경량 블록 암호 (128/192/256비트 키)
LEALightweight Encryption Algorithm — 고속·경량 블록 암호 (빅데이터·모바일)
HIGHT초경량 블록 암호 — IoT·RFID·센서 등 저전력 환경용 (64비트 블록)
블록 암호 vs 스트림 암호
  • 블록 암호 : 평문을 일정 크기 블록(예: 64/128비트) 단위로 나눠 암호화. (SEED·ARIA·LEA·HIGHT·AES·DES)
  • 스트림 암호 : 평문을 비트/바이트 단위로 연속 암호화 → 빠름, 실시간 통신에 유리. (예: RC4, LFSR 기반)
🔍 배경설명 — 스트림 암호

스트림 암호는 키스트림이라는 난수열을 만들어 평문과 XOR하는 방식이다.

  • RC4 : 대표적 스트림 암호. 구현이 간단하고 빠르나 취약점으로 현재는 비권장.
  • LFSR : 선형 피드백 시프트 레지스터 — 키스트림(난수) 생성에 쓰이는 하드웨어 구조.
  • 구별: 처리 단위가 핵심 — 블록=덩어리 단위, 스트림=비트/바이트 단위 연속.

(5) FIDO · SAML (인증)

기술설명
FIDOFast IDentity Online — 지문·홍채 등 생체정보 기반 인증 표준. 비밀번호를 대체(공개키 방식)
SAMLSecurity Assertion Markup Language — XML 기반으로 인증정보를 교환하는 SSO 표준
🔍 배경설명 — 인증 기술 정리 (SSO/OAuth/OTP와 비교)

기존 인증 기술을 보완·확장하는 관계로 이해하면 좋다.

  • SSO : 한 번 로그인으로 여러 시스템 이용. SAML은 이 SSO를 XML 표준으로 구현하는 대표 방식(서로 다른 도메인 간 인증정보 전달).
  • OAuth : 비밀번호 없이 제3자 서비스에 권한(인가)을 위임하는 프로토콜 (예: 구글 로그인).
  • OTP : 일회용 비밀번호 (매번 바뀜).
  • FIDO : 아예 비밀번호 없는(passwordless) 생체·기기 기반 인증으로 대체.
  • 구별: SAML=인증(SSO) 표준 / OAuth=인가(권한위임) / FIDO=생체 기반 무(無)비밀번호 인증.

(6) MITM (중간자 공격)

Man In The Middle — 통신하는 두 당사자 사이에 몰래 끼어들어 주고받는 데이터를 도청·가로채기·변조하는 공격. 양쪽은 서로 직접 통신한다고 착각한다. 대응: 종단 간 암호화(TLS)·인증서 검증.

(7) 개인정보 비식별화 ❗

개인을 식별할 수 없도록 데이터를 가공하는 기술. 처리 기법과 익명성 평가 모델을 구분해서 외운다.

비식별 기법설명
가명처리이름 등을 다른 값(가명)으로 대체 (홍길동 → 임꺽정)
총계처리개별 값을 합계·평균 등 통계값으로 대체 (홍길동 175cm → 평균 174cm)
데이터 삭제식별 가능한 항목 자체를 삭제 (주민번호 삭제)
범주화세부 값을 구간·범위로 일반화 (35세 → 30대)
데이터 마스킹일부를 *·공백 등으로 가림 (홍*동, 010-****-1234)
평가 모델설명
k-익명성같은 속성값을 가진 레코드가 최소 k개 존재 → 특정 개인 지목 곤란
l-다양성k-익명성 보완 — 각 그룹의 민감정보가 최소 l개로 다양 (동질성 공격 방어)
차등 프라이버시결과에 통계적 잡음(noise)을 추가해 개인 존재 여부를 알 수 없게 함

(8) PKI · 전자서명

PKI(공개키 기반구조) : 공개키 암호를 안전하게 쓰기 위한 인증서 발급·관리 체계.

구성요소설명
CA (인증기관)인증서를 발급·서명·폐기하는 신뢰의 핵심 주체
RA (등록기관)사용자 신원확인·등록을 대행 (CA 업무 분담)
인증서 (X.509)공개키 소유자를 증명하는 표준 전자문서 형식
CRL폐기된 인증서 목록 (Certificate Revocation List)

전자서명 : 송신자의 개인키로 서명, 수신자는 공개키로 검증. 무결성·인증·부인방지(서명 사실을 부정 못함)를 보장한다. 단, 기밀성은 제공하지 않음.

(9) 제로 트러스트 (Zero Trust)

"절대 신뢰하지 말고 항상 검증하라(Never Trust, Always Verify)"는 보안 모델. 내부/외부를 나눠 내부는 믿던 기존 경계 보안과 달리, 모든 접근을 매번 검증한다. 핵심 원칙: 최소 권한(Least Privilege) 부여.

(10) 엣지 · 포그 컴퓨팅 (신기술)

데이터를 멀리 있는 중앙 클라우드가 아니라 발생지 가까이에서 처리해 지연(latency)을 줄이고 트래픽을 절감하는 분산 컴퓨팅.

엣지 vs 포그
  • 엣지 컴퓨팅 : 단말(디바이스) 바로 근처(센서·게이트웨이 등 가장자리)에서 데이터를 처리.
  • 포그 컴퓨팅 : 단말과 클라우드 사이의 네트워크 계층(라우터·로컬 서버)에서 처리 → 엣지와 클라우드를 잇는 중간 층 개념.
  • 공통점: 둘 다 중앙 집중 클라우드의 지연·부하 문제를 해결하려는 분산 처리. IoT 환경에서 특히 유용.

🎨 SW설계·UML 보강 ❗

(1) UI 설계 산출물·도구 ❗

화면(UI)을 설계할 때 만드는 산출물은 충실도(정밀도)가 낮은 것에서 높은 것 순으로 발전한다. "무엇을 어디까지 표현하는가"로 구별한다.

산출물내용 · 특징
와이어프레임
(Wireframe)		화면의 뼈대·레이아웃만 선/박스로 표현. 색·디자인 없음. 요소 배치와 구조 확인용.
목업
(Mockup)		와이어프레임에 색·이미지·폰트를 입힌 정적 시안(실물 같은 겉모습). 동작은 안 함.
프로토타입
(Prototype)		클릭·화면전환 등 동작하는 모형. 인터랙션을 실제로 시험.
스토리보드
(Storyboard)		화면 + 설명 + 화면 흐름을 문서화한 최종 산출물. 디자이너·개발자 간 최종 지침서.
유스케이스 명세사용자와 시스템의 상호작용(시나리오)을 글로 서술한 명세.
와이어프레임(뼈대) → 목업(시안) → 프로토타입(동작) → 스토리보드(최종 문서)
🔍 배경설명 — 충실도(Fidelity)와 순서

충실도란 실제 완성품과 얼마나 닮았는가의 정도다. 와이어프레임은 저충실도, 프로토타입·스토리보드로 갈수록 고충실도다.

  • 와이어프레임 : 위치·구조만. "여기에 버튼이 온다"
  • 목업 : 정적이지만 실물처럼 보임. "이렇게 생겼다"
  • 프로토타입 : 눌러보면 반응함. "이렇게 동작한다"
  • 구별 : 스토리보드는 화면+설명+흐름까지 담은 최종 산출물이라는 점이 핵심. 목업/프로토타입은 특정 화면 표현, 스토리보드는 전체 흐름 문서.

(2) 코드체계(코드 분류) 종류 ❗🔥

데이터를 식별·분류하기 위해 부여하는 코드의 설계 방식. 예시로 구별하는 것이 시험 포인트다.

종류설명 · 예시
순차 코드
(Sequence)		일련번호를 순서대로 부여. 1, 2, 3, 4…
블록 코드
(Block)		공통 특성끼리 구간(블록)을 묶어 그 범위 안에서 번호 부여. 총무부 100~199, 영업부 200~299
그룹분류 코드
(Group)		대·중·소 그룹(자릿수 구간)으로 나눠 각 그룹에 의미 부여. 1-01-001
10진 코드
(Decimal)		10진 분류로 대분류→중분류→소분류 세분화. 도서 분류(KDC/DDC)식.
표의숫자 코드
(유효숫자)		대상의 물리적 수치(길이·넓이·무게 등)를 그대로 코드로. 지름100×길이200 → 100-200
연상 코드
(Mnemonic)		대상을 연상시키는 문자·기호로 표현. TV-40(40인치 TV), KR(한국)
합성 코드
(Combined)		둘 이상의 코드 방식을 조합. 예: 연상 + 순차.
표의숫자 코드 vs 연상 코드

표의숫자 = 대상의 실제 수치(물리량)를 코드화(100-200mm). 연상 = 대상을 떠올리게 하는 문자·약어로 코드화(TV-40, KR). 둘 다 "대상 자체를 표현"하지만 하나는 숫자 물리량, 하나는 연상 문자다.

(3) HIPO ❗

Hierarchy Input Process Output. 시스템의 입력·처리·출력 기능을 계층적으로 도식화하는 기법. 하향식(Top-Down) 개발·문서화 도구다.

도표(Chart)내용
가시적 도표
(도식 목차)		전체 기능을 계층(목차) 구조로 보여주는 트리. Visual Table of Contents.
총괄 도표
(개요 도표)		기능의 입력-처리-출력 관계를 개괄적으로 표현.
세부 도표
(상세 도표)		총괄 도표의 각 기능을 구체적으로 상세히 기술.

특징 : 하향식 소프트웨어 개발, 문서화·유지보수 용이, 기능과 자료의 의존관계 파악에 유리.

(4) N-S 차트(나시-슈나이더만) ❗

Nassi-Schneiderman Chart. 논리(제어) 흐름을 연속된 박스(상자)로만 표현하는 도구. GOTO·화살표가 없어 구조적 프로그래밍에 적합하다.

N-S 차트 vs 순서도(Flowchart)

순서도 : 화살표·분기선으로 흐름 표현 → GOTO식 임의 이동 가능, 논리 복잡해짐. N-S 차트 : 박스를 겹치고 채워 표현, 화살표·GOTO 사용 불가 → 흐름이 구조적으로 강제됨, 논리 오류 발견 쉬움. 단, 임의 제어이동 표현은 어렵고 복잡한 도표엔 부적합.

(5) 소프트웨어 아키텍처 품질 속성 ❗

아키텍처 관점에서 시스템이 갖춰야 할 품질 특성. (제품 품질 ISO/IEC 25010과는 별개로 아키텍처 설계에서 다루는 관점)

속성의미
가용성
(Availability)		장애 없이 정상 서비스가 가능한 정도(가동 유지).
변경 용이성
(Modifiability)		요구 변화에 맞춰 쉽게 수정·확장할 수 있는 정도.
성능
(Performance)		응답시간·처리량 등 요청을 빠르게 처리하는 능력.
보안성
(Security)		비인가 접근·공격으로부터 자원을 보호하는 능력.
사용성

표기의미
다중성

🔍 배경설명 — 가시성 기호 암기
  • + public : 누구나 접근(가장 개방)
  • − private : 해당 클래스 내부만(가장 폐쇄)

명세 원칙내용

(1) 이진트리 순회 (Traversal) ❗

이진트리의 모든 노드를 빠짐없이 한 번씩 방문하는 방법. 루트(root)를 언제 방문하느냐로 세 가지가 갈린다. L=왼쪽 서브트리, R=오른쪽 서브트리.

순회방문 순서 / 의미
전위 (Preorder)root → L → R · 루트를 먼저. 트리 복사·수식의 전위(Prefix) 표기
중위 (Inorder)L → root → R · 루트를 가운데. 이진탐색트리(BST)를 중위 순회하면 오름차순 정렬
후위 (Postorder)L → R → root · 루트를 마지막. 서브트리 삭제·수식의 후위(Postfix) 표기

아래 예제 트리로 세 순회 결과를 직접 확인:

예제 트리 A / \ B C / \ / \ D E F G 전위 Preorder (root→L→R) : A → B → D → E → C → F → G 중위 Inorder (L→root→R) : D → B → E → A → F → C → G 후위 Postorder (L→R→root) : D → E → B → F → G → C → A

암기 팁 : root(뿌리)가 앞이면 전위, 중간이면 중위, 뒤면 후위. "전/중/후 = 루트 위치".

🔍 배경설명 — 순회 순서 손으로 푸는 법

실기에서는 트리 그림을 주고 특정 순회 결과를 나열하라는 문제가 자주 나온다. 각 서브트리에도 같은 규칙을 재귀적으로 적용하는 것이 핵심.

  • 전위 : 노드에 도착하면 즉시 출력 후 왼쪽→오른쪽으로 내려간다.
  • 중위 : 왼쪽을 끝까지 다 처리한 뒤 자기 출력, 그다음 오른쪽.
  • 후위 : 왼쪽·오른쪽을 모두 처리한 뒤 마지막에 자기 출력.
  • 구별/암기 : Pre=Root 먼저, In=Root 사이, Post=Root 나중. BST 중위 순회 = 정렬된 값이 나온다는 성질은 단골 출제.

(2) 정렬 알고리즘 시간복잡도표 ❗

대표 정렬 7종의 평균·최악 시간복잡도와 안정성(Stable). 안정 정렬 = 같은 값의 원래 순서가 보존되는 정렬.

정렬평균 / 최악 · 안정성 · 특징
버블 (Bubble)O(n²) / O(n²) · 안정 · 인접 교환, 가장 단순·느림
선택 (Selection)O(n²) / O(n²) · 불안정 · 최솟값을 골라 앞으로, 교환 횟수 적음
삽입 (Insertion)O(n²) / O(n²) · 안정 · 거의 정렬된 데이터에 최상(최선 O(n))
퀵 (Quick)O(n log n) / O(n²) · 불안정 · 분할정복, 평균 가장 빠름(피벗 편향 시 최악)
병합 (Merge)O(n log n) / O(n log n) · 안정 · 분할정복, 추가 메모리 O(n) 필요
힙 (Heap)O(n log n) / O(n log n) · 불안정 · 최대/최소 힙 이용, 제자리(in-place)
기수 (Radix)O(dn) / O(dn) · 안정 · 비교 없이 자릿수 분배, 정수·문자열에 유리

O(n²) 그룹 = 버블·선택·삽입 / O(n log n) 그룹 = 퀵(평균)·병합·힙. 퀵의 최악은 O(n²) 인 점이 함정. 기수는 비교 기반이 아니어서 O(dn).

🔍 배경설명 — 안정 정렬 vs 불안정 정렬

키가 같은 원소들의 입력 순서가 정렬 후에도 유지되면 안정(Stable) 정렬이다.

  • 안정 : 버블, 삽입, 병합, 기수
  • 불안정 : 선택, 퀵, 힙
  • 암기 : "선택·퀵·힙은 불안정". 나머지(버블/삽입/병합/기수)는 안정. 안정성이 필요한 다중 키 정렬에서 중요.

(3) 빅오(Big-O) 표기 — 증가율 순서 ❗

입력 크기 n이 커질 때 연산 횟수가 얼마나 빨리 증가하는지를 나타내는 최악 시간복잡도 표기. 왼쪽일수록 효율적(빠름), 오른쪽일수록 비효율(느림).

증가율 (느림←빠름, 성능은 왼쪽이 우수) O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!) 상수 로그 선형 선형로그 제곱 지수 팩토리얼
표기의미 · 예시
O(1)상수 · 입력과 무관하게 일정 (배열 인덱스 접근, 해시 조회)
O(log n)로그 · 반씩 줄임 (이진 탐색, 균형 BST)
O(n)선형 · 한 번씩 훑음 (선형 탐색, 반복문 1중)
O(n log n)선형로그 · 효율적 정렬 (퀵·병합·힙 정렬)
O(n²)제곱 · 이중 반복문 (버블·선택·삽입 정렬)
O(2ⁿ)지수 · 부분집합·재귀 완전탐색 (피보나치 단순 재귀)
O(n!)팩토리얼 · 모든 순열 (외판원 완전탐색)

(4) COCOMO 모델 — 3가지 개발 유형 ❗

LOC(원시 코드 라인 수)를 기반으로 소프트웨어 개발 비용·노력(Man-Month)을 산정하는 대표 모델(Boehm 제안). 소프트웨어 규모에 따라 3가지 모드로 구분.

모드규모 · 특징
조직형 (Organic)5만(50 KLOC) 라인 이하 · 소규모, 익숙한 업무, 일괄자료처리·과학기술 계산용 SW
반결합형 (Semi-detached)30만(300 KLOC) 라인 이하 · 중규모, 조직형과 내장형의 중간 (컴파일러, 트랜잭션 처리)
내장형 (Embedded)30만 라인 초과 (대규모) · 하드웨어와 밀결합, 실시간 처리 (미사일·신호제어 등 초대형)

암기 : 조직(작음, 5만↓) → 반결합(중간, 30만↓) → 내장(큼, 30만↑). 라인 수가 커질수록 복잡도·노력 증가.

(5) CMMI 5단계 — 프로세스 성숙도 ❗

CMMI(Capability Maturity Model Integration) : 조직의 SW 개발 프로세스 성숙도를 5단계로 평가. 단계가 높을수록 프로세스가 체계적·정량적으로 관리됨.

단계이름 · 상태
1단계초기 (Initial) · 무질서, 개인 역량 의존. 예측 불가
2단계관리 (Managed) · 프로젝트 단위로 관리, 유사 프로젝트 반복 가능
3단계정의 (Defined) · 조직 표준 프로세스 정립·문서화
4단계정량적 관리 (Quantitatively Managed) · 정량적(통계적) 데이터로 프로세스 관리
5단계최적화 (Optimizing) · 지속적 프로세스 개선

암기 : 초·관·정·정·최 (초기→관리→정의→정량적관리→최적화).

(6) SPICE (ISO/IEC 15504) 6수준 ❗

SPICE : 소프트웨어 프로세스 평가·개선을 위한 국제 표준. 프로세스 수행 능력을 0~5의 6수준으로 평가.

수준이름 · 의미
수준 0불완전 (Incomplete) · 미구현, 목표 미달성
수준 1수행 (Performed) · 프로세스 수행·목적 달성
수준 2관리 (Managed) · 계획·관리·조정 하에 수행
수준 3확립 (Established) · 표준 프로세스 사용, 정의됨
수준 4예측 (Predictable) · 정량적으로 예측·측정 가능
수준 5최적화 (Optimizing) · 지속적 개선

암기 : 불·수·관·확·예·최 (0불완전→1수행→2관리→3확립→4예측→5최적화). CMMI와 최종 단계 이름(최적화)이 같은 점에 주의.

🔍 배경설명 — CMMI vs SPICE 헷갈림 방지

둘 다 프로세스 성숙도/능력 모델이라 실기에서 자주 섞여 출제된다.

  • CMMI : 미국(SEI) 제안, 1~5의 5단계 (초기·관리·정의·정량적관리·최적화)
  • SPICE : ISO/IEC 15504 국제표준, 0~5의 6수준 (불완전·수행·관리·확립·예측·최적화)
  • 구별 : "0수준(불완전)이 있으면 SPICE, 없으면 CMMI". SPICE는 수준이 6개, CMMI는 단계가 5개.

(= 소프트 링크)		원본 파일의 경로(이름)를 가리키는 별도의 링크 파일. 명령 ln -s 원본 링크. 원본을 삭제하면 링크가 깨짐(dangling). 다른 파일시스템·디렉토리도 링크 가능.
하드 링크
(비교용)		같은 inode(실제 데이터)를 공유. 명령 ln 원본 링크. 원본을 삭제해도 데이터 유지(참조수만 감소). 같은 파일시스템 내에서만 가능.

② Watering Hole (워터링 홀) — 보안 공격 (4년 만에 재출제)

공격 대상이 자주 방문하는 웹사이트를 미리 악성코드로 감염시켜 두고, 대상이 그 사이트에 접속하면 감염시키는 표적형(APT) 공격. (사자가 물웅덩이 옆에서 먹잇감을 기다리는 데서 유래)

③ ISMS — 정보보호 관리체계 (보안)

ISMS(Information Security Management System) : 정보 자산을 안전하게 보호하기 위한 관리 과정·대책을 수립·운영하고 이를 심사·인증하는 제도. 국내는 개인정보보호까지 결합한 ISMS-P 운영. 관리적·기술적·물리적 보호대책을 포함.

④ 요구사항 — 기능적 vs 비기능적 (2026-1 신유형)

요구사항키워드
기능적 요구사항
(Functional)		시스템이 무엇(What)을 해야 하는가 — 수행할 기능·동작 (예: 로그인, 결제, 검색)
비기능적 요구사항
(Non-functional)		시스템이 어떻게(How) 동작해야 하는가 — 성능·보안·신뢰성·사용성·확장성 등 품질·제약 (예: 응답 3초 이내, 동시접속 1만)
