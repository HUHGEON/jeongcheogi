# C
C는 Java와 함께 코딩 140문제의 대부분을 차지하는 언어다. 색인 기준으로 두 언어가 각각 60문제 안팎이고, 2023년 이후로는 회차마다 2~7문제, 대개 3~4문제가 C로 나온다. 반복해서 나오는 주제는 포인터와 배열, 문자열 포인터, 구조체, 재귀, static이다. 구조체 중에서도 특히 연결 리스트는 24-2부터 25-3까지 5회 연속으로 나왔다. 문제는 출력 결과 쓰기가 대부분이고, 여기에 정렬·진법 변환·잔돈 계산 같은 짧은 알고리즘의 빈칸 채우기가 섞여 나온다. 추적 표, 비트, 우선순위, 나눗셈, 형변환, 2차원 배열 같은 공통 규칙은 [코딩 공통] 페이지에 따로 모아 두었다.

각 묶음의 개념은 짧은 코드를 한 단계씩 돌려 보면서 쌓아 간다. `main`이 보이지 않는 짧은 코드 조각은 `#include <stdio.h>`, `<string.h>`, `<stdlib.h>`를 넣은 `main` 함수 안에 그대로 들어 있다고 보고 읽으면 되고, 아래 출력은 전부 실제로 컴파일해서 돌린 결과다.

## 문자열과 '\0', 문자열 포인터
출제: 25-3, 24-2, 24-1, 23-3, 23-2, 23-1, 22-2, 20-4
함정: 문자열 길이와 배열 크기는 다르다. `"hello"`는 길이 5, 저장에는 6바이트('\0' 포함)가 든다.

### 개념
C에는 문자열이라는 자료형이 따로 없다. 문자 여러 개를 `char` 배열에 나란히 넣고, 맨 끝에 `'\0'`이라는 끝 표시를 붙여 두는 것이 C의 문자열이다. 그래서 문자열 문제는 결국 "끝 표시가 어디 있는가"와 "지금 포인터가 몇 번째 글자를 가리키는가" 두 가지를 묻는다. `char s[10] = "hello"` 하나로 차근차근 살펴보자.

먼저 규칙을 표로 보면 이렇다. 아래에서 하나씩 코드로 확인한다.

| 규칙 | 내용 |
|---|---|
| 끝 표시 | 문자열은 `'\0'`(값 0)으로 끝난다. `while (*s)`, `while (s[i] != '\0')`은 끝까지 도는 관용구 |
| `%s` 출력 | 그 주소부터 '\0' 직전까지 찍는다. `p + 1`을 넘기면 두 번째 문자부터 |
| `*(p+3)` vs `*p+2` | `*`가 `+`보다 먼저 묶인다. `p = "KOREA"`일 때 `*(p+3)`은 네 번째 문자 'E', `*p+2`는 첫 문자 'K'에 2를 더한 'M'(20-4) |
| 중간에 '\0' 넣기 | `s[2] = '\0'`이면 그 뒤가 있어도 문자열은 거기서 끝난다 |
| `sizeof` vs `strlen` | `char s[10] = "hello"`에서 sizeof는 10, strlen은 5 |
| `*s++` | 현재 문자를 쓰고 포인터를 다음으로. `*s++ + 1`은 문자 값 + 1 |
| 리터럴 포인터 | `char *q = "abc"`는 읽기 전용. 내용을 바꾸는 코드는 `char s[] = "abc"` 쪽 |
| `<string.h>` 함수 | `strlen(s)` 길이('\0' 제외), `strcpy(d, s)` 복사, `strcat(d, s)` d 뒤에 이어 붙이기, `strcmp(a, b)` 같으면 0, 앞에서부터 다른 첫 글자의 문자 코드(ASCII)가 a 쪽이 작으면 음수, 크면 양수(값이 -1/1로 정해져 있지 않으니 부호만 본다. 'Z'(90) < 'a'(97)) |

#### 끝에는 '\0'이 숨어 있다
"hello"는 다섯 글자다. 그럼 배열에는 몇 칸이 쓰일까? 크기와 길이를 같이 찍으면 답이 나온다.

```c
char s[10] = "hello";
printf("%d %d\n", (int)sizeof(s), (int)strlen(s));
printf("%d %d\n", s[4], s[5]);
```
출력:
```
10 5
111 0
```

`sizeof`는 배열 전체 크기를 재므로 선언한 10이 그대로 나온다. 반면 `strlen`은 '\0'이 나오기 전까지의 글자를 센다. s[0]부터 s[4]까지 h, e, l, l, o 다섯 글자라 5다. `s[4]`는 마지막 글자 'o'의 문자 코드 111이고, 그다음 칸 `s[5]`에 값 0, 즉 '\0'이 들어 있다. 눈에 보이는 글자는 5개지만 s[0]부터 s[5]까지 '\0'을 포함해 6바이트가 쓰인다는 말이 바로 이 뜻이다.

#### %s는 주소를 받아 '\0' 직전까지 찍는다
`printf("%s", ...)`에 넘기는 것은 문자열 전체가 아니라 시작 주소 하나다. 그럼 시작 주소를 한 칸 옮겨서 넘기면 어떻게 될까?

```c
char s[10] = "hello";
char *p = s;
printf("%s\n", p);
printf("%s\n", p + 1);
printf("%s\n", &s[3]);
```
출력:
```
hello
ello
lo
```

`%s`는 받은 주소의 글자부터 '\0' 직전 글자까지를 찍는다. s는 0번 h, 1번 e, 2번 l, 3번 l, 4번 o다. `p + 1`은 1번 'e'의 주소라서 "ello"가 찍히고, `&s[3]`은 3번 'l'의 주소라서 "lo"가 찍힌다. 끝은 언제나 5번의 '\0'이고 시작 번호만 달라진다.

#### *(p+3)과 *p+2는 다르다
이번에는 글자 하나를 꺼낸다. 괄호 위치만 다른 두 식이 같은 값을 낼까?

```c
char *p = "KOREA";
printf("%c %c\n", *(p + 3), *p + 2);
```
출력:
```
E M
```

"KOREA"는 0번 K, 1번 O, 2번 R, 3번 E, 4번 A다. `*(p + 3)`은 0번에서 세 칸 옮긴 3번 칸의 문자를 꺼내므로 'E'다. 반면 `*p + 2`는 `*`가 `+`보다 먼저 묶이기 때문에 0번의 'K'를 먼저 꺼내고 거기에 2를 더한다. 문자 코드는 K, L, M 순서라 K에 2를 더하면 'M'이다. 20-4에 그대로 나온 함정이다.

#### 중간에 '\0'을 넣으면
'\0'이 끝 표시라면, 중간에 '\0'을 써 넣었을 때 뒤에 남은 글자는 어떻게 될까?

```c
char s[10] = "hello";
s[2] = '\0';
printf("%s %d\n", s, (int)strlen(s));
printf("%c\n", s[3]);
```
출력:
```
he 2
l
```

`%s`와 `strlen`은 둘 다 처음 나오는 '\0' 직전까지만 읽는다. 이제 처음 나오는 '\0'은 s[2]라서 문자열은 s[0], s[1]의 "he"다. 그런데 `s[3]`을 직접 꺼내 보면 'l'이 그대로 남아 있다. 글자가 지워진 게 아니라 첫 '\0'의 위치가 s[5]에서 s[2]로 바뀌었을 뿐이다.

#### *s++로 한 글자씩 훑기
`while (*q) ... *q++`는 문자열을 끝까지 훑는 관용구다. 한 줄씩 무슨 일이 일어나는지 따라가면 이렇다.

```c
char *q = "abc";
while (*q) printf("%c", *q++);
printf("\n");
q = "abc";
while (*q) printf("%c", *q++ + 1);
printf("\n");
```
출력:
```
abc
bcd
```

`*q++`는 q가 가리키는 문자를 꺼내 쓴 다음 q를 다음 칸으로 옮긴다. 그래서 q는 'a', 'b', 'c'를 차례로 가리키고, 'c'를 찍은 뒤에는 '\0'을 가리킨다. 이때 `while (*q)`의 조건이 0, 즉 거짓이 되어 반복이 끝난다. 두 번째 반복의 `*q++ + 1`은 꺼낸 문자 값에 1을 더하므로 a, b, c 대신 b, c, d가 찍힌다. q를 한 칸 더 옮기는 게 아니라 꺼낸 값이 1 커진다.

#### 바꿀 수 있는 문자열, 바꾸면 안 되는 문자열
같은 "abc"라도 `char s[]`로 받느냐 `char *q`로 받느냐에 따라 다르다.

```c
char s[] = "abc";
s[0] = 'X';
printf("%s\n", s);
```
출력:
```
Xbc
```

`char s[] = "abc"`는 "abc"를 내 배열에 복사해 두는 것이라 글자를 바꿀 수 있다. 반면 `char *q = "abc"`는 리터럴이 있는 곳의 주소만 받은 것이고, 그 리터럴은 읽기 전용이다. 그래서 `s[0] = 'X'`처럼 글자를 바꾸는 코드가 나온다면, 그 문자열은 배열로 선언된 것이다.

#### <string.h> 함수 네 개
마지막은 기출에 나오는 문자열 함수 네 개를 한 번에 돌린 결과다.

```c
char d[20] = "ab";
strcpy(d, "cat");
printf("%s %d\n", d, (int)strlen(d));
strcat(d, "dog");
printf("%s %d\n", d, (int)strlen(d));
printf("%d\n", strcmp("abc", "abc"));
printf("%d %d\n", strcmp("Z", "a") < 0, strcmp("b", "a") > 0);
```
출력:
```
cat 3
catdog 6
0
1 1
```

`strcpy`는 원래 있던 "ab"를 덮어쓰고 "cat"을 복사한다. `strcat`은 "cat" 바로 다음 칸인 d[3]의 '\0' 자리부터 "dog"를 이어 붙인다. `strcmp`는 같으면 0이고, 다르면 첫 글자부터 비교해 처음 다른 글자의 문자 코드를 비교한다. 'Z'(90)는 'a'(97)보다 작아서 음수, 'b'와 'a'는 그 반대로 양수가 나온다. 이때 값이 정확히 얼마인지는 정해져 있지 않다. 그래서 코드도 값 대신 `< 0`, `> 0` 비교 결과를 찍었고, 둘 다 참이라 1(참)이 두 번 나왔다.

### 예제
```c
#include <stdio.h>
int len(char *s) {
    int n = 0;
    while (*s++) n++;
    return n;
}
int main() {
    char s[10] = "hello";
    char *p = s;
    printf("%d %d\n", len(s), (int)sizeof(s));
    printf("%s %s\n", p + 1, &s[3]);
    printf("%c %c\n", *p, *(p + 4));
    s[2] = '\0';
    printf("%s %d\n", s, len(s));
    char *q = "abc";
    while (*q) printf("%c", *q++ + 1);
    printf("\n");
    return 0;
}
```
출력:
```
5 10
ello lo
h o
he 2
bcd
```
`while (*s++)`의 조건은 *s가 h, e, l, l, o일 때 참이고 '\0'일 때 거짓이다. 그래서 n은 5번 증가한다. `p + 1`은 'e'의 주소라서 거기서부터 찍으면 "ello"가 되고, 같은 식으로 `&s[3]`은 "lo"다. s[2]에 '\0'을 넣으면 뒤에 글자가 남아 있어도 문자열은 "he"에서 끝난다. 마지막 `*q++ + 1`은 각 문자 값에 1을 더해 a, b, c 대신 b, c, d를 찍는다.

```c
#include <stdio.h>
void copy(char *d, char *s) {
    while ((*d++ = *s++) != '\0');
}
void rev(char *s) {
    char *e = s, t;
    while (*e) e++;
    e--;
    while (s < e) { t = *s; *s = *e; *e = t; s++; e--; }
}
int main() {
    char a[20], b[] = "level", c[] = "stack";
    copy(a, c);
    rev(a);
    printf("%s %s\n", a, c);
    rev(b);
    printf("%s\n", b);
    int i, cnt = 0;
    for (i = 0; c[i] != '\0'; i++)
        if (c[i] == 'a' || c[i] == 'c') cnt++;
    printf("%d\n", cnt);
    return 0;
}
```
출력:
```
kcats stack
level
2
```
`copy`의 조건 `(*d++ = *s++) != '\0'`은 방금 대입한 문자가 '\0'일 때 거짓이 된다. 그래서 '\0'까지 복사한 다음 반복이 끝난다. `rev`에서 `while (*e) e++;`가 끝나면 e는 "stack"의 '\0'인 5번 칸을 가리키고, `e--`로 4번 칸 'k'를 가리키게 된다. 그다음 0번과 4번('s'와 'k'), 1번과 3번('t'와 'c')을 바꾸고, 포인터 s와 e가 둘 다 2번 칸을 가리키면 `s < e`가 거짓이라 끝난다. 원본 c가 stack 그대로인 이유는 뒤집은 것이 c가 아니라 c를 복사한 a이기 때문이다.

### 자주 틀리는 포인트
- `while (*s++)` 길이 함수의 반환값은 strlen과 같음('\0'은 n에 안 셈)
- `printf("%s", s + 2)`처럼 시작점을 옮겨 찍는 출력 자주 출제(`s + 2`는 0부터 센 2번 칸, 곧 세 번째 글자부터)
- 뒤집기 함수의 `e--` 누락 시 '\0'이 0번 칸으로 와서 빈 문자열 출력(빈칸 단골 줄)
- 23-2의 전역 `char n[]`에 `gets`로 입력받고 그 주소를 돌려주는 문제는 세 번 모두 마지막 문자열 출력

23-2 문제에서 돌려받은 포인터 여러 개는 전부 같은 배열 n을 가리킨다. n에는 마지막 입력만 남기 때문에 세 포인터를 찍으면 모두 마지막 문자열이 나온다.

## 구조체 (. 과 ->, 구조체 배열·포인터)
출제: 26-2, 25-3, 25-1, 24-1, 23-3, 21-3, 21-1
함정: 구조체 변수는 `.`, 구조체 포인터는 `->`. `(*p).name`과 `p->name`은 같다.

### 개념
구조체는 이름, 점수처럼 자료형이 서로 다른 값을 하나로 묶어 두는 틀이다. 시험에서 묻는 것은 결국 멤버를 꺼내는 방법인데, 구조체 변수에서 꺼내면 `.`, 구조체 포인터에서 꺼내면 `->`를 쓴다. 아래 조각들은 모두 맨 위(함수 밖)에 이 정의가 있다고 보고 읽으면 된다.

```c
struct Student {
    char name[10];
    int score;
};
```

접근식부터 표로 모았다. 각 줄은 이어지는 코드에서 실제로 찍어 본다.

| 식 | 뜻 |
|---|---|
| `s.score` | 구조체 변수 s의 멤버 |
| `p->score` | 포인터 p가 가리키는 구조체의 멤버. `(*p).score`와 같다 |
| `s[1].score` | 구조체 배열의 두 번째 원소 |
| `(p + 1)->score`, `p[1].score` | 구조체 배열을 포인터로 접근. 둘 다 s[1].score |
| `p++` | 다음 구조체로 이동(구조체 크기만큼 주소가 증가) |
| 자기 참조 구조체 | `struct Node { int v; struct Node *next; }` 연결 리스트·트리의 기본 모양 |

#### 구조체 변수는 . 으로
먼저 구조체 변수 하나를 만들고 멤버를 꺼내 보자.

```c
struct Student s = {"kim", 80};
printf("%s %d\n", s.name, s.score);
s.score = 90;
printf("%d\n", s.score);
```
출력:
```
kim 80
90
```

중괄호 안의 값은 선언한 멤버 순서대로 name, score에 들어간다. 변수 이름 뒤에 `.`을 찍고 멤버 이름을 쓰면 그 칸을 읽을 수도, 바꿀 수도 있다.

#### 포인터로 닿으면 ->
그럼 구조체를 가리키는 포인터에서는 어떻게 멤버를 꺼낼까? 방법은 두 가지이고, 아래에 나란히 적었다.

```c
struct Student s = {"kim", 80};
struct Student *p = &s;
printf("%d %d\n", p->score, (*p).score);
p->score += 5;
printf("%d\n", s.score);
```
출력:
```
80 80
85
```

`(*p).score`는 `*p`로 구조체 s를 얻은 다음 `.`으로 멤버를 꺼내는 식이고, `p->score`는 `(*p).score`를 줄여 쓴 표기라 둘 다 80이다. 괄호를 빼고 `*p.score`라고 쓰면 `.`이 먼저 묶여 뜻이 달라지므로, 매번 괄호를 치는 대신 `->`를 쓴다. 그리고 p에는 s의 주소가 들어 있으므로 `p->score += 5`는 s.score 자체를 80에서 85로 바꾼다.

#### 구조체 배열과 포인터
구조체도 배열로 만들 수 있다. 그럼 배열 이름을 포인터에 넣고 `+ 1`을 하면 어디를 가리킬까?

```c
struct Student s[3] = {{"kim", 80}, {"lee", 95}, {"park", 70}};
struct Student *p = s;
printf("%d %d %d\n", s[1].score, (p + 1)->score, p[1].score);
p++;
printf("%s %c\n", p->name, p->name[0]);
```
출력:
```
95 95 95
lee l
```

`s[1].score`, `(p + 1)->score`, `p[1].score`는 모두 두 번째 원소 lee의 점수다. `p++` 뒤의 p는 s[1]을 가리키므로 `p->name`은 "lee"다. 여기서 `p->name`은 문자 배열이므로 `%s`로 찍고, 그 첫 글자는 `p->name[0]`으로 꺼내 `%c`로 찍는다.

#### p++는 구조체 하나만큼 건너뛴다
`p + 1`이 다음 구조체를 가리킨다면, 주소 값은 몇 바이트 늘어날까? 주소 값은 실행할 때마다 달라지므로 아래 코드는 차이만 찍는다.

```c
struct Student s[3];
struct Student *p = s;
printf("%d\n", (int)sizeof(struct Student));
printf("%d %d\n", (int)((p + 1) - p), (int)((char *)(p + 1) - (char *)p));
```
출력:
```
16
1 16
```

이 컴퓨터에서는 구조체 하나가 16바이트다. 포인터끼리 빼면 원소 단위로 세서 1이지만, 바이트 단위(`char *`)로 바꿔 빼면 16이 나온다. 즉 `p++`는 주소를 1 늘리는 게 아니라 구조체 크기인 16바이트만큼 늘린다.

#### 자기 참조 구조체
구조체 안에 자기와 같은 구조체를 가리키는 포인터를 넣을 수도 있다. 이게 연결 리스트와 트리의 기본 모양이다.

```c
struct Node {
    int v;
    struct Node *next;
};
struct Node c = {30, NULL};
struct Node b = {20, &c};
struct Node a = {10, &b};
printf("%d %d %d\n", a.v, a.next->v, a.next->next->v);
printf("%d\n", a.next->next->next == NULL);
```
출력:
```
10 20 30
1
```

a는 구조체 변수이므로 `a.v`처럼 `.`을 쓴다. 하지만 `a.next`는 포인터이고, 그다음부터는 `->`로 꺼낸다. `a.next`는 b의 주소, `a.next->next`는 c의 주소라서 `a.next->next->v`는 c의 값 30이다. c의 next는 NULL이라 마지막 비교가 참(1)이다. 연결 리스트 문제는 이렇게 next를 차례로 따라가는 일을 반복문으로 하며, 바로 다음 묶음에서 이어서 본다.

### 정리

23-3에서는 "구조체 포인터로 멤버에 접근하는 연산자"를 단답으로 묻기도 했다. 답은 `->`다.

### 예제
```c
#include <stdio.h>
struct Student {
    char name[10];
    int score;
};
struct Node {
    int v;
    struct Node *left, *right;
};
void post(struct Node *n) {
    if (n == NULL) return;
    post(n->left);
    post(n->right);
    printf("%d ", n->v);
}
int main() {
    struct Student s[3] = {{"kim", 80}, {"lee", 95}, {"park", 70}};
    struct Student *p = s;
    int i, sum = 0;
    for (i = 0; i < 3; i++) sum += (p + i)->score;
    printf("%d %s\n", sum / 3, (*(p + 1)).name);
    p++;
    p->score += 5;
    printf("%d %c\n", s[1].score, p->name[0]);
    struct Node n4 = {4, NULL, NULL}, n5 = {5, NULL, NULL};
    struct Node n2 = {2, &n4, &n5}, n3 = {3, NULL, NULL};
    struct Node n1 = {1, &n2, &n3};
    post(&n1);
    printf("\n");
    return 0;
}
```
출력:
```
81 lee
100 l
4 5 2 3 1 
```
세 점수의 합은 80 + 95 + 70 = 245이고, 245를 3으로 나누는 245 / 3은 정수 나눗셈이라 81이 된다. `p++` 뒤의 p는 s[1]을 가리키므로 `p->score += 5`는 s[1].score를 95에서 100으로 만든다. 트리는 1(2(4,5),3) 모양, 곧 1의 왼쪽 자식이 2, 오른쪽 자식이 3이고 2의 왼쪽·오른쪽 자식이 4, 5다. post는 printf가 두 재귀 호출 뒤에 있는 후위 순회라 왼쪽·오른쪽·자기 순서로 찍고, 그래서 4 5 2 3 1이 나온다.

### 자주 틀리는 포인트
- `p->score += 5`처럼 포인터로 바꾼 값은 원본 배열 s에도 반영(복사본이 아닌 같은 메모리)
- 트리 순회 출력 순서는 전위 자기·왼·오, 중위 왼·자기·오, 후위 왼·오·자기(printf와 재귀 호출의 위치로 구분)
- 24-1의 복리·평균 계산처럼 구조체 멤버로 산술하는 문제는 정수 나눗셈과 실수 서식(`%.2f`) 주의
- 구조체 안의 문자열 멤버 `p->name`은 배열(주소), `p->name[0]`은 첫 글자

순회 종류는 printf가 두 재귀 호출보다 먼저 적혀 있으면 전위, 두 호출 사이에 있으면 중위, 두 호출 뒤에 있으면 후위다.

## 연결 리스트 순회·삽입·교환
출제: 25-3, 25-2, 25-1, 24-3, 24-2
함정: `next`를 바꾸는 순서가 틀리면 리스트가 끊긴다. 삽입은 "새 노드의 next를 먼저, 앞 노드의 next를 나중에".

### 개념
배열은 원소가 메모리에 나란히 붙어 있어서 중간에 하나를 끼우려면 뒤쪽을 전부 밀어야 한다. 연결 리스트는 노드마다 "다음 노드의 주소(next)"를 함께 저장해서 이 문제를 푼다. 그래서 끼우기, 빼기, 뒤집기가 모두 next 몇 개를 바꾸는 일이 되고, 시험은 그 바꾸는 순서를 따라갈 수 있는지를 묻는다. 아래 조각은 모두 함수 밖에 이 정의가 있다고 보면 된다.

```c
struct Node {
    int v;
    struct Node *next;
};
```

동작별 코드 모양은 아래 표와 같고, 이어지는 단계에서 하나씩 실행해 본다.

| 동작 | 코드 모양 | 추적 요령 |
|---|---|---|
| 순회 | `for (p = head; p != NULL; p = p->next)` | 노드를 상자로 그리고 화살표를 따라간다 |
| 끝에 추가 | `while (t->next != NULL) t = t->next; t->next = p;` | 빈 리스트일 때 head가 바뀌는 분기를 확인 |
| 중간 삽입 | `n->next = prev->next; prev->next = n;` | 이 두 줄의 순서가 핵심 |
| 삭제 | `prev->next = cur->next;` | cur가 가리키던 노드가 빠진다 |
| 역순 | `nx = cur->next; cur->next = prev; prev = cur; cur = nx;` | 세 포인터(prev, cur, nx)를 매 반복 표로 적는다 |
| 값 교환 | `t = p->v; p->v = p->next->v; p->next->v = t;` | 노드는 그대로, 값만 바뀐다 |
| 노드 교환 | prev→a→b를 prev→b→a로: `prev->next = b; a->next = b->next; b->next = a;` | next 세 개가 바뀐다. 0→1→2→3에서 prev=0, a=1, b=2이면 0→2→1→3이 된다. a가 첫 노드면 prev가 없으므로 첫 줄이 `head = b;`로 바뀐다 |

#### 순회: 화살표를 따라 끝까지
노드 세 개를 이어 놓고 처음부터 끝까지 따라가는 코드다.

```c
struct Node c = {3, NULL}, b = {2, &c}, a = {1, &b};
struct Node *head = &a, *p;
for (p = head; p != NULL; p = p->next) printf("%d ", p->v);
printf("\n");
```
출력:
```
1 2 3 
```

p는 head인 a에서 시작해 `p = p->next`를 할 때마다 a(1), b(2), c(3)를 차례로 가리킨다. 마지막 노드 c의 next가 NULL이라서, c 다음에 p가 NULL이 되면 조건 `p != NULL`이 거짓이 되어 반복이 끝난다. 연결 리스트 코드에서 거의 모든 반복이 이 모양이다.

#### 끝에 추가
그럼 맨 뒤에 4를 붙이려면 마지막 노드를 먼저 찾아야 한다.

```c
struct Node c = {3, NULL}, b = {2, &c}, a = {1, &b};
struct Node d = {4, NULL};
struct Node *head = &a, *t = head, *p;
while (t->next != NULL) t = t->next;
t->next = &d;
for (p = head; p != NULL; p = p->next) printf("%d ", p->v);
printf("\n");
```
출력:
```
1 2 3 4 
```

이번 반복의 조건은 `t != NULL`이 아니라 `t->next != NULL`이다. t가 a, b를 거쳐 c를 가리키면 c의 next가 NULL이라 조건이 거짓이 되고, 반복이 끝난 뒤에도 t는 마지막 노드 c를 가리킨다. 그래서 `t->next = &d`로 c의 next에 d를 연결할 수 있다. 조건이 `t != NULL`이었다면 t가 NULL이 될 때까지 반복해서, c를 가리키는 포인터가 남지 않는다.

#### 중간 삽입: 두 줄의 순서
1 다음에 9를 끼워 보자. 필요한 줄은 두 개다.

```c
struct Node c = {3, NULL}, b = {2, &c}, a = {1, &b};
struct Node n = {9, NULL};
struct Node *head = &a, *prev = &a, *p;
n.next = prev->next;
prev->next = &n;
for (p = head; p != NULL; p = p->next) printf("%d ", p->v);
printf("\n");
```
출력:
```
1 9 2 3 
```

`n.next = prev->next`로 새 노드 9의 next가 먼저 2를 가리키게 하고, 그다음 `prev->next = &n`으로 1의 next를 9로 바꿨다. 그럼 두 줄의 순서를 바꾸면 어떻게 될까?

```c
struct Node c = {3, NULL}, b = {2, &c}, a = {1, &b};
struct Node n = {9, NULL};
struct Node *head = &a, *prev = &a, *p;
int k = 0;
prev->next = &n;
n.next = prev->next;
for (p = head; p != NULL && k < 6; p = p->next, k++) printf("%d ", p->v);
printf("\n");
```
출력:
```
1 9 9 9 9 9 
```

2의 주소는 1의 next에만 들어 있었다. 그래서 `prev->next = &n`을 먼저 하면 그 순간 2의 주소를 잃는다. 그 상태에서 `n.next = prev->next`를 하면 prev->next가 이미 n이므로 n의 next가 n 자신이 되고, 순회는 9만 계속 찍는다(끝없이 돌지 않게 k로 6번만 찍었다). "새 노드의 next를 먼저, 앞 노드의 next를 나중에"라는 순서가 그래서 중요하다.

#### 삭제: 건너뛰게 만든다
노드를 빼는 코드는 한 줄이다. 1, 2, 3에서 2를 뺀다.

```c
struct Node c = {3, NULL}, b = {2, &c}, a = {1, &b};
struct Node *head = &a, *prev = &a, *cur = &b, *p;
prev->next = cur->next;
for (p = head; p != NULL; p = p->next) printf("%d ", p->v);
printf("\n");
```
출력:
```
1 3 
```

prev(1)의 next에 `cur->next`, 곧 3의 주소를 넣으면 1 다음이 바로 3이 된다. 2를 가리키는 next가 하나도 없으니 순회에서 2가 빠진다. 노드 b가 메모리에서 지워지는 것은 아니고, 1의 next가 2를 건너뛰어 3을 가리킬 뿐이다.

#### 역순: 포인터 세 개를 표로
이번에는 리스트 뒤집기다. 반복이 한 번 끝날 때마다 prev와 cur가 어디를 가리키는지 찍게 했다.

```c
struct Node c = {3, NULL}, b = {2, &c}, a = {1, &b};
struct Node *head = &a, *prev = NULL, *cur = head, *nx, *p;
while (cur != NULL) {
    nx = cur->next;
    cur->next = prev;
    prev = cur;
    cur = nx;
    if (cur) printf("prev=%d cur=%d\n", prev->v, cur->v);
    else printf("prev=%d cur=NULL\n", prev->v);
}
head = prev;
for (p = head; p != NULL; p = p->next) printf("%d ", p->v);
printf("\n");
```
출력:
```
prev=1 cur=2
prev=2 cur=3
prev=3 cur=NULL
3 2 1 
```

첫 반복을 보면 cur가 1일 때 `cur->next = prev`로 1의 next를 NULL로 바꾸고, 이어서 prev는 1, cur는 2가 된다. 출력 첫 줄 prev=1 cur=2가 이 상태다. 반복마다 이렇게 cur 노드의 next를 직전 노드(prev)로 바꾸고, prev와 cur를 원래 리스트의 다음 노드로 하나씩 옮긴다. 그런데 1의 next를 NULL로 바꾸면 2의 주소가 사라지므로, 바꾸기 전에 `nx = cur->next`로 2의 주소를 먼저 저장해 둔다. 반복이 끝나면 cur는 NULL, prev는 원래 마지막 노드였던 3이다. head는 아직 1을 가리키고 있어서 `head = prev`를 해야 3, 2, 1로 읽힌다.

#### 값 교환과 노드 교환
0, 1, 2, 3에서 1과 2의 자리를 바꾸는 방법은 두 가지다. 첫째는 값만 바꾸는 방법이다.

```c
struct Node n3 = {3, NULL}, n2 = {2, &n3}, n1 = {1, &n2}, n0 = {0, &n1};
struct Node *head = &n0, *q = &n1, *p;
int t = q->v; q->v = q->next->v; q->next->v = t;
for (p = head; p != NULL; p = p->next) printf("%d ", p->v);
printf("/ n1.v=%d\n", n1.v);
```
출력:
```
0 2 1 3 / n1.v=2
```

둘째는 값은 그대로 두고 노드를 바꾸는 방법이다.

```c
struct Node n3 = {3, NULL}, n2 = {2, &n3}, n1 = {1, &n2}, n0 = {0, &n1};
struct Node *head = &n0, *prev = &n0, *a = &n1, *b = &n2, *p;
prev->next = b;
a->next = b->next;
b->next = a;
for (p = head; p != NULL; p = p->next) printf("%d ", p->v);
printf("/ n1.v=%d\n", n1.v);
```
출력:
```
0 2 1 3 / n1.v=1
```

순회 결과는 둘 다 0 2 1 3으로 같다. 하지만 값 교환은 노드 n1에 든 값이 2로 바뀌었고 next는 하나도 안 건드렸다. 노드 교환은 n1의 값은 1 그대로이고 n0, n1, n2의 next 세 개가 바뀌어 n1이 세 번째 자리로 옮겨 갔다. 코드가 `->v`를 바꾸는지 `->next`를 바꾸는지로 둘을 가른다.

### 정리

그림을 그릴 때는 노드마다 `[값 | next]` 상자를 하나씩 그리고, head·p·prev 같은 포인터 변수는 상자 위에 이름표로 붙여 둔다. 그다음 한 문장이 실행될 때마다 그 문장이 바꾸는 화살표 하나만 고쳐 그린다.

```mermaid
제목: 노드는 값과 다음 노드의 주소(next)를 가진다. 마지막 노드의 next는 NULL
flowchart LR
  H(["head"]) --> A("10 | next")
  A --> B("20 | next")
  B --> N(["NULL"])
```

### 예제
```c
#include <stdio.h>
#include <stdlib.h>
typedef struct Node {
    int data;
    struct Node *next;
} Node;
Node *make(int d, Node *n) {
    Node *p = malloc(sizeof(Node));
    p->data = d;
    p->next = n;
    return p;
}
int main() {
    Node *head = make(1, make(2, make(3, NULL)));
    Node *cur = head, *prev = NULL;
    while (cur != NULL) {
        Node *nx = cur->next;
        cur->next = prev;
        prev = cur;
        cur = nx;
    }
    head = prev;
    Node *n = make(9, head->next);
    head->next = n;
    for (cur = head; cur != NULL; cur = cur->next) printf("%d ", cur->data);
    printf("\n%d\n", head->next->next->data);
    return 0;
}
```
출력:
```
3 9 2 1 
2
```
처음 리스트는 1→2→3이다. 역순 반복을 돌 때마다 (prev, cur)를 표로 적어 보면 (NULL,1) → (1,2) → (2,3) → (3,NULL) 순서로 바뀌고, 반복이 끝났을 때의 prev가 새 head가 되므로 리스트는 3→2→1이다. 그 뒤 9를 head 다음에 끼우면 3→9→2→1이 되고, `head->next->next`는 세 번째 노드인 2다.

```c
#include <stdio.h>
#include <stdlib.h>
struct Node { int v; struct Node *next; };
struct Node *add(struct Node *head, int v) {
    struct Node *p = malloc(sizeof(struct Node)), *t = head;
    p->v = v; p->next = NULL;
    if (head == NULL) return p;
    while (t->next != NULL) t = t->next;
    t->next = p;
    return head;
}
int main() {
    struct Node *head = NULL, *p;
    int i;
    for (i = 1; i <= 5; i++) head = add(head, i * 10);
    for (p = head; p != NULL && p->next != NULL; p = p->next->next) {
        int t = p->v; p->v = p->next->v; p->next->v = t;
    }
    int cnt = 0;
    for (p = head; p != NULL; p = p->next) { printf("%d ", p->v); cnt++; }
    printf("\n%d\n", cnt);
    return 0;
}
```
출력:
```
20 10 40 30 50 
5
```
add로 10→20→30→40→50을 만든 뒤, 교환 반복은 `p = p->next->next`로 p를 두 노드씩 옮긴다. 그래서 p는 10, 30, 50이 든 노드를 차례로 가리키고, p와 그다음 노드의 값을 바꿔 (10,20)은 (20,10)이, (30,40)은 (40,30)이 된다. p가 50일 때는 `p->next`가 NULL이라 `p->next != NULL` 조건이 거짓이 되어 반복이 끝나고, 50은 그대로 남는다.

### 자주 틀리는 포인트
- 역순 코드의 `nx = cur->next` 저장 누락 시 다음 노드 분실(빈칸 단골 줄)
- `head = prev` 누락 시 head가 옛 첫 노드 1(이제 마지막 노드)을 가리켜 1만 출력
- 값 교환과 노드 교환 혼동, 값 교환은 `->v`만 바꾸고 next 그대로, 노드 교환은 `->next` 여러 개 변경
- 25-2처럼 글자마다 새 노드를 head 자리에 넣는 "앞에 삽입"(`p->next = head; head = p;`)은 넣기만 해도 역순

## 숫자 알고리즘 패턴 (완전수·소수·자릿수 뒤집기·잔돈)
출제: 23-3, 23-2, 23-1, 22-3, 22-1, 21-2, 20-3
함정: 소수 판별에서 `break`로 빠져나왔는지 끝까지 돌았는지를 `i == n`으로 구분한다.

### 개념
이 묶음의 코드는 거의 다 `%`(나머지)와 `/`(몫) 두 연산으로 만들어진다. 나누어떨어지는지 보려면 `%`가 0인지 확인하고, 자릿수를 떼어 내려면 `% 10`과 `/ 10`을 쓰고, 잔돈은 몫과 나머지를 차례로 구한다. 패턴마다 짧은 코드와 출력을 두고, 어느 줄이 빈칸으로 나오기 좋은지 함께 짚는다.

패턴별 핵심 줄부터 표로 모으면 이렇다.

| 패턴 | 코드 핵심 | 결과 |
|---|---|---|
| 완전수 | `for (i = 1; i < n; i++) if (n % i == 0) s += i;` 뒤 `s == n` | 6, 28 |
| 소수 | `for (i = 2; i < n; i++) if (n % i == 0) break;` 뒤 `i == n`이면 소수 | 2 3 5 7 11 13 17 19 |
| 자릿수 뒤집기 | `rev = rev * 10 + x % 10; x /= 10;` | 1234 → 4321 |
| 자릿수 합 | `s += x % 10; x /= 10;` | 1234 → 10 |
| 잔돈(큰 단위부터) | `cnt = m / coin; m %= coin;` | 1270 → 500×2, 100×2, 50×1, 10×2 |
| 잔돈(m을 바꾸지 않는 한 줄 식) | `a = m/1000; b = m%1000/500; c = m%500/100; d = m%100/10;` 바로 위 단위로 나눈 나머지를 다시 나눈다 | 4620 → 4, 1, 1, 2 (23-2 빈칸. `m/500%2`, `m/100%5`, `m/10%10`도 정답) |
| 거듭제곱·팩토리얼 | `r *= b` n번 / `r *= i` | 반복 또는 재귀 |
| 2진 → 10진 (정수에 0/1을 적은 경우) | `sum += (n % 10) * w; w *= 2; n /= 10;` | 101110 → 46 (23-1 빈칸 유형) |

#### 완전수: 약수의 합이 자기 자신
완전수는 자기 자신을 뺀 약수를 모두 더했을 때 자기 자신이 되는 수다. 6이 그 예다.

```c
int n = 6, i, s = 0;
for (i = 1; i < n; i++) if (n % i == 0) { printf("%d ", i); s += i; }
printf("-> %d %d\n", s, s == n);
```
출력:
```
1 2 3 -> 6 1
```

조건이 `i < n`이라 자기 자신 6은 빼고 i = 1부터 5(n-1)까지 나누어 본다. 나누어떨어지는 1, 2, 3을 더하면 6이고 `s == n`이 참(1)이니 6은 완전수다. 여러 n을 검사하는 코드라면 n이 바뀔 때마다 s를 0으로 되돌리는 `s = 0` 줄이 반드시 있어야 한다.

#### 소수: break로 나왔는지 i == n으로 본다
소수는 1과 자기 자신 말고는 나누어떨어지는 수가 없는 수다. 그럼 반복이 끝난 뒤 i에는 무엇이 남아 있을까? 7과 9로 비교해 보자.

```c
int n, i;
n = 7;
for (i = 2; i < n; i++) if (n % i == 0) break;
printf("n=%d i=%d %d\n", n, i, i == n);
n = 9;
for (i = 2; i < n; i++) if (n % i == 0) break;
printf("n=%d i=%d %d\n", n, i, i == n);
```
출력:
```
n=7 i=7 1
n=9 i=3 0
```

7은 2부터 6까지 아무것도 나누어떨어지지 않는다. 반복이 끝까지 돌고, 조건 `i < n`이 거짓이 되는 순간의 i, 즉 7이 남는다. 9는 3에서 나누어떨어져 `break`로 중간에 빠져나오고, 그때의 i 3이 그대로 남는다. 그래서 반복 뒤의 `i == n`이 "끝까지 돌았다", 곧 소수라는 뜻이 된다.

#### 자릿수 떼어 내기: % 10과 / 10
1234의 자릿수를 뒤집는 것과 자릿수를 더하는 것은 같은 반복으로 할 수 있다. 한 바퀴가 끝날 때마다 x, rev, s가 어떻게 바뀌는지가 핵심이다.

```c
int x = 1234, rev = 0, s = 0;
while (x > 0) {
    rev = rev * 10 + x % 10;
    s += x % 10;
    x /= 10;
    printf("x=%d rev=%d s=%d\n", x, rev, s);
}
```
출력:
```
x=123 rev=4 s=4
x=12 rev=43 s=7
x=1 rev=432 s=9
x=0 rev=4321 s=10
```

`x % 10`은 끝자리 하나를 떼어 내고, `x /= 10`은 그 끝자리를 지운다. 뒤집기는 rev에 10을 곱해 일의 자리를 0으로 비운 다음 떼어 낸 숫자를 더한다. 4에 10을 곱하고 3을 더해 43, 다시 10을 곱하고 2를 더해 432, 마지막에 4321이 된다. 합은 떼어 낸 4, 3, 2, 1을 그냥 더해 10이다. 빈칸이 `% 10`, `/ 10`, `* 10` 중 하나인 이유가 여기 있다.

#### 잔돈: 큰 단위부터 몫과 나머지
1270원을 500, 100, 50, 10원으로 거슬러 줄 때, 각 동전의 개수는 몫이고 남은 돈은 나머지다.

```c
int coin[] = {500, 100, 50, 10}, m = 1270, i;
for (i = 0; i < 4; i++) {
    printf("%d원 %d개, ", coin[i], m / coin[i]);
    m %= coin[i];
    printf("남은 돈 %d\n", m);
}
```
출력:
```
500원 2개, 남은 돈 270
100원 2개, 남은 돈 70
50원 1개, 남은 돈 20
10원 2개, 남은 돈 0
```

몫을 구한 뒤 `m %= coin[i]`로 m을 줄여 가는 방식이다. 그런데 23-2는 m을 바꾸지 않고 한 줄 식으로 바로 구하는 빈칸이었다. 4620을 넣으면 이렇게 된다.

```c
int m = 4620;
printf("%d %d %d %d\n", m / 1000, m % 1000 / 500, m % 500 / 100, m % 100 / 10);
printf("%d %d %d\n", m / 500 % 2, m / 100 % 5, m / 10 % 10);
```
출력:
```
4 1 1 2
1 1 2
```

`m % 1000 / 500`은 1000원짜리로 거슬러 주고 남은 620을 500으로 나눈 몫이다. 같은 방식으로 100원은 `m % 500`(120)을 100으로, 10원은 `m % 100`(20)을 10으로 나눈다. 구하려는 동전보다 한 단계 큰 단위로 나눈 나머지를 쓰기 때문에 m을 줄이지 않아도 된다. 두 번째 줄처럼 먼저 몫을 구한 뒤 나머지를 구하는 `m/500%2`, `m/100%5`, `m/10%10`도 같은 1, 1, 2가 나와서 정답으로 인정된다.

#### 2진수를 10진수로
정수 101110에 0과 1을 적어 두고 이걸 2진수로 읽어 10진으로 바꾸는 유형이다.

```c
int n = 101110, sum = 0, w = 1;
while (n > 0) {
    sum += (n % 10) * w;
    w *= 2;
    n /= 10;
}
printf("%d\n", sum);
```
출력:
```
46
```

자릿수 떼어 내기와 같은 `% 10`, `/ 10`이지만, 떼어 낸 자리에 곱하는 가중치 w가 1, 2, 4, 8로 두 배씩 커진다. 그래서 끝자리부터 0×1 + 1×2 + 1×4 + 1×8 + 0×16 + 1×32 = 46이다.

#### 거듭제곱·팩토리얼: 초기값부터 본다
곱해 가는 반복은 초기값이 결과를 좌우한다. 아래는 같은 반복에 초기값만 다르게 준 것이다.

```c
int i, r1 = 1, r0 = 0;
for (i = 1; i <= 5; i++) { r1 *= i; r0 *= i; }
printf("%d %d\n", r1, r0);
```
출력:
```
120 0
```

1에서 시작하면 1×2×3×4×5 = 120이지만, 0에서 시작하면 무엇을 곱해도 0이다. 20-3이 이 함정이었다.

### 예제
```c
#include <stdio.h>
int main() {
    int n, i, s, cnt = 0, rev = 0, x = 1234;
    for (n = 2; n <= 30; n++) {
        s = 0;
        for (i = 1; i < n; i++) if (n % i == 0) s += i;
        if (s == n) printf("%d ", n);
    }
    printf("\n");
    for (n = 2; n <= 20; n++) {
        for (i = 2; i < n; i++) if (n % i == 0) break;
        if (i == n) cnt++;
    }
    printf("%d\n", cnt);
    while (x > 0) { rev = rev * 10 + x % 10; x /= 10; }
    printf("%d\n", rev);
    int coin[] = {500, 100, 50, 10}, m = 1270;
    for (i = 0; i < 4; i++) { printf("%d ", m / coin[i]); m %= coin[i]; }
    printf("\n");
    return 0;
}
```
출력:
```
6 28 
8
4321
2 2 1 2 
```
30 이하의 완전수는 6(1+2+3)과 28이고, 20 이하의 소수는 2, 3, 5, 7, 11, 13, 17, 19의 8개다. 자릿수 뒤집기는 x%10으로 끝자리를 떼어 내서 rev의 끝에 붙이는 일을 반복한다. 잔돈은 몫을 찍은 다음, 남은 나머지로 m을 갱신하고 다음 단위로 넘어간다.

### 자주 틀리는 포인트
- 완전수 판별의 `s = 0` 위치는 바깥 반복 안, 안쪽 반복 시작 직전(빈칸이면 답은 `s = 0`)
- 소수 판별 반복이 `i <= n / 2`나 `i * i <= n`이면 "끝까지 돌았다"를 판단하는 조건도 달라짐(조건식은 코드 그대로)
- 반복해서 곱하는 코드의 초기값이 0이면 결과는 항상 0(20-3), 초기값부터 확인
- 자릿수 뒤집기 빈칸은 `% 10`, `/ 10`, `* 10` 세 개가 번갈아 출제

완전수 판별에서 `s = 0`이 그 자리에 있어야 하는 이유는, n이 바뀔 때마다 약수의 합을 0부터 다시 더해야 하기 때문이다.

## 배열과 포인터 연산
출제: 26-2, 26-1, 22-2, 21-2
함정: `p + 1`은 주소가 1 느는 것이 아니라 "다음 원소"다. `*(p + i)`와 `p[i]`와 `a[i]`는 같다.

### 개념
포인터는 쉽게 말해 "주소를 담는 변수"다. 그런데 배열과 같이 쓰면 주소 계산이 원소 단위로 바뀌어서, 포인터로도 배열을 인덱스처럼 다룰 수 있게 된다. 시험은 `a[i]`, `p[i]`, `*(p + i)`가 같다는 이 대응을 한 글자씩 비틀어 묻는다. 주소를 보는 것부터 하나씩 쌓아 간다.

식부터 표로 모으면 이렇다.

| 식 | 뜻 |
|---|---|
| `int *p = a;` | p는 a[0]의 주소. `p = &a[0]`과 같다 |
| `*(p + i)` = `p[i]` | i번째 원소 |
| `p++` | 다음 원소를 가리킴. 배열 이름 a는 `a++` 불가 |
| `*p++` | `*(p++)`: 현재 값을 쓰고 p를 이동 |
| `(*p)++`, `++*p` | 가리키는 값을 증가. p는 그대로 |
| `&a[3] - p` | 두 주소의 거리(원소 단위, 바이트 아님). p가 a[1]이면 2 |
| `*(a + 4) - *a` | a[4] - a[0] (값의 뺄셈) |

#### 주소 꺼내기: &
`&`는 변수의 주소를 꺼낸다. 그럼 배열 이름 a를 포인터에 넣으면 어느 주소가 들어갈까? 주소 값은 실행할 때마다 달라지니 비교 결과와 차이만 찍는다.

```c
int a[5] = {10, 20, 30, 40, 50};
int *p = a;
printf("%d %d\n", p == &a[0], p == a);
printf("%d\n", (int)((char *)&a[1] - (char *)&a[0]));
```
출력:
```
1 1
4
```

배열 이름 a는 첫 원소 a[0]의 주소로 쓰이기 때문에 `int *p = a;`는 `p = &a[0]`과 같다. 그리고 a[0]과 a[1]의 주소는 4바이트 차이가 난다. int 하나가 4바이트인 이 컴퓨터에서는 원소가 4바이트 간격으로 붙어 있다.

#### 따라가기: *
주소를 얻었으면 그 주소로 가서 값을 꺼내거나 바꿀 수 있다. 이때 쓰는 것이 `*`다.

```c
int a[5] = {10, 20, 30, 40, 50};
int *p = a;
printf("%d\n", *p);
*p = 11;
printf("%d\n", a[0]);
```
출력:
```
10
11
```

`*p`는 p가 가리키는 칸, 곧 a[0]이다. 그래서 `*p = 11`을 하면 p를 거쳐 a[0] 자체가 11로 바뀐다. `&`가 변수에서 주소를 꺼낸다면, `*`는 반대로 주소에서 그 칸의 변수를 꺼낸다. 이 페이지에서 "주소를 따라간다"는 말은 이렇게 `*`를 붙이는 일을 뜻한다.

#### p + 1은 다음 원소
그럼 p에 1을 더하면 주소가 1바이트 늘어날까?

```c
int a[5] = {10, 20, 30, 40, 50};
int *p = a;
printf("%d %d\n", *(p + 1), *(p + 3));
printf("%d %d\n", (int)((p + 1) - p), (int)((char *)(p + 1) - (char *)p));
```
출력:
```
20 40
1 4
```

`p + 1`을 따라간 `*(p + 1)`은 a[1] = 20, `p + 3`을 따라간 `*(p + 3)`은 a[3] = 40이다. 둘째 줄을 보면 `p + 1`과 p의 차이가 포인터끼리 빼면 1, 바이트(`char *`)로 빼면 4다. 포인터에 1을 더하면 주소가 1 느는 게 아니라 다음 원소의 주소가 되고, 주소가 몇 바이트 늘지는 가리키는 자료형 크기(이 컴퓨터의 int는 4)가 정한다.

#### *(p + i)와 p[i]와 a[i]는 같다
그럼 `a[i]`, `*(p + i)`, `p[i]`는 정말 같은 값일까?

```c
int a[5] = {10, 20, 30, 40, 50};
int *p = a, i;
for (i = 0; i < 5; i++) printf("%d %d %d\n", a[i], *(p + i), p[i]);
```
출력:
```
10 10 10
20 20 20
30 30 30
40 40 40
50 50 50
```

세 줄이 모두 같다. `p[i]`는 `*(p + i)`를 줄여 쓴 표기라서, 포인터에도 대괄호를 붙일 수 있다. 그럼 p를 한 칸 옮긴 다음 대괄호를 쓰면 어떻게 될까?

```c
int a[5] = {10, 20, 30, 40, 50};
int *p = a;
p++;
printf("%d %d %d\n", *p, p[0], p[2]);
```
출력:
```
20 20 40
```

`p++` 뒤로는 p가 a[1]을 가리키므로 `p[0]`은 a[1] = 20이고 `p[2]`는 a[1 + 2], 곧 a[3] = 40이다. 대괄호 번호는 a[0]이 아니라 지금 p가 가리키는 a[1]부터 센다. 참고로 같은 일을 `a++`로 하려고 하면 컴파일 오류가 난다. 배열 이름은 옮길 수 없고 포인터 변수만 옮길 수 있다.

#### *p++와 (*p)++
생김새가 비슷한 두 식은 바꾸는 대상이 다르다.

```c
int a[3] = {10, 20, 30};
int *p = a;
int x = *p++;
printf("%d %d\n", x, *p);
(*p)++;
printf("%d %d\n", *p, a[1]);
++*p;
printf("%d %d %d\n", *p, a[1], (int)(p - a));
```
출력:
```
10 20
21 21
22 22 1
```

괄호가 없으면 `++`는 p에 붙어서 `*p++`는 `*(p++)`로 읽힌다. 그래서 지금 값 10을 x에 주고 p는 a[1]로 옮겨 간다. 반대로 `(*p)++`와 `++*p`는 가리키는 값 a[1]을 20에서 21, 22로 하나씩 키우고 p는 그대로 둔다. 마지막 줄의 `p - a`가 1, 곧 p가 여전히 a[1]을 가리킨다는 것이 그 증거다.

#### 주소끼리 빼면 원소 개수
마지막으로 뺄셈 두 가지를 구분하자.

```c
int a[5] = {10, 20, 30, 40, 50};
int *p = &a[1];
printf("%d\n", (int)(&a[3] - p));
printf("%d\n", *(a + 4) - *a);
```
출력:
```
2
40
```

`&a[3] - p`는 주소끼리의 뺄셈이라 a[3]과 a[1] 사이가 원소 몇 개인지를 돌려준다. 바이트로는 int 두 개만큼 떨어져 있지만 답은 2다. `*(a + 4) - *a`는 `*`가 붙어 있으니 값끼리의 뺄셈, 곧 a[4] - a[0] = 50 - 10이다.

### 예제
```c
#include <stdio.h>
int main() {
    int a[5] = {10, 20, 30, 40, 50};
    int *p = a;
    printf("%d %d\n", *p, *(p + 2));
    p++;
    printf("%d %d\n", *p, p[2]);
    printf("%d\n", *(a + 4) - *a);
    printf("%d\n", (int)(&a[3] - p));
    int s = 0, i;
    for (i = 0; i < 5; i++) s += *(a + i);
    printf("%d\n", s / 5);
    ++*p;
    printf("%d %d\n", *p, a[1]);
    return 0;
}
```
출력:
```
10 30
20 40
40
2
30
21 21
```
`p++`를 하고 나면 p는 a[1]을 가리킨다. 그래서 `p[2]`는 a[1]에서 두 칸 뒤인 a[3] = 40이 된다. `&a[3] - p`도 a[3]과 a[1] 사이의 거리라서 2이고, `++*p`는 p가 가리키는 a[1]을 21로 바꾼다.

### 자주 틀리는 포인트
- `p++` 이후의 `p[i]`는 a[i + 1](p가 가리키는 위치를 그림에 표시)
- `*p++`와 `(*p)++` 혼동, 괄호가 없으면 `++`는 p에 붙음
- 합이 int인 평균 계산의 `/ 5`는 정수 나눗셈, `%.1f`로 찍는 문제는 `(double)` 형변환 위치 확인
- 함수에 넘긴 배열은 포인터가 되므로 함수 안의 `sizeof(arr)`는 배열 크기가 아닌 포인터 크기

평균 문제의 예로 26-1은 `double ar`에 `(double)p[i]`를 누적해서 처음부터 실수 나눗셈으로 계산된다.

## 포인터 배열과 배열 포인터
출제: 24-2, 21-3
함정: `int *pa[2]`는 포인터가 2개 들어 있는 배열이고, `int (*ap)[3]`은 "길이 3 배열"을 가리키는 포인터 하나다.

### 개념
이 두 선언은 글자 배치만 다르고 뜻은 정반대라서 이름부터 헷갈린다. 가르는 기준은 우선순위 하나다. 선언에서도 `[]`가 `*`보다 먼저 묶이기 때문에, `int *pa[2]`는 "pa는 배열인데 그 원소가 포인터"이고, 괄호로 `*`를 먼저 묶은 `int (*ap)[3]`은 "ap는 포인터인데 그 포인터가 int 3개짜리 배열을 가리킨다"가 된다.

선언별로 정리하면 이렇다. 각 줄은 이어지는 코드에서 하나씩 확인한다.

| 선언 | 뜻 | 쓰임 |
|---|---|---|
| `int *pa[2]` | int 포인터 2개짜리 배열 | `pa[i] = a[i]`로 각 행의 시작 주소를 담아 2차원처럼 사용 |
| `int (*ap)[3]` | int[3]을 가리키는 포인터 | `ap = a`(a는 `int a[?][3]`). `ap[1][2]`, `(*(ap+1))[2]` |
| `char *names[]` | 문자열 포인터 배열 | `names[2]`는 "park", `*names[1]`은 'l' |
| `**(a + 1)` | `*(a + 1)`은 1행, 그것의 `*`는 1행 0열 | `a[1][0]` |

#### 포인터 배열: 포인터를 여러 개 담은 배열
가장 단순한 경우는 변수 두 개의 주소를 배열에 담는 것이다.

```c
int x = 1, y = 2;
int *pa[2] = {&x, &y};
printf("%d %d\n", *pa[0], *pa[1]);
*pa[1] = 20;
printf("%d\n", y);
```
출력:
```
1 2
20
```

pa는 칸이 두 개인 배열이고 각 칸에 주소가 들어 있다. `*pa[1]`은 `[]`가 먼저 묶여 pa[1]을 꺼낸 다음 그 주소를 따라간 값, 곧 y다. 그래서 `*pa[1] = 20`이 y를 바꾼다.

#### 포인터 배열로 2차원 다루기
이번에는 각 칸에 2차원 배열의 행 시작 주소를 넣어 보자.

```c
int a[2][3] = {{1, 2, 3}, {4, 5, 6}};
int *pa[2] = {a[0], a[1]};
printf("%d %d\n", pa[1][2], *(pa[0] + 1));
```
출력:
```
6 2
```

pa[1]에는 a[1]의 시작 주소가 들어 있으니 `pa[1][2]`는 그 행에서 2번 칸, a[1][2] = 6이다. `pa[0] + 1`은 0행 1열의 주소이고 거기에 `*`를 붙이면 값 2가 된다.

#### 문자열 포인터 배열
포인터 배열은 문자열 여러 개를 담는 `char *names[]` 모양으로도 나온다.

```c
char *names[] = {"kim", "lee", "park"};
printf("%s %c %c\n", names[2], *names[1], *(names[0] + 1));
```
출력:
```
park l i
```

각 칸에는 문자열의 시작 주소가 들어 있다. 그래서 `names[2]`를 `%s`로 찍으면 "park" 전체가, `*names[1]`은 "lee"의 첫 글자가 나온다. `names[0] + 1`은 "kim"의 1번 칸 주소라서 `*(names[0] + 1)`은 두 번째 글자 i다.

#### 배열 포인터: 행 하나를 가리키는 포인터
이제 괄호가 있는 쪽이다. `int (*ap)[3]`은 int 3개짜리 배열 하나를 통째로 가리킨다. 그럼 `ap + 1`은 얼마나 움직일까?

```c
int a[2][3] = {{1, 2, 3}, {4, 5, 6}};
int (*ap)[3] = a;
printf("%d %d\n", ap[1][2], (*(ap + 1))[2]);
printf("%d %d\n", (int)((ap + 1) - ap), (int)((char *)(ap + 1) - (char *)ap));
```
출력:
```
6 6
1 12
```

포인터끼리 빼면 1이지만 바이트로는 12(이 컴퓨터 기준), 곧 int 3개만큼 움직였다. ap가 가리키는 단위가 원소 하나가 아니라 행 하나이기 때문이다. 그래서 `ap + 1`은 1행이고, `*(ap + 1)`로 그 행을 꺼내 `[2]`를 붙이면 a[1][2] = 6이다. `ap[1][2]`는 같은 것을 줄여 쓴 것이다.

#### 2차원 배열 이름에 *를 두 번
2차원 배열 이름 a도 배열 포인터처럼 행 단위로 움직인다. 그래서 값을 꺼내려면 `*`가 두 번 필요하다.

```c
int a[2][3] = {{1, 2, 3}, {4, 5, 6}};
printf("%d %d %d\n", **a, **(a + 1), *(*(a + 1) + 2));
```
출력:
```
1 4 6
```

`*(a + 1)`은 1행이고, 거기에 한 번 더 `*`를 붙인 `**(a + 1)`은 1행 0열 a[1][0] = 4다. 열을 옮기려면 바깥 `*`를 붙이기 전에 `*(a + 1)`에 열 번호를 더한다. 그래서 `*(*(a + 1) + 2)`는 1행 2열 a[1][2] = 6이다.

### 정리

정리하자면 포인터 배열에서 `pa[i] + j`는 i행 j열의 주소이고, 여기에 `*`를 붙인 `*(pa[i] + j)`는 그 칸의 값이다.

### 예제
```c
#include <stdio.h>
int main() {
    int a[2][3] = {{1, 2, 3}, {4, 5, 6}};
    int *pa[2] = {a[0], a[1]};
    int (*ap)[3] = a;
    printf("%d %d\n", pa[1][2], *(pa[0] + 1));
    printf("%d %d\n", ap[1][0], (*(ap + 1))[2]);
    printf("%d\n", **(a + 1));
    char *names[] = {"kim", "lee", "park"};
    printf("%s %c\n", names[2], *names[1]);
    printf("%c\n", *(names[0] + 1));
    int i, s = 0;
    for (i = 0; i < 2; i++) s += *(pa[i] + i);
    printf("%d\n", s);
    return 0;
}
```
출력:
```
6 2
4 6
4
park l
i
6
```
`pa[1]`에는 a[1]의 시작 주소가 들어 있으니 `pa[1][2]`는 a[1][2] = 6이고, 같은 원리로 `*(pa[0] + 1)`은 a[0][1] = 2다. 문자열 쪽은 `*names[1]`이 "lee"의 첫 글자, `*(names[0] + 1)`이 "kim"의 두 번째 글자다. 마지막 합은 `*(pa[i] + i)`라서 a[0][0] + a[1][1] = 1 + 5가 된다.

### 자주 틀리는 포인트
- `*names[1]`은 `*(names[1])`(`[]`가 `*`보다 먼저 묶임), 결과는 문자열의 첫 글자
- 포인터 배열의 합 문제는 `*(pa[i] + j)`에서 i와 j 중 고정된 쪽을 반복문으로 확인
- `int (*ap)[3]`의 `ap + 1`은 원소 하나가 아닌 3개 원소, 곧 한 행만큼 이동

## 이중 포인터
출제: 25-2, 25-1, 24-3
함정: `*pp = &b`는 p를 바꾸고, `**pp = 5`는 p가 가리키는 변수를 바꾼다. 별 개수를 세어 어느 층을 건드리는지 본다.

### 개념
이중 포인터는 "포인터 변수의 주소"를 담는 포인터다. 왜 이런 게 필요할까? 함수가 호출한 쪽의 포인터 변수 자체를 바꾸고 싶을 때, 또 행마다 따로 만든 2차원 배열을 다룰 때 쓰기 때문이다. 여기서는 `int **pp = &p;`일 때 pp를 2층, p를 1층, p가 가리키는 int를 0층이라고 부른다. 식에 별이 몇 개 붙었느냐가 어느 층을 건드리느냐를 정한다.

층별로 정리하면 이렇다.

| 식 | 층 | 뜻 |
|---|---|---|
| `pp` | 2층 | p의 주소 |
| `*pp` | 1층 | p 자체(어떤 int의 주소). `*pp = &b`는 p를 b로 돌림 |
| `**pp` | 0층 | p가 가리키는 int 값 |
| 함수 인자 `int **q` | | 함수 안에서 `*q = ...`로 호출자의 포인터 변수를 바꿀 수 있다 |
| `int **m = malloc(...)` | | 행 포인터 배열. `m[i] = malloc(...)`로 각 행을 만들면 `m[i][j]` 사용 |

#### 포인터의 주소를 담는 포인터
a를 가리키는 p를 만들고, 다시 p를 가리키는 pp를 만들어 보자.

```c
int a = 1;
int *p = &a;
int **pp = &p;
printf("%d %d %d\n", **pp, *pp == p, pp == &p);
```
출력:
```
1 1 1
```

pp에는 p의 주소가 들어 있다(2층). `*pp`로 한 번 따라가면 p 자체가 나오고(1층), `**pp`로 한 번 더 따라가면 a의 값 1이 나온다(0층). 세 비교가 모두 참이다.

#### 별 하나는 p를, 별 둘은 a를 바꾼다
그럼 `*pp`에 대입하는 것과 `**pp`에 대입하는 것은 무엇이 다를까?

```c
int a = 1, b = 2;
int *p = &a;
int **pp = &p;
**pp = 10;
printf("%d %d\n", a, b);
*pp = &b;
**pp = 5;
printf("%d %d %d\n", a, b, *p);
```
출력:
```
10 2
10 5 5
```

처음 `**pp = 10`은 p가 가리키는 a를 바꾼다. 그다음 `*pp = &b`는 값이 아니라 p 자체를 바꿔서 p가 b를 가리키게 만든다. 그래서 같은 `**pp = 5`가 이번에는 b를 바꾸고, `*p`도 b인 5가 된다. 같은 식이라도 p가 가리키는 대상이 바뀐 다음에는 다른 변수를 건드린다는 점이 이 유형의 함정이다.

#### 함수가 호출자의 포인터를 바꾸려면
이번에는 함수 안에서 호출한 쪽의 p가 전역 변수 g를 가리키도록 바꾸려 한다. `int *`로 받는 것과 `int **`로 받는 것을 나란히 둔다.

```c
#include <stdio.h>
int g = 99;
void bad(int *q) { q = &g; }
void good(int **q) { *q = &g; }
int main() {
    int a = 1;
    int *p = &a;
    bad(p);
    printf("%d\n", *p);
    good(&p);
    printf("%d\n", *p);
    return 0;
}
```
출력:
```
1
99
```

`bad`는 p의 값(a의 주소)을 복사해 받은 q를 바꿨을 뿐이라 호출자의 p는 여전히 a를 가리킨다. `good`은 p의 주소를 받았기 때문에 `*q = &g`가 호출자의 p 자체를 바꾼다. 연결 리스트에서 head를 바꾸는 함수가 `struct Node **head`를 받는 이유도 똑같다.

#### malloc으로 만드는 2차원
`int **m`은 행 포인터들을 담은 배열을 가리킨다. 아래 코드는 행마다 따로 malloc해서 2×3을 만든다.

```c
int **m = malloc(2 * sizeof(int *));
int i, j;
for (i = 0; i < 2; i++) {
    m[i] = malloc(3 * sizeof(int));
    for (j = 0; j < 3; j++) m[i][j] = i * 3 + j;
}
printf("%d %d %d\n", m[1][2], *(*(m + 1) + 2), *m[1]);
```
출력:
```
5 5 3
```

`m[i]`는 i행의 시작 주소이고 `m[i][j]`는 그 행의 j번 칸이다. 1행 2열은 1*3+2 = 5이고, 이것을 별로 풀어 쓴 `*(*(m + 1) + 2)`도 같은 5다. `*m[1]`은 1행의 첫 칸이라 3이다.

### 정리

구조체 이중 포인터(`struct Node **head`)를 쓰는 이유도 같다. 함수 안에서 head 자체를 바꾸고 싶기 때문이다. 그래서 함수 안의 `*head = newNode;`가 호출자의 head를 바꾼다.

### 예제
```c
#include <stdio.h>
#include <stdlib.h>
void set(int **q) { **q = 100; }
int main() {
    int a = 1, b = 2;
    int *p = &a;
    int **pp = &p;
    **pp = 10;
    printf("%d %d\n", a, *p);
    *pp = &b;
    **pp += 5;
    printf("%d %d %d\n", a, b, *p);
    set(pp);
    printf("%d %d\n", a, b);
    int **m = malloc(2 * sizeof(int *));
    int i, j;
    for (i = 0; i < 2; i++) {
        m[i] = malloc(3 * sizeof(int));
        for (j = 0; j < 3; j++) m[i][j] = i * 3 + j;
    }
    printf("%d %d\n", m[1][2], *(*(m + 1) + 0));
    return 0;
}
```
출력:
```
10 10
10 7 7
10 100
5 3
```
처음에는 p가 a를 가리키니 `**pp = 10`은 a를 바꾼다. `*pp = &b`로 p가 b를 가리키게 되므로 `**pp += 5`는 b를 7로 만들고, 이어지는 `set(pp)`도 b를 100으로 만든다. p 자체가 b를 가리키도록 바뀌었기 때문이다. a는 그 뒤로 건드리지 않으니 10 그대로다. m은 2×3 배열처럼 쓰여서 m[1][2] = 1*3+2 = 5, m[1][0] = 3이다.

### 자주 틀리는 포인트
- `*pp = &b` 이후의 `*p`는 b(p가 가리키는 대상이 바뀐 시점을 표에 기록)
- `int *p`로 받은 매개변수에 `p = ...` 재대입은 호출자의 포인터에 반영 안 됨, 바꾸려면 `int **`로 받아 `*p = ...`
- malloc으로 만든 2차원도 `m[i][j]`와 `*(*(m + i) + j)`가 같음, 순서는 행 i, 열 j

연결 리스트 삽입 함수에서 호출자의 head가 안 바뀌는 문제도 head를 포인터 하나(`struct Node *`)로 받아 재대입한 경우다.

## 비트·삼항·시프트 (마스크 연산)
출제: 25-3, 25-1, 24-1
함정: 결과를 `%x`로 찍으면 16진 소문자다. 10진으로 쓰면 틀린다.

### 개념
비트 연산은 수를 2진수 자리 하나하나로 펼쳐 놓고 자리끼리 계산한다. 그래서 이 유형은 머리로 10진 계산을 하려 들면 꼬이고, 먼저 2진으로 적어 두면 거의 기계적으로 풀린다. 아래 표의 기준 값인 0xA5 하나에 연산자를 하나씩 붙여 간다.

0xA5를 기준으로 정리하면 이렇다.

| 연산 | 뜻 | 0xA5(1010 0101) 기준 (16진 / 10진) |
|---|---|---|
| `v & 0x0F` | 하위 4비트만 남김 | 0101 = 0x5 / 5 |
| `v \| 0x0F` | 하위 4비트를 전부 1로 | 1010 1111 = 0xaf / 175 |
| `v ^ 0xFF` | 8비트 반전 | 0101 1010 = 0x5a / 90 |
| `v >> 4` | 상위 4비트를 아래로 | 1010 = 0xa / 10 |
| `(v << 1) & 0xFF` | 왼쪽 시프트 후 8비트만 유지 | 0100 1010 = 0x4a / 74 |
| `n & (1 << i)` | i번째 비트 검사 | 1인 비트 개수 세기에 사용 |

#### 먼저 2진으로 펼쳐 놓기
0xA5는 10진으로 얼마이고, 서식에 따라 어떻게 찍힐까?

```c
unsigned char v = 0xA5;
printf("%d %x %X\n", v, v, v);
```
출력:
```
165 a5 A5
```

16진 한 자리는 2진 네 자리와 딱 맞는다. A는 1010, 5는 0101이니 0xA5는 1010 0101이고, 10진으로는 165다. `%x`는 소문자 a5, `%X`는 대문자 A5로 찍힌다.

#### &는 남기고, |는 켜고, ^는 뒤집는다
이번에는 0x0F(0000 1111)와 0xFF(1111 1111)를 마스크로 건다.

```c
unsigned char v = 0xA5;
printf("%x %x %x\n", v & 0x0F, v | 0x0F, v ^ 0xFF);
printf("%d %d %d\n", v & 0x0F, v | 0x0F, v ^ 0xFF);
```
출력:
```
5 af 5a
5 175 90
```

자리를 맞춰 적어 보면 바로 보인다.

```
v        1010 0101
& 0x0F   0000 0101   마스크가 1인 자리만 남음
| 0x0F   1010 1111   마스크가 1인 자리를 1로
^ 0xFF   0101 1010   마스크가 1인 자리를 반전
```

`&`는 둘 다 1일 때만 1이 되어 하위 4비트만 남는다. `|`는 하나라도 1이면 1이므로 하위 4비트가 전부 켜진다. `^`는 서로 다를 때 1이 되는 연산이고, 1과 XOR한 자리는 뒤집힌다. 첫 줄과 둘째 줄은 같은 결과를 16진과 10진으로 찍은 것일 뿐인데 답은 전혀 달라 보인다.

#### 시프트: 자리를 통째로 민다
`>>`와 `<<`는 비트를 오른쪽, 왼쪽으로 민다. 그럼 왼쪽으로 민 결과가 8비트를 넘으면 어떻게 될까?

```c
unsigned char v = 0xA5;
printf("%d %d\n", v >> 4, v << 1);
printf("%d %x\n", (v << 1) & 0xFF, (v << 1) & 0xFF);
```
출력:
```
10 330
74 4a
```

`v >> 4`는 1010 0101에서 오른쪽 네 자리 0101이 밀려 사라지고 왼쪽 네 자리 1010만 남으므로 10이다. `v << 1`은 계산이 int로 이루어져서 맨 왼쪽 비트 1이 버려지지 않고 9비트짜리 1 0100 1010, 곧 330이 된다. 그래서 8비트만 보려면 `& 0xFF`를 한 번 더 걸어야 하고, 그 결과가 0100 1010 = 74(0x4a)다.

#### i번째 비트 검사: n & (1 << i)
`1 << i`는 맨 오른쪽 자리를 0번으로 세었을 때 i번 자리만 1인 마스크다. 이것과 AND하면 그 자리가 1인지 알 수 있다. 아래는 37의 경우다.

```c
int n = 37, i, bits = 0;
for (i = 0; i < 8; i++)
    if (n & (1 << i)) { printf("%d ", i); bits++; }
printf("-> %d\n", bits);
```
출력:
```
0 2 5 -> 3
```

37은 2진으로 100101이다. 맨 오른쪽부터 0번, 2번, 5번 자리가 1이라서 그 i에서만 결과가 0이 아니고, 1인 비트는 모두 3개다.

#### 우선순위: 시프트는 +보다 늦고 |보다 빠르다
괄호 없이 섞어 쓰면 무엇부터 계산될까?

```c
printf("%d %d %d\n", 1 << 2 + 1, 1 << 3 | 1 << 1, (1 << 2) + 1);
```
출력:
```
8 10 5
```

`1 << 2 + 1`은 덧셈이 먼저라 `1 << 3` = 8이다. 괄호로 시프트를 먼저 묶은 `(1 << 2) + 1`은 4 + 1 = 5가 되어 전혀 다른 값이 나온다. `1 << 3 | 1 << 1`은 반대로 시프트가 `|`보다 먼저 묶여 8 | 2 = 10이다.

#### 삼항 연산자
마지막은 묶음 제목에 같이 들어 있는 삼항 연산자 `조건 ? 참일 때 : 거짓일 때`다.

```c
int a = 7, b = 12;
printf("%d %s\n", a > b ? a : b, (a & 1) ? "odd" : "even");
printf("%s\n", (b & 1) ? "odd" : "even");
```
출력:
```
12 odd
even
```

`a > b ? a : b`는 둘 중 큰 값을 고르는 식이다. `(a & 1)`은 맨 오른쪽 비트(0번)만 보는데, 홀수는 이 비트가 1이고 짝수는 0이다. 그래서 7은 odd, 12는 even이다.

### 정리

삼항 연산자 쪽은 `a > b ? a : b`가 최댓값을 고르는 식이고 `(a & 1) ? "odd" : "even"`은 홀짝을 가리는 식이다. 비트 연산자 전체 표는 [코딩 공통] 비트 연산 주제에 있다.

### 예제
```c
#include <stdio.h>
int main() {
    unsigned char v = 0xA5;
    printf("%x %x %x\n", v & 0x0F, v | 0x0F, v ^ 0xFF);
    printf("%d %d\n", v >> 4, (v << 1) & 0xFF);
    int n = 37, i, bits = 0;
    for (i = 0; i < 8; i++) if (n & (1 << i)) bits++;
    printf("%d\n", bits);
    int a = 7, b = 12;
    int max = a > b ? a : b;
    printf("%d %s\n", max, (a & 1) ? "odd" : "even");
    printf("%d\n", 1 << 3 | 1 << 1);
    return 0;
}
```
출력:
```
5 af 5a
10 74
3
12 odd
10
```
이런 문제는 0xA5를 2진 1010 0101로 펼쳐 놓고 자리별로 계산하면 된다. 37도 2진으로 바꾸면 100101이라 1인 비트가 3개다. 마지막 `1 << 3 | 1 << 1`은 시프트가 먼저 묶여서 8 | 2 = 10이 된다.

### 자주 틀리는 포인트
- 25-1처럼 구조체 멤버에 `& 0xA5` 같은 마스크를 거는 문제는 멤버 값을 2진으로 바꾼 뒤 자리 맞춰 AND
- `%x`는 소문자(af), `%X`는 대문자(AF), 답도 서식 문자대로
- 시프트의 우선순위는 `|`보다 높고 `+`보다 낮음(`1 << 2 + 1`은 덧셈부터 해서 `1 << 3`)

## 정렬 코드 빈칸 (버블·선택)
출제: 25-1, 23-2, 20-1
함정: 빈칸은 대개 반복 범위(`n - 1 - i`), 비교 부호(`>` 오름차순 / `<` 내림차순), 교환 세 줄 중 하나다.

### 개념
정렬 문제는 알고리즘 이름을 묻기보다 코드의 한 줄을 비워 두고 채우게 한다. 그래서 각 정렬이 "무엇을 비교하고, 언제 교환하고, 한 회전이 끝나면 어디가 확정되는가"를 손으로 따라갈 수 있어야 한다. 교환 세 줄부터 시작해 버블, 선택 순서로 회전마다 배열 상태를 본다.

정렬별로 빈칸이 나오는 자리를 정리하면 이렇다.

| 정렬 | 모양 | 빈칸이 자주 나오는 자리 |
|---|---|---|
| 버블 | 이웃한 `a[j]`와 `a[j+1]`을 비교·교환. 바깥 i 1회전마다 뒤에서부터 하나씩 확정 | 안쪽 범위 `j < n - 1 - i`, 비교 `a[j] > a[j+1]` |
| 선택 | i 자리에 올 최솟값(최댓값)의 인덱스 k를 찾은 뒤 한 번만 교환 | `k = i` 초기화, 비교 `b[j] < b[k]`, 교환 `b[i]↔b[k]` |
| 교환 | `t = a[j]; a[j] = a[j+1]; a[j+1] = t;` | 임시 변수 줄 |

#### 교환은 임시 변수 세 줄
두 값을 바꾸려면 왜 변수가 하나 더 필요할까? 임시 변수 없이 해 보면 바로 알 수 있다.

```c
int x = 5, y = 3, t;
t = x; x = y; y = t;
printf("%d %d\n", x, y);
x = 5; y = 3;
x = y; y = x;
printf("%d %d\n", x, y);
```
출력:
```
3 5
3 3
```

`x = y`를 하는 순간 x에 있던 5는 사라진다. 그 뒤에 `y = x`를 해 봐야 3이 다시 들어갈 뿐이다. 그래서 5를 t에 먼저 저장해 두는 세 줄이 필요하고, 빈칸으로 나오면 이 순서(`t = a`, `a = b`, `b = t`)를 그대로 쓴다.

#### 버블 정렬: 이웃끼리 비교해 큰 값을 뒤로
버블 정렬은 바로 옆 두 칸을 비교해서 순서가 틀리면 바꾼다. 아래 코드는 회전(i)이 끝날 때마다 배열을 찍는다.

```c
int a[5] = {5, 3, 8, 1, 4};
int i, j, t, n = 5;
for (i = 0; i < n - 1; i++) {
    for (j = 0; j < n - 1 - i; j++)
        if (a[j] > a[j + 1]) { t = a[j]; a[j] = a[j + 1]; a[j + 1] = t; }
    printf("i=%d: ", i);
    for (j = 0; j < n; j++) printf("%d ", a[j]);
    printf("\n");
}
```
출력:
```
i=0: 3 5 1 4 8 
i=1: 3 1 4 5 8 
i=2: 1 3 4 5 8 
i=3: 1 3 4 5 8 
```

한 회전이 끝날 때마다 아직 확정되지 않은 값 중 가장 큰 값이 남은 칸의 마지막에 자리 잡는다. i=0 뒤에는 8이 a[4]에, i=1 뒤에는 5가 a[3]에 확정된다. 확정된 칸은 다시 비교할 필요가 없어서 안쪽 범위가 `j < n - 1 - i`로 회전마다 하나씩 줄어든다. i=0이면 j는 0부터 3까지, i=1이면 2까지 돈다. 1회전만 보면 3 5 1 4 8로, 아직 전체가 정렬된 상태가 아니라는 점도 확인할 수 있다.

#### 선택 정렬: 최솟값의 위치를 찾아 한 번만 교환
선택 정렬은 i 자리에 올 값을 먼저 찾고 교환은 한 번만 한다. 이번에는 회전마다 찾은 위치 k도 같이 찍었다.

```c
int b[5] = {5, 3, 8, 1, 4};
int i, j, t, k, n = 5;
for (i = 0; i < n - 1; i++) {
    k = i;
    for (j = i + 1; j < n; j++) if (b[j] < b[k]) k = j;
    t = b[i]; b[i] = b[k]; b[k] = t;
    printf("i=%d k=%d: ", i, k);
    for (j = 0; j < n; j++) printf("%d ", b[j]);
    printf("\n");
}
```
출력:
```
i=0 k=3: 1 3 8 5 4 
i=1 k=1: 1 3 8 5 4 
i=2 k=4: 1 3 4 5 8 
i=3 k=3: 1 3 4 5 8 
```

i=0에서는 전체에서 가장 작은 1의 위치 3을 찾아 b[3]의 1과 b[0]의 5를 바꾼다. i=1에서는 3이 이미 제자리라 k가 1 그대로이고, 자기 자신과의 교환이 일어나 배열은 변하지 않는다. 버블은 마지막 칸 a[4]부터 값이 확정되고, 선택은 첫 칸 b[0]부터 확정된다는 차이가 여기서 드러난다. 비교가 `<`라서 오름차순이고, 이것을 `>`로 바꾸면 최댓값을 찾게 되어 내림차순이 된다(아래 예제가 그 경우다).

### 정리

"몇 회전 후의 배열 상태"를 묻는 문제가 나오면 i 값마다 배열을 한 줄씩 적어 가며 푼다.

### 예제
```c
#include <stdio.h>
int main() {
    int a[5] = {5, 3, 8, 1, 4};
    int i, j, t, n = 5;
    for (i = 0; i < n - 1; i++) {
        for (j = 0; j < n - 1 - i; j++)
            if (a[j] > a[j + 1]) { t = a[j]; a[j] = a[j + 1]; a[j + 1] = t; }
        if (i == 0) {
            for (j = 0; j < n; j++) printf("%d ", a[j]);
            printf("\n");
        }
    }
    int b[5] = {5, 3, 8, 1, 4}, k;
    for (i = 0; i < n - 1; i++) {
        k = i;
        for (j = i + 1; j < n; j++) if (b[j] > b[k]) k = j;
        t = b[i]; b[i] = b[k]; b[k] = t;
    }
    for (i = 0; i < n; i++) printf("%d ", b[i]);
    printf("\n");
    return 0;
}
```
출력:
```
3 5 1 4 8 
8 5 4 3 1 
```
버블 1회전(i=0)을 따라가 보면 5와 3을 교환해서 3,5,8,1,4가 되고, 8과 1을 교환해서 3,5,1,8,4, 다시 8과 4를 교환해서 3,5,1,4,8이 된다. 한 회전 만에 가장 큰 8이 마지막 칸 a[4]에 자리 잡았다. 코드 뒷부분의 선택 정렬은 비교가 `>`라서 내림차순이 된다.

### 자주 틀리는 포인트
- 비교 부호 하나로 오름차순과 내림차순이 뒤집힘(출력 순서로 부호를 거꾸로 추정하는 빈칸도 출제)
- 버블 정렬 1회전 후 확정되는 것은 끝 한 자리뿐, 전체가 정렬됐다고 보면 오답
- 선택 정렬의 안쪽 반복은 `j = i + 1`부터 시작(`j = 0`이면 다른 알고리즘)
- 23-1의 Java 정렬 빈칸도 같은 모양, swap 세 줄의 순서를 물음

## 함수 호출 (값 전달과 주소 전달)
출제: 26-2, 24-2, 20-3
함정: `swap(a, b)`는 복사본을 바꾸므로 원본이 안 변한다. `swap(&a, &b)`와 포인터 매개변수여야 변한다.

### 개념
C에서 함수에 인자를 넘기면 언제나 값이 복사되어 넘어간다. 그런데 그 값이 주소라면, 복사본으로도 원본이 있는 곳을 찾아가 바꿀 수 있다. 원본이 바뀌느냐 안 바뀌느냐는 이 차이 하나로 정해진다.

전달 방식별로 정리하면 이렇다.

| 전달 방식 | 선언 | 호출 | 원본 변화 |
|---|---|---|---|
| 값 전달 | `void f(int x)` | `f(a)` | 없음 |
| 주소 전달 | `void f(int *x)` | `f(&a)` | `*x = ...`로 바뀜 |
| 배열 전달 | `void f(int arr[])` 또는 `int *arr` | `f(a)` | 배열은 항상 주소가 넘어가므로 바뀜 |
| 반환값 | `int f(int x) { x++; return x; }` | `r = f(a)` | a는 그대로, r만 새 값 |
| 중첩 호출 | `f(g(2))` | 안쪽 g부터 | g의 반환값이 f의 인자가 된다. f(x)=x*2, g(x)=x+3이면 f(g(2)) = 10 |

#### 값 전달: 복사본이 넘어간다
함수 안에서 매개변수를 바꾸면 호출한 쪽 변수도 바뀔까? 헷갈리게 하려고 이름도 똑같이 a로 맞췄다.

```c
#include <stdio.h>
void f(int a) { a = 100; printf("f 안: %d\n", a); }
int main() {
    int a = 1;
    f(a);
    printf("main: %d\n", a);
    return 0;
}
```
출력:
```
f 안: 100
main: 1
```

f의 a는 main의 a 값 1을 복사해 받은 별개의 변수다. 이름이 같아도 메모리의 서로 다른 칸이라서 f 안에서 100으로 바꿔도 main의 a는 1 그대로다.

#### 주소 전달: 원본을 찾아가 바꾼다
이번에는 a의 주소를 넘기고, 함수 안에서 `*`로 따라간다.

```c
#include <stdio.h>
void f(int *x) { *x = 100; }
int main() {
    int a = 1;
    f(&a);
    printf("%d\n", a);
    return 0;
}
```
출력:
```
100
```

x에 복사된 것은 a의 주소다. 주소는 복사해도 같은 곳을 가리키니 `*x = 100`이 main의 a를 바꾼다. 원본을 바꾸는 swap이 `swap(&a, &b)`와 포인터 매개변수로 짜이는 이유다.

#### 배열은 주소가 넘어간다
배열을 넘기면 어떻게 될까? 원소를 바꾸는 함수와, 매개변수에 다른 배열을 대입하는 함수를 나란히 두었다.

```c
#include <stdio.h>
int other[3] = {7, 7, 7};
void fill(int arr[], int n) { int i; for (i = 0; i < n; i++) arr[i] *= 2; }
void reset(int *arr) { arr = other; arr[0] = 0; }
int main() {
    int a[3] = {1, 2, 3};
    fill(a, 3);
    printf("%d %d %d\n", a[0], a[1], a[2]);
    reset(a);
    printf("%d %d %d / %d\n", a[0], a[1], a[2], other[0]);
    return 0;
}
```
출력:
```
2 4 6
2 4 6 / 0
```

배열 이름은 첫 원소의 주소로 넘어가기 때문에 fill이 `arr[i]`를 바꾸면 main의 a가 1 2 3에서 2 4 6으로 두 배가 된다. 반면 reset의 `arr = other`는 복사받은 주소 변수 arr가 other를 가리키도록 바꿀 뿐이다. 그 뒤의 `arr[0] = 0`은 other를 바꾸고, main의 a는 2 4 6에서 변하지 않는다.

#### 반환값과 중첩 호출
마지막으로 원본 대신 반환값으로 결과를 돌려받는 경우다.

```c
#include <stdio.h>
int f(int x) { return x * 2; }
int g(int x) { return x + 3; }
int inc(int x) { x++; return x; }
int main() {
    int a = 2;
    int r = inc(a);
    printf("%d %d\n", a, r);
    printf("%d %d\n", f(g(2)), g(f(2)));
    return 0;
}
```
출력:
```
2 3
10 7
```

inc는 복사본 x를 3으로 만들어 돌려줄 뿐이라 a는 2, r만 3이다. 중첩 호출은 안쪽부터 계산한다. `f(g(2))`는 g(2) = 5가 f에 들어가 10이고, 순서를 바꾼 `g(f(2))`는 f(2) = 4에 3을 더해 7이다.

### 예제
```c
#include <stdio.h>
void swap1(int a, int b) { int t = a; a = b; b = t; }
void swap2(int *a, int *b) { int t = *a; *a = *b; *b = t; }
void fill(int arr[], int n) { int i; for (i = 0; i < n; i++) arr[i] *= 2; }
int inc(int x) { x++; return x; }
int main() {
    int x = 1, y = 2;
    swap1(x, y);
    printf("%d %d\n", x, y);
    swap2(&x, &y);
    printf("%d %d\n", x, y);
    int a[3] = {1, 2, 3};
    fill(a, 3);
    printf("%d %d %d\n", a[0], a[1], a[2]);
    int r = inc(x);
    printf("%d %d\n", x, r);
    return 0;
}
```
출력:
```
1 2
2 1
2 4 6
2 3
```
swap1은 복사본만 바꾸기 때문에 1 2 그대로다. 반면 swap2는 주소로 받아서 원본을 바꾸므로 2 1이 된다. 배열은 주소가 넘어가니 fill이 끝나면 원본 자체가 두 배가 되어 있다. inc는 반환값만 3이고 x는 2다.

### 자주 틀리는 포인트
- 매개변수 이름이 호출 쪽 변수와 같아도(`int a`와 `a`) 서로 다른 변수(일부러 이름을 같게 만든 문제 있음)
- 24-2처럼 값 전달 swap 뒤에 switch가 이어지는 문제는 swap 효과 없음부터 확정
- 배열 매개변수에 `arr = 다른배열` 재대입은 호출자 배열에 반영 안 됨, 반영되는 것은 원소 대입(`arr[i] = `)뿐

## 재귀
출제: 23-3, 22-1
함정: 반환식에 `n *`이 붙어 있으면 팩토리얼, `+`이면 합, 두 번 호출하면 피보나치다. 호출 횟수는 트리 노드 수다.

### 개념
재귀는 함수가 자기 자신을 다시 부르는 것이다. fact(3)은 fact(2)를 부르고, fact(2)는 fact(1)을 부른다. 매번 n이 1 작은 같은 문제를 맡기는 것이다. fact(1)은 종료 조건 `n <= 1`에 해당하므로 더 부르지 않고 처음으로 값 1을 돌려준다. 그 값을 받은 fact(2)가 먼저 계산을 끝내고, 마지막으로 fact(3)이 끝난다. 그래서 추적할 때는 "호출이 쌓이는 단계(fact(3), fact(2), fact(1) 순서)"와 "값이 계산되는 단계(fact(1), fact(2), fact(3) 순서)"를 나눠서 본다.

기출에 나오는 재귀 함수는 이 네 가지다.

| 함수 | 모양 | 값 |
|---|---|---|
| 팩토리얼 | `n <= 1 ? 1 : n * fact(n-1)` | fact(5) = 120 |
| 거듭제곱 | `e == 0 ? 1 : b * power(b, e-1)` | power(2,10) = 1024 |
| 자릿수 합 | `n == 0 ? 0 : n % 10 + sumd(n/10)` | sumd(1234) = 10 |
| 피보나치 | `n < 2 ? n : fib(n-1) + fib(n-2)` | fib(5) = 5, 호출 15번 |

#### 호출이 쌓인다
fact(3)을 부르면 어떤 순서로 함수가 불릴까? fact가 호출될 때마다 한 줄씩 찍게 했다.

```c
#include <stdio.h>
int fact(int n) {
    printf("fact(%d) 호출\n", n);
    if (n <= 1) return 1;
    return n * fact(n - 1);
}
int main() {
    printf("%d\n", fact(3));
    return 0;
}
```
출력:
```
fact(3) 호출
fact(2) 호출
fact(1) 호출
6
```

fact(3)의 반환식은 `3 * fact(2)`다. 이 곱셈은 fact(2)의 값이 나와야 할 수 있으므로, fact(3)은 곱셈을 하지 못한 채 끝나지 않고 남아 있다. fact(2)도 같은 이유로 `2 * fact(1)`을 계산하지 못한 채 남는다. 이렇게 끝나지 않은 호출이 fact(3), fact(2), fact(1) 순서로 쌓인다. 세 번째로 불린 fact(1)은 `n <= 1`이므로 더 부르지 않고 바로 1을 돌려준다.

#### 풀리면서 값이 계산된다
그럼 미뤄 둔 곱셈은 언제 계산될까? 이번에는 돌려줄 때도 한 줄을 찍는다.

```c
#include <stdio.h>
int fact(int n) {
    int r;
    printf("fact(%d) 호출\n", n);
    if (n <= 1) r = 1;
    else r = n * fact(n - 1);
    printf("fact(%d) = %d 반환\n", n, r);
    return r;
}
int main() {
    fact(3);
    return 0;
}
```
출력:
```
fact(3) 호출
fact(2) 호출
fact(1) 호출
fact(1) = 1 반환
fact(2) = 2 반환
fact(3) = 6 반환
```

반환은 쌓인 순서의 반대인 fact(1), fact(2), fact(3) 순서로 일어난다. fact(1)이 1을 돌려주면 남아 있던 fact(2)가 2 × 1 = 2를 계산하고, 그 값을 받은 fact(3)이 3 × 2 = 6을 계산한다. 자릿수 합 sumd도 같은 방식으로 계산된다. sumd(1234)는 4 + sumd(123)을, sumd(123)은 3 + sumd(12)를 계산해야 하므로 호출이 sumd(12), sumd(1), sumd(0)까지 이어진다. sumd(0)이 0을 돌려준 뒤에는 sumd(0) = 0, sumd(1) = 1, sumd(12) = 3, sumd(123) = 6, sumd(1234) = 10 순서로 값이 정해진다.

#### printf가 호출 앞이냐 뒤냐
바로 위 출력에서 "호출" 줄은 3, 2, 1 순서로, "반환" 줄은 1, 2, 3 순서로 찍혔다. 그 코드에서 "호출" printf는 재귀 호출 `fact(n - 1)`보다 먼저 적혀 있고, "반환" printf는 그보다 나중에 적혀 있다. 재귀 호출보다 먼저 적힌 문장은 호출이 쌓이는 동안 실행되고, 나중에 적힌 문장은 재귀 호출이 값을 돌려준 뒤에 실행된다. printf 위치만 바꾼 두 함수를 비교하면 차이가 분명하다.

```c
#include <stdio.h>
void before(int n) { if (n == 0) return; printf("%d ", n); before(n - 1); }
void after(int n) { if (n == 0) return; after(n - 1); printf("%d ", n); }
int main() {
    before(3); printf("\n");
    after(3); printf("\n");
    return 0;
}
```
출력:
```
3 2 1 
1 2 3 
```

before는 printf가 재귀 호출보다 먼저 있다. before(3)이 3을 찍고 before(2)를 부르고, before(2)가 2를 찍고 before(1)을 부르는 식이어서 3 2 1이 나온다. after는 printf가 재귀 호출 다음에 있다. after(3)은 아무것도 찍기 전에 after(2)를 부르고, after(2)는 after(1)을, after(1)은 after(0)을 부른다. n이 0인 after(0)은 바로 끝난다. 그다음 after(1)이 1을 찍고 끝나고, 이어서 after(2)가 2, after(3)이 3을 찍는다. 그래서 1, 2, 3 순서다. 코드 한 줄의 위치 차이로 출력 순서가 뒤집힌다.

#### 두 번 부르면 트리가 된다: 피보나치
반환식에서 자기 자신을 두 번 부르면 호출이 한 줄로 쌓이지 않고 갈래가 생긴다. 아래 코드는 n을 0부터 5까지 바꿔 가며 fib(n) 한 번에 fib가 모두 몇 번 호출되는지 센다.

```c
#include <stdio.h>
int cnt = 0;
int fib(int n) {
    cnt++;
    if (n < 2) return n;
    return fib(n - 1) + fib(n - 2);
}
int main() {
    int n;
    for (n = 0; n <= 5; n++) {
        cnt = 0;
        int r = fib(n);
        printf("fib(%d)=%d 호출 %d번\n", n, r, cnt);
    }
    return 0;
}
```
출력:
```
fib(0)=0 호출 1번
fib(1)=1 호출 1번
fib(2)=1 호출 3번
fib(3)=2 호출 5번
fib(4)=3 호출 9번
fib(5)=5 호출 15번
```

fib(5)는 fib(4)와 fib(3)을 부르고, fib(4)와 fib(3)도 각각 두 번씩 부른다. 호출 하나를 점(노드) 하나로, 부른 쪽과 불린 쪽을 선으로 이어 그리면 나뭇가지처럼 갈라지는 그림이 되는데, 이것을 호출 트리라고 한다. 호출 횟수는 이 트리의 노드 수다. 그래서 fib(5)의 호출 횟수는 fib(5) 자신 1번에 fib(4) 쪽 호출 수와 fib(3) 쪽 호출 수를 더한 값이다. 출력에서 fib(4)가 9번, fib(3)이 5번이므로 fib(5)의 15는 1 + 9 + 5다.

### 정리

추적은 [코딩 공통]의 재귀 추적법대로 호출 트리를 그려서 한다. fib처럼 함수 첫 줄에서 전역 변수 cnt를 1씩 더하는 코드라면 cnt 값이 곧 호출 횟수다.

### 예제
```c
#include <stdio.h>
int fact(int n) { return n <= 1 ? 1 : n * fact(n - 1); }
int power(int b, int e) { return e == 0 ? 1 : b * power(b, e - 1); }
int sumd(int n) { return n == 0 ? 0 : n % 10 + sumd(n / 10); }
int cnt = 0;
int fib(int n) {
    cnt++;
    if (n < 2) return n;
    return fib(n - 1) + fib(n - 2);
}
int main() {
    printf("%d %d %d\n", fact(5), power(2, 10), sumd(1234));
    int r = fib(5);
    printf("%d %d\n", r, cnt);
    return 0;
}
```
출력:
```
120 1024 10
5 15
```
그럼 fib 호출 횟수는 왜 15일까? fib(n)의 호출 횟수를 calls(n)이라고 하자. 자기 자신 1번에 두 갈래의 호출 횟수를 더하므로 calls(n) = 1 + calls(n-1) + calls(n-2)이고, calls(0) = calls(1) = 1이다. 이 식에 작은 n부터 차례로 넣으면 calls(2) = 1 + 1 + 1 = 3, calls(3) = 1 + 3 + 1 = 5, calls(4) = 1 + 5 + 3 = 9, calls(5) = 1 + 9 + 5 = 15가 된다.

### 자주 틀리는 포인트
- 종료 조건이 `n == 1`이면 fact(0) 호출 시 무한 재귀 (기출 조건은 `n <= 1`, 코드 그대로 옮김)
- 피보나치 종료 조건 `n < 2`에서 `return n`이면 fib(0)=0, fib(1)=1, `return 1`이면 값이 달라짐
- 재귀 함수 안의 printf가 호출 전인지 후인지에 따라 출력 순서가 뒤집힘([코딩 공통] 재귀 추적법 예제 참고)

## static 변수와 전역 변수
출제: 24-3, 23-2
함정: `static int s = 0;`은 처음 한 번만 0이 되고 이후 호출에서는 이전 값을 유지한다. 지역 변수는 매번 다시 0이다.

### 개념
변수는 어디에 선언했느냐에 따라 언제 만들어지고 언제 사라지는지가 다르다. 함수를 여러 번 부르는 코드에서 값이 이어지느냐 끊기느냐가 바로 여기서 갈리기 때문에, 출력 문제의 답이 이 차이 하나로 바뀐다. 지역, static, 전역 순서로 정리한다.

먼저 종류별로 정리하면 이렇다. 아래에서 하나씩 코드로 확인한다.

| 종류 | 선언 위치 | 초기화 시점 | 수명 |
|---|---|---|---|
| 지역 변수 | 함수 안 | 호출마다 | 함수가 끝나면 사라짐 |
| static 지역 변수 | 함수 안 `static` | 프로그램 시작 시 한 번 | 프로그램 끝까지. 호출 사이에 값 유지 |
| 전역 변수 | 함수 밖 | 프로그램 시작 시 한 번(초기값 없으면 0) | 프로그램 끝까지. 모든 함수가 공유 |
| 같은 이름의 지역 변수 | 블록 안 | | 그 블록에서는 지역이 전역을 가린다 |

#### 지역 변수는 매번 새로, static은 한 번만
함수 f 안에 일반 지역 변수 l과 static 변수 s를 함께 선언하고, f를 세 번 부른다.

```c
#include <stdio.h>
void f() {
    int l = 0;
    static int s = 0;
    l++; s++;
    printf("l=%d s=%d\n", l, s);
}
int main() {
    f(); f(); f();
    return 0;
}
```
출력:
```
l=1 s=1
l=1 s=2
l=1 s=3
```

l은 f가 호출될 때마다 새로 만들어져 0이 되고, `l++`로 1이 된 뒤 f가 끝나면 사라진다. 그래서 몇 번을 불러도 1이다. 반면 s는 프로그램이 시작할 때 한 번만 0으로 초기화되고 프로그램이 끝날 때까지 남아 있다. `static int s = 0;` 줄이 매번 실행되는 것처럼 보이지만, 두 번째 호출은 이전 값 1에서, 세 번째 호출은 이전 값 2에서 1을 더한다. 그래서 s는 1, 2, 3으로 늘어난다.

#### 전역 변수는 모든 함수가 공유한다
함수 밖에 선언한 변수는 어느 함수에서 쓰든 같은 변수 하나다. 아래 코드는 g의 초기값도 일부러 쓰지 않았다.

```c
#include <stdio.h>
int g;
void add() { g += 10; }
void show() { printf("%d\n", g); }
int main() {
    show();
    add(); add();
    show();
    return 0;
}
```
출력:
```
0
20
```

g에 초기값을 쓰지 않았는데도 처음 찍은 값이 0이다. 전역 변수는 초기값이 없으면 0으로 시작하기 때문이다. 그다음 add를 두 번 부르면 같은 g에 10이 두 번 더해져 20이 되고, show도 그 g를 읽으므로 두 번째 출력은 20이다.

#### 같은 이름이면 안쪽이 가린다
전역 변수와 같은 이름의 지역 변수를 블록 안에 만들면 어느 쪽이 쓰일까?

```c
#include <stdio.h>
int g = 3;
int main() {
    printf("%d\n", g);
    {
        int g = 100;
        g++;
        printf("%d\n", g);
    }
    printf("%d\n", g);
    return 0;
}
```
출력:
```
3
101
3
```

중괄호 블록 안에서 g라고 쓰면 그 블록에서 새로 만든 지역 g를 뜻한다. 이것을 지역 변수가 전역 변수를 가린다고 한다. 그래서 `g++`도 지역 g를 100에서 101로 만든다. 블록이 끝나면 지역 g는 사라지고, 그 뒤에 쓴 g는 전역 g다. 전역 g는 한 번도 바뀌지 않았으므로 3 그대로다.

#### 전역 배열의 주소를 돌려주는 함수
23-2에 나온 모양이다. 함수가 전역 배열에 문자열을 넣고 그 주소를 돌려주면, 돌려받은 포인터들은 무엇을 가리킬까?

```c
#include <stdio.h>
#include <string.h>
char n[10];
char *save(char *src) { strcpy(n, src); return n; }
int main() {
    char *p1 = save("kim");
    char *p2 = save("lee");
    char *p3 = save("park");
    printf("%s %s %s\n", p1, p2, p3);
    printf("%d %d\n", p1 == p2, p2 == p3);
    return 0;
}
```
출력:
```
park park park
1 1
```

save는 부를 때마다 같은 배열 n의 주소를 돌려준다. 그래서 p1, p2, p3에는 모두 n의 주소가 들어 있고, `p1 == p2`와 `p2 == p3`가 둘 다 참(1)이다. 한편 n의 내용은 save가 불릴 때마다 strcpy로 덮어써져 kim, lee, park 순서로 바뀌고, 마지막에는 "park"만 남는다. 세 포인터가 모두 이 n을 가리키므로 셋 다 park를 찍는다. 23-2는 `gets`로 입력을 받았다는 점만 다르고 원리는 같다.

### 예제
```c
#include <stdio.h>
int g = 0;
int counter() {
    static int s = 0;
    int l = 0;
    s++; l++; g++;
    return s + l;
}
int main() {
    int i, r = 0;
    for (i = 0; i < 3; i++) r = counter();
    printf("%d %d\n", r, g);
    {
        int g = 100;
        printf("%d\n", g);
    }
    printf("%d\n", g);
    return 0;
}
```
출력:
```
4 3
100
3
```
r에는 반복마다 counter의 반환값이 새로 대입되므로, 마지막에 남는 것은 세 번째 호출의 반환값이다. 세 번째 호출에서 s는 그동안 누적되어 3이고, l은 매번 0에서 새로 시작해 1이다. 그래서 반환값 s + l은 4다. g는 counter가 3번 불리는 동안 1씩 늘어 3이 된다. 안쪽 블록에서 찍은 100은 `int g = 100`으로 새로 만든 지역 g의 값이다. 이 g는 전역 g와 이름만 같은 별개 변수이므로, 블록이 끝난 뒤 찍은 g는 전역 g의 값 3이다.

### 자주 틀리는 포인트
- `static int s = 0;` 줄의 초기화는 한 번뿐 (두 번째 호출부터는 초기화 없이 이전 값 사용)
- 초기값을 안 쓴 전역 변수는 0, 지역 변수는 쓰레기값 (기출은 반드시 초기화)
- 23-2의 `char *gamja(){ gets(n); return n; }`처럼 전역 버퍼를 돌려주는 함수는 호출마다 **같은 배열 n의 주소** 반환

그래서 23-2에서 gamja의 반환값을 받은 p1·p2·p3는 모두 n 하나를 가리킨다. 세 번째 입력이 앞 입력을 덮어쓰므로, 출력은 세 줄 모두 마지막 입력인 박영희다.

## 스택·큐 코드 읽기
출제: 25-2, 23-2
함정: 원형 큐의 `rear = (rear + 1) % N`은 끝에서 0으로 돌아간다. front와 rear 값을 매 연산마다 적는다.

### 개념
스택과 큐는 배열 하나와 위치를 기억하는 정수 변수(top, front, rear)로 만든다. 그래서 코드 읽기 문제는 결국 연산 한 번마다 이 정수들이 얼마가 되는지를 적어 가는 일이다. 스택, 선형 큐, 원형 큐 순서로 살펴본다.

먼저 자료구조별로 정리하면 이렇다. 아래에서 하나씩 코드로 확인한다.

| 자료구조 | 변수 | push/enqueue | pop/dequeue | 빈 상태 |
|---|---|---|---|---|
| 스택(배열) | `top = -1` | `st[++top] = v` | `return st[top--]` | `top == -1` |
| 큐(선형) | `front = rear = 0` | `q[rear++] = v` | `return q[front++]` | `front == rear` |
| 원형 큐 | `front = rear = 0`, 크기 N | `q[rear] = v; rear = (rear+1) % N` | `v = q[front]; front = (front+1) % N` | `front == rear` |

#### 스택: top은 -1에서 시작한다
스택은 마지막에 넣은 것이 먼저 나오는 LIFO다. 1, 2, 3을 넣고 두 번 빼면 이렇다.

```c
int st[4], top = -1;
st[++top] = 1;
st[++top] = 2;
st[++top] = 3;
printf("top=%d\n", top);
printf("%d ", st[top--]);
printf("%d\n", st[top--]);
printf("top=%d\n", top);
```
출력:
```
top=2
3 2
top=0
```

top은 마지막에 넣은 원소의 인덱스이고, 비어 있을 때는 -1이다. 넣을 때는 `++top`이므로 top을 먼저 1 늘린 뒤 그 칸에 쓴다. 첫 `st[++top] = 1`은 top을 -1에서 0으로 바꾸고 st[0]에 1을 넣는다. 그래서 세 개를 넣으면 st[0], st[1], st[2]에 1, 2, 3이 들어가고 top은 2다. 뺄 때는 `top--`이므로 지금 top 칸의 값을 먼저 읽고 그다음 top을 1 줄인다. 첫 번째로 빼면 st[2]의 3을 읽고 top이 1이 되고, 두 번째로 빼면 st[1]의 2를 읽고 top이 0이 된다. 넣을 때 `st[top++]`라고 쓰면 top이 -1인 채로 칸 번호에 쓰이므로 첫 원소가 st[-1]에 들어가 버린다. 전위와 후위를 구분해야 하는 이유다.

#### 선형 큐: front와 rear는 앞으로만 간다
큐는 먼저 넣은 것이 먼저 나오는 FIFO다. rear로 넣고 front로 뺀다.

```c
int q[10], front = 0, rear = 0;
q[rear++] = 10;
q[rear++] = 20;
q[rear++] = 30;
printf("%d ", q[front++]);
printf("%d\n", q[front++]);
printf("front=%d rear=%d\n", front, rear);
```
출력:
```
10 20
front=2 rear=3
```

넣을 때마다 rear가, 뺄 때마다 front가 1씩 커진다. 둘 다 커지기만 하고 줄지 않으므로, 이미 빼서 비어 있는 q[0], q[1]은 다시 쓰지 못한다. 그리고 rear가 배열 크기 10이 되면 더 넣을 수 없다. 이 낭비를 없앤 것이 원형 큐다.

#### 원형 큐: % N으로 0으로 돌아온다
원형 큐는 마지막 칸 다음을 다시 0번 칸으로 본다. 크기 4라면 3번 칸 다음이 0번 칸이다. 그럼 크기 4에서 rear를 여섯 번 옮기면 rear는 어떤 값이 될까?

```c
int i, rear = 0;
for (i = 0; i < 6; i++) {
    printf("%d ", rear);
    rear = (rear + 1) % 4;
}
printf("\n");
```
출력:
```
0 1 2 3 0 1 
```

rear가 0, 1, 2일 때 `(rear + 1) % 4`는 1을 더한 1, 2, 3이고, rear가 3일 때는 4 % 4 = 0이 된다. 쉽게 말해 "다음 칸 번호, 단 마지막 칸 다음은 0"이라는 뜻이다. front도 같은 식으로 바뀐다.

#### 원소 수와 가득 참
front와 rear만 보고 원소가 몇 개인지 알 수 있을까? 크기 N = 4에서 몇 가지 경우를 계산했다.

```c
#define N 4
int front = 1, rear = 3;
printf("%d\n", (rear - front + N) % N);
front = 3; rear = 1;
printf("%d\n", (rear - front + N) % N);
front = 2; rear = 1;
printf("%d %d\n", (rear - front + N) % N, (rear + 1) % N == front);
```
출력:
```
2
2
3 1
```

첫 번째 경우(front = 1, rear = 3)처럼 rear가 front보다 크면 rear - front = 2가 그대로 원소 수다. 두 번째 경우(front = 3, rear = 1)는 rear가 3번 칸을 지나 0번 칸으로 넘어간 뒤여서 rear가 front보다 작고, 1 - 3 = -2로 음수가 된다. 그래서 N을 더한 뒤 `% N`을 해서 결과를 언제나 0부터 N-1 사이로 맞춘다. (-2 + 4) % 4 = 2다. 마지막 경우(front = 2, rear = 1)는 (1 - 2 + 4) % 4 = 3이므로 원소가 3개, 곧 N-1개다. 또 (1 + 1) % 4 = 2가 front와 같으므로 `(rear + 1) % N == front`가 참(1)이다. 한 칸을 비워 두는 방식에서는 이 상태를 가득 참으로 본다.

### 정리

23-2 빈칸으로 나온 `(i + 1) % 5`도 같은 식이다. 크기 5 배열에서 i의 다음 칸 번호를 구하되, 마지막 칸 다음은 0으로 돌린다. 스택은 마지막에 넣은 것이 먼저 나오는 LIFO, 큐는 FIFO다.

### 예제
```c
#include <stdio.h>
#define N 4
int q[N], front = 0, rear = 0;
int st[N], top = -1;
void push(int v) { st[++top] = v; }
int pop() { return st[top--]; }
void enq(int v) { q[rear] = v; rear = (rear + 1) % N; }
int deq() { int v = q[front]; front = (front + 1) % N; return v; }
int main() {
    push(1); push(2); push(3);
    printf("%d ", pop());
    push(4);
    printf("%d ", pop());
    printf("%d\n", pop());
    enq(10); enq(20); enq(30);
    printf("%d ", deq());
    enq(40);
    enq(50);
    printf("%d %d\n", front, rear);
    printf("%d ", deq());
    printf("%d\n", q[0]);
    return 0;
}
```
출력:
```
3 4 2
10 1 1
20 50
```
스택부터 보면, 1,2,3을 넣고 3을 뺀 뒤 4를 넣으므로 st[0]부터 [1,2,4]가 되고, 그다음 4와 2가 차례로 나온다. 큐는 10,20,30을 넣으면 rear=3이 되고, 10을 빼면 front=1이 된다. 원형 큐다운 부분은 여기부터다. 40은 q[3]에 들어가고 rear는 (3+1)%4 = 0이 된다. 이어서 50은 q[0]에 들어가고 rear=1이 된다. 그래서 front와 rear를 찍으면 1 1이다. 다음 deq는 q[1]의 20을 꺼내고, q[0]에는 10 대신 50이 들어 있다.

### 자주 틀리는 포인트
- `st[++top]`과 `st[top++]`는 다름 (top 초기값이 -1이면 전위 `++top`)
- 원형 큐에서 rear가 0으로 돌아가 덮어쓰는 q[0]은 이미 뺀 자리 (데이터 손실 없음)
- 큐의 원소 수는 `(rear - front + N) % N`, front == rear는 빈 상태
- 가득 참 판정은 한 칸을 비워 두고 `(rear + 1) % N == front` (최대 N-1개)

바로 위 예제는 가득 참 검사가 없어서, 4칸이 다 찼는데도 front == rear == 1이 되어 버렸다. 이러면 빈 것과 가득 찬 것이 구분되지 않으므로 보통은 한 칸을 비워 둔다.

## switch fall-through
출제: 24-2, 23-2
함정: `break`가 없으면 일치한 case부터 아래 case들을 전부 실행한다. default도 지나간다.

### 개념
switch는 값에 맞는 case 하나만 실행하는 문장처럼 보이지만, 실제로는 "값과 같은 case 라벨로 점프한 다음 그 뒤 줄을 차례로 실행"하는 문장이다. case 라벨은 실행을 시작할 위치만 표시하므로, 실행 도중 다음 case 라벨이 나와도 실행은 계속된다. switch를 빠져나가는 때는 `break`를 만나거나 switch의 끝에 이르렀을 때뿐이다. 그래서 떨어짐(fall-through) 문제는 점프한 case부터 break까지 실행되는 줄을 차례로 적어 풀면 된다.

먼저 규칙을 표로 보면 이렇다. 아래에서 하나씩 코드로 확인한다.

| 규칙 | 내용 |
|---|---|
| 진입 | 값과 같은 `case`로 점프한다. 없으면 `default` |
| 진행 | `break`를 만날 때까지 아래로 계속 실행. 다음 case 라벨은 무시 |
| default 위치 | 중간에 있어도 된다. 위에서 떨어져 내려오면 실행된다 |
| 반복문 안 | `break`는 switch만 빠져나간다. 반복문을 끝내지 않는다 |

#### break가 있으면 그 case만
먼저 모든 case에 break가 있는 평범한 모양이다.

```c
int x = 2;
switch (x) {
    case 1: printf("one "); break;
    case 2: printf("two "); break;
    case 3: printf("three "); break;
}
printf("\n");
```
출력:
```
two 
```

x가 2이니 `case 2:`로 점프해서 two를 찍고, 바로 뒤의 break로 switch를 빠져나온다.

#### break가 없으면 아래로 떨어진다
그럼 break를 모두 지우면 어떻게 될까?

```c
int x = 2;
switch (x) {
    case 1: printf("one ");
    case 2: printf("two ");
    case 3: printf("three ");
}
printf("\n");
```
출력:
```
two three 
```

점프하는 곳은 똑같이 `case 2:`다. 그런데 break가 없으므로 two를 찍은 뒤 다음 `case 3:` 라벨과 상관없이 three까지 찍고, switch의 끝에서 빠져나온다. 코드에서 `case 2:`보다 위에 있는 `case 1:`은 점프로 건너뛰었으므로 one은 찍히지 않는다.

#### default가 중간에 있으면
일치하는 case가 없으면 default로 점프한다. 그 default가 맨 끝이 아니라 중간에 있으면 어떻게 될까?

```c
int x = 9;
switch (x) {
    case 1: printf("one ");
    default: printf("default ");
    case 2: printf("two "); break;
    case 3: printf("three ");
}
printf("\n");
```
출력:
```
default two 
```

x는 9인데 `case 9:`가 없으므로 default로 점프한다. default도 시작 위치만 표시하므로, default를 찍은 뒤 바로 다음 줄인 `case 2:`의 two까지 실행하고 그 줄의 break에서 switch를 빠져나온다. three는 break보다 뒤에 있어서 찍히지 않는다. 결국 default가 어디에 있느냐보다 "점프한 곳부터 break까지 어느 줄이 실행되는가"가 답을 정한다.

#### 반복문 안의 break
switch가 for 안에 있을 때 break는 어디까지 빠져나갈까?

```c
int i;
for (i = 0; i < 3; i++) {
    switch (i) {
        case 1: printf("[1] "); break;
        default: printf("%d ", i);
    }
}
printf("end i=%d\n", i);
```
출력:
```
0 [1] 2 end i=3
```

i가 0일 때는 같은 case가 없어 default에서 0을 찍는다. i가 1일 때는 [1]을 찍고 break를 만나지만, 이 break는 switch만 빠져나가므로 for 반복은 계속된다. 그래서 i=2에서 default의 2가 찍힌다. 반복문 전체가 끝난 것은 조건 `i < 3`이 거짓이 된 i=3에서다.

### 예제
```c
#include <stdio.h>
int main() {
    int i, s = 0;
    for (i = 0; i < 4; i++) {
        switch (i) {
            case 0: s += 1;
            case 1: s += 10; break;
            case 2: s += 100;
            default: s += 1000;
        }
    }
    printf("%d\n", s);
    char g = 'B';
    switch (g) {
        case 'A': printf("A");
        case 'B': printf("B");
        case 'C': printf("C"); break;
        case 'D': printf("D");
    }
    printf("\n");
    return 0;
}
```
출력:
```
2121
BC
```
i 값마다 따라가 보면 이렇다. i=0은 `case 0:`에서 1을 더하고, break가 없어서 `case 1:`의 10까지 더한 뒤 break를 만나므로 s는 11이다. i=1은 `case 1:`에서 10만 더해서 21, i=2는 `case 2:`에서 100을 더하고 break 없이 default의 1000까지 더해서 1121이다. i=3은 같은 case가 없어 default만 실행되어 2121이 된다. 뒤의 switch는 g가 'B'이므로 `case 'B':`로 점프해 B를 찍고, 이어서 C를 찍은 뒤 break에서 빠져나온다.

### 자주 틀리는 포인트
- i 값마다 "어느 case로 점프해서 어디서 break하는가"를 한 줄씩 기록 (누적값만 적으면 떨어짐을 놓치기 쉬움)
- `case 2: ... default: ...`처럼 마지막이 아닌 default (위치보다 "떨어지는 경로"로 판단)
- 24-2처럼 값 전달 swap 뒤에 오는 switch는 swap 전 값으로 점프

## printf 서식과 자료형
출제: 26-1, 24-1
함정: 같은 값도 서식에 따라 다르게 나온다. 97을 `%d`는 97, `%c`는 a, `%x`는 61.

### 개념
printf 문제는 계산을 맞혀도 서식을 잘못 옮기면 틀린다. 메모리에 든 값은 하나인데 `%d`, `%c`, `%x` 중 무엇으로 찍느냐에 따라 화면에 나오는 모양이 완전히 달라지기 때문이다. 정수, 실수, 폭 순서로 정리한다.

먼저 서식별로 정리하면 이렇다. 아래에서 하나씩 코드로 확인한다.

| 서식 | 뜻 | 예(255, 'a', 3.14159) |
|---|---|---|
| `%d` | 10진 정수 | 255 |
| `%u` / `%ld` | 부호 없는 정수 / long | (unsigned)-1은 4294967295 |
| `%x` / `%X` | 16진 소문자 / 대문자 | ff / FF |
| `%o` | 8진 | 377 |
| `%c` | 문자 | a (97을 넘겨도 a) |
| `%s` | 문자열 | |
| `%f` | 실수 소수점 6자리 | 3.141590 |
| `%lf` | double. printf에서는 `%f`와 같고, scanf로 double을 읽을 때는 반드시 `%lf` | 3.141590 |
| `%.2f` | 소수점 2자리 (반올림) | 3.14 |
| `%5.1f` | 전체 5칸, 소수 1자리, 오른쪽 정렬 | `  3.1` |
| `%-5d` | 왼쪽 정렬 5칸 | `255  ` |
| `%05d` | 0으로 채워 5칸 | 00255 |
| `%%` | % 문자 | % |

#### 같은 값, 다른 서식
97 하나를 네 가지 서식으로 찍으면 무엇이 나올까?

```c
int n = 97;
printf("%d %c %x %o\n", n, n, n, n);
printf("%c %c\n", 'a', 'a' - 32);
```
출력:
```
97 a 61 141
a A
```

`%d`는 10진 97, `%c`는 문자 코드 97에 해당하는 a, `%x`는 16진 61, `%o`는 8진 141이다. 문자 'a'도 결국 문자 코드 97인 정수이므로 `'a' - 32`는 65가 되고, 65를 `%c`로 찍으면 대문자 A다. 소문자에서 32를 빼면 대문자, 대문자에 32를 더하면 소문자가 된다.

#### 실수 서식: 자릿수와 폭
`%f`는 기본으로 소수 몇 자리까지 찍을까? 폭을 확인하려고 양옆에 `|`를 붙였다.

```c
double d = 3.14159;
printf("%f\n", d);
printf("%.2f|%5.1f|\n", d, d);
```
출력:
```
3.141590
3.14|  3.1|
```

`%f`는 소수점 아래 6자리까지 찍어서 모자란 자리를 0으로 채운다. `%.2f`는 소수 2자리로 반올림한 3.14다. `%5.1f`는 소수 1자리로 만든 "3.1" 세 글자를 전체 5칸 중 오른쪽 3칸에 놓으므로, 왼쪽 2칸이 공백이다.

#### 정수 폭: 정렬과 0 채우기
정수에도 폭을 줄 수 있다. 폭보다 자릿수가 많으면 어떻게 될까?

```c
int n = 255;
printf("|%5d|%-5d|%05d|\n", n, n, n);
printf("|%2d|\n", 12345);
```
출력:
```
|  255|255  |00255|
|12345|
```

255는 세 자리라 5칸 중 2칸이 남는다. `%5d`는 오른쪽 정렬이므로 255 왼쪽에 공백 2칸이, `%-5d`는 왼쪽 정렬이므로 255 오른쪽에 공백 2칸이 붙는다. `%05d`는 그 왼쪽 2칸을 공백 대신 0으로 채운다. 폭이 2인데 12345는 다섯 자리라서, 잘리지 않고 다섯 자리가 그대로 다 나온다.

#### 부호 없는 정수와 % 문자
마지막은 `%u`와 % 문자 자체를 찍는 법이다.

```c
printf("%u\n", (unsigned)-1);
printf("%d%%\n", 50);
```
출력:
```
4294967295
50%
```

-1을 부호 없는 정수로 바꿔 `%u`로 찍으면 unsigned가 표현하는 가장 큰 값이 나오는데, unsigned가 4바이트(32비트)인 이 컴퓨터에서는 4294967295다. 그리고 서식 문자열 안에서 % 기호 자체를 찍고 싶으면 `%%`처럼 두 번 써야 한다.

#### 문자 순환 이동 (24-1)
24-1의 문자 이동 규칙을 그대로 코드로 옮기고 "It is 8"을 넣었다.

```c
#include <stdio.h>
#include <ctype.h>
int main() {
    char s[] = "It is 8";
    int i;
    for (i = 0; s[i] != '\0'; i++) {
        char c = s[i];
        if (isupper(c)) c = (c - 'A' + 5) % 26 + 'A';
        else if (islower(c)) c = (c - 'a' + 10) % 26 + 'a';
        else if (isdigit(c)) c = (c - '0' + 3) % 10 + '0';
        printf("%c", c);
    }
    printf("\n");
    return 0;
}
```
출력:
```
Nd sc 1
```

대문자 식은 세 단계로 읽는다. 먼저 `c - 'A'`로 문자를 번호로 바꾼다. A가 0번, B가 1번, Z가 25번이다. 여기에 이동할 칸 수를 더하고, `% 26`으로 26 이상이 된 번호를 다시 0번부터 센다. 마지막으로 `'A'`를 더해 번호를 문자로 되돌린다. 소문자 't'는 같은 방식으로 19번이고, 10을 더하면 29, 29를 26으로 나눈 나머지 3이 되어 'd'다. 숫자는 `% 10`을 쓴다. '8'은 8번이고, 3을 더한 11을 10으로 나눈 나머지 1이 되어 '1'이다. 공백은 세 조건 어디에도 해당하지 않아 그대로 남는다.

### 정리

자료형 크기는 일반적인 64비트 환경에서 char 1, int 4, double 8이고, `sizeof`가 돌려주는 것은 바이트 수다. 대소문자 변환은 `c - 32`가 소문자를 대문자로, `c + 32`가 대문자를 소문자로 바꾼다. `isupper`, `toupper`는 `<ctype.h>`에 들어 있다.

24-1에는 문자 순환 이동 문제가 나왔다. 먼저 판별 함수부터 보면 `isupper(c)`는 대문자, `islower(c)`는 소문자, `isdigit(c)`는 숫자인지 검사하고, 참이면 0이 아닌 값을 돌려준다. `(c-'A'+5)%26+'A'`는 대문자를 알파벳 순서로 5글자 뒤의 문자로 바꾸는 식이다. I는 N이 되고, Z 다음은 다시 A부터 센다. 숫자는 같은 모양으로 `(c-'0'+3)%10+'0'`이다. 24-1은 대문자 +5, 소문자 +10, 숫자 +3이고 나머지(공백)는 그대로 두었기 때문에 "It is 8"이 **Nd sc 1**이 된다('I'→'N', 't'→'d', 'i'→'s', 's'→'c', '8'→'1').

### 예제
```c
#include <stdio.h>
int main() {
    int n = 255;
    char c = 'a';
    double d = 3.14159;
    printf("%d %x %o %c\n", n, n, n, c);
    printf("%c %d\n", c - 32, c);
    printf("%.2f %5.1f|%-5d|%05d\n", d, d, n, n);
    printf("%d %d %d\n", (int)sizeof(char), (int)sizeof(int), (int)sizeof(double));
    printf("%d\n", 'A' + 1);
    printf("%c\n", 'A' + 1);
    printf("%d%%\n", 50);
    return 0;
}
```
출력:
```
255 ff 377 a
A 97
3.14   3.1|255  |00255
1 4 8
66
B
50%
```
`c - 32`를 `%c`로 찍으면 대문자 A가 나오고, c를 그대로 `%d`로 찍으면 97이 나온다. `%5.1f`는 "3.1" 세 글자가 5칸보다 2칸 짧으므로 왼쪽에 공백 2칸이 붙는다.

### 자주 틀리는 포인트
- `%x` 출력은 접두사 0x 없이 소문자 ("0xff", "FF"는 서식과 다른 답)
- `%.2f`는 반올림, 단 2.675는 2.67로 출력
- `char`에 'A' + 1 저장 가능, 답은 출력 서식(`%d`인지 `%c`인지)으로 결정
- 폭 지정(`%5d`)보다 자릿수가 크면 잘리지 않고 전부 출력

2.675가 2.67로 나오는 것은 이진 표현이 2.67499…이기 때문이다. 이렇게 기대와 다를 수 있어서 기출은 깔끔한 값을 쓴다.

## 함수 포인터
출제: 26-1
함정: `int (*fp)(int, int)`는 "함수를 가리키는 포인터"다. `int *fp(int, int)`는 포인터를 반환하는 함수 선언이다.

### 개념
함수도 메모리 어딘가에 있으니 주소가 있다. 함수 포인터는 그 주소를 담아 두었다가 나중에 그 함수를 부르는 변수다. 어느 함수를 부를지 실행 중에 바꿀 수 있어서, 함수를 인자로 넘기거나 이름과 짝지어 표로 만드는 데 쓰인다. 시험은 "지금 fp가 어느 함수를 가리키는가"를 따라갈 수 있는지를 본다.

먼저 식마다 뜻을 정리하면 이렇다. 아래에서 하나씩 코드로 확인한다.

| 식 | 뜻 |
|---|---|
| `int (*fp)(int, int);` | int 둘을 받아 int를 돌려주는 함수를 가리키는 포인터 |
| `fp = add;` | 함수 이름이 곧 주소. `&add`도 같다 |
| `fp(2, 3)`, `(*fp)(2, 3)` | 둘 다 호출. 같은 결과 |
| 구조체 멤버 `int (*fn)(int, int);` | `ops[i].fn(4, 5)`로 호출. 이름 문자열과 짝지어 표로 쓰는 유형 |
| 매개변수 `int (*f)(int, int)` | 함수를 인자로 넘김. `apply(mul, 3, 7)` |

#### 함수 이름이 곧 주소다
add를 가리키는 포인터를 만들어 두 가지 방법으로 부른다.

```c
#include <stdio.h>
int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }
int main() {
    int (*fp)(int, int) = add;
    printf("%d %d\n", fp == add, fp == &add);
    printf("%d %d\n", fp(2, 3), (*fp)(2, 3));
    fp = mul;
    printf("%d\n", fp(2, 3));
    return 0;
}
```
출력:
```
1 1
5 5
6
```

배열 이름이 첫 원소의 주소이듯 함수 이름 add는 그 함수의 주소다. 그래서 `add`와 `&add`가 같은 값이고, 첫 줄의 두 비교가 모두 참(1)이다. 부를 때도 `fp(2, 3)`과 `(*fp)(2, 3)` 둘 다 add(2, 3)을 호출해 5가 나온다. 그다음 `fp = mul`로 대입하면 같은 `fp(2, 3)`이 이번에는 곱셈 6을 돌려준다.

#### 함수를 인자로 넘기기
매개변수를 함수 포인터로 선언하면 "어떤 계산을 할지"를 호출할 때 정할 수 있다.

```c
#include <stdio.h>
int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }
int apply(int (*f)(int, int), int x, int y) { return f(x, y); }
int main() {
    printf("%d %d\n", apply(add, 3, 7), apply(mul, 3, 7));
    return 0;
}
```
출력:
```
10 21
```

apply(add, 3, 7)을 부르면 매개변수 f에 add의 주소가 들어가므로, apply 안의 `f(x, y)`는 add(3, 7)이 되어 10이다. apply(mul, 3, 7)이면 같은 `f(x, y)`가 mul(3, 7)이 되어 21이다. apply 안의 코드는 그대로이고, f에 들어온 함수만 다르다.

#### 구조체 멤버로 이름과 짝짓기
함수 포인터를 구조체 멤버로 두면 이름 문자열과 함수를 한 줄씩 짝지은 표를 만들 수 있다.

```c
#include <stdio.h>
int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }
struct Op { char *name; int (*fn)(int, int); };
int main() {
    struct Op ops[2] = {{"add", add}, {"mul", mul}};
    int i;
    for (i = 0; i < 2; i++) printf("%s=%d\n", ops[i].name, ops[i].fn(4, 5));
    return 0;
}
```
출력:
```
add=9
mul=20
```

`ops[i].fn`은 ops[i]에 이름과 함께 넣어 둔 함수이고, 뒤에 `(4, 5)`를 붙이면 바로 호출된다. ops[0]의 fn은 add이므로 add(4, 5) = 9, ops[1]의 fn은 mul이므로 mul(4, 5) = 20이다.

#### 괄호 하나 차이: 포인터를 돌려주는 함수
그럼 `(*fp)`의 괄호를 빼면 무엇이 될까? 포인터 배열에서 본 `[]`처럼, 함수 호출의 `()`도 `*`보다 먼저 이름 fp와 묶인다. 그래서 `int *fp(int, int)`는 "int 포인터를 돌려주는 함수 fp"의 선언이 된다. 아래는 이런 함수와 그것을 가리키는 포인터를 같이 만든 코드다.

```c
#include <stdio.h>
int *pick(int *a, int i) { return &a[i]; }
int main() {
    int a[3] = {10, 20, 30};
    int *(*fp)(int *, int) = pick;
    printf("%d %d\n", *pick(a, 1), *fp(a, 2));
    return 0;
}
```
출력:
```
20 30
```

pick은 &a[i], 곧 포인터를 돌려주는 함수이므로 결과에 `*`를 붙여야 값이 나온다. `*pick(a, 1)`은 a[1]의 값 20이다. 이 pick을 가리키는 포인터 fp를 선언하려면 `*`와 이름 fp를 `(*fp)`처럼 괄호로 묶어야 하므로, 선언이 `int *(*fp)(int *, int)`처럼 길어진다. `*fp(a, 2)`는 fp가 가리키는 pick을 불러 a[2]의 주소를 받고, 거기에 `*`를 붙여 30이 된다. 정리하자면 `(*fp)`처럼 이름과 `*`가 함께 괄호 안에 있으면 함수 포인터, 괄호 없이 `*fp(int, int)` 모양이면 포인터를 돌려주는 함수 선언이다.

#### 결과를 %x로 찍으면
26-1처럼 함수 포인터로 구한 값을 `%x`로 찍는 경우가 있다.

```c
printf("%x %x %d\n", 32, 20, 0x20);
```
출력:
```
20 14 32
```

10진 32를 `%x`로 찍으면 16진 20이고, 10진 20은 16진 14다. 거꾸로 0x20을 `%d`로 찍으면 32다. 계산 결과를 구한 다음 서식을 한 번 더 확인해야 하는 이유다.

### 예제
```c
#include <stdio.h>
int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }
struct Op { char *name; int (*fn)(int, int); };
int apply(int (*f)(int, int), int x, int y) { return f(x, y); }
int main() {
    int (*fp)(int, int) = add;
    printf("%d\n", fp(2, 3));
    fp = mul;
    printf("%d\n", (*fp)(2, 3));
    struct Op ops[2] = {{"add", add}, {"mul", mul}};
    int i;
    for (i = 0; i < 2; i++) printf("%s=%d ", ops[i].name, ops[i].fn(4, 5));
    printf("\n%d\n", apply(ops[1].fn, 3, 7));
    return 0;
}
```
출력:
```
5
6
add=9 mul=20 
21
```
fp가 add를 가리킬 때는 5가 나오고, mul로 바꾸면 6이 나온다. 구조체 배열의 fn 멤버는 ops[0]이 add, ops[1]이 mul이므로 add(4, 5) = 9와 mul(4, 5) = 20이다. 마지막 `apply(ops[1].fn, 3, 7)`은 ops[1].fn이 mul이므로 결국 mul(3, 7)을 불러 21이 나온다.

### 자주 틀리는 포인트
- 함수 포인터 문제의 핵심은 지금 가리키는 함수 (대입하는 줄마다 표시)
- 결과를 `%x`로 찍는 경우 16진 변환
- `(*fp)(2, 3)`에 붙은 괄호는 호출 문법일 뿐, 이중 포인터와 무관

26-1 문제는 32를 `%x`로 찍었기 때문에 답이 20(16진)이었다. 반대로 10진 20은 `%x`로 14가 찍힌다.
