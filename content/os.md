# 운영체제

21개 회차 420문제 가운데 운영체제 이론은 14문제다. 그중 가장 많은 게 프로세스 스케줄링으로 5회차에 걸쳐 6문제가 나왔고, 이 가운데 3문제는 도착·실행 시간 표를 주고 평균 대기시간을 구하는 계산이었다. 특히 SRT 6.5는 24-2와 26-2에 같은 표로 두 번 나왔다. 페이지 교체도 부재 횟수를 세는 계산으로 나왔다. 나머지는 UNIX 명령어·chmod·프로세스 상태·IPC처럼 상황 설명을 주고 용어나 명령어를 쓰게 하는 형태다. 계산 절차는 [계산] 페이지에 따로 있으니, 여기서는 알고리즘을 고르는 단서와 용어만 정리한다.

## CPU 스케줄링 알고리즘
출제: 26-2, 25-2, 24-2, 22-3, 20-1
형태: 도착·실행 시간 표 → 평균 대기시간 계산, 설명 2~3개 → 영문 약어, HRN 우선순위 식 빈칸

### 프로세스 스케줄링 알고리즘 정리
먼저 알고리즘들을 비선점형과 선점형 두 칸으로 갈라 두고 시작하자.

| 비선점형 | 선점형 |
|---|---|
| FIFO(도착 순서대로 할당) | Round Robin(FIFO + 시간 지정) |
| SJF(실행 시간 짧은 프로세스에 할당, 비선점형/선점형 둘 다 가능) | SRT(선점형 SJF) |
| HRN(SJF + 대기 시간 고려) | |
| 기한부(마감 시간 임박한 프로세스 먼저) | |
| 우선순위(우선순위에 따라 할당) | |

### 프로세스 스케줄링이 필요한 이유
컴퓨터는 여러 프로세스를 동시에 처리해야 한다. 이때 어느 프로세스에 CPU를 줄지 정하는 규칙이 **프로세스 스케줄링**이다. 스케줄링의 목표는 CPU를 효율적으로 쓰고, 모든 프로세스에 공평한 기회를 주며, 사용자의 대기 시간을 최소로 줄이는 것이다. 방식은 크게 둘로 나뉜다.

- **비선점형(Non-preemptive) 스케줄링**: 한 프로세스가 CPU를 받으면 그 프로세스가 끝나거나 입출력(I/O) 작업 때문에 스스로 CPU를 반납할 때까지 다른 프로세스가 빼앗을 수 없음
- **선점형(Preemptive) 스케줄링**: 운영체제가 필요하다고 판단하면 실행 중인 프로세스를 멈추고 다른 프로세스에 CPU를 강제로 할당 가능, 시분할 시스템에 적합

### 비선점형 스케줄링 (Non-preemptive Scheduling)
한 번 할당되면 끝날 때까지 아무도 막을 수 없는 방식이다.

#### 1. FCFS (First-Come, First-Served)
FIFO(First-In, First-Out)라고도 부르는 가장 간단한 방식으로, 준비 큐(Ready Queue)에 도착한 순서대로 CPU를 할당한다.

- **장점**: 구현이 쉽고 공평함
- **단점**: 실행 시간이 긴 프로세스가 먼저 오면 뒤따르는 짧은 프로세스들이 하염없이 기다리는 콘보이 효과(Convoy Effect) 발생 가능

#### 2. SJF (Shortest Job First)
실행 시간이 가장 짧은 프로세스에게 먼저 CPU를 할당한다. 여기서 주의할 점이 있다. SJF는 비선점형과 선점형 두 방식 모두 가능하고, 그중 선점형이 SRT다. 둘을 구분해 둔다.

- **장점**: 평균 대기 시간을 최소화하는 최적의 알고리즘
- **단점**: 실행 시간이 긴 프로세스가 새로 오는 짧은 프로세스에 계속 밀려 무한정 기다리는 기아 현상(Starvation) 발생 가능, 각 프로세스의 실행 시간을 미리 정확히 예측하기 어려움

#### 3. HRN (Highest Response-ratio Next)
HRN은 SJF의 기아 현상을 보완하려고 만들었다. 대기 시간과 실행 시간(서비스 시간)을 모두 따져 우선순위를 동적으로 정한다.

- **우선순위 계산**: **(대기 시간 + 서비스 시간) / 서비스 시간**
- **특징**: 이 값이 가장 높은 프로세스에게 CPU 할당, 대기 시간이 길어질수록 우선순위가 높아져 기아 현상 방지

#### 4. 기한부 (Deadline)
프로세스에 주어진 마감 시간(Deadline) 안에 작업을 끝내야 하는 실시간 시스템에서 쓴다. 마감 시간이 가장 임박한 프로세스에 높은 우선순위를 준다.

#### 5. 우선순위 (Priority)
각 프로세스에 부여된 정적 우선순위에 따라 CPU를 할당한다. 우선순위가 가장 높은 프로세스가 먼저 실행되고, SJF처럼 기아 현상이 생길 수 있다.

### 선점형 스케줄링 (Preemptive Scheduling)
실행 중인 프로세스를 언제든 멈추고 다른 프로세스에 CPU를 넘겨줄 수 있는 유연한 방식이다.

#### 6. RR (Round Robin)
라운드 로빈은 한마디로 FIFO에 시간 지정(같은 시간 할당)을 더한 방식이다. FIFO에 시간 할당량(Time Quantum 또는 Time Slice) 개념을 붙여서, 모든 프로세스가 정해진 할당량만큼만 CPU를 쓰고 시간이 다 되면 준비 큐의 맨 뒤로 돌아간다.

- **장점**: 모든 프로세스가 공평하게 CPU 시간을 보장받아 대화형 시스템에 적합
- **단점**: 할당량이 너무 크면 FIFO와 같아지고, 너무 작으면 문맥 교환이 잦아져 오버헤드 증가, 적절한 할당량 설정이 중요

#### 7. SRT (Shortest Remaining Time)
SRT는 선점형 SJF 알고리즘이다. 실행 중인 프로세스의 남은 시간보다 실행 시간이 더 짧은 새 프로세스가 도착하면, 즉시 CPU를 빼앗아 새 프로세스에 준다.

- **장점**: 평균 대기 시간을 더 줄일 수 있음
- **단점**: 잦은 문맥 교환(Context Switching)으로 오버헤드 발생 가능, 여전히 기아 현상 발생 가능

### 기출에서 이렇게 나왔다
- 26-2: 도착·버스트 시간 표 → SRT 평균 대기시간 **6.5** (24-2와 같은 표)
- 25-2: 도착·실행 시간 표, 할당량 4 → RR 평균 대기시간 **11.75**
- 25-2: 설명 2개 → **SJF / SRT**
- 24-2: 표 → SRT 평균 대기시간 **6.5**
- 22-3: 설명 3개 → 영문 약어 **SJF / RR / SRT**
- 20-1: HRN 우선순위 공식 빈칸 → **(대기 시간 + 서비스 시간) ÷ 서비스 시간**

### 답 쓸 때
알고리즘 이름은 영문 약어로 요구한다. HRN 식은 분자가 "대기 + 서비스"이고 분모가 "서비스"다. 대기 시간이 분자에 있어서 오래 기다릴수록 값이 커지는데, 표에서 말한 에이징 효과가 바로 이것이다. 간트 차트를 그려 평균 대기시간을 구하는 절차는 [계산] 페이지에서 풀이한다.

위 정리 표에서 SJF는 비선점형 칸에 있으면서 "비선점형/선점형 둘 다 가능"이라고 적혀 있다. 25-2 지문도 SJF를 "실행 시간이 짧은 프로세스를 우선 처리하며 선점형·비선점형 모두 가능"이라고 설명하고 그 선점형을 SRT라고 했다. 왜 이렇게 되냐면, 교재에 따라 선점형 SJF(SRT)까지 SJF로 묶기 때문이다. 그러니 "짧은 것 먼저 + 둘 다 가능"이면 **SJF**, "그중 선점형, 더 짧은 프로세스가 오면 CPU를 빼앗음"이면 **SRT**로 쓴다. 여기서 함정이 하나 있다. "선점·비선점 모두 가능"이라는 말만 보고 우선순위로 고르지 않는다.

요약 교재는 우선순위를 비선점 칸에만 넣기도 한다. 비선점 기법을 고르라는 보기에 우선순위가 있으면 비선점 쪽으로 고른다.

## 페이지 교체 알고리즘
출제: 24-3, 24-1
형태: 페이지 참조열과 프레임 수 → 페이지 부재 횟수

### 페이지 교체 알고리즘 정리
**페이지 교체 알고리즘**은 가상 메모리 시스템에서 물리 메모리(RAM)의 프레임이 부족할 때, 어느 페이지를 보조기억장치로 내보낼지 정하는 알고리즘이다. 대표적인 세 가지를 먼저 표로 보면 이렇다.

| 알고리즘 | 교체 대상 | 기반 원리 |
|---|---|---|
| FIFO | 가장 먼저 메모리에 들어온 페이지 | 선입선출 |
| LRU | 가장 오랫동안 사용되지 않은 페이지 | 시간 지역성 |
| LFU | 참조 횟수가 가장 적은 페이지 | 참조 빈도 |

### 페이지 교체가 필요한 이유
페이지 교체 알고리즘은 가상 메모리 위에서 동작한다. 문제를 풀 때 필요한 용어만 짧게 정리하면 아래와 같다.

| 용어 | 뜻 |
|---|---|
| 페이지 | 프로그램이 보는 메모리 공간(논리 주소 공간)을 일정한 크기로 나눈 블록 |
| 프레임(페이지 프레임) | RAM을 페이지와 같은 크기로 나눈 자리. "페이지 프레임이 3개"는 페이지를 담을 자리가 3칸이라는 뜻 |
| 참조 | 프로그램이 어떤 페이지를 사용하는 것. 문제에 주어지는 페이지 순서가 참조 순서 |
| 페이지 부재 | 참조한 페이지가 RAM(프레임)에 없어 보조기억장치에서 가져와야 하는 상황 |

페이지 부재가 났는데 빈 프레임이 없으면, RAM에 있는 페이지 하나를 보조기억장치로 내보내고(swap-out) 그 자리에 필요한 페이지를 가져온다(swap-in). 이때 "어느 페이지를 내보낼까"를 정하는 규칙이 페이지 교체 알고리즘이다. 페이지 테이블로 주소를 바꾸는 과정과 페이지 부재 처리 순서는 [가상 메모리] 묶음에서 다룬다.

### 주요 페이지 교체 알고리즘
페이지 교체 알고리즘의 목표는 페이지 부재 횟수를 최소로 줄여 시스템 성능을 높이는 것이다. 대표가 FIFO, LRU, LFU다.

#### 1. FIFO (First In First Out)
가장 간단한 알고리즘으로, RAM에 가장 먼저 들어온 페이지를 가장 먼저 내보낸다. 줄을 서서 먼저 온 사람이 먼저 나가는 것과 같다. 이미 메모리에 있는 페이지가 다시 참조되면 페이지 부재가 나지 않고, 교체 없이 그대로 남으며 들어온 순서도 바뀌지 않는다.

- **장점**: 구현이 매우 간단함
- **단점**: 자주 쓰는 페이지도 먼저 들어왔다는 이유만으로 교체될 수 있어 비효율적

프레임 수를 늘렸는데도 페이지 부재가 더 많이 나는 현상이 생길 수 있는데, 이것을 Belady의 모순(Belady's Anomaly)이라고 한다.

#### 2. LRU (Least Recently Used)
가장 오랫동안 사용되지 않은 페이지를 교체한다. "최근에 쓴 페이지는 가까운 미래에도 다시 쓸 것"이라는 시간 지역성(Temporal Locality)에 기반한다. 이미 메모리에 있는 페이지가 다시 참조되면 페이지 부재는 나지 않고, 교체 없이 그 페이지의 사용 시간만 현재로 갱신된다. 곧 메모리 안에서 순서만 바뀔 뿐 새로 들어오는 것이 아니다.

- **장점**: FIFO보다 페이지 부재율이 낮고 일반적으로 성능이 좋음
- **단점**: 각 페이지의 최근 사용 시간을 기록·유지해야 해서 운영체제 부담이 크고 구현이 복잡함

#### 3. LFU (Least Frequently Used)
참조 횟수가 가장 적은 페이지를 교체한다. "과거에 많이 쓴 페이지는 앞으로도 많이 쓸 것"이라는 가정에 기반한다. 이미 메모리에 있는 페이지가 다시 참조되면 페이지 부재는 나지 않고, 교체 없이 그 페이지의 참조 횟수만 1 늘어난다. LRU와 달리 자리를 위로 옮기지 않으므로, 표에서도 그 페이지가 있던 줄에 그대로 두고 횟수만 올리면 된다.

여기서 놓치기 쉬운 규칙이 하나 있다. 교체되어 메모리에서 빠진 페이지는 참조 횟수가 초기화된다. 나중에 같은 페이지가 다시 들어오면 참조 횟수 1부터 새로 시작하고, 이전에 몇 번 참조됐는지는 남지 않는다.

- **장점**: LRU가 잡아내지 못하는 장기적인 참조 패턴 고려 가능
- **단점**: 참조 횟수 계산 오버헤드가 큼, 초기에 많이 쓰였지만 더는 안 쓰는 페이지가 계속 메모리에 남을 수 있음, 참조 횟수가 같은 페이지가 여럿이면 교체 대상을 정할 추가 규칙(예: FIFO) 필요

### 기출에서 이렇게 나왔다

- 24-1: 참조열, 프레임 3 → LRU·LFU 페이지 부재 횟수 **6 / 6**

## Unix/Linux 명령어와 UNIX 특징

### Unix/Linux 명령어 요약
Unix/Linux 명령어는 운영체제를 다루는 기본 도구다. 실기에서는 파일과 디렉터리를 다루는 기본 명령어가 자주 나온다. 아래에는 시험에 나온 핵심 명령어와 실무에서 자주 쓰는 명령어를 함께 모았다.

| 명령어 | 기능 | 사용 예시 |
|---|---|---|
| pwd | 현재 작업 디렉터리 경로 출력 | `pwd` |
| ls | 디렉터리 내용 출력 | `ls -al` |
| cd | 디렉터리 이동 | `cd /home/user` |
| cp | 파일/디렉터리 복사 | `cp file1.txt file2.txt` |
| mv | 파일/디렉터리 이동 또는 이름 변경 | `mv old.txt new.txt` |
| rm | 파일/디렉터리 삭제 | `rm -rf folder` |
| mkdir | 디렉터리 생성 | `mkdir newdir` |
| rmdir | 빈 디렉터리 삭제 | `rmdir emptydir` |
| cat | 파일 내용 출력 | `cat file.txt` |
| chmod | 파일 권한 변경 | `chmod 755 script.sh` |
| chown | 파일 소유자 변경 | `chown user:group file.txt` |
| grep | 패턴 검색 | `grep "error" log.txt` |
| find | 파일 검색 | `find / -name "*.txt"` |
| ps | 프로세스 목록 조회 | `ps aux` |
| kill | 프로세스 종료 | `kill -9 1234` |

### 디렉터리 탐색 명령어

#### 1. pwd (Print Working Directory)
현재 작업 중인 디렉터리의 절대 경로를 출력한다.

```bash
$ pwd
/home/user/documents
```

- 현재 위치를 확인할 때 사용
- 절대 경로(루트 /부터 시작하는 전체 경로) 반환

#### 2. ls (List)
디렉터리의 내용, 곧 파일과 하위 디렉터리 목록을 출력한다.

```bash
$ ls
file1.txt  file2.txt  folder1

$ ls -al
total 12
drwxr-xr-x  3 user group 4096 Jan 11 10:00 .
drwxr-xr-x 10 user group 4096 Jan 10 09:00 ..
-rw-r--r--  1 user group  100 Jan 11 10:00 file1.txt
drwxr-xr-x  2 user group 4096 Jan 11 10:00 folder1
```

| 옵션 | 설명 |
|---|---|
| -a | 숨김 파일(.으로 시작)까지 모두 표시 |
| -l | 상세 정보(권한, 소유자, 크기 등) 표시 |
| -h | 파일 크기를 읽기 쉬운 형태로 표시 (KB, MB) |
| -R | 하위 디렉터리까지 재귀적으로 표시 |
| -t | 수정 시간 순으로 정렬 |

#### 3. cd (Change Directory)
디렉터리 위치를 이동한다.

```bash
$ cd /home/user        # 절대 경로로 이동
$ cd documents         # 상대 경로로 이동
$ cd ..                # 상위 디렉터리로 이동
$ cd ~                 # 홈 디렉터리로 이동
$ cd -                 # 이전 디렉터리로 이동
```

| 경로 표현 | 의미 |
|---|---|
| . | 현재 디렉터리 |
| .. | 상위 디렉터리 |
| ~ | 현재 사용자의 홈 디렉터리 |
| / | 루트(최상위) 디렉터리 |

### 파일 및 디렉터리 관리 명령어

#### 4. cp (Copy)
파일 또는 디렉터리를 복사한다.

```bash
$ cp source.txt dest.txt           # 파일 복사
$ cp source.txt /home/user/backup/ # 다른 디렉터리로 복사
$ cp -r folder1 folder2            # 디렉터리 전체 복사 (-r 필수)
$ cp -i source.txt dest.txt        # 덮어쓰기 전 확인
```

| 옵션 | 설명 |
|---|---|
| -r | 디렉터리를 재귀적으로 복사 |
| -i | 덮어쓰기 전 확인 |
| -f | 강제로 복사 (확인 없이) |
| -p | 파일 속성(권한, 시간 등) 유지 |

#### 5. mv (Move)
파일 또는 디렉터리를 이동하거나 이름을 바꾼다.

```bash
$ mv old.txt new.txt               # 파일 이름 변경
$ mv file.txt /home/user/backup/   # 파일 이동
$ mv folder1 folder2               # 디렉터리 이름 변경 또는 이동
```

- cp와 달리 원본이 삭제됨
- 같은 디렉터리 안에서 쓰면 이름 변경, 다른 디렉터리로 쓰면 이동

#### 6. rm (Remove)
파일 또는 디렉터리를 삭제한다.

```bash
$ rm file.txt                      # 파일 삭제
$ rm -r folder                     # 디렉터리와 하위 내용 삭제
$ rm -rf folder                    # 강제로 디렉터리 삭제 (주의)
$ rm -i file.txt                   # 삭제 전 확인
```

| 옵션 | 설명 |
|---|---|
| -r | 디렉터리를 재귀적으로 삭제 |
| -f | 강제 삭제 (확인 없이, 오류 무시) |
| -i | 삭제 전 확인 |

#### 7. mkdir (Make Directory)
새 디렉터리를 만든다.

```bash
$ mkdir newdir                     # 디렉터리 생성
$ mkdir -p parent/child/grandchild # 중간 디렉터리까지 함께 생성
```

#### 8. rmdir (Remove Directory)
빈 디렉터리를 삭제한다. 디렉터리 안에 파일이 있으면 삭제되지 않으므로, 내용이 있는 디렉터리는 `rm -r`을 써야 한다.

```bash
$ rmdir emptydir
```

### 파일 내용 관련 명령어

#### 9. cat (Concatenate)
파일 내용을 출력하거나 여러 파일을 이어 붙인다.

```bash
$ cat file.txt                     # 파일 내용 출력
$ cat file1.txt file2.txt          # 여러 파일 연결해서 출력
$ cat file1.txt file2.txt > merged.txt  # 파일 병합
```

#### 10. head / tail
파일의 처음 또는 끝부분을 출력한다.

```bash
$ head -n 10 file.txt              # 처음 10줄 출력
$ tail -n 10 file.txt              # 마지막 10줄 출력
$ tail -f log.txt                  # 실시간으로 파일 변화 추적
```

#### 11. grep (Global Regular Expression Print)
파일에서 특정 패턴을 찾는다.

```bash
$ grep "error" log.txt             # "error" 포함된 줄 출력
$ grep -i "error" log.txt          # 대소문자 구분 없이 검색
$ grep -r "function" ./src         # 디렉터리 내 재귀 검색
$ grep -n "error" log.txt          # 줄 번호와 함께 출력
```

| 옵션 | 설명 |
|---|---|
| -i | 대소문자 구분 안 함 |
| -r | 디렉터리 내 재귀 검색 |
| -n | 줄 번호 표시 |
| -v | 패턴이 없는 줄만 출력 |
| -c | 매칭된 줄 개수만 출력 |

### 파일 검색 명령어

#### 12. find
여러 조건으로 파일을 검색한다.

```bash
$ find /home -name "*.txt"         # 이름으로 검색
$ find . -type f -size +1M         # 1MB 이상 파일 검색
$ find . -mtime -7                 # 7일 이내 수정된 파일
$ find . -name "*.log" -delete     # 검색 후 삭제
```

| 옵션 | 설명 |
|---|---|
| -name | 파일명으로 검색 |
| -type f | 파일만 검색 |
| -type d | 디렉터리만 검색 |
| -size | 파일 크기로 검색 |
| -mtime | 수정 시간으로 검색 |
| -exec | 검색된 파일에 명령 실행 |

### 권한 관리 명령어

#### 13. chmod (Change Mode)
파일의 접근 권한을 바꾼다. 8진수 표기법과 기호 방식으로 권한을 설정할 수 있고, 자세한 내용은 [chmod와 파일 권한] 묶음에서 다룬다.

```bash
$ chmod 755 script.sh              # 숫자 방식
$ chmod u+x script.sh              # 기호 방식 (사용자에 실행 권한 추가)
```

#### 14. chown (Change Owner)
파일의 소유자를 바꾼다.

```bash
$ chown user file.txt              # 소유자 변경
$ chown user:group file.txt        # 소유자와 그룹 동시 변경
$ chown -R user:group ./folder     # 디렉터리 내 모든 파일에 적용
```

### 프로세스 관리 명령어

#### 15. ps (Process Status)
현재 실행 중인 프로세스 목록을 조회한다.

```bash
$ ps                               # 현재 터미널의 프로세스
$ ps aux                           # 시스템 전체 프로세스
$ ps -ef                           # 전체 프로세스 (다른 형식)
```

| 옵션 | 설명 |
|---|---|
| a | 다른 사용자의 프로세스도 표시 |
| u | 프로세스 소유자 정보 표시 |
| x | 터미널에 연결되지 않은 프로세스도 표시 |

#### 16. kill
프로세스를 종료한다.

```bash
$ kill 1234                        # PID 1234 프로세스에 SIGTERM 전송
$ kill -9 1234                     # 강제 종료 (SIGKILL)
$ kill -15 1234                    # 정상 종료 요청 (SIGTERM)
```

| 시그널 | 번호 | 설명 |
|---|---|---|
| SIGTERM | 15 | 정상 종료 요청 (기본값) |
| SIGKILL | 9 | 강제 종료 (무시 불가) |
| SIGHUP | 1 | 터미널 연결 끊김 |

#### 17. top
시스템 상태와 프로세스를 실시간으로 모니터링한다.

```bash
$ top                              # 실시간 프로세스 모니터링
```

### 기타 명령어

#### 18. touch
빈 파일을 만들거나 파일의 수정 시간을 바꾼다.

```bash
$ touch newfile.txt                # 빈 파일 생성
$ touch -t 202501011200 file.txt   # 수정 시간 지정
```

#### 19. echo
문자열을 출력한다. 리다이렉션과 함께 파일에 내용을 쓸 때도 쓴다.

```bash
$ echo "Hello World"               # 화면에 출력
$ echo "content" > file.txt        # 파일에 덮어쓰기
$ echo "content" >> file.txt       # 파일에 추가
```

#### 20. clear
터미널 화면을 지운다.

```bash
$ clear
```

### UNIX 특징
감자 명령어 페이지에는 UNIX 운영체제의 특징이 없다. 20-4가 이 특징을 그대로 지문으로 주고 **UNIX**를 쓰게 했으므로, 그 기출 지문에 나온 항목만 옮겨 둔다.

- 다중 사용자(Multi-User) 시스템, 다중 작업(Multi-Tasking) 지원
- C 언어로 작성되어 이식성이 높음
- 트리 구조의 계층적 파일 시스템
- 강력한 셸(Shell) 제공
- 시분할 운영체제

### 자료 보고 맞히기
**자료 1**

```
$ ( ① ) /usr
$ ( ② )
/usr
$ ( ③ )

```

→ ① cd, ② pwd, ③ ls. 25-3 보기의 명령을 macOS 터미널에서 실제로 돌린 화면이다. 출력 없이 위치만 바뀌면 cd(이동), 경로 한 줄이 나오면 pwd(현재 경로 확인), 파일·디렉터리 이름이 늘어서면 ls(내용 출력)다.

→ ① cp. 원본 report.txt가 그대로 있고 같은 내용의 backup.txt가 하나 늘었으니 복사다. 원본이 사라지고 이름만 바뀌었다면 mv다.

## chmod와 파일 권한
출제: 23-3, 20-2
형태: 사용자·그룹·기타의 권한 요구 → 명령어와 8진수 세 자리

### chmod 명령어란
**chmod**는 'change mode'의 약자로, 리눅스와 유닉스 계열 운영체제에서 파일이나 디렉터리의 접근 권한을 바꾸는 명령어다. 실기에서는 특정 권한을 주는 상황을 주고, 그것을 8진수(Octal) 숫자로 표현해 명령어를 완성하게 하는 문제가 자주 나온다.

### 접근 권한의 종류와 대상
chmod를 이해하려면 먼저 권한의 종류와, 누구에게 권한을 줄지부터 알아야 한다.

#### 권한의 종류

| 권한 | 기호 | 설명 | 8진수 값 |
|---|---|---|---|
| 읽기 | r | 파일 내용 읽기, 디렉터리 목록 보기 | 4 |
| 쓰기 | w | 파일 내용 수정/삭제, 디렉터리 안 파일 생성/삭제 | 2 |
| 실행 | x | 파일 실행, 디렉터리로 접근(cd) | 1 |

#### 권한의 대상

| 대상 | 기호 | 설명 |
|---|---|---|
| 사용자 | u | 파일을 소유한 사용자 (user) |
| 그룹 | g | 파일이 속한 그룹 (group) |
| 기타 | o | 그 외 모든 사용자 (others) |

### 8진수(Octal)로 권한 설정하기
chmod의 핵심은 8진수 표기법이다. 각 권한(r, w, x)에 붙은 숫자를 더해 권한 조합을 만든다.

- **r(읽기)** = 4
- **w(쓰기)** = 2
- **x(실행)** = 1

예를 들어 읽고 쓸 수 있는 권한(rw-)은 4 + 2 = 6이다. 0부터 7까지 모두 적으면 아래와 같다.

| 8진수 | 권한 조합 (rwx) | 설명 |
|---|---|---|
| 7 | rwx(4+2+1) | 읽기, 쓰기, 실행 모두 가능 |
| 6 | rw-(4+2) | 읽기, 쓰기 가능 |
| 5 | r-x(4+1) | 읽기, 실행 가능 |
| 4 | r--(4) | 읽기만 가능 |
| 3 | -wx(2+1) | 쓰기, 실행 가능 |
| 2 | -w-(2) | 쓰기만 가능 |
| 1 | --x(1) | 실행만 가능 |
| 0 | ---(0) | 아무 권한 없음 |

명령어는 `chmod [사용자권한][그룹권한][기타권한] [파일명]` 형식이다. 예를 들어 `chmod 754 file.txt`는 이런 뜻이다.

- 사용자(7): rwx (읽기 + 쓰기 + 실행)
- 그룹(5): r-x (읽기 + 실행)
- 기타(4): r-- (읽기)

숫자 대신 기호 방식으로 쓸 수도 있다. [Unix/Linux 명령어] 묶음의 chmod 예처럼 `chmod u+x script.sh`라고 쓰면 사용자에 실행 권한을 추가한다.

### 자료 보고 맞히기
아래 출력은 macOS에서 실제로 돌린 결과다. `ls -l` 앞 10자리만 보도록 `cut -c1-10`을 붙였다.

**자료 1**

```
$ ls -l gamja.sh | cut -c1-10
-rw-r--r--
$ ( ① ) ( ② ) gamja.sh
$ ls -l gamja.sh | cut -c1-10
-rwxr-x--x
```

→ ① chmod, ② 751. 23-3의 gamja.sh다. 기출은 "사용자는 모든 권한, 그룹에게는 읽기/실행, 그 외는 실행만"이라는 문장으로 줬고, 바뀐 뒤 모양이 `rwx` `r-x` `--x`다. 4+2+1, 4+1, 1을 붙이면 751이다.

**자료 2**

```
$ ls -l file.txt | cut -c1-10
-rw-r--r--
$ chmod ( ① ) file.txt
$ ls -l file.txt | cut -c1-10
-rwxr-xr--
```

→ ① 754. 위 「8진수로 권한 설정하기」의 방식이다. `rwx`는 7, `r-x`는 5, `r--`는 4다.

**자료 3**

```
$ ls -l run.sh | cut -c1-10
-rw-r--r--
$ chmod ( ① ) run.sh
$ ls -l run.sh | cut -c1-10
-rwxr--r--
```

→ ① u+x. 위에서 본 기호 방식이다. 소유자 자리에 x 하나만 늘고 나머지는 그대로라서, 숫자로 다시 지정하지 않고 u+x로 더했다. 숫자로 쓰면 744다.

### 기출에서 이렇게 나왔다
- 23-3: 사용자는 모든 권한, 그룹은 읽기·실행, 기타는 실행만 → **chmod 751**
- 20-2: 같은 권한 요구 → **751**

### 답 쓸 때
문제가 "명령어까지 쓰라"고 하면 `chmod 751 파일명` 형태로 쓰고, 숫자만 요구하면 751만 쓴다. 권한 문장을 8진수로 바꾸는 절차는 [계산] 페이지에서 풀이한다.

## 프로세스 상태 전이와 IPC
출제: 21-1, 20-4
형태: 상태 설명 3개 → 이름, IPC 기법을 나열한 한 줄 → 용어

### 프로세스 상태 (Process State)
스케줄러가 어느 프로세스에 CPU를 줄지 정하려면, 먼저 각 프로세스가 지금 어떤 상태인지 알아야 한다. 실기에서는 아래 세 가지 주요 상태를 짝짓는 형태로 자주 나온다.

- **준비(Ready)**: 실행에 필요한 자원을 모두 갖고 CPU만 할당되면 즉시 실행 가능한 상태. 준비 큐(Ready Queue)에서 자기 차례 대기
- **실행(Run / Running)**: 스케줄러가 CPU를 할당해 실제로 명령어를 수행 중인 상태. CPU 코어 1개당 한 시점에 한 프로세스만 실행 상태
- **대기(Wait / Block / Blocked)**: 입출력(I/O) 같은 외부 사건이 끝날 때까지 CPU를 반납하고 멈춘 상태. 사건이 완료되면 다시 준비 상태로 복귀

상태는 아래 흐름으로 옮겨 간다.

```mermaid
제목: 준비에서 디스패치되면 실행, 실행 중 I/O를 요청하면 대기, I/O가 끝나면 준비로 돌아가고, 선점형에서 할당 시간이 다 되면 실행에서 준비로 간다
%% 폰: TB
flowchart LR
  R["준비"] -->|"디스패치"| U["실행"]
  U -->|"I/O 요청"| W["대기"]
  W -->|"I/O 완료"| R
  U -->|"시간 할당량 만료<br/>(선점형 스케줄링)"| R
```

- 준비 → (디스패치) → 실행
- 실행 → (I/O 요청) → 대기
- 대기 → (I/O 완료) → 준비
- 실행 → (시간 할당량 만료, 선점형 스케줄링) → 준비

### IPC (Inter-Process Communication)
운영체제는 프로세스마다 독립된 메모리 공간을 할당한다. 그래서 한 프로세스가 다른 프로세스의 변수를 직접 읽거나 쓸 수 없다. 대신 운영체제가 제공하는 통신 메커니즘으로만 데이터를 주고받을 수 있는데, 이것을 **IPC(Inter-Process Communication)**라고 한다. 대표적인 IPC 기법은 아래와 같다.

| 기법 | 설명 |
|---|---|
| 공유 메모리(Shared Memory) | 여러 프로세스가 같은 메모리 영역을 매핑해 직접 읽고 씀, 가장 빠른 IPC 기법, 동기화는 별도 처리 |
| 소켓(Socket) | 네트워크 프로토콜을 이용한 양방향 통신 채널, 같은 호스트뿐 아니라 다른 호스트의 프로세스와도 통신 |
| 세마포어(Semaphore) | 임계 구역(Critical Section)에 대한 동시 접근을 제어하는 동기화 도구, P(wait)/V(signal) 연산으로 자원 카운트 관리 |
| 메시지 큐(Message Queue) | 커널이 관리하는 큐에 메시지를 넣고 다른 프로세스가 꺼내 가는 비동기 통신 방식 |
| 파이프(Pipe)·시그널(Signal) | 부모-자식 관계 프로세스 간 단방향 데이터 전달이나 비동기 알림에 사용 |

### 기출에서 이렇게 나왔다
- 21-1: 공유 메모리·소켓·세마포어·메시지 큐를 포함하는 기법의 총칭 한 줄 → **IPC**
- 20-4: 상태 설명 3개 → **준비 / 실행 / 대기**

### 답 쓸 때
IPC는 영문 약어로 쓰고, 상태 이름은 "준비·실행·대기"처럼 한글로 쓴다. 대기 상태는 교재에 따라 Blocked라고 적기도 하고 Waiting이라고 적기도 한다.

## 가상 메모리
출제: 없음

### 개념
**가상 메모리(Virtual Memory)**는 프로그램마다 0번지부터 시작하는 자기만의 주소를 주고, 그 주소를 운영체제와 하드웨어가 실제 RAM 위치로 바꿔 주는 메모리 관리 기법이다. 덕분에 RAM보다 큰 프로그램도 실행할 수 있고, 여러 프로그램이 서로의 메모리를 건드리지 않고 동시에 실행될 수 있다. 페이지 교체 알고리즘(FIFO, LRU, LFU)도 이 가상 메모리 위에서 동작한다.

가상 메모리 개념 자체를 묻는 실기 기출은 아직 없다. 실기에 나오는 페이지 교체 알고리즘을 이해하기 위한 바탕 개념이므로, 용어를 통째로 외우기보다 '주소 변환 → 페이지 부재 → 페이지 교체'로 이어지는 흐름을 잡으면 된다. 아래에서 볼 용어를 먼저 모으면 이렇다.

| 용어 | 뜻 |
|---|---|
| 가상 메모리 | 프로그램마다 자기만의 주소를 주고, 작은 RAM을 큰 메모리처럼 쓰게 하는 기법 |
| 논리 주소 | 프로그램이 쓰는 주소. 가상 주소라고도 하며 프로그램마다 0번지부터 시작 |
| 물리 주소 | RAM 안의 실제 위치를 가리키는 주소 |
| 페이지 | 프로그램이 보는 메모리 공간(논리 주소 공간)을 일정한 크기로 나눈 블록 |
| 프레임 | RAM을 페이지와 같은 크기로 나눈 블록 |
| 페이지 테이블 | 각 페이지가 어느 프레임에 있는지(또는 RAM에 없는지) 적어 둔 표 |
| 페이지 부재 | 필요한 페이지가 RAM에 없어 보조기억장치에서 가져와야 하는 상황 |
| 스와핑 | RAM과 보조기억장치 사이에서 데이터를 옮기는 동작 |

### 가상 메모리란
컴퓨터의 저장 공간은 크게 두 가지다. RAM(주기억장치, 물리 메모리)은 책상처럼 CPU가 바로 꺼내 쓸 만큼 빠르지만 좁고, 보조기억장치(HDD, SSD)는 창고처럼 넓지만 꺼내 오는 데 오래 걸린다. 그래서 프로그램이 SSD에 설치돼 있어도 실행하려면 그 코드와 데이터를 RAM에 올려야 한다. 그런데 RAM은 용량이 한정돼 있어서, 게임·브라우저·메신저를 함께 켜면 각 프로그램이 쓰려는 메모리를 합친 크기가 RAM보다 커지기 쉽다. 가상 메모리는 이 문제를 두 가지 아이디어로 푼다.

1. **당장 필요한 부분만 RAM에 올림**: 프로그램 전체를 한꺼번에 올리지 않고 일정한 크기로 잘게 나눈 뒤, 지금 쓰는 조각만 RAM에 두고 나머지는 보조기억장치에 둠
2. **프로그램이 쓰는 주소와 RAM의 실제 위치를 분리**: 프로그램은 자기 조각이 RAM 어디에 있는지 몰라도 됨, 주소를 실제 위치로 바꾸는 일은 운영체제와 하드웨어가 대신 처리

한 문장으로 정리하면, 가상 메모리는 보조기억장치의 일부를 주기억장치처럼 써서 용량이 작은 주기억장치를 큰 것처럼 쓰는 기법이다. 이 설명은 1번 아이디어에 해당하고, 그것을 가능하게 하는 바탕이 2번의 주소 분리다.

### 논리 주소와 물리 주소
메모리는 1바이트짜리 칸이 한 줄로 길게 늘어선 사물함과 같다. 칸마다 0번, 1번, 2번… 번호가 붙어 있고, 이 번호를 주소(번지)라고 한다. "100번지에 값을 저장한다"는 말은 100번 칸에 값을 넣는다는 뜻이다.

RAM이라는 사물함은 하나뿐이고 모든 프로그램이 나눠 쓴다. 그런데 가상 메모리에서는 프로그램이 이 사물함 번호를 직접 쓰지 않는다. 각 프로그램은 "내 메모리는 0번지부터 시작한다"고 여기고 자기만의 번호를 쓰는데, 이 번호가 **논리 주소**이고 RAM 사물함에 실제로 붙은 번호가 **물리 주소**다. 그래서 "프로그램마다 자기만의 메모리 공간을 가진다"는 말은 RAM을 칸막이로 미리 잘라 준다는 뜻이 아니다. 프로그램마다 0번지부터 시작하는 번호 체계를 따로 주고, 그 번호가 RAM의 어느 칸을 가리키는지는 운영체제가 장부(페이지 테이블)로 관리한다는 뜻이다.

| 구분 | 논리 주소 | 물리 주소 |
|---|---|---|
| 다른 이름 | 가상 주소 | 실제 주소 |
| 누구 기준 번호인가 | 각 프로그램 기준 | RAM 기준 |
| 번호 매기는 방식 | 프로그램마다 0번지부터 따로 매김 | RAM 전체에 한 줄로 한 번만 매김 |
| 같은 번호가 있나 | 프로그램끼리 같은 번호가 겹쳐도 됨 | 칸마다 번호가 하나뿐이라 겹치지 않음 |

예를 들어 프로그램 A와 B가 둘 다 "100번지"에 값을 저장해도 서로 덮어쓰지 않는다. 1반과 2반에 모두 출석번호 1번이 있어도 다른 학생인 것처럼, 두 프로그램의 100번지는 번호만 같다. 실제로는 아래처럼 A의 100번지는 물리 주소 5,220번지로, B의 100번지는 9,316번지로 바뀌어 RAM의 서로 다른 칸에 저장된다.

```mermaid
제목: 번호는 같은 100번지지만, 페이지 테이블을 거치면 RAM의 서로 다른 칸으로 간다
%% 폰: TB
flowchart LR
  A("프로그램 A<br/>100번지") --> T["페이지 테이블"]
  B("프로그램 B<br/>100번지") --> T
  T --> P1["RAM<br/>5,220번지"]
  T --> P2["RAM<br/>9,316번지"]
```

이렇게 논리 주소를 물리 주소로 바꾸는 일을 **주소 변환**이라고 하고, 둘을 짝지어 잇는다는 뜻에서 매핑(Mapping)이라고도 부른다. 주소 변환은 프로그램이 메모리에 접근할 때마다 CPU 안의 전용 하드웨어가 자동으로 처리하고, 운영체제는 변환에 필요한 페이지 테이블을 만들고 관리한다.

여기서 헷갈리기 쉬운 점이 두 가지 있다.

- **네트워크의 논리 주소·물리 주소와는 다른 이야기**: 네트워크에서는 IP 주소를 논리 주소, MAC 주소를 물리 주소라고 부르고 데이터 링크 계층의 데이터 단위도 프레임이라고 부르지만, 여기서의 논리 주소·물리 주소·프레임은 모두 메모리(RAM) 이야기로 이름만 같음
- **프로그램은 자기 데이터가 RAM 어디에 있는지 모름**: 프로그램은 논리 주소만 쓰므로, 다시 실행해 RAM의 다른 위치에 올라가도 프로그램 입장에서는 달라지는 것이 없음, 실제 위치를 아는 것은 페이지 테이블

### 페이지, 프레임, 페이지 테이블
주소 변환 정보를 사물함 칸 하나하나마다 기록하면 관리할 정보가 너무 많아진다. 그래서 가상 메모리는 칸을 일정한 개수씩 묶은 구역(블록) 단위로 관리한다. 1KB(1,024바이트)씩 묶으면 1,024칸을 장부 한 줄로 관리할 수 있다.

- **페이지(Page)**: 프로그램 쪽 번호(논리 주소 공간)를 일정한 크기로 묶은 구역
- **프레임(Frame, 페이지 프레임)**: RAM 사물함(물리 메모리)을 페이지와 같은 크기로 묶은 구역

참고로 "가상 메모리"라는 말은 이 기법의 이름이면서, 프로그램이 보는 가상의 메모리 공간(논리 주소 공간)을 가리킬 때도 쓴다. 그래서 "가상 메모리를 페이지로 나눈다"는 "논리 주소 공간을 페이지로 나눈다"는 뜻이다.

페이지와 프레임은 크기가 같아서 어떤 페이지든 빈 프레임 아무 곳에나 들어갈 수 있다. 이렇게 메모리를 같은 크기의 페이지로 나눠 관리하는 방식을 페이징(Paging)이라고 한다. 가상 메모리를 구현하는 방식은 여러 가지지만, 여기서는 페이지 교체 알고리즘과 바로 이어지는 페이징을 기준으로 본다.

각 페이지가 지금 어느 프레임에 있는지 기록한 표가 **페이지 테이블(Page Table)**이다. 페이지 테이블은 실행 중인 프로그램(프로세스)마다 하나씩 있고 운영체제가 관리한다. 어떤 프로그램의 페이지 테이블이 아래와 같다고 해보자.

| 페이지 번호 | 프레임 번호 | RAM에 있나? |
|---|---|---|
| 0 | 3 | O |
| 1 | - | X (보조기억장치에 있음) |
| 2 | 5 | O |
| 3 | 1 | O |

```mermaid
제목: 페이지 순서와 상관없이 0, 2, 3번 페이지가 3, 5, 1번 프레임에 흩어져 들어가고, 1번 페이지는 SSD에 있다
%% 폰: TB
flowchart LR
  subgraph PG["프로그램 A의 페이지"]
    direction TB
    p0["페이지 0"]
    p1["페이지 1"]
    p2["페이지 2"]
    p3["페이지 3"]
  end
  p0 --> f3["RAM 프레임 3"]
  p2 --> f5["RAM 프레임 5"]
  p3 --> f1["RAM 프레임 1"]
  p1 -.-> S[("SSD")]
```

- 0번 페이지는 RAM 3번 프레임, 2번 페이지는 5번 프레임, 3번 페이지는 1번 프레임에 있음
- 1번 페이지는 지금 RAM에 없고 보조기억장치에만 있음, 이 페이지에 접근하면 페이지 부재 발생

둘 다 같은 크기의 블록이라 헷갈리기 쉬운데, 프로그램 쪽(논리 주소)을 나눈 것이 페이지, RAM 쪽(물리 주소)을 나눈 것이 프레임이다. 페이지 교체 문제에서 '페이지 프레임이 3개'라고 하면 RAM에 페이지를 담을 자리가 3칸이라는 뜻이다.

#### 논리 주소를 물리 주소로 바꾸는 계산
페이지 테이블로 실제 주소를 구하는 과정을 숫자로 따라가 보면 구조가 더 분명해진다. 페이지 크기가 1KB이고 위 페이지 테이블을 쓴다고 해보자. 메모리 크기를 셀 때 1KB는 1,000이 아니라 1,024바이트다. 페이지 하나가 1,024칸이므로 논리 주소는 1,024칸씩 페이지에 나뉘어 들어간다.

| 페이지 번호 | 논리 주소 범위 |
|---|---|
| 0 | 0 ~ 1,023번지 |
| 1 | 1,024 ~ 2,047번지 |
| 2 | 2,048 ~ 3,071번지 |
| 3 | 3,072 ~ 4,095번지 |

논리 주소 2,100번지는 2번 페이지 범위 안에 있다. 계산으로 옮기면 이렇다.

1. 페이지 번호: 2,100 ÷ 1,024의 몫 2 → 2번 페이지
2. 페이지 안 위치: 2,100 − (2 × 1,024) = 52 → 2번 페이지 시작점(2,048번지)에서 52칸 떨어진 곳
3. 페이지 테이블 확인: 2번 페이지는 5번 프레임
4. 물리 주소: 5번 프레임은 5 × 1,024 = 5,120번지부터 시작하므로 5,120 + 52 = 5,172번지

페이지 번호만 페이지 테이블을 거쳐 프레임 번호로 바뀌고, 페이지 안 위치(52)는 그대로라는 점이 핵심이다. 논리 주소가 1,500번지였다면 1,500 ÷ 1,024의 몫이 1이라 1번 페이지를 찾는데, 1번 페이지는 RAM에 없으므로 곧바로 페이지 부재가 난다.

### 페이지 부재
가상 메모리는 프로그램을 시작할 때 모든 페이지를 RAM에 올리지 않고, 실제로 필요해진 페이지만 그때그때 가져온다. 이렇게 요구된 페이지만 가져오는 방식을 요구 페이징(Demand Paging)이라고 한다. 이때 따지는 단위는 기능이 아니라 페이지다. 운영체제는 코드가 어떤 기능인지 모르고, 프로그램을 일정한 크기로 자른 페이지 중 어느 것이 필요해졌는지만 본다. 그래서 기능 하나가 여러 페이지에 걸칠 수도 있고, 한 페이지에 여러 기능이 섞일 수도 있다.

예를 들어 문서 편집 프로그램에서 인쇄 기능 코드만 든 페이지는 인쇄 버튼을 누르기 전까지 한 번도 쓰이지 않으므로 RAM에 올라오지 않는다. 프로그램에는 이렇게 거의 안 쓰는 부분이 많아서, 필요한 페이지만 올리면 RAM을 훨씬 아낄 수 있다. 그러다 보니 프로그램이 쓰려는 페이지가 아직 RAM에 없는 상황이 자연스럽게 생기는데, 이것이 **페이지 부재(Page Fault)**다. 프로그램이 어떤 페이지를 사용(접근)하는 것을 참조라고 하고, 페이지 교체 문제의 "참조 순서", "참조 횟수"도 이 뜻이다.

페이지 부재가 나면 아래 순서로 처리된다. 4번과 5번은 빈 프레임이 있는지에 따라 둘 중 하나만 일어난다.

```steps
제목: 빈 프레임이 있으면 4번, 꽉 찼으면 5번으로 처리한 뒤 장부를 고치고 다시 실행한다
1. 페이지 테이블 확인 | 참조한 페이지가 RAM에 없음
2. CPU가 운영체제에 넘김 | 하던 일 멈춤
3. 보조기억장치에서 찾기 | 필요한 페이지 탐색
4. 빈 프레임에 넣기 | 빈 프레임이 있을 때 (스왑 인)
5. 하나 내보내고 넣기 | 빈 프레임이 없을 때 (스왑 아웃 후 스왑 인)
6. 페이지 테이블 고치고 재실행 | 멈췄던 명령 다시 실행
```

1. 프로그램이 어떤 논리 주소를 참조하고, 하드웨어가 페이지 테이블을 보고 그 페이지가 RAM에 없음을 확인
2. CPU가 하던 일을 멈추고 운영체제에 처리를 넘김
3. 운영체제가 보조기억장치에서 필요한 페이지를 찾음
4. RAM에 빈 프레임이 있으면 그 프레임으로 페이지를 들여옴(스왑 인, swap-in)
5. 빈 프레임이 없으면 RAM의 페이지 하나를 골라 보조기억장치로 내보내고(스왑 아웃, swap-out), 비워진 프레임에 필요한 페이지를 들여옴
6. 페이지 테이블에서 들여온 페이지는 새 프레임 번호로, 내보낸 페이지는 'RAM에 없음'으로 고친 뒤 멈췄던 명령을 다시 실행

빈 프레임이 없을 때(5단계) 어떤 페이지를 내보내느냐에 따라 이후 페이지 부재 횟수가 달라진다. 프레임이 3칸이고 페이지를 1, 2, 3, 4, 1 순서로 참조한다고 해보자.

- 1, 2, 3을 참조하면 세 칸이 모두 참
- 4를 참조할 때 빈칸이 없으므로 한 페이지를 내보내야 함
- 이때 1을 내보냈다면 바로 다음 1 참조에서 또 페이지 부재, 2나 3을 내보냈다면 1이 RAM에 남아 있어 부재 없음

| 4를 넣을 때 내보낸 페이지 | 프레임 | 다음 1 참조 |
|---|---|---|
| 1 | 4, 2, 3 | 페이지 부재 |
| 2 | 1, 4, 3 | 부재 없음 |

이렇게 RAM의 페이지 중 어느 것을 내보낼지 정하는 규칙이 페이지 교체 알고리즘이고, FIFO·LRU·LFU의 동작은 [페이지 교체 알고리즘] 묶음에서 다룬다.

이름에 fault(결함)가 들어가지만 페이지 부재는 오류가 아니다. 프로그램이 잘못된 게 아니라, 필요한 페이지를 가져와 달라는 정상적인 신호다. 다만 보조기억장치는 RAM보다 훨씬 느려서 페이지 부재가 잦을수록 프로그램이 느려진다. 그래서 페이지 교체 알고리즘의 목표가 '페이지 부재 횟수 최소화'다.

### 가상 메모리와 스와핑의 차이
"가상 메모리는 RAM이 부족할 때 HDD/SSD를 RAM처럼 쓰는 것"이라는 설명은 1번 아이디어와 같은 이야기라 틀린 말은 아니다. 다만 이 설명에는 가상 메모리가 쓰는 동작 하나(스와핑)만 드러나고, 그것을 가능하게 하는 주소 분리가 빠져 있다.

- **스와핑(Swapping)**: RAM과 보조기억장치 사이에서 데이터를 옮기는 동작. RAM에서 내보내는 스왑 아웃과 들여오는 스왑 인이 해당, 원래는 실행 중인 프로세스 전체를 통째로 옮기는 기법을 가리키는 말
- **가상 메모리**: 논리 주소와 물리 주소를 분리하고 페이지 단위로 필요한 부분만 RAM에 두는 메모리 관리 방식 전체. 페이지 부재가 나면 페이지 단위로 들이고 내보내므로, 스와핑은 가상 메모리가 쓰는 수단 중 하나

| 구분 | 가상 메모리 | 스와핑 |
|---|---|---|
| 성격 | 메모리 관리 방식(개념) | RAM과 보조기억장치 사이의 데이터 이동(동작) |
| 관리 단위 | 페이지 | 원래는 프로세스 전체, 가상 메모리에서는 페이지 |
| 주소 분리 | 논리 주소와 물리 주소를 분리함 | 주소 분리와는 별개 |
| 주된 효과 | 프로그램마다 따로 쓰는 주소, RAM보다 큰 프로그램 실행 | RAM의 빈 공간 확보 |

Windows 설정의 "가상 메모리"(페이징 파일)나 리눅스의 스왑 영역은, 스와핑으로 내보낸 데이터를 보관하는 보조기억장치 쪽 공간을 가리킨다. 이 이름 때문에 "가상 메모리 = 디스크 공간"으로 오해하기 쉽다. 보조기억장치를 주기억장치처럼 쓸 수 있는 것도 그 바탕에 논리 주소와 물리 주소의 분리가 있기 때문이다.

정리하면 가상 메모리는 주소 변환 → 페이지 부재 → 페이지 교체 순서로 동작하고, 페이지를 들이고 내보낼 때 스와핑을 쓴다.

## 교착 상태 (Deadlock)
출제: 없음

### 개념
**교착 상태(Deadlock)** 는 둘 이상의 프로세스가 서로 상대가 가진 자원을 기다리느라 아무도 진행하지 못하는 상태다. 이 상태는 아래 네 조건이 **모두** 성립할 때 생긴다.

| 발생 조건 | 뜻 |
|---|---|
| **상호 배제(Mutual Exclusion)** | 자원을 한 번에 한 프로세스만 쓴다 |
| **점유와 대기(Hold and Wait)** | 자원을 가진 채 다른 자원을 기다린다 |
| **비선점(Non-preemption)** | 다른 프로세스의 자원을 강제로 빼앗지 못한다 |
| **환형 대기(Circular Wait)** | 대기 관계가 원을 이룬다 |

### 발생 조건 하나씩 보기
네 조건은 장면 하나에 다 들어 있다. 프로세스 두 개와 자원 두 개가 있다.

```
P1 : 프린터를 가진 채 스캐너를 기다림
P2 : 스캐너를 가진 채 프린터를 기다림
```

#### 1. 상호 배제 (Mutual Exclusion)
- 자원을 한 번에 한 프로세스만 사용

프린터는 두 프로세스가 동시에 쓸 수 없다. 여럿이 함께 쓸 수 있는 자원이었다면 P2가 프린터를 기다릴 이유부터 없다.

#### 2. 점유와 대기 (Hold and Wait)
- 자원을 가진 채 다른 자원을 기다림

P1은 프린터를 가진 채로 스캐너를 기다린다. 기다리는 동안 프린터를 반납했다면 P2가 프린터를 받아 일을 끝내고 스캐너도 반납했을 것이다.

#### 3. 비선점 (Non-preemption)
- 다른 프로세스의 자원을 강제로 빼앗지 못함

P1이 아무리 급해도 P2의 스캐너를 뺏어 올 수 없다. CPU 스케줄링에서 본 비선점과 같은 말인데, 여기서 못 뺏는 대상은 CPU 사용 시간이 아니라 프린터·스캐너 같은 자원이다.

#### 4. 환형 대기 (Circular Wait)
- 대기 관계가 원을 이룸

아래 그림처럼 P1은 P2가 가진 것을, P2는 P1이 가진 것을 기다려서 대기 관계가 한 바퀴 닫힌다.

```mermaid
제목: 화살표를 따라가면 P1에서 출발해 다시 P1로 돌아온다. 이 닫힌 원이 환형 대기다
flowchart LR
  P1(("P1")) -->|"기다림"| S["스캐너"]
  S -->|"할당"| P2(("P2"))
  P2 -->|"기다림"| R["프린터"]
  R -->|"할당"| P1
```

프로세스가 셋 이상이어도 P1은 P2를, P2는 P3를, P3는 다시 P1을 기다리는 식으로 원이 닫히면 똑같다.

네 조건이 **모두** 성립해야 교착 상태가 생긴다. 뒤집어 말하면 네 조건 중 하나만 깨도 교착 상태는 생기지 않는다. 바로 아래 표의 해결 방법 중 예방이 이 점을 이용한다.

### 한눈에 구분
| 해결 방법 | 하는 일 |
|---|---|
| **예방(Prevention)** | 네 조건 중 하나를 미리 없앤다 |
| **회피(Avoidance)** | 자원을 줄 때마다 안전 상태가 유지되는지 확인하고, 불안전하면 주지 않는다. 대표가 **은행원 알고리즘(Banker's Algorithm)** |
| **발견(Detection)** | 자원 할당 그래프 등으로 교착 상태가 생겼는지 검사한다 |
| **회복(Recovery)** | 교착에 걸린 프로세스를 종료하거나 자원을 선점해 풀어 준다 |

네 방법은 교착 상태가 생기기 전에 손을 쓰는지(예방·회피), 생긴 뒤에 손을 쓰는지(발견·회복)로 먼저 나뉜다. 아마 가장 헷갈리는 게 같은 쪽인 예방과 회피일 것이다. 예방은 네 조건 중 하나를 규칙으로 아예 없애서 교착 상태가 생길 수 없게 만든다. 회피는 조건을 그대로 두고, 자원 요청이 올 때마다 줘도 안전한지 계산해서 판단한다. 그래서 지문에 "조건 하나를 제거"가 나오면 예방이고, "은행원·안전 상태"가 나오면 회피다. 발견은 교착 상태를 찾아내기만 하고, 찾아낸 교착 상태를 푸는 일은 회복이 맡는다.

예방은 네 조건을 하나씩 부정하는 식으로 없앤다.

- 상호 배제: 자원을 여럿이 함께 쓸 수 있게 만듦. 프린터 같은 자원은 대개 불가
- 점유와 대기: 필요한 자원을 한꺼번에 요청하게 함
- 비선점: 기다려야 할 때 가진 자원을 내놓게 함
- 환형 대기: 자원에 번호를 매겨 오름차순으로만 요청하게 함

은행원 알고리즘에는 값 네 개가 나온다.

- Max: 프로세스가 최대로 필요한 자원 수
- Allocation: 지금 가지고 있는 수
- Need: 앞으로 더 받아야 하는 수
- Available: 아무에게도 할당되지 않고 남은 수

계산은 먼저 프로세스마다 Need = Max − Allocation을 구한다. 그다음 Need ≤ Available인 프로세스를 하나 골라 끝낸다고 가정하고, 그 프로세스의 Allocation을 Available에 더한다. 이 과정을 반복한다. 이렇게 해서 모든 프로세스를 끝낼 수 있는 순서가 있으면 안전 상태이고, 이 순서를 안전 순서라고 한다.

### 해결 방법 하나씩 보기
위의 프린터·스캐너 장면에 네 가지 해결 방법을 차례로 적용한다. 회피만은 장면 대신 은행원 알고리즘을 숫자로 계산한다.

#### 1. 예방 (Prevention)
- 네 조건 중 하나를 미리 제거
- 상호 배제 부정은 대개 불가, 나머지 셋 중 하나를 제거

프린터에 1번, 스캐너에 2번을 매기고 번호 오름차순으로만 요청하게 규칙을 정한다. 그러면 P2도 스캐너보다 프린터를 먼저 요청해야 한다. 프린터를 먼저 얻은 프로세스가 스캐너까지 받아 일을 끝내고, 다른 프로세스는 아무 자원도 갖지 않은 채 프린터를 기다린다. 스캐너를 가진 채 프린터를 기다리는 경우가 생기지 않으니 대기 관계가 원을 이루지 못한다. 이 규칙이 없애는 조건이 환형 대기다.

#### 2. 회피 (Avoidance)
- 자원을 줄 때마다 안전 상태 유지 여부 확인
- 불안전 상태가 되면 할당 보류
- 대표: **은행원 알고리즘(Banker's Algorithm)**

자원은 한 종류, 전부 10개다.

| 프로세스 | Max | Allocation | Need |
|---|---|---|---|
| P1 | 7 | 2 | 5 |
| P2 | 4 | 2 | 2 |
| P3 | 9 | 3 | 6 |

할당된 것이 2 + 2 + 3 = 7개이므로 Available은 3이다. 위에서 말한 절차대로 Need ≤ Available인 프로세스부터 끝내 보면 이렇다.

```
Available 3  : P2(Need 2) 실행 가능 → 끝나면 2 반납, Available 5
Available 5  : P1(Need 5) 실행 가능 → 끝나면 2 반납, Available 7
Available 7  : P3(Need 6) 실행 가능 → 끝나면 3 반납, Available 10
```

P2, P1, P3 순서로 모두 끝낼 수 있다. 안전 순서가 있으므로 안전 상태다. 그럼 이 상태에서 P3가 하나를 더 달라고 하면 줄 수 있을까? 주고 나면 Available은 2, P3의 Need는 5가 된다. P2를 끝내 Available을 4로 만든 뒤에는 Need 5인 P1도 P3도 진행할 수 없다. 불안전 상태가 되므로 은행원 알고리즘은 이 요청을 들어주지 않는다.

#### 3. 발견 (Detection)
- 자원 할당 그래프 등으로 교착 상태 발생 여부 검사
- 미리 막지 않고, 생긴 뒤에 찾아내는 방식

```
P1 ──기다림──▶ 스캐너 ──할당──▶ P2
P2 ──기다림──▶ 프린터 ──할당──▶ P1
```

화살표를 이어 보면 P1, 스캐너, P2, 프린터를 거쳐 다시 P1으로 닫히는 사이클이 보인다. 이런 사이클을 찾아내는 것이 발견이다.

#### 4. 회복 (Recovery)
- 교착에 걸린 프로세스 종료
- 또는 자원을 선점해 교착 해제

발견한 사이클에서 P2를 종료하면 스캐너가 풀려 P1이 진행된다. P2를 끝내지 않고 스캐너만 빼앗아 P1에게 줘도 사이클은 끊긴다. 스캐너를 빼앗는 두 번째 방법은 비선점 조건을 강제로 깬다.

## 주기억장치 배치 전략
출제: 없음

### 개념
주기억장치 배치 전략이란 새 프로그램을 주기억장치의 빈 공간(가용 공간) 가운데 어디에 넣을지 정하는 규칙을 말한다. 어떤 빈 공간을 고르느냐에 따라 세 가지로 나뉜다.

| 전략 | 넣는 곳 |
|---|---|
| **최초 적합(First Fit)** | 앞에서부터 찾다가 처음 만나는, 들어갈 수 있는 빈 공간 |
| **최적 적합(Best Fit)** | 들어간 뒤 남는 공간이 **가장 작은** 빈 공간 |
| **최악 적합(Worst Fit)** | 들어간 뒤 남는 공간이 **가장 큰** 빈 공간 |

예를 들어 빈 공간이 첫 번째부터 5K, 15K, 10K, 25K 순서로 있고, 여기에 9K 프로그램을 넣는다. 5K는 9K보다 작아서 세 전략 모두 후보에서 뺀다. 아래 그림처럼 최초 적합은 15K에 넣어 6K가 남고, 최적 적합은 10K에 넣어 1K가 남고, 최악 적합은 25K에 넣어 16K가 남는다.

```mermaid
제목: 5K는 9K보다 작아 빠지고, 세 전략은 남은 빈 공간 중 서로 다른 곳을 고른다
flowchart LR
  P("9K 프로그램")
  H1["5K: 9K보다 작음"]
  H2["15K: 6K 남음"]
  H3["10K: 1K 남음"]
  H4["25K: 16K 남음"]
  P ~~~ H1
  P -->|"최초 적합"| H2
  P -->|"최적 적합"| H3
  P -->|"최악 적합"| H4
  classDef out stroke-dasharray:5 4,color:#8a9099
  class H1 out
```

이렇게 프로그램을 넣고 나면 남는 공간이 두 종류로 갈린다.

- **내부 단편화**: 프로그램이 들어간 뒤 그 분할 안에 남는 공간. 이 예의 6K·1K·16K
- **외부 단편화**: 프로그램보다 작아서 아예 쓰지 못하는 빈 공간. 이 예의 5K

필기에서는 "최악 적합으로 17K를 넣을 때 내부 단편화 크기"처럼 물었다. 빈 공간이 20K·16K·8K·40K였고, 최악 적합은 가장 큰 40K를 고르므로 40K에서 17K를 뺀 23K가 답이다.

### 배치 전략 하나씩 보기
위 예에서 프로그램을 셋으로 늘린다. 같은 빈 공간 5K, 15K, 10K, 25K에 프로그램 세 개가 9K, 12K, 20K 순서로 들어온다. 한 빈 공간에는 프로그램 하나만 들어가고, 넣고 남은 공간은 위에서 말한 내부 단편화로 남는다고 하자.

#### 1. 최초 적합 (First Fit)
- 빈 공간 목록의 첫 번째부터 차례로 보아 처음 만나는, 들어갈 수 있는 빈 공간에 배치
- 찾는 시간이 가장 짧은 방식

| 요청 | 넣는 곳 | 남는 공간 |
|---|---|---|
| 9K | 15K | 6K |
| 12K | 25K | 13K |
| 20K | 없음 | |

9K는 15K에 들어간다. 12K가 오면 첫 번째 빈 공간부터 다시 보는데, 5K와 10K는 12K보다 작고 15K는 이미 찼다. 그래서 네 번째인 25K에 들어간다. 20K가 올 때 남은 빈 공간은 5K와 10K뿐이라 들어갈 곳이 없다.

#### 2. 최적 적합 (Best Fit)
- 들어간 뒤 남는 공간이 **가장 작은** 빈 공간에 배치
- 빈 공간 전체를 비교해야 함

| 요청 | 넣는 곳 | 남는 공간 |
|---|---|---|
| 9K | 10K | 1K |
| 12K | 15K | 3K |
| 20K | 25K | 5K |

9K는 10K에, 12K는 15K에 넣어 남는 공간이 가장 작은 곳부터 썼다. 그 덕에 가장 큰 25K가 마지막까지 비어 있었고, 20K가 거기에 들어갔다. 이 순서에서 세 프로그램이 모두 자리를 찾은 것은 최적 적합뿐이다.

#### 3. 최악 적합 (Worst Fit)
- 들어간 뒤 남는 공간이 **가장 큰** 빈 공간에 배치
- 빈 공간 전체를 비교해야 함

| 요청 | 넣는 곳 | 남는 공간 |
|---|---|---|
| 9K | 25K | 16K |
| 12K | 15K | 3K |
| 20K | 없음 | |

9K가 가장 큰 25K를 차지했고, 12K는 남은 것 중 가장 큰 15K에 들어갔다. 20K가 올 때 남은 빈 공간은 5K와 10K뿐이라 들어갈 곳이 없다. 이름 그대로 남는 공간을 가장 크게 만드는 쪽을 고르기 때문에, 큰 빈 공간부터 먼저 쪼개진다.

## 디스크 스케줄링
출제: 없음

### 개념
디스크 스케줄링이란 디스크 헤드가 여러 트랙 요청을 어떤 순서로 처리할지 정하는 기법을 말한다. 순서를 따지는 이유는 헤드 이동 거리(탐색 시간)를 줄이기 위해서다.

| 기법 | 처리 순서 | 단서 |
|---|---|---|
| **FCFS** | 요청이 도착한 순서 | 공평하지만 이동이 많음 |
| **SSTF(Shortest Seek Time First)** | 현재 헤드에서 **가장 가까운** 트랙부터 | 먼 요청은 기아 발생 가능 |
| **SCAN** | 한 방향으로 끝까지 가며 처리하고 반대 방향으로 돌아옴 | 엘리베이터 알고리즘 |
| **C-SCAN** | 한 방향으로만 처리하고, 끝에 닿으면 처리 없이 시작점으로 돌아감 | 대기 시간이 고름 |
| **LOOK / C-LOOK** | SCAN / C-SCAN과 같지만 끝까지 가지 않고 마지막 요청이 있는 곳에서 방향을 바꿈 | SCAN의 개선 |

헤드 이동 거리는 처리 순서대로 이웃한 두 트랙 번호의 차(절댓값)를 모두 더한 값이다. 예를 들어 헤드가 53에 있고 요청이 98·183·37·122·14·124·65·67이라면, FCFS로 처리했을 때는 640이고 SSTF(65→67→37→14→98→122→124→183)로 처리했을 때는 236이다. 아래 그림처럼 같은 요청이라도 처리 순서에 따라 헤드가 오가는 폭이 크게 달라진다.

### 디스크 스케줄링 하나씩 보기
위 예를 그대로 가져와 나머지 기법까지 늘어놓는다. 헤드는 53에 있고 요청은 98, 183, 37, 122, 14, 124, 65, 67이다. SCAN 계열은 방향과 디스크 끝을 알아야 한다. 그래서 트랙은 0~199번이고 헤드는 지금 0 쪽(작은 번호 쪽)으로 움직이는 중이라고 하자.

#### 1. FCFS (First Come First Served)
- 요청이 도착한 순서대로 처리
- 공평하지만 헤드 이동이 많음

```
53 → 98 → 183 → 37 → 122 → 14 → 124 → 65 → 67
이동: 45 + 85 + 146 + 85 + 108 + 110 + 59 + 2 = 640
```

183까지 갔다가 37로 돌아오고, 다시 122로 가는 식으로 디스크를 몇 번이나 가로지른다. 여섯 기법 중 이동 거리가 가장 길다.

#### 2. SSTF (Shortest Seek Time First)
- 현재 헤드에서 **가장 가까운** 트랙부터 처리
- 먼 요청은 기아 발생 가능

```
53 → 65 → 67 → 37 → 14 → 98 → 122 → 124 → 183
이동: 12 + 2 + 30 + 23 + 84 + 24 + 2 + 59 = 236
```

매번 가장 가까운 곳만 골랐더니 이동 거리가 확 줄었다. 그런데 헤드 근처에 요청이 계속 들어오면 183 같은 먼 요청은 처리 순서가 계속 뒤로 밀릴 수 있다. 이렇게 먼 요청이 오래 처리되지 못하는 현상이 기아다.

#### 3. SCAN
- 한 방향으로 디스크 끝까지 가며 처리하고, 반대 방향으로 돌아오며 처리
- 엘리베이터 알고리즘이라고도 함

```
53 → 37 → 14 → 0 → 65 → 67 → 98 → 122 → 124 → 183
이동: 53(53에서 0까지) + 183(0에서 183까지) = 236
```

0 쪽으로 가면서 37, 14를 처리하고, 요청이 없어도 끝인 0까지 간 뒤에 방향을 바꾼다. 엘리베이터가 맨 끝 층까지 갔다가 되돌아오는 모습과 같다.

#### 4. C-SCAN (Circular SCAN)
- 한 방향으로만 처리
- 끝에 닿으면 처리 없이 반대쪽 끝으로 돌아가 같은 방향으로 다시 처리
- 대기 시간이 고름

```
53 → 37 → 14 → 0 → (처리 없이) 199 → 183 → 124 → 122 → 98 → 67 → 65
이동: 53 + 199(돌아가는 이동) + 134 = 386
```

SCAN이었다면 0에서 바로 방향을 바꿔 65부터 처리했을 것이다. C-SCAN은 반대쪽 끝 199로 건너간 뒤 다시 작은 번호 쪽으로 내려오며 처리한다. 여기서는 돌아가는 이동 199도 거리에 넣었는데, 교재에 따라서는 이 구간을 빼고 53 + 134 = 187로 세기도 한다. 문제에 조건이 있으면 그대로 따른다. 처리 방향이 늘 같아서 트랙 위치에 따라 기다리는 시간이 크게 갈리지 않는다.

#### 5. LOOK
- SCAN과 같지만 디스크 끝까지 가지 않음
- 그 방향의 마지막 요청에서 방향 전환

```
53 → 37 → 14 → 65 → 67 → 98 → 122 → 124 → 183
이동: 39(53에서 14까지) + 169(14에서 183까지) = 208
```

SCAN과 처리 순서는 같지만, 0까지 가지 않고 그 방향의 마지막 요청인 14에서 방향을 바꿨다. 0까지 갔다 오는 28만큼이 줄어 236이 208이 됐다.

#### 6. C-LOOK
- C-SCAN과 같지만 디스크 끝까지 가지 않음
- 마지막 요청에서 반대쪽의 첫 요청으로 바로 이동

```
53 → 37 → 14 → (처리 없이) 183 → 124 → 122 → 98 → 67 → 65
이동: 39 + 169(돌아가는 이동) + 118 = 326
```

0과 199를 찍지 않고 요청이 있는 14와 183 사이만 오간다. 돌아가는 이동을 똑같이 넣어 세면 C-SCAN의 386보다 60이 짧다. 이 구간을 빼는 교재 기준이라면 39 + 118 = 157이다.
