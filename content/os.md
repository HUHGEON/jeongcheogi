# 운영체제

21개 회차 420문제 가운데 운영체제 이론은 14문제다. 그중 가장 많은 게 프로세스 스케줄링으로 5회차에 걸쳐 6문제가 나왔고, 이 가운데 3문제는 도착·실행 시간 표를 주고 평균 대기시간을 구하는 계산이었다. 특히 SRT 6.5는 24-2와 26-2에 같은 표로 두 번 나왔다. 페이지 교체도 부재 횟수를 세는 계산으로 나왔다. 나머지는 UNIX 명령어·chmod·프로세스 상태·IPC처럼 상황 설명을 주고 용어나 명령어를 쓰게 하는 형태다. 계산 절차는 [계산] 페이지에 따로 있으니, 여기서는 알고리즘을 고르는 단서와 용어만 정리한다.

## CPU 스케줄링 알고리즘
출제: 26-2, 25-2, 24-2, 22-3, 20-1
형태: 도착·실행 시간 표 → 평균 대기시간 계산, 설명 2~3개 → 영문 약어, HRN 우선순위 식 빈칸

### 개념
**CPU 스케줄링**이란 준비 큐에 있는 프로세스 중 어느 것에 CPU를 줄지 정하는 일을 말한다. 여기서 먼저 갈라야 하는 게 선점과 비선점이다. 실행 중인 프로세스에게서 CPU를 뺏을 수 있으면 **선점(Preemptive)**이고, 그 프로세스가 스스로 끝내거나 입출력을 요청할 때까지 기다리면 **비선점(Non-preemptive)**이다.

계산 문제에서는 아래 네 가지 시간을 쓴다.

- **실행 시간(버스트 시간, Burst Time)**: 프로세스가 CPU를 쓰는 시간.
- **반환 시간(Turnaround Time)** = 종료 시각 − 도착 시각.
- **대기 시간(Waiting Time)** = 반환 시간 − 실행 시간. 준비 큐에서 기다린 시간의 합.
- **응답 시간(Response Time)**: 도착 후 처음 CPU를 받기까지의 시간.

프로세스를 골랐다고 끝이 아니다. 고른 프로세스에 실제로 CPU를 넘겨주는 모듈이 따로 있는데, 이것이 **디스패처(Dispatcher)**다. 그리고 이때 레지스터·PC를 저장하고 복원하는 일을 **문맥 교환(Context Switching)**이라고 한다.

### 한눈에 구분
| 알고리즘 | 선점 여부 | 고르는 기준 | 지문 단서 |
|---|---|---|---|
| **FCFS(First Come First Served)** | 비선점 | 먼저 도착한 순서 | FIFO, 긴 작업 뒤에 짧은 작업이 줄줄이 기다리는 호위 효과(Convoy Effect) |
| **SJF(Shortest Job First)** | 비선점 | **실행 시간이 가장 짧은** 프로세스 | 비선점 방식 중 평균 대기시간이 가장 짧음(선점형까지 보면 SRT가 더 짧다), 긴 작업의 기아(Starvation) |
| **HRN(Highest Response-ratio Next)** | 비선점 | **우선순위 = (대기 시간 + 서비스 시간) / 서비스 시간**이 큰 것 | SJF의 기아를 보완, 오래 기다릴수록 우선순위 상승(에이징 효과) |
| **우선순위(Priority)** | 비선점·선점 모두 가능 | 우선순위 값 | 낮은 우선순위의 기아, 에이징(Aging)으로 해결 |
| **기한부(Deadline)** | 비선점 | 정해진 시간 안에 끝내야 하는 작업 | 제한 시간, 실시간 |
| **RR(Round Robin)** | 선점 | **시간 할당량(Time Quantum, Time Slice)**만큼 돌아가며 | 시분할 시스템, 할당량이 크면 FCFS와 같아지고 작으면 문맥 교환 부담 증가 |
| **SRT(Shortest Remaining Time)** | 선점 | **남은 실행 시간이 가장 짧은** 프로세스 | SJF의 선점형, 새 프로세스가 도착할 때마다 남은 시간 비교 |
| **다단계 큐(Multilevel Queue)** | 선점 | 프로세스 성격별로 여러 큐에 고정 배치 | 큐마다 다른 알고리즘, 큐 사이 이동 없음 |
| **다단계 피드백 큐(Multilevel Feedback Queue)** | 선점 | 큐 사이를 옮겨 다님 | 할당량 안에 못 끝낸(CPU를 오래 쓰는) 프로세스는 아래 큐로 내려감, 위 큐일수록 할당량이 짧고 아래로 갈수록 길어짐, 마지막 큐는 보통 FCFS(교재에 따라 RR) |

표에서 가장 헷갈리는 게 SJF와 SRT다. 둘 다 "짧은 것 먼저"라는 점은 같고, 다른 건 **선점 여부** 하나뿐이다. 그래서 지문에 "실행 중 더 짧은 프로세스가 도착하면 교체"라는 말이 있으면 SRT로 보면 된다. RR은 "시간 할당량"이 단서다.

### 기출에서 이렇게 나왔다
- 26-2: 도착·버스트 시간 표 → SRT 평균 대기시간 **6.5** (24-2와 같은 표)
- 25-2: 도착·실행 시간 표, 할당량 4 → RR 평균 대기시간 **11.75**
- 25-2: 설명 2개 → **SJF / SRT**
- 24-2: 표 → SRT 평균 대기시간 **6.5**
- 22-3: 설명 3개 → 영문 약어 **SJF / RR / SRT**
- 20-1: HRN 우선순위 공식 빈칸 → **(대기 시간 + 서비스 시간) ÷ 서비스 시간**

### 답 쓸 때
알고리즘 이름은 영문 약어로 요구한다. HRN 식은 분자가 "대기 + 서비스"이고 분모가 "서비스"다. 대기 시간이 분자에 있으니 오래 기다릴수록 값이 커지는데, 표에서 말한 에이징 효과가 바로 이것이다. 간트 차트를 그려 평균 대기시간을 구하는 절차는 [계산] 페이지에서 풀이한다.

그런데 위 표에서는 SJF를 비선점이라고 했는데, 25-2 지문은 SJF를 "실행 시간이 짧은 프로세스를 우선 처리하며 선점형·비선점형 모두 가능"이라고 설명하고 그 선점형을 SRT라고 했다. 왜 이렇게 되냐면, 교재에 따라 선점형 SJF(SRT)까지 SJF로 묶기 때문이다. 그러니 "짧은 것 먼저 + 둘 다 가능"이면 **SJF**, "그중 선점형, 더 짧은 프로세스가 오면 CPU를 빼앗음"이면 **SRT**로 쓴다. 여기서 함정이 하나 있다. 표에서 비선점·선점이 모두 가능한 건 우선순위(Priority)였지만, "선점·비선점 모두 가능"이라는 말만 보고 우선순위로 고르지 않는다.

## 페이지 교체 알고리즘
출제: 24-3, 24-1
형태: 페이지 참조열과 프레임 수 → 페이지 부재 횟수

### 개념
빈 프레임이 없는데 새 페이지를 올려야 한다고 해보자. 그럼 기존 페이지 하나를 내보내야 하는데, 이때 어느 것을 내보낼지 정하는 규칙이 **페이지 교체 알고리즘**이다. 그리고 요청한 페이지가 메모리에 없어서 디스크에서 가져오는 사건을 **페이지 부재(Page Fault)**라고 한다. 문제는 참조열을 차례로 넣어 가며 부재가 몇 번 나는지 센다. 여기서 헷갈리기 쉬운 게 처음 프레임을 채우는 동안인데, 이때도 부재로 센다.

### 한눈에 구분
| 알고리즘 | 내보내는 페이지 | 비고 |
|---|---|---|
| **FIFO(First In First Out)** | **가장 먼저 들어온** 페이지 | 구현이 가장 단순. 프레임을 늘렸는데 부재가 오히려 느는 **벨레이디의 모순(Belady's Anomaly)** |
| **LRU(Least Recently Used)** | **가장 오랫동안 사용되지 않은** 페이지(마지막 참조 시점이 가장 오래된 것) | 카운터 또는 스택으로 구현. 참조될 때마다 "최근"으로 갱신된다는 점이 FIFO와 다름 |
| **LFU(Least Frequently Used)** | **참조 횟수가 가장 적은** 페이지 | 초기에 많이 쓰이고 안 쓰이는 페이지가 계속 남는 단점. 횟수가 같을 때의 처리 규칙을 문제에서 확인 |
| **OPT(Optimal)** | **앞으로 가장 오랫동안 사용되지 않을** 페이지 | 부재가 가장 적은 이론상 최적. 미래 참조를 알아야 해 실제 구현은 불가, 다른 알고리즘의 비교 기준 |
| **NUR(Not Used Recently)** | **참조 비트·변형 비트**가 (0, 0)인 페이지부터. 순서는 (0,0) → (0,1) → (1,0) → (1,1) | LRU의 근사. 비트 2개로 최근 사용 여부와 수정 여부를 봄. NRU라고도 씀 |
| **MFU(Most Frequently Used)** | 참조 횟수가 가장 많은 페이지 | LFU의 반대 |
| **SCR(Second Chance)** | FIFO 순서이되 참조 비트가 1이면 0으로 바꾸고 한 번 더 기회 | FIFO + 참조 비트. **2차 기회** 알고리즘 |
| **클럭(Clock)** | 2차 기회와 같은 규칙 | 페이지를 원형 큐에 두고 시계 바늘처럼 돌며 참조 비트를 확인 |

벨레이디의 모순은 FIFO에서 생기는 현상이고, LRU와 OPT에서는 생기지 않는다. LFU는 참조 횟수가 같은 페이지가 여럿일 때 그중 어느 것을 내보낼지를 문제에서 FIFO나 LRU 같은 조건으로 따로 준다.

이름이 비슷한 LRU와 LFU는 "언제"와 "몇 번"으로 가르면 된다. LRU는 마지막으로 쓰인 시각을 보고, LFU는 지금까지 쓰인 횟수를 본다. 같은 참조열이라도 두 값이 다를 수 있기 때문에 문제가 둘을 함께 묻는다.

### 기출에서 이렇게 나왔다
- 24-3: 참조열 20개, 프레임 3 → LRU 페이지 부재 횟수 **12**
- 24-1: 참조열, 프레임 3 → LRU·LFU 페이지 부재 횟수 **6 / 6**

### 답 쓸 때
문제가 부재 횟수를 묻는지, 적중 횟수를 묻는지부터 확인한다. 표를 그려 세는 절차는 [계산] 페이지에서 풀이한다.

## Unix/Linux 명령어와 UNIX 특징
출제: 25-3, 20-4
형태: 상황 설명 4개 → 보기에서 명령어 고르기, 운영체제 설명 → 이름

### 개념
명령어 문제는 "무엇을 하고 싶은가"를 문장으로 주고 거기에 맞는 명령어를 고르게 한다. 이때 명령어 이름의 원래 영어 표현을 같이 외워 두면 상황 설명과 바로 이어진다. 예를 들어 pwd가 print working directory라는 걸 알면 "지금 내가 있는 디렉터리 경로"라는 말에서 바로 떠오른다.

### 한눈에 구분
| 상황 | 명령어 | 원래 뜻 |
|---|---|---|
| 지금 내가 있는 디렉터리 경로를 본다 | **pwd** | print working directory |
| 디렉터리 안의 파일 목록을 본다 | **ls** | list |
| 다른 디렉터리로 이동한다 | **cd** | change directory |
| 파일을 복사한다 | **cp** | copy |
| 파일을 이동하거나 이름을 바꾼다 | **mv** | move |
| 파일을 삭제한다 | **rm** | remove |
| 디렉터리를 만든다 | **mkdir** | make directory |
| 빈 디렉터리를 삭제한다 | **rmdir** | remove directory |
| 파일 내용을 화면에 출력한다 | **cat** | concatenate |
| 파일의 앞부분 몇 줄을 본다 | **head** | |
| 파일의 뒷부분 몇 줄을 본다 | **tail** | |
| 파일 안에서 문자열(패턴)을 찾는다 | **grep** | |
| 조건에 맞는 파일을 디렉터리에서 찾는다 | **find** | |
| 파일의 접근 권한을 바꾼다 | **chmod** | change mode |
| 파일의 소유자를 바꾼다 | **chown** | change owner |
| 실행 중인 프로세스 목록을 본다 | **ps** | process status |
| 프로세스에 시그널을 보내 종료한다 | **kill** | |
| 실행 중인 프로세스를 실시간으로 본다 | **top** | |
| 빈 파일을 만들거나 시간 정보를 갱신한다 | **touch** | |
| 문자열을 화면에 출력한다 | **echo** | |
| 터미널 화면을 지운다 | **clear** | |
| 새 프로세스(자식 프로세스)를 만든다 | **fork** | 시스템 호출. exec로 다른 프로그램을 덮어 실행 |
| 시스템·커널 정보(버전)를 본다 | **uname** | unix name. `uname -r`은 커널 버전 |

**UNIX**의 특징은 시험 지문에 그대로 나오므로, 아래 항목을 하나씩 알아 둔다.

- 1960년대 말 **AT&T 벨 연구소(Bell Labs)**에서 개발했고, **시분할 시스템(Time Sharing System)**을 위해 설계된 대화식 운영체제다. 지문에 "벨 연구소가 MIT·GE와 공동 개발"이라는 표현이 붙어 나오기도 해서 헷갈릴 수 있는데, 이건 UNIX의 전신인 Multics 프로젝트 이야기가 섞인 것이다.
- **다중 사용자(Multi-user)·다중 작업(Multi-tasking)**을 지원한다.
- 대부분이 **C 언어**로 작성됐기 때문에 **이식성**이 높다.
- **계층적(트리) 파일 시스템**을 쓴다.
- 대화식 운영체제이고, BSD·Solaris·AIX·HP-UX 같은 변종이 많다. Linux는 UNIX를 본떠 새로 만든 유닉스 계열(Unix-like) 운영체제다.
- 구조는 **커널(Kernel)** 과 **쉘(Shell)** 로 나뉜다. 커널은 프로세스·기억장치·파일·입출력 관리를 맡는다. 쉘은 사용자 명령을 해석해서 커널에 전달하는 **명령어 해석기**로, sh, csh, ksh, bash 같은 것이 있다.

### 기출에서 이렇게 나왔다
- 25-3: 상황 설명 4개 → 보기에서 **pwd / ls / cd / cp**
- 20-4: 다중 사용자·다중 작업, C 언어, 계층적 파일 시스템 설명 → **UNIX**

### 답 쓸 때
명령어는 소문자 영문 그대로 쓴다. 상황 설명에서 "현재 위치"가 나오면 pwd, "목록"이면 ls, "이동"이면 cd, "복사"면 cp로 바로 이으면 된다.

## chmod와 파일 권한
출제: 23-3, 20-2
형태: 사용자·그룹·기타의 권한 요구 → 명령어와 8진수 세 자리

### 개념
Unix 파일 권한은 **소유자(u, user)**, **그룹(g, group)**, **기타(o, other)** 세 대상에게 각각 **읽기(r)·쓰기(w)·실행(x)** 을 줄지 말지로 정한 것이다. `ls -l`로 목록을 보면 맨 앞에 10자리가 찍히는데, 첫 글자는 종류를 나타내서 `-`면 파일, `d`면 디렉터리, `l`이면 링크다. 나머지 9자리가 `rwxrwxrwx` 순서로 u·g·o 권한이다.

**chmod(change mode)** 는 이 권한을 바꾸는 명령어다. 숫자 모드로 쓸 때는 r=4, w=2, x=1을 더한 값을 u·g·o 순서로 늘어놓아 세 자리 8진수로 만든다. 예를 들어 rwx는 4+2+1이라 7이 된다.

### 한눈에 구분
| 8진수 | 비트 | 권한 |
|---|---|---|
| 7 | 111 | rwx |
| 6 | 110 | rw- |
| 5 | 101 | r-x |
| 4 | 100 | r-- |
| 3 | 011 | -wx |
| 2 | 010 | -w- |
| 1 | 001 | --x |
| 0 | 000 | --- |

숫자 대신 기호로 쓰는 기호 모드도 있다. 대상(u/g/o/a)과 연산(+ 추가, − 제거, = 지정), 권한(r/w/x)을 이어 붙여 쓰는데, 예를 들어 `chmod u+x f`는 소유자에게 실행 권한을 더하고 `chmod go-w f`는 그룹과 기타에게서 쓰기 권한을 뺀다. 여기서 헷갈리기 쉬운 게 디렉터리의 권한이다. 디렉터리에서 x는 그 안으로 들어갈 수 있는 권한이고, r은 목록을 볼 수 있는 권한이다. `-R` 옵션을 붙이면 하위 디렉터리까지 적용된다. 참고로 소유자를 바꾸는 명령은 chmod가 아니라 **chown**이다.

## 프로세스 상태 전이와 IPC
출제: 21-1, 20-4
형태: 상태 설명 3개 → 이름, IPC 기법을 나열한 한 줄 → 용어

### 개념
**프로세스(Process)** 란 쉽게 말해 실행 중인 프로그램을 말한다. 운영체제는 프로세스마다 **PCB(Process Control Block)** 를 하나씩 두고, 여기에 PID, 프로세스 상태, 프로그램 카운터(PC), 레지스터, 우선순위 같은 스케줄링 정보, 페이지 테이블 같은 메모리 관리 정보, 입출력·계정 정보를 보관한다. PCB는 프로세스가 생성될 때 만들어지고 종료되면 제거된다. 위에서 문맥 교환 때 레지스터·PC를 저장하고 복원한다고 했었는데, 이때 상태를 저장하고 복원하는 대상이 바로 PCB다. 프로세스의 상태는 다섯 가지다.

- **생성(New)**: 만들어졌지만 아직 준비 큐에 들어가지 않음.
- **준비(Ready)**: CPU만 받으면 실행할 수 있는 상태. 준비 큐에서 대기.
- **실행(Running)**: CPU를 할당받아 명령을 수행 중.
- **대기(Waiting, Blocked)**: 입출력 완료 같은 사건을 기다리는 상태. CPU가 비어도 실행 못 함.
- **종료(Terminated)**: 실행이 끝나 자원을 반납.

```mermaid
제목: 대기에서 실행으로 바로 가는 화살표는 없다. 사건이 끝나면 준비로 돌아간다
%% 폰: TB
stateDiagram-v2
  direction LR
  state "생성" as New
  state "준비" as Ready
  state "실행" as Run
  state "대기" as Wait
  state "종료" as Done
  [*] --> New
  New --> Ready: 승인
  Ready --> Run: 디스패치
  Run --> Ready: 타이머 만료
  Run --> Wait: 블록 (입출력 요청)
  Wait --> Ready: 깨움 (입출력 완료)
  Run --> Done: 종료
  Done --> [*]
```

### 한눈에 구분
| 전이 | 이름 | 일어나는 때 |
|---|---|---|
| 생성 → 준비 | 승인(Admit) | 메모리에 올라감 |
| 준비 → 실행 | **디스패치(Dispatch)** | 스케줄러가 CPU를 줌 |
| 실행 → 준비 | **타이머 만료(Timer Run Out)**, 선점 | 할당량 소진 또는 더 급한 프로세스 등장 |
| 실행 → 대기 | **블록(Block)** | 입출력 요청 등 사건을 기다리기 시작 |
| 대기 → 준비 | **깨움(Wake Up)** | 기다리던 사건이 완료 |
| 실행 → 종료 | 종료(Exit) | 실행 완료 |

여기서 많이들 헷갈리는 게 대기 다음 상태다. 기다리던 사건이 끝났으니 바로 실행으로 갈 것 같지만, 대기에서 실행으로 곧장 가는 전이는 없다. 사건이 끝나면 준비 큐로 돌아가서 다시 CPU를 기다려야 한다.

**IPC(Inter-Process Communication)** 는 기법 하나의 이름이 아니라, 프로세스끼리 데이터를 주고받거나 동기화하는 기법을 통틀어 부르는 말이다. 아래 기법들이 모두 IPC로 묶인다.

| 기법 | 특징 |
|---|---|
| **공유 메모리(Shared Memory)** | 같은 메모리 영역을 함께 접근. 가장 빠르지만 동기화가 필요 |
| **메시지 큐(Message Queue)** | 커널이 관리하는 큐에 메시지를 넣고 꺼냄 |
| **세마포어(Semaphore)** | 공유 자원 접근을 조절하는 동기화 도구 |
| **소켓(Socket)** | 네트워크를 통해 다른 호스트의 프로세스와도 통신 |
| **파이프(Pipe)** | 한 방향 통신, 부모·자식 프로세스 사이. 이름 있는 파이프(FIFO)는 무관한 프로세스 사이도 가능 |
| **시그널(Signal)** | 사건 발생을 프로세스에 알림 |

**스레드(Thread)** 는 프로세스 안에서 실제로 실행되는 흐름이다. 프로세스와 나란히 놓고 보면 구분이 쉬운데, 프로세스는 **자원 할당 단위**이고 스레드는 **실행(CPU 스케줄링) 단위**다. 표로 정리하면 이렇다.

| 구분 | 내용 |
|---|---|
| 공유하는 것 | 같은 프로세스의 코드(Code)·데이터(Data)·힙(Heap) |
| 스레드마다 따로 갖는 것 | 스택(Stack), 레지스터, PC |
| 멀티스레드 장점 | 자원 공유로 메모리 절약, 생성·전환 비용이 작음, 응답성 향상 |
| 멀티스레드 단점 | 공유 자원 동기화 문제, 한 스레드 오류가 프로세스 전체에 영향 |
| 사용자 수준 스레드 | 라이브러리가 관리. 전환이 빠르지만 커널이 몰라서 하나가 블록되면 전체가 멈춤 |
| 커널 수준 스레드 | 커널이 직접 관리·스케줄링. 하나가 블록돼도 다른 스레드는 실행되지만 전환 부담이 큼 |

위 표에서 멀티스레드의 단점으로 공유 자원 동기화 문제를 들었다. 그래서 공유 자원을 여럿이 쓸 때 나오는 **동기화** 용어도 같이 정리해 둔다.

| 용어 | 뜻 |
|---|---|
| **임계 구역(Critical Section)** | 공유 자원에 접근하는 코드 영역. 한 번에 하나의 프로세스만 들어가야 함 |
| **상호 배제(Mutual Exclusion)** | 한 프로세스가 임계 구역에 있으면 다른 프로세스는 못 들어가게 하는 것 |
| **세마포어(Semaphore)** | 정수 변수와 P(wait)·V(signal) 연산으로 진입을 제어. 값이 1보다 크면 여러 개 진입 허용. 다익스트라가 제안 |
| **뮤텍스(Mutex)** | 잠금 하나(0/1)로 상호 배제만 보장 |

### 기출에서 이렇게 나왔다
- 21-1: 공유 메모리·소켓·세마포어·메시지 큐를 포함하는 기법의 총칭 한 줄 → **IPC**
- 20-4: 상태 설명 3개 → **준비 / 실행 / 대기**

### 답 쓸 때
IPC는 영문 약어로 쓰고, 상태 이름은 "준비·실행·대기"처럼 한글로 쓴다. 대기 상태는 교재에 따라 Blocked라고 적기도 하고 Waiting이라고 적기도 한다.

## 가상 메모리
출제: 없음

### 개념
**가상 메모리(Virtual Memory)** 란 보조기억장치 일부를 메모리처럼 쓰는 기법을 말한다. 왜 이렇게 하냐면, 그래야 물리 메모리보다 큰 프로그램도 실행할 수 있기 때문이다. 이때 프로세스는 **논리 주소(가상 주소)** 를 쓰고, 이 주소를 **물리 주소**로 바꿔 주는 일은 **MMU(Memory Management Unit)** 가 맡는다.

### 한눈에 구분
| 용어 | 뜻 |
|---|---|
| **페이지(Page) / 프레임(Frame)** | 논리 메모리 조각 / 물리 메모리 조각. 크기가 같다(페이징). 크기가 다른 논리 단위로 나누면 세그먼테이션 |
| **페이지 테이블(Page Table)** | 페이지 번호 → 프레임 번호 대응표 |
| **페이지 부재(Page Fault)** | 참조한 페이지가 메모리에 없어 디스크에서 가져와야 하는 사건. 참조될 때 올리는 방식이 요구 페이징 |
| **스와핑(Swapping)** | 페이지나 프로세스를 디스크의 스왑 영역으로 내보내고(Swap-out) 다시 들여오는(Swap-in) 일 |
| **지역성(Locality)** | 짧은 시간 동안 일부 주소만 집중해서 쓰는 성질. 최근 쓴 것을 또 쓰는 **시간 지역성**(반복문·스택·부프로그램·카운터), 가까운 주소를 이어 쓰는 **공간 지역성**(배열 순회·순차 코드 실행) |
| **스래싱(Thrashing)** | 프레임이 부족해 페이지 부재가 너무 잦아, 실행보다 교체에 시간을 더 쓰고 CPU 이용률이 급감하는 상태. 다중 프로그래밍 정도를 낮추거나 자주 참조하는 페이지 집합(**워킹 셋, Working Set**)을 메모리에 보장해 해결 |

메모리를 어떻게 나누느냐에 따라 생기는 단편화도 다르다. 페이징에서는 마지막 페이지가 덜 차는 내부 단편화가 생기고, 세그먼테이션에서는 빈 공간이 여기저기 흩어지는 외부 단편화가 생긴다. 페이지 교체 횟수 계산은 [계산] 페이지에서 풀이한다.

## 교착 상태 (Deadlock)
출제: 없음

### 개념
**교착 상태(Deadlock)** 는 둘 이상의 프로세스가 서로 상대가 가진 자원을 기다리느라 아무도 진행하지 못하는 상태다. 이 상태는 아래 네 조건이 **모두** 성립할 때 생긴다.

| 발생 조건 | 뜻 |
|---|---|
| **상호 배제(Mutual Exclusion)** | 자원을 한 번에 한 프로세스만 쓴다 |
| **점유와 대기(Hold and Wait)** | 자원을 가진 채 다른 자원을 기다린다 |
| **비선점(Non-preemption)** | 다른 프로세스의 자원을 강제로 빼앗지 못한다 |
| **환형 대기(Circular Wait)** | 대기 관계가 원을 이룬다 |

### 한눈에 구분
| 해결 방법 | 하는 일 |
|---|---|
| **예방(Prevention)** | 네 조건 중 하나를 미리 없앤다 |
| **회피(Avoidance)** | 자원을 줄 때마다 안전 상태가 유지되는지 확인하고, 불안전하면 주지 않는다. 대표가 **은행원 알고리즘(Banker's Algorithm)** |
| **발견(Detection)** | 자원 할당 그래프 등으로 교착 상태가 생겼는지 검사한다 |
| **회복(Recovery)** | 교착에 걸린 프로세스를 종료하거나 자원을 선점해 풀어 준다 |

아마 가장 헷갈리는 게 예방과 회피일 것이다. 지문에 "조건 하나를 제거"가 나오면 예방이고, "은행원·안전 상태"가 나오면 회피다.

예방은 네 조건을 하나씩 부정하는 식으로 없앤다. 상호 배제를 부정하려면 자원을 공유 가능하게 만들어야 하는데, 이건 대개 불가능하다. 점유와 대기는 필요한 자원을 한꺼번에 요청하게 해서 부정하고, 비선점은 기다려야 할 때 가진 자원을 내놓게 해서 부정한다. 환형 대기는 자원에 번호를 매겨 오름차순으로만 요청하게 하면 부정된다.

은행원 알고리즘은 이렇게 돌아간다. 먼저 프로세스마다 Need = Max − Allocation을 구한다. 그다음 Need ≤ Available인 프로세스를 하나씩 끝낸다고 가정하고, 끝낸 프로세스의 Allocation을 Available에 돌려준다. 이렇게 해서 모든 프로세스를 끝낼 수 있는 순서가 있으면 안전 상태이고, 이 순서를 안전 순서라고 한다.

## 주기억장치 배치 전략
출제: 없음

### 개념
주기억장치 배치 전략이란 새 프로그램을 주기억장치의 빈 공간(가용 공간) 가운데 어디에 넣을지 정하는 규칙을 말한다. 어떤 빈 공간을 고르느냐에 따라 세 가지로 나뉜다.

| 전략 | 넣는 곳 |
|---|---|
| **최초 적합(First Fit)** | 앞에서부터 찾다가 처음 만나는, 들어갈 수 있는 빈 공간 |
| **최적 적합(Best Fit)** | 들어간 뒤 남는 공간이 **가장 작은** 빈 공간 |
| **최악 적합(Worst Fit)** | 들어간 뒤 남는 공간이 **가장 큰** 빈 공간 |

예를 들어 빈 공간이 순서대로 5K, 15K, 10K, 25K 있고, 여기에 9K 프로그램을 넣는다고 해보자. 5K는 9K보다 작아서 처음부터 후보가 아니다. 그러면 최초 적합은 15K에 넣어 6K가 남고, 최적 적합은 10K에 넣어 1K가 남고, 최악 적합은 25K에 넣어 16K가 남는다. 이렇게 들어간 뒤 그 분할 안에 남는 공간(6K·1K·16K)을 **내부 단편화**라고 하고, 프로그램보다 작아서 아예 쓰지 못하는 빈 공간(이 예의 5K)을 **외부 단편화**라고 부른다. 필기에서는 "최악 적합으로 17K를 넣을 때 내부 단편화 크기"처럼 물었는데, 빈 공간이 20K·16K·8K·40K였으니 40K에 넣어 23K가 남는다.

## 디스크 스케줄링
출제: 없음

### 개념
디스크 스케줄링이란 디스크 헤드가 여러 트랙 요청을 어떤 순서로 처리할지 정하는 기법을 말한다. 순서를 따지는 이유는 헤드 이동 거리(탐색 시간)를 줄이기 위해서다.

| 기법 | 처리 순서 | 단서 |
|---|---|---|
| **FCFS** | 요청이 도착한 순서 | 공평하지만 이동이 많음 |
| **SSTF(Shortest Seek Time First)** | 현재 헤드에서 **가장 가까운** 트랙부터 | 먼 요청은 기아 발생 가능 |
| **SCAN** | 한 방향으로 끝까지 가며 처리하고 반대 방향으로 돌아옴 | 엘리베이터 알고리즘 |
| **C-SCAN** | 한 방향으로만 처리하고, 끝에 닿으면 처리 없이 시작점으로 돌아감 | 대기 시간이 고름 |
| **LOOK / C-LOOK** | SCAN / C-SCAN과 같지만 끝까지 가지 않고 마지막 요청이 있는 곳에서 방향을 바꿈 | SCAN의 개선 |

헤드 이동 거리는 처리 순서대로 이웃한 트랙 번호 차의 절댓값을 구해 모두 더하면 된다. 예를 들어 헤드가 53에 있고 요청이 98·183·37·122·14·124·65·67이라면, FCFS로 처리했을 때는 640이고 SSTF(65→67→37→14→98→122→124→183)로 처리했을 때는 236이다.
