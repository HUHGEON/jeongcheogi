# 운영체제

21개 회차 420문제 가운데 운영체제 이론은 14문제다. 프로세스 스케줄링이 5회차 6문제로 가장 많고, 그중 3문제는 도착·실행 시간 표를 주고 평균 대기시간을 구하는 계산이다(SRT 6.5는 24-2와 26-2에 같은 표로 두 번). 페이지 교체도 부재 횟수 계산으로 나왔다. 나머지는 UNIX 명령어·chmod·프로세스 상태·IPC처럼 상황 설명을 주고 용어나 명령어를 쓰는 형태다. 계산 절차는 [계산] 페이지에 있고, 여기서는 알고리즘을 고르는 단서와 용어만 정리한다.

## CPU 스케줄링 알고리즘
출제: 26-2, 25-2, 24-2, 22-3, 20-1
형태: 도착·실행 시간 표 → 평균 대기시간 계산, 설명 2~3개 → 영문 약어, HRN 우선순위 식 빈칸

### 개념
**CPU 스케줄링**은 준비 큐에 있는 프로세스 중 어느 것에 CPU를 줄지 정하는 일이다. 실행 중인 프로세스에서 CPU를 뺏을 수 있으면 **선점(Preemptive)**, 스스로 끝내거나 입출력을 요청할 때까지 기다리면 **비선점(Non-preemptive)**이다.

계산 문제에 쓰는 용어는 다음과 같다.

- **실행 시간(버스트 시간, Burst Time)**: 프로세스가 CPU를 쓰는 시간.
- **반환 시간(Turnaround Time)** = 종료 시각 − 도착 시각.
- **대기 시간(Waiting Time)** = 반환 시간 − 실행 시간. 준비 큐에서 기다린 시간의 합.
- **응답 시간(Response Time)**: 도착 후 처음 CPU를 받기까지의 시간.

고른 프로세스에 실제로 CPU를 넘기는 모듈이 **디스패처(Dispatcher)**이고, 이때 레지스터·PC를 저장하고 복원하는 것이 **문맥 교환(Context Switching)**이다.

### 한눈에 구분
| 알고리즘 | 선점 여부 | 고르는 기준 | 지문 단서 |
|---|---|---|---|
| **FCFS(First Come First Served)** | 비선점 | 먼저 도착한 순서 | FIFO, 긴 작업 뒤에 짧은 작업이 줄줄이 기다리는 호위 효과(Convoy Effect) |
| **SJF(Shortest Job First)** | 비선점 | **실행 시간이 가장 짧은** 프로세스 | 평균 대기시간이 가장 짧음, 긴 작업의 기아(Starvation) |
| **HRN(Highest Response-ratio Next)** | 비선점 | **우선순위 = (대기 시간 + 서비스 시간) / 서비스 시간**이 큰 것 | SJF의 기아를 보완, 오래 기다릴수록 우선순위 상승(에이징 효과) |
| **우선순위(Priority)** | 비선점·선점 모두 가능 | 우선순위 값 | 낮은 우선순위의 기아, 에이징(Aging)으로 해결 |
| **기한부(Deadline)** | 비선점 | 정해진 시간 안에 끝내야 하는 작업 | 제한 시간, 실시간 |
| **RR(Round Robin)** | 선점 | **시간 할당량(Time Quantum, Time Slice)**만큼 돌아가며 | 시분할 시스템, 할당량이 크면 FCFS와 같아지고 작으면 문맥 교환 부담 증가 |
| **SRT(Shortest Remaining Time)** | 선점 | **남은 실행 시간이 가장 짧은** 프로세스 | SJF의 선점형, 새 프로세스가 도착할 때마다 남은 시간 비교 |
| **다단계 큐(Multilevel Queue)** | 선점 | 프로세스 성격별로 여러 큐에 고정 배치 | 큐마다 다른 알고리즘, 큐 사이 이동 없음 |
| **다단계 피드백 큐(Multilevel Feedback Queue)** | 선점 | 큐 사이를 옮겨 다님 | 위 큐일수록 할당량이 짧고 아래로 갈수록 길어짐, 마지막 큐는 FCFS |

SJF와 SRT는 "짧은 것 먼저"가 같고, **선점 여부**만 다르다. 지문에 "실행 중 더 짧은 프로세스가 도착하면 교체"가 있으면 SRT다. RR은 "시간 할당량"이 단서다.

### 기출에서 이렇게 나왔다
- 26-2: 도착·버스트 시간 표 → SRT 평균 대기시간 **6.5** (24-2와 같은 표)
- 25-2: 도착·실행 시간 표, 할당량 4 → RR 평균 대기시간 **11.75**
- 25-2: 설명 2개 → **SJF / SRT**
- 24-2: 표 → SRT 평균 대기시간 **6.5**
- 22-3: 설명 3개 → 영문 약어 **SJF / RR / SRT**
- 20-1: HRN 우선순위 공식 빈칸 → **(대기 시간 + 서비스 시간) ÷ 서비스 시간**

### 답 쓸 때
알고리즘 이름은 영문 약어로 요구한다. HRN 식은 분자가 "대기 + 서비스", 분모가 "서비스"다. 간트 차트를 그려 평균 대기시간을 구하는 절차 → 풀이는 [계산] 페이지.

## 페이지 교체 알고리즘
출제: 24-3, 24-1
형태: 페이지 참조열과 프레임 수 → 페이지 부재 횟수

### 개념
빈 프레임이 없을 때 새 페이지를 올리려면 기존 페이지 하나를 내보내야 한다. 어느 것을 내보낼지 정하는 규칙이 **페이지 교체 알고리즘**이고, 요청한 페이지가 메모리에 없어 디스크에서 가져오는 사건이 **페이지 부재(Page Fault)**다. 문제는 참조열을 차례로 넣으며 부재가 몇 번 나는지 센다. 처음 프레임을 채우는 동안도 부재로 센다.

### 한눈에 구분
| 알고리즘 | 내보내는 페이지 | 비고 |
|---|---|---|
| **FIFO(First In First Out)** | **가장 먼저 들어온** 페이지 | 구현이 가장 단순. 프레임을 늘렸는데 부재가 오히려 느는 **벨레이디의 모순(Belady's Anomaly)** |
| **LRU(Least Recently Used)** | **가장 오랫동안 사용되지 않은** 페이지(마지막 참조 시점이 가장 오래된 것) | 카운터 또는 스택으로 구현. 참조될 때마다 "최근"으로 갱신된다는 점이 FIFO와 다름 |
| **LFU(Least Frequently Used)** | **참조 횟수가 가장 적은** 페이지 | 초기에 많이 쓰이고 안 쓰이는 페이지가 계속 남는 단점. 횟수가 같을 때의 처리 규칙을 문제에서 확인 |
| **OPT(Optimal)** | **앞으로 가장 오랫동안 사용되지 않을** 페이지 | 부재가 가장 적은 이론상 최적. 미래 참조를 알아야 해 실제 구현은 불가, 다른 알고리즘의 비교 기준 |
| **NUR(Not Used Recently)** | **참조 비트·변형 비트**가 (0, 0)인 페이지부터 | LRU의 근사. 비트 2개로 최근 사용 여부와 수정 여부를 봄 |
| **MFU(Most Frequently Used)** | 참조 횟수가 가장 많은 페이지 | LFU의 반대 |
| **SCR(Second Chance)** | FIFO 순서이되 참조 비트가 1이면 0으로 바꾸고 한 번 더 기회 | FIFO + 참조 비트 |

LRU와 LFU의 차이는 "언제"와 "몇 번"이다. LRU는 마지막으로 쓰인 시각, LFU는 지금까지 쓰인 횟수를 본다. 같은 참조열이라도 두 값이 다를 수 있으므로 문제가 둘 다 묻는다.

### 기출에서 이렇게 나왔다
- 24-3: 참조열 20개, 프레임 3 → LRU 페이지 부재 횟수 **12**
- 24-1: 참조열, 프레임 3 → LRU·LFU 페이지 부재 횟수 **6 / 6**

### 답 쓸 때
부재 횟수를 묻는지 적중 횟수를 묻는지 확인한다. 표를 그려 세는 절차 → 풀이는 [계산] 페이지.

## Unix/Linux 명령어와 UNIX 특징
출제: 25-3, 20-4
형태: 상황 설명 4개 → 보기에서 명령어 고르기, 운영체제 설명 → 이름

### 개념
명령어 문제는 "무엇을 하고 싶은가"를 문장으로 주고 명령어를 고르게 한다. 명령어 이름의 원래 영어 표현을 같이 외우면 상황 설명과 바로 이어진다.

### 한눈에 구분
| 상황 | 명령어 | 원래 뜻 |
|---|---|---|
| 지금 내가 있는 디렉터리 경로를 본다 | **pwd** | print working directory |
| 디렉터리 안의 파일 목록을 본다 | **ls** | list |
| 다른 디렉터리로 이동한다 | **cd** | change directory |
| 파일을 복사한다 | **cp** | copy |
| 파일을 이동하거나 이름을 바꾼다 | **mv** | move |
| 파일을 삭제한다 | **rm** | remove |
| 디렉터리를 만든다 | **mkdir** | make directory |
| 빈 디렉터리를 삭제한다 | **rmdir** | remove directory |
| 파일 내용을 화면에 출력한다 | **cat** | concatenate |
| 파일의 앞부분 몇 줄을 본다 | **head** | |
| 파일의 뒷부분 몇 줄을 본다 | **tail** | |
| 파일 안에서 문자열(패턴)을 찾는다 | **grep** | |
| 조건에 맞는 파일을 디렉터리에서 찾는다 | **find** | |
| 파일의 접근 권한을 바꾼다 | **chmod** | change mode |
| 파일의 소유자를 바꾼다 | **chown** | change owner |
| 실행 중인 프로세스 목록을 본다 | **ps** | process status |
| 프로세스에 시그널을 보내 종료한다 | **kill** | |
| 실행 중인 프로세스를 실시간으로 본다 | **top** | |
| 빈 파일을 만들거나 시간 정보를 갱신한다 | **touch** | |
| 문자열을 화면에 출력한다 | **echo** | |

**UNIX**의 특징은 시험 지문에 그대로 나온다.

- **다중 사용자(Multi-user)·다중 작업(Multi-tasking)**을 지원한다.
- 대부분이 **C 언어**로 작성되어 **이식성**이 높다.
- **계층적(트리) 파일 시스템**을 쓴다.
- 대화식 운영체제이고, 소스가 공개되어 Linux 등 파생 운영체제가 많다.
- 구조는 **커널(Kernel)** 과 **쉘(Shell)** 로 나뉜다. 커널은 프로세스·기억장치·파일·입출력 관리를 맡고, 쉘은 사용자 명령을 해석해 커널에 전달하는 **명령어 해석기**다(sh, csh, ksh, bash).

### 기출에서 이렇게 나왔다
- 25-3: 상황 설명 4개 → 보기에서 **pwd / ls / cd / cp**
- 20-4: 다중 사용자·다중 작업, C 언어, 계층적 파일 시스템 설명 → **UNIX**

### 답 쓸 때
명령어는 소문자 영문 그대로 쓴다. "현재 위치"는 pwd, "목록"은 ls, "이동"은 cd, "복사"는 cp로 바로 잇는다.

## chmod와 파일 권한
출제: 23-3, 20-2
형태: 사용자·그룹·기타의 권한 요구 → 명령어와 8진수 세 자리

### 개념
Unix 파일 권한은 **소유자(u, user)**, **그룹(g, group)**, **기타(o, other)** 세 대상에게 각각 **읽기(r)·쓰기(w)·실행(x)** 을 줄지 말지로 정한다. `ls -l`의 맨 앞 10자리 중 첫 글자는 종류(`-` 파일, `d` 디렉터리, `l` 링크)이고, 나머지 9자리가 `rwxrwxrwx` 순서로 u·g·o 권한이다.

**chmod(change mode)** 는 이 권한을 바꾸는 명령어다. 숫자 모드에서는 r=4, w=2, x=1을 더한 값을 u·g·o 순서로 세 자리 8진수로 쓴다.

### 한눈에 구분
| 8진수 | 비트 | 권한 |
|---|---|---|
| 7 | 111 | rwx |
| 6 | 110 | rw- |
| 5 | 101 | r-x |
| 4 | 100 | r-- |
| 3 | 011 | -wx |
| 2 | 010 | -w- |
| 1 | 001 | --x |
| 0 | 000 | --- |

기호 모드는 대상(u/g/o/a) + 연산(+ 추가, − 제거, = 지정) + 권한(r/w/x)으로 쓴다. 예: `chmod u+x f`, `chmod go-w f`. 디렉터리에서 x는 안으로 들어갈 수 있는 권한, r은 목록을 볼 수 있는 권한이다. `-R` 옵션은 하위 디렉터리까지 적용한다. 소유자를 바꾸는 명령은 **chown**이다.

### 기출에서 이렇게 나왔다
- 23-3: 사용자는 모든 권한, 그룹은 읽기·실행, 기타는 실행만 → **chmod 751**
- 20-2: 같은 권한 요구 → **751**

### 답 쓸 때
"명령어까지 쓰라"면 `chmod 751 파일명` 형태로, 숫자만 요구하면 751만 쓴다. 권한 문장을 8진수로 바꾸는 절차 → 풀이는 [계산] 페이지.

## 프로세스 상태 전이와 IPC
출제: 21-1, 20-4
형태: 상태 설명 3개 → 이름, IPC 기법을 나열한 한 줄 → 용어

### 개념
**프로세스(Process)** 는 실행 중인 프로그램이다. 운영체제는 프로세스마다 **PCB(Process Control Block)** 에 상태·PC·레지스터·우선순위·메모리 정보를 보관한다. 프로세스의 상태는 다섯 가지다.

- **생성(New)**: 만들어졌지만 아직 준비 큐에 들어가지 않음.
- **준비(Ready)**: CPU만 받으면 실행할 수 있는 상태. 준비 큐에서 대기.
- **실행(Running)**: CPU를 할당받아 명령을 수행 중.
- **대기(Waiting, Blocked)**: 입출력 완료 같은 사건을 기다리는 상태. CPU가 비어도 실행 못 함.
- **종료(Terminated)**: 실행이 끝나 자원을 반납.

```mermaid
제목: 대기에서 실행으로 바로 가는 화살표는 없다. 사건이 끝나면 준비로 돌아간다
stateDiagram-v2
  direction TB
  state "생성" as New
  state "준비" as Ready
  state "실행" as Run
  state "대기" as Wait
  state "종료" as Done
  [*] --> New
  New --> Ready: 승인
  Ready --> Run: 디스패치
  Run --> Ready: 타이머 만료
  Run --> Wait: 블록 (입출력 요청)
  Wait --> Ready: 깨움 (입출력 완료)
  Run --> Done: 종료
  Done --> [*]
```

### 한눈에 구분
| 전이 | 이름 | 일어나는 때 |
|---|---|---|
| 생성 → 준비 | 승인(Admit) | 메모리에 올라감 |
| 준비 → 실행 | **디스패치(Dispatch)** | 스케줄러가 CPU를 줌 |
| 실행 → 준비 | **타이머 만료(Timer Run Out)**, 선점 | 할당량 소진 또는 더 급한 프로세스 등장 |
| 실행 → 대기 | **블록(Block)** | 입출력 요청 등 사건을 기다리기 시작 |
| 대기 → 준비 | **깨움(Wake Up)** | 기다리던 사건이 완료 |
| 실행 → 종료 | 종료(Exit) | 실행 완료 |

대기에서 바로 실행으로 가는 전이는 없다. 사건이 끝나면 준비 큐로 돌아가 다시 CPU를 기다린다.

**IPC(Inter-Process Communication)** 는 프로세스끼리 데이터를 주고받거나 동기화하는 기법의 총칭이다.

| 기법 | 특징 |
|---|---|
| **공유 메모리(Shared Memory)** | 같은 메모리 영역을 함께 접근. 가장 빠르지만 동기화가 필요 |
| **메시지 큐(Message Queue)** | 커널이 관리하는 큐에 메시지를 넣고 꺼냄 |
| **세마포어(Semaphore)** | 공유 자원 접근을 조절하는 동기화 도구 |
| **소켓(Socket)** | 네트워크를 통해 다른 호스트의 프로세스와도 통신 |
| **파이프(Pipe)** | 한 방향 통신, 부모·자식 프로세스 사이. 이름 있는 파이프(FIFO)는 무관한 프로세스 사이도 가능 |
| **시그널(Signal)** | 사건 발생을 프로세스에 알림 |

### 기출에서 이렇게 나왔다
- 21-1: 공유 메모리·소켓·세마포어·메시지 큐를 포함하는 기법의 총칭 한 줄 → **IPC**
- 20-4: 상태 설명 3개 → **준비 / 실행 / 대기**

### 답 쓸 때
IPC는 영문 약어로 쓴다. 상태 이름은 "준비·실행·대기" 한글로 쓴다. 대기는 교재에 따라 Blocked 또는 Waiting으로 적는다.

## 가상 메모리
출제: 없음

### 개념
**가상 메모리(Virtual Memory)** 는 물리 메모리보다 큰 프로그램을 실행할 수 있도록 보조기억장치 일부를 메모리처럼 쓰는 기법이다. 프로세스는 **논리 주소(가상 주소)** 를 쓰고, **MMU(Memory Management Unit)** 가 이를 **물리 주소**로 바꾼다.

### 한눈에 구분
| 용어 | 뜻 |
|---|---|
| **페이지(Page) / 프레임(Frame)** | 논리 메모리 조각 / 물리 메모리 조각. 크기가 같다(페이징). 크기가 다른 논리 단위로 나누면 세그먼테이션 |
| **페이지 테이블(Page Table)** | 페이지 번호 → 프레임 번호 대응표 |
| **페이지 부재(Page Fault)** | 참조한 페이지가 메모리에 없어 디스크에서 가져와야 하는 사건. 참조될 때 올리는 방식이 요구 페이징 |
| **스와핑(Swapping)** | 페이지나 프로세스를 디스크의 스왑 영역으로 내보내고(Swap-out) 다시 들여오는(Swap-in) 일 |
| **지역성(Locality)** | 짧은 시간 동안 일부 주소만 집중해서 쓰는 성질. 최근 쓴 것을 또 쓰는 **시간 지역성**, 가까운 주소를 이어 쓰는 **공간 지역성** |
| **스래싱(Thrashing)** | 프레임이 부족해 페이지 부재가 너무 잦아, 실행보다 교체에 시간을 더 쓰고 CPU 이용률이 급감하는 상태. 다중 프로그래밍 정도를 낮추거나 자주 참조하는 페이지 집합(**워킹 셋, Working Set**)을 메모리에 보장해 해결 |

페이징은 마지막 페이지가 덜 차는 내부 단편화, 세그먼테이션은 빈 공간이 흩어지는 외부 단편화가 생긴다. 페이지 교체 횟수 계산 → 풀이는 [계산] 페이지.
