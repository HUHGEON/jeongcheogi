# 계산 문제 풀이법

실기에서 "값을 직접 구하는" 문제는 서브넷·IP, 프로세스 스케줄링, 페이지 교체, 관계대수 결과 표, LoC, Fan-in/out, chmod다. 2022년 이후 서브넷·IP 계산은 7개 회차에 나왔고, 2024년 이후 스케줄링·페이지 교체가 4개 회차에 나왔다. 아래 예제의 숫자는 모두 실제 기출과 같은 값이고, 결과는 프로그램으로 다시 계산해 확인했다.

## 서브넷 1. 마스크·프리픽스·블록 크기 대응표
출제: 26-2, 26-1, 25-2, 25-1, 24-1, 22-3, 22-2
형태: 호스트 IP + 서브넷 마스크(또는 /n) → 네트워크 주소, 브로드캐스트 주소, 사용 가능 호스트 수, 할당 범위

### 개념
IP 주소 32비트 중 앞 n비트가 네트워크, 뒤 32−n비트가 호스트다. `/n`을 **프리픽스 길이**라 하고, 서브넷 마스크는 앞 n비트가 1인 값이다. 마지막으로 1이 섞인 옥텟만 계산하면 된다.

| 프리픽스 | 마스크(해당 옥텟) | 블록 크기 = 256 − 마스크 | 주소 개수 | 사용 가능 호스트 |
|---|---|---|---|---|
| /24 | 0 | 256 | 256 | 254 |
| /25 | 128 | 128 | 128 | 126 |
| /26 | 192 | 64 | 64 | 62 |
| /27 | 224 | 32 | 32 | 30 |
| /28 | 240 | 16 | 16 | 14 |
| /29 | 248 | 8 | 8 | 6 |
| /30 | 252 | 4 | 4 | 2 |
| /22 | 252 (세 번째 옥텟) | 4 (세 번째 옥텟 단위) | 1024 | 1022 |
| /23 | 254 (세 번째 옥텟) | 2 (세 번째 옥텟 단위) | 512 | 510 |

주소 개수 = 2^(32−n). 사용 가능 호스트 = 주소 개수 − 2 (네트워크 주소와 브로드캐스트 주소 제외).

```bits
제목: 25-2 기출 223.13.234.132/26. 네 번째 옥텟 앞 2비트까지 네트워크라서 132가 128로 내려간다
223.13.234.132/26
```

### 풀이 절차
1. 마스크에서 255가 아닌 옥텟을 찾는다. 블록 크기 = 256 − 그 옥텟 값.
2. 호스트 IP의 같은 자리 옥텟을 블록 크기로 나눈 몫 × 블록 크기 = **네트워크 주소**의 그 옥텟. (뒤 옥텟은 0)
3. 네트워크 주소 + 블록 크기 − 1 = **브로드캐스트 주소**의 그 옥텟. (뒤 옥텟은 255)
4. 사용 가능 호스트 = 블록 크기 − 2 (마지막 옥텟이 아니면 블록 크기 × 256 − 2).
5. 할당 가능 범위 = 네트워크 주소 + 1 ~ 브로드캐스트 주소 − 1.

### 예제 (25-2 / 22-2 기출 수치)
- 호스트 223.13.234.132, 마스크 255.255.255.192
  - 블록 = 256 − 192 = 64. 132 ÷ 64 = 2 → 2 × 64 = 128.
  - 네트워크 주소 **223.13.234.128**, 브로드캐스트 223.13.234.191, 호스트 **62**개, 할당 범위 .129 ~ .190
- 호스트 192.168.1.150, 마스크 255.255.255.224
  - 블록 = 32. 150 ÷ 32 = 4 → 128. 네트워크 **192.168.1.128**, 브로드캐스트 .159, 호스트 **30**개

### 답 쓸 때
- "사용 가능한 호스트 수"는 −2를 한 값, "주소 개수"는 −2 하지 않은 값이다. 문제 문장을 확인한다.
- 네트워크 주소를 CIDR로 쓰라고 하면 `192.168.1.128/27`처럼 프리픽스를 붙인다.

## 서브넷 2. 세 번째 옥텟에서 끊기는 경우와 CIDR 표기
출제: 26-1, 25-1
형태: 마스크 255.255.254.0 / 255.255.252.0 → 네트워크 주소를 CIDR로, 또는 같은 네트워크에 속한 IP 모두 고르기

### 풀이 절차
마스크의 세 번째 옥텟이 255가 아니면 블록 크기는 세 번째 옥텟 단위다. 네 번째 옥텟은 0(네트워크) 또는 255(브로드캐스트)가 된다.

### 예제 (26-1 기출 수치)
호스트 A 192.168.11.20, 호스트 B 192.168.12.200, 마스크 255.255.254.0 (/23)
- 블록 = 256 − 254 = 2. 세 번째 옥텟을 2로 나눈 몫 × 2.
- A: 11 ÷ 2 = 5 → 10 → **192.168.10.0/23** (범위 10.0 ~ 11.255)
- B: 12 ÷ 2 = 6 → 12 → **192.168.12.0/23** (범위 12.0 ~ 13.255)

```bits
제목: 26-1 기출 192.168.11.20/23. 세 번째 옥텟의 마지막 비트가 호스트 쪽이라 11이 10으로 내려간다
192.168.11.20/23
```

### 예제 (25-1 기출 수치)
192.168.35.10, 마스크 255.255.252.0 (/22). 블록 = 4. 35 ÷ 4 = 8 → 32. 네트워크 192.168.32.0, 브로드캐스트 192.168.35.255. 범위가 32.0 ~ 35.255이므로 192.168.32.19, 33.138, 34.1, 35.50, 35.200은 **모두 같은 네트워크**다(기출 답: 보기 1~5 전부).

## 서브넷 3. FLSM 분할
출제: 22-3
형태: /24 네트워크를 n개의 서브넷으로 나눌 때 k번째 서브넷의 네트워크/브로드캐스트 주소

### 풀이 절차
1. n개로 나누려면 2^b ≥ n인 최소 b비트를 호스트 부분에서 빌린다. (3개 → b=2, 4개 생김)
2. 새 프리픽스 = 원래 프리픽스 + b. 블록 크기 = 2^(32−새 프리픽스)… 마지막 옥텟 기준으로는 256 ÷ 2^b.
3. k번째 서브넷의 네트워크 주소 = (k−1) × 블록, 브로드캐스트 = k × 블록 − 1.

### 예제 (22-3 기출 수치)
234.122.1.0/24를 3개 서브넷으로 FLSM 분할. b = 2 → /26, 블록 64.
- 1번째 0 ~ 63, 2번째 64 ~ 127, 3번째 128 ~ 191, (4번째 192 ~ 255)
- 두 번째 서브넷의 브로드캐스트 주소 = **234.122.1.127**

## 서브넷 4. 주소 개수에서 프리픽스 길이 거꾸로 구하기
출제: 26-2
형태: 서브넷 범위를 주고 "프리픽스 비트 길이를 쓰시오"

### 풀이 절차
범위에 들어 있는 주소 개수를 센다 → 2^h개면 호스트 비트 h → 프리픽스 = 32 − h.

### 예제 (26-2 기출 수치)
10.0.0.0/27을 10.0.0.0 ~ 10.0.0.15와 10.0.0.16 ~ 10.0.0.31로 나눴다. 각 서브넷은 16개 주소 = 2^4 → 호스트 비트 4 → 프리픽스 **28**.

## 서브넷 5. 라우터 인터페이스에 할당 가능한 IP 고르기
출제: 26-2, 24-1
형태: 라우터 그림에 몇몇 인터페이스의 IP/프리픽스만 적혀 있고, 나머지 인터페이스에 들어갈 IP를 보기에서 고르기

### 풀이 절차
1. 같은 링크(같은 선)로 연결된 두 인터페이스는 **같은 네트워크**에 있어야 한다.
2. 적혀 있는 IP와 프리픽스로 그 링크의 네트워크 범위를 구한다(서브넷 1·2 절차).
3. 보기 중 그 범위 안에 있으면서 **네트워크 주소도 브로드캐스트 주소도 아닌** 것을 고른다.

### 예제 (24-1 = 26-2 기출 수치)
- ① 192.168.35.3/24와 연결된 ②: 192.168.35.0/24 범위(35.1 ~ 35.254) → 보기 중 **192.168.35.72** (192.168.35.0은 네트워크 주소라 불가)
- ③ 129.200.10.16/22와 연결된 ④: 블록 4, 10 ÷ 4 = 2 → 129.200.8.0/22 범위(8.0.1 ~ 11.254) → **129.200.8.249** (129.200.8.0은 네트워크 주소라 불가)
- ⑥ 192.168.36.24/24와 연결된 ⑤: **192.168.36.249** (192.168.36.0 불가)

제목: 같은 선으로 이어진 두 인터페이스는 같은 네트워크에 있다 (24-1·26-2 기출 수치)

## 프로세스 스케줄링 평균 대기시간
출제: 26-2, 25-2, 24-2, 22-3, 20-1
형태: 도착 시간·실행(서비스, 버스트) 시간 표 → 특정 알고리즘의 평균 대기시간. HRN은 우선순위 식 빈칸

### 공통 규칙
- **대기시간 = 종료 시각 − 도착 시각 − 실행 시간** (반환시간 = 종료 − 도착)
- 간트 차트를 그리면서 "지금 CPU를 누가 잡는가"만 결정하면 된다.
- 평균 = 각 프로세스 대기시간 합 ÷ 프로세스 수. 소수로 답한다(6.5, 11.75처럼).

### 알고리즘별 선택 규칙
| 알고리즘 | 선점 | 다음에 실행할 프로세스 |
|---|---|---|
| FCFS(FIFO) | 비선점 | 먼저 도착한 것 |
| SJF | 비선점 | 도착해 있는 것 중 실행 시간이 가장 짧은 것. 끝날 때까지 안 뺏김 |
| SRT | 선점 | 매 순간 **남은** 시간이 가장 짧은 것. 더 짧은 것이 도착하면 즉시 교체 |
| RR | 선점 | 큐 순서대로 시간 할당량(q)만큼. 못 끝내면 큐 맨 뒤로 |
| HRN | 비선점 | 우선순위 = (대기시간 + 서비스시간) ÷ 서비스시간 이 가장 큰 것 |

RR에서 할당량이 끝나는 순간 새 프로세스가 도착해 있으면, **새로 도착한 프로세스가 먼저 큐에 들어가고** 밀려난 프로세스는 그 뒤에 선다. 기출 답(11.75)은 이 순서를 따른다.

### 예제: SRT (24-2 = 26-2 기출 수치, 답 6.5)
| 프로세스 | 도착 | 실행 |
|---|---|---|
| P1 | 0 | 8 |
| P2 | 1 | 4 |
| P3 | 2 | 9 |
| P4 | 3 | 5 |

1. t=0 P1 시작(남은 8). t=1 P2 도착(4 < 7) → P2로 교체.
2. t=2 P3(9), t=3 P4(5) 도착하지만 P2 남은 시간이 더 짧다. P2는 t=5에 끝.
3. t=5 남은 시간: P1 7, P3 9, P4 5 → P4 실행, t=10 끝.
4. t=10 P1(7) 실행, t=17 끝. 마지막 P3, t=26 끝.
5. 대기: P1 = 17 − 0 − 8 = 9, P2 = 5 − 1 − 4 = 0, P3 = 26 − 2 − 9 = 15, P4 = 10 − 3 − 5 = 2. 합 26 ÷ 4 = **6.5**

```gantt
제목: SRT 간트 차트. 대기 = 종료 - 도착 - 실행 = P1 9, P2 0, P3 15, P4 2 → 평균 6.5
P1 0-1
P2 1-5
P4 5-10
P1 10-17
P3 17-26
```

### 예제: RR, q = 4 (25-2 기출 수치, 답 11.75)
같은 표. 간트: P1(0~4) → P2(4~8, 끝) → P3(8~12) → P4(12~16) → P1(16~20, 끝) → P3(20~24) → P4(24~25, 끝) → P3(25~26, 끝)
- t=4에 P1이 밀려날 때 이미 P2, P3, P4가 도착해 있으므로 큐는 P2, P3, P4, P1 순.
- 대기: P1 = 20 − 0 − 8 = 12, P2 = 8 − 1 − 4 = 3, P3 = 26 − 2 − 9 = 15, P4 = 25 − 3 − 5 = 17. 합 47 ÷ 4 = **11.75**

참고로 같은 표를 SJF(비선점)로 풀면 P1 → P2 → P4 → P3 순이고 평균 7.75, FCFS는 8.75다.

```gantt
제목: RR(q=4) 간트 차트. 대기 = P1 12, P2 3, P3 15, P4 17 → 평균 11.75
P1 0-4
P2 4-8
P3 8-12
P4 12-16
P1 16-20
P3 20-24
P4 24-25
P3 25-26
```

### HRN 우선순위 (20-1 기출)
우선순위 = **(대기시간 + 서비스시간) ÷ 서비스시간**. 값이 큰 것부터 실행한다. 대기가 길수록, 서비스가 짧을수록 커져서 SJF의 기아 문제를 줄인다. 예: 대기 5, 서비스 4면 (5 + 4) ÷ 4 = 2.25.

## 페이지 교체 알고리즘 페이지 부재 횟수
출제: 24-3, 24-1
형태: 페이지 참조 순서와 프레임 수 → LRU(또는 LFU, FIFO)의 페이지 부재 횟수

### 공통 규칙
- 프레임이 비어 있을 때 들어가는 것도 **부재(fault)로 센다**.
- 참조한 페이지가 프레임에 있으면 부재 아님(hit). 없으면 부재이고, 프레임이 꽉 찼으면 하나를 내보낸다.
- 표를 그린다: 열 = 참조 순서, 행 = 프레임. 부재 난 열에 표시.

### 무엇을 내보내는가
| 알고리즘 | 교체 대상 |
|---|---|
| FIFO | 가장 먼저 들어온 페이지 |
| LRU | 가장 오랫동안 **사용되지 않은** 페이지 (마지막 참조 시점이 가장 오래된 것) |
| LFU | 참조 **횟수**가 가장 적은 페이지 (같으면 보통 LRU 기준) |
| OPT | 앞으로 가장 늦게 쓰이거나 다시 안 쓰이는 페이지 |
| NUR | 참조 비트·변경 비트가 (0,0)인 것부터 |

LRU는 hit가 나도 "최근 사용" 순서가 바뀐다는 점이 FIFO와의 차이다.

### 예제 (24-1 기출 수치, 프레임 3, 답 LRU 6 / LFU 6)
참조: 1, 2, 3, 1, 2, 4, 1, 2, 5, 7

LRU:
| 참조 | 1 | 2 | 3 | 1 | 2 | 4 | 1 | 2 | 5 | 7 |
|---|---|---|---|---|---|---|---|---|---|---|
| 프레임 | 1 | 1 2 | 1 2 3 | 1 2 3 | 1 2 3 | 1 2 4 | 1 2 4 | 1 2 4 | 1 2 5 | 1 2 7 |
| 부재 | F | F | F | | | F(3 교체) | | | F(4 교체) | F(5 교체) |

부재 **6**. (4가 들어올 때 가장 오래 안 쓴 것은 3, 5가 들어올 때는 4, 7이 들어올 때는 5.)
LFU도 같은 참조열에서 **6**이다(1과 2는 횟수가 많아 끝까지 남고, 3·4·5가 차례로 나간다). FIFO는 8, OPT는 6.

### 예제 (24-3 기출 수치, 프레임 3, LRU 답 12)
참조: 7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1
부재가 나는 자리: 7, 0, 1, 2, 3, 4, 2, 3, 0, 1, 0, 7 → **12**. (hit는 0(5번째), 0(7번째), 3(12번째), 2(13번째), 2(15번째), 1(17번째), 0(19번째), 1(20번째))

## 관계대수 결과 표
출제: 25-3, 25-2, 22-2
형태: 테이블을 주고 π, ÷ 등의 연산 결과 표를 빈칸으로 채우게 함. 결과 표의 **첫 칸은 속성 이름**인 경우가 많다

### 연산별 결과 만드는 법
| 연산 | 기호 | 결과 |
|---|---|---|
| 셀렉트 | σ조건(R) | 조건을 만족하는 **행**만. 열은 그대로 |
| 프로젝트 | π속성(R) | 지정한 **열**만. 중복 행은 **하나로 합친다** |
| 조인 | R ⋈ S | 공통 속성 값이 같은 행끼리 붙인다. 자연 조인은 공통 열을 한 번만 |
| 디비전 | R ÷ S | S의 **모든** 값과 짝지어진 R의 나머지 속성 값 |
| 합집합 | R ∪ S | 두 표를 합치고 중복 제거 |
| 차집합 | R − S | R에만 있는 행 |
| 교집합 | R ∩ S | 둘 다 있는 행 |
| 카티션 프로덕트 | R × S | 모든 행 조합. 행 수 = R 행 수 × S 행 수 |

### 예제: 프로젝션 (25-2 기출)
EMPLOYEE(EMPNO, NAME, DEPT, TTL)에 π_TTL → 결과 표는 **TTL** 열 하나, 값은 부장·과장·대리. 결과 표 빈칸이 4개면 첫 칸은 속성 이름 TTL이다.

### 예제: 디비전 (25-3 기출)
R(A, B) = {(a1, b1), (a2, b2), (a1, b3)}, S(B) = {b1, b3}
1. S의 속성(B)을 R에서 지운 나머지 속성(A)의 후보: a1, a2.
2. a1은 b1, b3 **둘 다** 가지고 있다 → 포함. a2는 b2만 있다 → 제외.
3. 결과 표: 속성 **A**, 값 **a1**. 나머지 빈칸은 비어 있음(기출은 x로 표기).

## 카디널리티·차수 세기
출제: 24-2, 21-1
형태: 테이블 하나 → 카디널리티와 차수

- **카디널리티(Cardinality) = 튜플(행) 수**, 제목 행은 세지 않는다.
- **차수(Degree) = 속성(열) 수**.
- 기출 두 번 모두 5행 4열 표 → 카디널리티 5, 차수 4.

## LoC 기반 비용·기간
출제: 20-1
형태: 총 라인 수, 인원, 1인당 월 생산성 → 개발 기간(개월)

- 노력(인월, M/M) = 총 LoC ÷ 1인당 월 생산성
- **개발 기간 = 노력 ÷ 투입 인원 = 총 LoC ÷ (인원 × 1인당 월 생산성)**
- 비용 = 노력 × 1인당 월 단가
- 예(20-1): 36,000 ÷ (6 × 300) = **20개월**

## Fan-in / Fan-out 세기
출제: 22-2, 20-1
형태: 모듈 호출 다이어그램 → 특정 모듈의 Fan-in·Fan-out, 또는 Fan-in이 2 이상인 모듈 찾기

- **Fan-in = 그 모듈을 호출하는(들어오는 화살표) 모듈 수**, **Fan-out = 그 모듈이 호출하는(나가는 화살표) 모듈 수**.
- 화살표 방향이 "호출 방향"인지 그림 설명을 먼저 확인한다.
- Fan-in이 높으면 재사용이 잘 된 공통 모듈, Fan-out이 높으면 한 모듈이 너무 많은 일을 시키는 것이라 줄이는 쪽이 좋다.

## chmod 8진수
출제: 23-3, 20-2
형태: "사용자는 모든 권한, 그룹은 읽기·실행, 그 외는 실행만" → `chmod ( ) 파일`

- 자리: **사용자(u) 그룹(g) 기타(o)** 순으로 한 자리씩.
- 값: r = 4, w = 2, x = 1. 합산.
- 모든 권한 rwx = 7, 읽기·실행 r-x = 5, 실행만 --x = 1 → **751**
- 거꾸로: 644 = rw- r-- r--, 755 = rwx r-x r-x.

## 진법 변환
출제: 없음 (코드 문제의 %x 출력, 2진수 변환 코드 빈칸에서 필요)

- 10진 → 2진: 2로 나눈 나머지를 거꾸로 읽는다. 10 → 1010.
- 2진 → 16진: 4비트씩 끊는다. 0010 0000 → 0x20. (26-1 C 문제: 32를 %x로 출력하면 20)
- 10진 → 8진: 8로 나눈 나머지. 16진 한 자리는 4비트, 8진 한 자리는 3비트.
