# 신기술

신기술 용어는 21개 회차에서 단독 문제로 9개 정도 나왔고, 2023년 이후로는 클라우드 서비스 모델(23-3)과 애드혹 네트워크(24-3) 두 번뿐이다. 형태는 전부 "설명 2~3줄 → 용어 쓰기"다. 같은 설명이 그대로 다시 나오는 경우가 있어(애드혹 21-2와 24-3), 출제된 용어는 지문 단서를 그대로 외우고 나머지는 한 줄 정의와 단서 키워드만 알아 둔다.

## DB·빅데이터 신기술
출제: 22-3, 20-4, 20-2, 20-1
형태: 설명 2~3줄 → 용어

### 개념
빅데이터 처리는 **수집 → 저장 → 처리 → 분석 → 활용** 순서로 진행된다. 하둡 생태계 도구는 이 단계 중 어디를 맡는지로 구분하고(척와는 수집, HDFS는 저장, 맵리듀스는 처리), 나머지 용어는 "데이터를 어떻게 다루는가"로 구분하면 된다.

### 한눈에 구분
| 용어 | 한 줄 정의 | 지문 단서 |
|---|---|---|
| **하둡(Hadoop)** | 대용량 데이터를 여러 대의 범용 컴퓨터에 나눠 저장·처리하는 오픈 소스 분산 컴퓨팅 프레임워크 | "분산 컴퓨팅", "HDFS", "MapReduce", "오픈 소스", "범용 하드웨어 클러스터" |
| **HDFS(Hadoop Distributed File System)** | 하둡의 분산 파일 시스템. 파일을 블록으로 나눠 여러 노드에 복제 저장 | "블록 단위 복제", "네임노드·데이터노드" |
| **맵리듀스(MapReduce)** | 데이터를 키-값으로 나눠 처리(Map)한 뒤 모아서 집계(Reduce)하는 분산 병렬 처리 모델 | "Map", "Reduce", "병렬 처리" |
| **척와(Chukwa)** | 분산 환경의 로그 데이터를 수집해 HDFS에 저장하는 도구 | "로그 수집", "모니터링" |
| **스쿱(Sqoop)** | 관계형 DB와 하둡 사이에서 데이터를 옮기는 도구 | "RDBMS ↔ 하둡", "가져오기·내보내기" |
| **스크래피(Scrapy)** | 파이썬으로 만든 웹 크롤링 프레임워크 | "웹 크롤링", "Python" |
| **데이터 마이닝(Data Mining)** | 대용량 데이터에서 숨은 패턴·규칙·상관관계를 찾아내는 기법 | "대용량 데이터", "패턴·규칙 발견", "예측" |
| **데이터 웨어하우스(Data Warehouse)** | 의사결정을 위해 여러 운영 시스템의 데이터를 주제별로 통합해 모아 둔 저장소 | "주제 지향", "통합", "시계열", "비휘발성" |
| **데이터 마트(Data Mart)** | 특정 부서·주제용으로 웨어하우스에서 떼어 낸 소규모 저장소 | "부서 단위", "소규모 웨어하우스" |
| **메타데이터(Metadata)** | 데이터를 설명하는 데이터 | "데이터에 대한 데이터", "구조·속성 정보" |
| **디지털 아카이빙(Digital Archiving)** | 디지털 정보를 장기 보존하기 위해 수집·변환·저장하는 것 | "장기 보존", "디지털화" |
| **마이데이터(MyData)** | 개인이 자기 데이터의 주체가 되어 열람·전송·활용을 직접 통제하는 것 | "정보 주체", "개인이 통제", "제3자 전송" |
| **LOD(Linked Open Data)** | 공개 데이터(Open Data)를 웹에서 서로 연결(Linked Data)해 누구나 참조할 수 있게 한 것 | "Linked Data + Open Data", "URI로 연결", "RDF" |
| **다크 데이터(Dark Data)** | 수집·저장은 되지만 분석되거나 활용되지 않은 채 쌓여 있는 데이터 | "저장만 되고 활용 안 됨", "방치", "비용만 발생" |
| **NoSQL(Not Only SQL)** | 고정 스키마·조인 없이 키-값·문서·컬럼·그래프 형태로 대용량 데이터를 수평 확장해 저장하는 비관계형 DB | "비관계형", "스키마 없음", "수평 확장", "BASE" |

참고로 빅데이터의 특징은 흔히 **3V(Volume 양, Velocity 속도, Variety 다양성)** 로 요약한다.

### 용어 하나씩 보기
표의 용어를 다 똑같이 외울 필요는 없다. 아래는 기출 정답으로 나온 용어 네 개와, 그 옆에서 같이 헷갈리는 웨어하우스·마트만 따로 꺼내 본 것이다.

#### 1. 하둡 (Hadoop)
- 대용량 데이터를 여러 대의 범용 컴퓨터에 나눠 저장·처리하는 오픈 소스 분산 컴퓨팅 프레임워크
- 저장 담당 **HDFS**: 파일을 블록으로 나눠 여러 노드에 복제 저장
- 처리 담당 **맵리듀스**: 키-값으로 나눠 처리(Map)한 뒤 모아서 집계(Reduce)
- 지문 단서: "분산 컴퓨팅", "HDFS", "MapReduce", "범용 하드웨어 클러스터"

예를 들어 서버 한 대에 다 담기지 않는 로그 파일이 있다고 해보자. 하둡에서는 이 파일을 블록으로 잘라 여러 노드에 복제해 저장하고, 집계할 때도 각 노드가 자기 몫을 동시에 처리한 뒤 결과만 모은다.

20-4 지문은 "분산 컴퓨팅, HDFS, MapReduce"를 한꺼번에 주었다. HDFS와 맵리듀스는 하둡을 이루는 부품이라, 셋이 같이 보이면 답은 전체 이름인 하둡이다.

#### 2. 데이터 마이닝 (Data Mining)
- 대용량 데이터에서 숨은 패턴·규칙·상관관계를 **찾아내는** 기법
- 지문 단서: "대용량 데이터", "패턴·규칙 발견", "예측"

쇼핑몰의 몇 년 치 구매 기록을 뒤져 "이 상품을 산 사람은 저 상품도 같이 산다" 같은 규칙을 뽑아내고, 그 규칙으로 다음 구매를 예측한다면 그게 데이터 마이닝이다.

데이터를 쌓아 두는 일이 아니라, 이미 쌓인 데이터에서 규칙을 캐내는 일이다. 이름의 Mining도 광산에서 캐낸다는 뜻이다.

#### 3. 데이터 웨어하우스 (Data Warehouse)
- 의사결정을 위해 여러 운영 시스템의 데이터를 주제별로 통합해 **모아 둔** 저장소
- 지문 단서: "주제 지향", "통합", "시계열", "비휘발성"

회사에 주문 시스템, 회원 시스템, 재고 시스템이 따로 돌아간다고 하면, 경영진이 매출 흐름을 보려고 이 데이터를 한곳에 주제별로 모아 둔 것이 웨어하우스다. 한번 들어간 데이터는 지우거나 고치지 않고 시간 순서대로 쌓아 두기 때문에 "시계열", "비휘발성"이 단서로 붙는다.

마이닝과 헷갈리면 동사로 가른다. 웨어하우스는 모아 두는 곳이고, 마이닝은 거기서 패턴을 찾아내는 일이다.

#### 4. 데이터 마트 (Data Mart)
- 특정 부서·주제용으로 웨어하우스에서 떼어 낸 **소규모** 저장소
- 지문 단서: "부서 단위", "소규모 웨어하우스"

앞의 웨어하우스에서 마케팅 부서가 쓸 데이터만 따로 떼어 내면 마케팅용 데이터 마트가 된다. 범위가 전사냐 부서냐가 웨어하우스와 마트를 가르는 기준이다.

#### 5. LOD (Linked Open Data)
- 공개 데이터(Open Data)를 웹에서 서로 연결(Linked Data)해 누구나 참조할 수 있게 한 것
- URI로 데이터를 식별하고 RDF로 기술해 연결
- 지문 단서: "Linked Data + Open Data", "URI로 연결"

여러 기관이 각자 공개한 데이터가 있을 때, 항목마다 URI를 붙여 두면 한 기관의 데이터에서 다른 기관의 같은 항목으로 링크를 따라갈 수 있다. 공개만 한 것이 아니라 연결까지 해 두었다는 점이 LOD다.

20-2는 "Linked Data와 Open Data의 합성어"라고 이름을 거의 풀어 준 문제였다. 마이데이터도 데이터 개방과 관련이 있어 보이지만 대상이 다르다. LOD는 공개 데이터를 누구나 참조할 수 있게 연결하는 것이고, 마이데이터는 개인이 자기 데이터의 열람·전송·활용을 직접 통제하는 것이다.

#### 6. 다크 데이터 (Dark Data)
- 수집·저장은 되지만 분석·활용되지 않은 채 쌓여 있는 데이터
- 지문 단서: "저장만 되고 활용 안 됨", "방치", "비용만 발생"

서버에 몇 년째 쌓여만 있고 아무도 열어 보지 않는 로그가 대표적이다. 저장 공간 비용은 계속 나가는데 거기서 얻는 가치는 없다.

데이터가 없어서가 아니라 있는데도 안 쓰여서 "어둡다"는 이름이 붙었다. 그래서 지문에 "저장"이 있어도 "활용 안 됨"이 같이 보이면 다크 데이터를 먼저 떠올린다.

### 기출에서 이렇게 나왔다
- 22-3: 설명 2개 중 하나(다른 하나는 사회공학) → **다크 데이터**
- 20-4: 분산 컴퓨팅, HDFS, MapReduce → **하둡(Hadoop)**
- 20-2: Linked Data와 Open Data의 합성어 → **LOD**
- 20-1: 대용량 데이터에서 패턴·규칙 발견 → **데이터 마이닝**

### 답 쓸 때
하둡은 Hadoop, LOD는 약어 그대로 쓴다. 여기서 헷갈리기 쉬운 짝이 데이터 마이닝과 데이터 웨어하우스인데, 마이닝은 패턴을 "찾아낸다", 웨어하우스는 데이터를 "모아 둔다"로 가른다. 다크 데이터는 저장은 되어 있어도 "활용 안 됨"이 핵심이다.

## SW 신기술
출제: 22-3, 22-1, 20-2
형태: 설명 2~3줄 → 용어 또는 영문 약어

### 개념
SW 신기술은 용어가 제각각이라 다섯 묶음으로 나눠서 보면 된다. 아키텍처 용어(MSA·SOA), 현실과 가상을 결합하는 용어(CPS·디지털 트윈·메타버스·VR/AR/MR), 플랫폼·인터페이스 용어(안드로이드·NUI·매시업), 보안 관련 용어(TrustZone·Typosquatting), 인공지능 용어(머신러닝·딥러닝)다. 이 중 NUI는 [SW 설계]의 UI 종류에서, TrustZone·Typosquatting은 [보안]에서도 다룬다.

### 한눈에 구분
| 용어 | 한 줄 정의 | 지문 단서 |
|---|---|---|
| **MSA(Microservice Architecture)** | 애플리케이션을 독립적으로 배포할 수 있는 작은 서비스들로 나누고 API로 연결하는 구조 | "작은 서비스", "독립 배포", "서비스별 DB" |
| **SOA(Service Oriented Architecture)** | 기능을 서비스 단위로 만들고 느슨하게 결합해 재사용하는 구조. ESB가 기반 | "서비스 단위", "느슨한 결합", "재사용", "ESB" |
| **CPS(Cyber-Physical System)** | 센서·액추에이터가 있는 물리 세계와 컴퓨팅이 결합해 실시간으로 제어하는 시스템 | "물리 세계 + 사이버", "센서", "실시간 제어" |
| **디지털 트윈(Digital Twin)** | 현실의 사물·공정을 가상 공간에 그대로 복제해 시뮬레이션·예측하는 기술 | "가상 복제", "시뮬레이션", "예측" |
| **메타버스(Metaverse)** | 아바타로 사회·경제 활동을 하는 3차원 가상 세계 | "가상 세계", "아바타", "사회·경제 활동" |
| **VR / AR / MR** | VR은 완전한 가상 환경, AR은 현실 위에 가상 정보를 겹침, MR은 현실과 가상이 서로 상호작용 | "몰입", "현실 위에 겹침", "현실·가상 상호작용" |
| **안드로이드(Android)** | 구글이 주도하는 리눅스 커널 기반의 오픈 소스 모바일 운영체제 | "리눅스 기반", "모바일 OS", "오픈 소스", "자바·코틀린" |
| **NUI(Natural User Interface)** | 말·몸짓·터치처럼 사람의 자연스러운 행동으로 조작하는 인터페이스 | "말·행동", "자연스러운 표현", "별도 학습 불필요" |
| **TrustZone** | ARM 프로세서에서 하드웨어로 일반 영역과 보안 영역을 분리하는 기술 | "ARM", "하드웨어 보안 영역", "일반/보안 월드" |
| **Typosquatting** | 사용자가 URL을 잘못 입력하는 것을 노려 비슷한 도메인을 등록하는 공격 | "URL 오타", "유사 도메인", "URL 하이재킹" |
| **매시업(Mashup)** | 여러 웹 서비스나 공개 API를 조합해 새로운 서비스를 만드는 것 | "여러 서비스 조합", "오픈 API" |

인공지능 용어는 서로 포함 관계라는 점을 먼저 잡아야 한다. **AI(인공지능) ⊃ 머신러닝(Machine Learning) ⊃ 딥러닝(Deep Learning)** 순으로 좁아지는데, 아래 정의에서 머신러닝을 AI의 한 분야로, 딥러닝을 머신러닝 기법으로 설명하는 것도 그래서다.

| 용어 | 한 줄 정의 | 지문 단서 |
|---|---|---|
| **머신러닝** | 규칙을 사람이 짜지 않고 데이터에서 스스로 학습하는 AI의 한 분야 | "데이터로 학습", "패턴 학습" |
| **딥러닝** | 여러 층의 인공 신경망(심층 신경망)을 쓰는 머신러닝 기법 | "심층 신경망", "CNN(이미지)·RNN(순차 데이터)" |
| 지도 / 비지도 / 강화 학습 | 정답(라벨)이 있는 데이터로 학습 / 정답 없이 숨은 구조를 찾음(군집화) / 행동의 보상으로 최적 행동을 학습 | "분류·회귀" / "군집" / "보상" |

### 용어 하나씩 보기
기출 정답으로 나온 안드로이드·NUI·TrustZone·Typosquatting 네 개와, 서로 헷갈리기 쉬운 MSA·SOA, VR·AR·MR을 하나씩 푼다.

#### 1. MSA (Microservice Architecture)
- 애플리케이션을 독립 배포 가능한 **작은 서비스**들로 나누고 API로 연결하는 구조
- 서비스별 DB를 따로 두는 경우가 많음
- 지문 단서: "작은 서비스", "독립 배포", "서비스별 DB"

쇼핑몰을 주문, 결제, 회원 서비스로 잘게 나눠 두었다고 해보자. 결제 기능만 고쳤다면 결제 서비스 하나만 다시 배포하면 되고, 나머지 서비스는 그대로 돌아간다.

#### 2. SOA (Service Oriented Architecture)
- 기능을 서비스 단위로 만들고 **느슨하게 결합**해 재사용하는 구조
- ESB 기반으로 서비스 통합
- 지문 단서: "서비스 단위", "느슨한 결합", "재사용", "ESB"

회사 안에서 고객 조회 기능을 서비스 하나로 만들어 두면, 여러 시스템이 ESB를 거쳐 그 서비스를 함께 가져다 쓴다.

MSA와 SOA는 둘 다 이름에 "서비스"가 들어가서 헷갈린다. 작게 쪼개 각자 독립 배포하는 쪽이 MSA, 서비스를 ESB로 통합해 재사용하는 쪽이 SOA다.

#### 3. VR / AR / MR
- **VR**: 완전한 가상 환경
- **AR**: 현실 위에 가상 정보를 겹쳐 보여 줌
- **MR**: 현실과 가상이 서로 상호작용

같은 거실이라도, 헤드셋을 쓰고 거실이 아예 안 보이는 가상 공간에 들어가면 VR이다. 휴대폰 카메라에 비친 거실 위에 가구 그림을 겹쳐 띄우기만 하면 AR이고, 그 가상 가구가 실제 벽과 바닥에 맞춰 놓이고 손으로 옮길 수도 있으면 MR이다.

AR과 MR이 가장 헷갈리는데, 겹치기만 하면 AR, 현실과 가상이 서로 반응하면 MR로 가른다.

#### 4. 안드로이드 (Android)
- 구글이 주도하는 **리눅스 커널 기반**의 오픈 소스 모바일 운영체제
- 앱 개발 언어: 자바·코틀린
- 지문 단서: "리눅스 기반", "모바일 OS", "오픈 소스", "자바·코틀린"

20-2 지문은 리눅스 기반 모바일 OS에 자바·코틀린까지 같이 줬다. 모바일 OS라는 말에 리눅스 기반과 오픈 소스가 붙으면 안드로이드다.

#### 5. NUI (Natural User Interface)
- 말·몸짓·터치처럼 사람의 **자연스러운 행동**으로 조작하는 인터페이스
- 별도 학습 없이 사용 가능
- 지문 단서: "말·행동", "자연스러운 표현", "별도 학습 불필요"

스마트폰 화면을 손가락으로 벌려 사진을 키우거나, 스피커에 말로 음악을 틀어 달라고 하는 장면이 NUI다. 명령어를 외우거나 마우스 사용법을 익히지 않아도 평소 하던 행동 그대로 조작한다.

22-1에서는 영문 약자 NUI로 답을 요구했다. UI 종류 전체는 [SW 설계]에서 다룬다.

#### 6. TrustZone
- ARM 프로세서에서 **하드웨어로** 일반 영역과 보안 영역을 분리하는 기술
- 지문 단서: "ARM", "하드웨어 보안 영역", "일반/보안 월드"

스마트폰을 예로 들면, 일반 앱이 도는 영역과 지문 정보나 결제 키 같은 민감한 처리가 도는 영역을 프로세서 수준에서 갈라 둔다. 일반 영역이 공격당해도 보안 영역의 데이터에는 바로 접근할 수 없다.

소프트웨어로 격리하는 게 아니라 하드웨어로 나눈다는 점, 그리고 ARM이라는 단서가 답을 가른다.

#### 7. Typosquatting
- 사용자가 URL을 **잘못 입력**하는 것을 노려 비슷한 도메인을 등록하는 공격
- 다른 이름: URL 하이재킹
- 지문 단서: "URL 오타", "유사 도메인", "URL 하이재킹"

자주 가는 사이트 주소를 치다가 글자 하나를 빠뜨렸는데, 공격자가 바로 그 오타 주소를 미리 등록해 두고 진짜와 비슷한 화면을 띄워 두는 식이다.

이름도 Typo(오타)와 squatting(무단 점유)을 합친 말이다. 22-3에서 TrustZone과 함께 두 개가 한 문제로 나왔고, 둘 다 [보안]에서도 다룬다.

### 기출에서 이렇게 나왔다
- 22-3: 설명 2개 → **TrustZone / Typosquatting**
- 22-1: 말·행동 등 자연스러운 표현으로 상호작용 → **NUI**
- 20-2: 리눅스 기반 모바일 OS, 자바·코틀린 → **안드로이드**

### 답 쓸 때
NUI는 영문 약자로 요구된 적이 있다. 헷갈리기 쉬운 짝은 MSA와 SOA다. 둘 다 이름에 "서비스"가 들어가지만, 작게 쪼개서 **독립 배포** 하면 MSA이고 **ESB로 통합** 하면 SOA다. AR과 MR도 비슷하게 헷갈리는데, "겹치기만" 하면 AR, "서로 상호작용"하면 MR로 가른다.

## 네트워크 신기술
출제: 24-3, 21-2
형태: 설명 2~3줄 → 용어

### 개념
네트워크 신기술은 세 가지 질문으로 묶어 보면 정리가 된다. 기지국이 있느냐, 제어를 어디서 하느냐, 전송 거리가 얼마나 되느냐다.

### 용어 하나씩 보기
기출 정답은 두 번 다 애드혹 네트워크였다. 그 밖에는 "제어 분리"와 "장비 가상화"로 짝지어 헷갈리는 SDN·NFV, 처리 위치로 갈리는 엣지·포그·MEC, 거리로 갈리는 Zing·LoRa가 이어진다.

#### 1. 애드혹 네트워크 (Ad-hoc Network)
- 기지국·AP 없이 단말(노드)들이 **스스로 망을 구성**하는 임시 무선 네트워크
- 이동 노드가 라우터 역할까지 겸함
- 지문 단서: "기지국·AP 없이", "노드가 자율적으로 구성", "군사·재난 현장", "이동 노드가 라우터 역할"

지진으로 통신 기지국이 무너진 재난 현장을 떠올려 보자. 구조대원들이 가진 단말끼리 서로 신호를 이어 받아 전달하면, 기지국 없이도 그 자리에서 임시 망이 만들어진다. 멀리 있는 대원에게 가는 메시지는 중간에 있는 대원의 단말이 넘겨준다.

21-2와 24-3에는 같은 설명이 그대로 나왔다. "기지국·AP 없이"와 "자율적으로 구성"이 같이 보이면 바로 애드혹이다.

#### 2. SDN (Software Defined Networking)
- 네트워크 장비의 **제어 기능을 분리**해 소프트웨어(컨트롤러)로 중앙에서 제어하는 기술
- 지문 단서: "제어 평면·데이터 평면 분리", "중앙 집중 제어", "OpenFlow"

예전에는 스위치마다 들어가서 경로 설정을 바꿨다면, SDN에서는 중앙 컨트롤러에서 정책을 한 번 바꾸면 그 아래 장비들이 OpenFlow 같은 규격으로 지시를 받아 패킷을 보낸다. 장비는 패킷 전달(데이터 평면)만 하고, 어디로 보낼지(제어 평면)는 컨트롤러가 정한다.

#### 3. NFV (Network Functions Virtualization)
- 라우터·방화벽 같은 네트워크 기능을 전용 장비 대신 **범용 서버의 가상 머신**으로 구현하는 기술
- 지문 단서: "네트워크 기능 가상화", "전용 장비 대체", "범용 서버"

방화벽 장비를 새로 사서 랙에 꽂는 대신, 범용 서버에 방화벽 소프트웨어를 가상 머신으로 하나 더 띄우는 식이다.

SDN과 자주 짝지어 나오는데, SDN은 제어를 장비에서 떼어 내는 것이고 NFV는 장비 자체를 소프트웨어로 바꾸는 것이다.

#### 4. 엣지 컴퓨팅 (Edge Computing)
- 데이터가 생기는 단말·센서 바로 옆, 네트워크의 **가장자리**에서 처리
- 지연·트래픽 감소
- 지문 단서: "발생지 근처", "지연·트래픽 감소"

공장 카메라가 불량품을 찍을 때마다 영상을 클라우드로 보내 판정을 기다리면 늦는다. 카메라 옆 장치에서 바로 판정하면 그만큼 빨라진다.

#### 5. 포그 컴퓨팅 (Fog Computing)
- 단말과 클라우드 **사이**의 네트워크 장비(라우터·로컬 서버)에서 처리
- 지문 단서: "엣지와 클라우드 사이 중간 계층"

공장으로 치면 센서 바로 옆도, 멀리 있는 클라우드도 아닌 공장 안 로컬 서버가 여러 센서의 데이터를 모아 처리한다. 구름(cloud)보다 땅에 가까이 깔린 안개(fog)라는 이름 그대로다.

엣지와 헷갈리면 처리하는 위치를 본다. 단말 바로 옆이면 엣지, 엣지와 클라우드 사이의 중간 계층이면 포그다.

#### 6. MEC (Mobile Edge Computing)
- 중앙 클라우드 대신 **기지국 가까운** 엣지에서 데이터를 처리해 지연을 줄이는 기술
- 현재 이름: Multi-access Edge Computing
- 지문 단서: "기지국 근처", "지연 감소", "엣지"

이동통신망에서 기지국 옆에 서버를 두고, 휴대폰이 보낸 요청을 멀리 있는 중앙 데이터센터까지 보내지 않고 거기서 처리하는 것이다. 엣지 컴퓨팅인데 처리 위치가 "기지국 근처"로 정해져 있다고 보면 된다.

#### 7. Zing
- NFC처럼 기기를 갖다 대는 **초근접** 통신, 거리 10cm 이내
- 기가급 속도
- 쓰임: 키오스크에서 대용량 콘텐츠 전송

키오스크에 휴대폰을 갖다 대고 영화 한 편 같은 큰 파일을 받을 때 쓴다. 갖다 댄다는 점은 교통카드를 찍는 NFC와 같다. 다만 NFC가 교통카드·결제에 쓰인다면, Zing은 기가급 속도로 대용량 콘텐츠를 옮기는 데 쓰인다는 점이 다르다.

#### 8. LoRa (Long Range)
- 저전력 **장거리** 광역망(LPWAN), 거리 수 km
- 배터리로 수년 동작
- 쓰임: IoT 센서

넓은 농장 곳곳에 흙의 습도를 재는 센서를 깔아 둔다고 하면, 센서들은 배터리를 몇 년씩 갈지 않고도 수 km 떨어진 곳까지 값을 보낼 수 있다.

표에서는 블루투스·NFC·지그비 같은 단거리 무선과 한자리에 있지만, LoRa만 거리가 수 km다. 이름이 Long Range인 것도 그래서다.

- 21-2: 같은 설명 → **애드혹 네트워크**

### 답 쓸 때
애드혹은 Ad-hoc Network로도, 애드혹 네트워크로도 쓰인다. 실제로 24-3에서는 영문이, 21-2에서는 한글이 답이었다. SDN과 NFV는 "제어를 분리"하느냐 "장비를 가상화"하느냐로 가른다. 그리고 LoRa는 단거리 무선 표에 같이 들어 있지만, 단거리가 아니라 장거리 저전력이라는 점에 주의한다.

## 클라우드·가상화
출제: 23-3, 20-4
형태: 설명 3개 → 서비스 모델 3종 구분 / 설명 → 용어

### 개념
클라우드 서비스 모델은 **제공자가 어디까지 관리해 주느냐** 로 나뉜다. IaaS, PaaS, SaaS 순으로 제공자가 맡는 범위가 넓어지고, 그만큼 사용자가 관리할 것은 줄어든다. 아래 표의 "사용자가 관리하는 것" 칸을 보면 IaaS는 OS부터 애플리케이션까지, PaaS는 애플리케이션과 데이터만, SaaS는 없음(사용만)으로 점점 짧아진다. 다만 BaaS는 이 축과는 별개로, 블록체인이라는 특정 환경을 서비스로 제공하는 모델이다.

| 모델 | 제공하는 것 | 사용자가 관리하는 것 | 지문 단서 |
|---|---|---|---|
| **IaaS(Infrastructure as a Service)** | 서버·스토리지·네트워크 등 인프라 | OS부터 애플리케이션까지 | "가상 서버", "인프라 자원을 빌림" |
| **PaaS(Platform as a Service)** | 개발·실행 플랫폼(OS·미들웨어·런타임) | 애플리케이션과 데이터만 | "개발 환경 제공", "배포만 하면 됨" |
| **SaaS(Software as a Service)** | 완성된 응용 소프트웨어 | 없음(사용만) | "브라우저로 바로 사용", "설치 없이" |
| **BaaS(Blockchain as a Service)** | 블록체인 개발·운영 환경(노드·인프라)을 클라우드로 제공 | 블록체인 응용 | "블록체인 인프라를 추상화", "클라우드로 블록체인 환경". 정처기 자료는 이 뜻으로 쓴다. 같은 약어가 Backend as a Service(인증·DB·푸시 같은 앱 백엔드 제공)로도 쓰인다 |

배포 모델은 퍼블릭(공용), 프라이빗(단일 조직 전용), 그리고 둘을 섞은 하이브리드로 나뉜다. 여러 클라우드를 함께 쓰는 방식은 이름이 비슷비슷하니 아래 표처럼 이름으로 구분해 둔다.

| 용어 | 한 줄 정의 | 지문 단서 |
|---|---|---|
| **멀티 클라우드(Multi Cloud)** | 둘 이상의 클라우드 제공자 서비스를 함께 쓰는 것 | "특정 업체 종속(Vendor Lock-in) 방지" |
| **인터클라우드(Inter-Cloud)** | 서로 다른 클라우드끼리 연동해 자원을 주고받는 것 | "클라우드 간 연동", "상호 운용성", "표준화" |
| **메타 클라우드(Meta Cloud)** | 여러 클라우드를 하나처럼 묶어 통합 관리하는 상위 계층 | "통합 관리 포털", "하나처럼 관리" |
| **N-Screen** | 하나의 콘텐츠를 스마트폰·PC·TV 등 여러 기기에서 이어서 보는 서비스 | "여러 기기에서 연속 시청" |

블록체인은 "기록을 누가 어떻게 공유하는가"로, 가상화 용어는 "무엇을 묶어 격리하는가"로 구분한다.

| 용어 | 한 줄 정의 | 지문 단서 |
|---|---|---|
| **블록체인(Blockchain)** | 거래 기록을 블록에 담아 체인으로 연결하고 참여자 모두가 복사본을 가지는 분산 원장 | "분산 원장", "P2P", "참여자가 공동 기록", "위·변조 어려움", "해시로 연결" |
| **하이퍼바이저(Hypervisor)** | 한 물리 서버에서 여러 가상 머신(VM)을 만들고 실행하는 소프트웨어 | "VM", "Type 1(베어메탈) / Type 2(호스트형)" |
| **도커(Docker)** | 호스트 OS 커널을 공유하는 컨테이너로 애플리케이션과 실행 환경을 묶는 기술 | "컨테이너", "이미지", "커널 공유로 가벼움" |
| **쿠버네티스(Kubernetes)** | 많은 컨테이너의 배포·확장·복구를 자동으로 관리하는 오케스트레이션 도구 | "컨테이너 오케스트레이션", "자동 확장", "자가 복구" |
| **서버리스(Serverless)** | 서버 관리 없이 함수 단위로 코드를 올리면 이벤트가 있을 때만 실행되고 사용량만큼 과금 | "FaaS", "이벤트 기반", "사용량 과금", "서버 관리 불필요" |

### 서비스 모델 하나씩 보기
23-3은 IaaS·PaaS·SaaS 세 개를 한 문제에서 모두 가르게 했다. 위에서 말한 "제공자가 어디까지 관리해 주느냐"의 차이는 같은 상황 하나에 셋을 나란히 놓으면 드러난다. 상황은 웹 서비스를 하나 운영하려는 팀이다.

#### 1. IaaS (Infrastructure as a Service)
- 제공: 서버·스토리지·네트워크 같은 **인프라**
- 사용자 관리: OS부터 애플리케이션까지
- 지문 단서: "가상 서버", "인프라 자원을 빌림"

팀이 가상 서버를 몇 대 빌린 다음 OS를 고르고, 웹 서버와 DB를 직접 설치하고, 보안 패치도 손수 한다. 하드웨어만 안 샀을 뿐 그 위는 전부 팀 몫이다.

#### 2. PaaS (Platform as a Service)
- 제공: OS·미들웨어·런타임을 갖춘 **개발·실행 플랫폼**
- 사용자 관리: 애플리케이션과 데이터만
- 지문 단서: "개발 환경 제공", "배포만 하면 됨"

이번에는 OS 설치나 런타임 설정 없이, 팀이 만든 코드를 플랫폼에 올리기만 하면 바로 실행된다. 팀이 관리하는 것은 코드와 데이터뿐이다.

#### 3. SaaS (Software as a Service)
- 제공: **완성된 응용 소프트웨어**
- 사용자 관리: 없음(사용만)
- 지문 단서: "브라우저로 바로 사용", "설치 없이"

팀이 업무용 메일이나 문서 도구가 필요하면, 아무것도 설치하지 않고 브라우저로 접속해 바로 쓴다. 서버도 코드도 볼 일이 없다.

세 장면을 이어 보면 팀이 직접 하는 일이 점점 줄어든다. 23-3처럼 셋을 한꺼번에 구분하는 문제는 지문에 "서버·스토리지"가 보이는지, "개발 환경·플랫폼"이 보이는지, "바로 사용"이 보이는지를 차례로 확인한다.

#### 4. BaaS (Blockchain as a Service)
- 제공: 블록체인 개발·운영 환경(노드·인프라)을 **클라우드로**
- 사용자 관리: 블록체인 응용
- 지문 단서: "블록체인 인프라를 추상화", "클라우드로 블록체인 환경"

블록체인 서비스를 만들려는 팀이라면 노드를 직접 구축하지 않고, 클라우드가 준비해 둔 블록체인 환경을 빌려 응용만 올린다.

위의 세 모델과 같은 축으로 줄을 세우면 안 된다. 관리 범위가 아니라 블록체인이라는 특정 환경을 서비스로 준다는 점이 다르다. 같은 약어가 Backend as a Service로도 쓰이지만, 정처기 자료는 블록체인 쪽 뜻으로 쓴다.

### 여러 클라우드·가상화 용어 하나씩 보기
여기서는 이름이 비슷비슷한 멀티·인터·메타 클라우드, 기출 정답이었던 블록체인, 그리고 서로 섞이기 쉬운 하이퍼바이저·도커·쿠버네티스를 본다.

#### 1. 멀티 클라우드 (Multi Cloud)
- 둘 이상의 클라우드 제공자 서비스를 **함께** 쓰는 것
- 지문 단서: "특정 업체 종속(Vendor Lock-in) 방지"

서비스 일부는 한 회사 클라우드에, 나머지는 다른 회사 클라우드에 올려 두는 식이다. 한 업체가 가격을 올리거나 장애가 나도 거기에 통째로 묶여 있지 않게 된다.

#### 2. 인터클라우드 (Inter-Cloud)
- 서로 다른 클라우드끼리 **연동**해 자원을 주고받는 것
- 지문 단서: "클라우드 간 연동", "상호 운용성", "표준화"

한 클라우드의 자원이 모자랄 때 다른 클라우드의 자원을 빌려 오려면, 두 클라우드가 서로 연동할 수 있어야 한다. 그래서 상호 운용성과 표준화가 단서로 붙는다.

#### 3. 메타 클라우드 (Meta Cloud)
- 여러 클라우드를 **하나처럼** 묶어 통합 관리하는 상위 계층
- 지문 단서: "통합 관리 포털", "하나처럼 관리"

여러 클라우드에 흩어진 서버를 회사마다 다른 관리 화면에 들어가 볼 필요 없이, 포털 하나에서 한꺼번에 보고 관리한다.

세 개를 나란히 놓으면, 그냥 같이 쓰기만 하면 멀티, 클라우드끼리 서로 연결해 자원을 주고받으면 인터, 그 위에서 하나처럼 통합 관리하면 메타다.

#### 4. 블록체인 (Blockchain)
- 거래 기록을 블록에 담아 체인으로 연결하고 참여자 **모두가 복사본**을 가지는 분산 원장
- 해시로 연결된 블록, 위·변조 어려움
- 지문 단서: "분산 원장", "P2P", "참여자가 공동 기록", "해시로 연결"

은행 한 곳이 장부를 쥐고 있는 게 아니라, P2P로 연결된 참여자가 모두 같은 장부를 나눠 갖고 새 거래가 생기면 함께 기록한다. 누군가 자기 장부의 과거 기록을 몰래 고쳐도, 해시로 이어진 뒤 블록들과 다른 참여자의 장부가 맞지 않게 되어 바로 드러난다.

20-4에서 블록체인이 답으로 나왔다. 기록을 "누가 어떻게 공유하는가"를 물으면 블록체인이다.

#### 5. 하이퍼바이저 (Hypervisor)
- 한 물리 서버에서 여러 **가상 머신**(VM)을 만들고 실행하는 소프트웨어
- 종류: Type 1(베어메탈, 하드웨어 위에 바로 설치), Type 2(호스트형, 호스트 OS 위에서 실행)
- 지문 단서: "VM", "Type 1(베어메탈) / Type 2(호스트형)"

서버 한 대 위에 리눅스 VM과 윈도우 VM을 나란히 띄울 수 있고, 이때 VM마다 OS가 통째로 따로 들어간다.

#### 6. 도커 (Docker)
- 호스트 OS 커널을 공유하는 **컨테이너**로 애플리케이션과 실행 환경을 묶는 기술
- 지문 단서: "컨테이너", "이미지", "커널 공유로 가벼움"

개발자 노트북에서 돌던 앱을 실행 환경째 이미지로 묶어 두면, 서버에서도 같은 이미지로 컨테이너를 띄워 똑같이 돌릴 수 있다.

하이퍼바이저와 다른 점은 무엇을 격리하느냐다. VM은 OS까지 통째로 따로 갖지만, 컨테이너는 호스트 OS 커널을 함께 쓰기 때문에 가볍다.

#### 7. 쿠버네티스 (Kubernetes)
- 많은 컨테이너의 배포·확장·복구를 **자동으로 관리**하는 오케스트레이션 도구
- 지문 단서: "컨테이너 오케스트레이션", "자동 확장", "자가 복구"

접속자가 몰리면 컨테이너 수를 자동으로 늘리고, 컨테이너 하나가 멈추면 새 컨테이너를 자동으로 띄우는 일을 쿠버네티스가 맡는다.

도커와 쿠버네티스는 둘 다 컨테이너 이야기라 섞이기 쉽다. 컨테이너 하나를 만들고 실행하는 것이 도커, 컨테이너 여러 개를 관리하는 것이 쿠버네티스다.

### 기출에서 이렇게 나왔다
- 23-3: 설명 3개 → **IaaS / PaaS / SaaS**
- 20-4: 블록체인 설명 → **블록체인**

### 답 쓸 때
IaaS·PaaS·SaaS는 약어 그대로 쓴다. 23-3처럼 세 개를 한꺼번에 구분하는 문제라면 지문의 단어를 보면 된다. "서버·스토리지"가 보이면 IaaS, "개발 환경·플랫폼"이면 PaaS, "소프트웨어를 바로 사용"이면 SaaS다. 가상화 쪽은 하이퍼바이저는 VM, 도커는 컨테이너, 쿠버네티스는 컨테이너 여러 개의 관리로 가른다. 도커와 쿠버네티스는 둘 다 컨테이너 이야기라 섞이기 쉬운데, 컨테이너 자체냐 그걸 여러 개 관리하느냐의 차이다.
