# 신기술

신기술 용어는 21개 회차에서 단독 문제로 9개 정도 나왔고, 2023년 이후로는 클라우드 서비스 모델(23-3)과 애드혹 네트워크(24-3) 두 번뿐이다. 형태는 전부 "설명 2~3줄 → 용어 쓰기"다. 같은 설명이 그대로 다시 나오는 경우가 있어(애드혹 21-2와 24-3), 출제된 용어는 지문 단서를 그대로 외우고 나머지는 한 줄 정의와 단서 키워드만 알아 둔다.

## DB·빅데이터 신기술
출제: 22-3, 20-4, 20-2, 20-1
형태: 설명 2~3줄 → 용어

### 개념
빅데이터·데이터베이스 쪽 신기술로 Hadoop, HDFS, 데이터 마이닝, 데이터 웨어하우스, 메타데이터, 마이데이터 같은 용어를 근본 원리부터 정리한다. 데이터 신기술은 실기에서 많이 다뤄지지 않은 부분이라, 나온다면 가장 근본이 되는 주요 용어가 나올 것으로 본다. 먼저 전체를 표로 보면 이렇다.

| 분류 | 기술 | 핵심 키워드 |
|---|---|---|
| 빅데이터 기반 | Hadoop | 분산 처리 프레임워크, HDFS + MapReduce, 에코시스템 |
| 빅데이터 기반 | HDFS | 분산 파일 시스템, 내고장성, Write-Once-Read-Many |
| 데이터 수집/전송 | Chukwa | 대규모 로그 수집, 에이전트-컬렉터, HDFS 기반 |
| 데이터 수집/전송 | Sqoop | RDBMS와 Hadoop 간 데이터 전송, Import/Export |
| 데이터 수집/전송 | 스크래피(Scrapy) | 웹 크롤링 프레임워크, 파이썬, 자동화된 데이터 수집 |
| 데이터 분석/활용 | 데이터 마이닝 | 패턴/규칙 발견, 분류, 군집, 연관 분석, 지식 추출 |
| 데이터 분석/활용 | 데이터 웨어하우스 | 의사결정 지원, 주제 중심, 통합, 시계열, 비휘발성 |
| 데이터 분석/활용 | 데이터 마트 | 웨어하우스의 축소판, 특정 부서/주제, 신속한 구축 |
| 데이터 관리 | 메타데이터 | 데이터에 대한 데이터, 데이터 관리의 핵심, 데이터 카탈로그 |
| 데이터 관리 | 디지털 아카이빙 | 장기 보존, 진본성/무결성, 법적/역사적 가치 |
| 데이터 관리 | 마이데이터 | 정보 주권, 데이터 이동권, 개인 맞춤형 서비스 |

### 데이터 기술을 관통하는 두 원리
용어가 많아 보여도 밑바닥에 깔린 원리는 둘이다. 분산, 그리고 통합과 추출이다.

| 기술 | 핵심 원리 | 이 기술이 기반이 되는 것들 |
|---|---|---|
| Hadoop & 분산 기술 | 분산: 대용량 데이터를 여러 곳에 나눠 저장하고 처리 | 거의 모든 빅데이터 기술, 클라우드 스토리지, 대규모 AI 모델 학습 |
| 데이터 웨어하우스 & 마이닝 | 통합과 추출: 데이터를 모으고 정제해 지식을 발견 | 비즈니스 인텔리전스(BI), 고객 관계 관리(CRM), 추천 시스템 |

**분산**은 고성능 컴퓨터 한 대 대신 일반 컴퓨터 여러 대를 묶어 하나의 거대한 컴퓨터처럼 동작하게 만드는 원리다. 데이터는 여러 조각으로 나뉘어 각 컴퓨터에 저장(HDFS)되고, 계산도 각 컴퓨터가 나눠서 동시에 처리(MapReduce)한다. 이 분산 패러다임이 없었다면 오늘날의 빅데이터, AI, 클라우드 기술은 나올 수 없었다. 페타바이트급 데이터를 처리하고 파라미터가 수천억 개인 AI 모델을 학습시키는 작업 전부가 여기에 기대고 있다.

**통합과 추출**은 데이터에서 숨겨진 가치를 찾아내는 원리다. 데이터 웨어하우스는 여러 곳에 흩어진 데이터(ERP, CRM, 로그 등)를 한곳에 모아 '통합'하고 분석하기 좋게 '정제'하는 저장소이고, 데이터 마이닝은 그렇게 정제된 데이터 속에서 의미 있는 패턴과 규칙, 곧 '지식'을 '추출'하는 기술이다. 데이터를 쌓아 두는 데서 그치지 않고 기업이 데이터를 근거로 의사결정을 하게 해 주는 핵심 과정이라, BI(Business Intelligence), CRM, 추천 시스템의 근간이 된다.

### 빅데이터 기반 기술

#### 1. 하둡 (Hadoop)
**하둡**은 대용량 데이터를 분산 처리하는 오픈 소스 프레임워크이자 빅데이터 생태계의 출발점이다.

- 핵심 구성: HDFS(Hadoop Distributed File System, 데이터를 여러 서버에 분산 저장하는 파일 시스템), MapReduce(분산된 데이터를 병렬로 처리하는 프로그래밍 모델)
- 특징: 저렴한 범용 하드웨어를 묶어 대규모 클러스터를 구성해 비용 효율적, 내고장성(Fault Tolerance)이 뛰어나 일부 서버에 장애가 나도 데이터 유실 없이 안정적으로 동작

#### 2. HDFS (Hadoop Distributed File System)
하둡을 위해 설계된, 대용량 파일을 분산 저장하는 파일 시스템이다.

- 특징: 'Write-Once-Read-Many' 모델에 최적화, 한 번 저장한 데이터는 수정보다 주로 읽는 용도로 사용
- 특징: 데이터를 여러 블록으로 나누고 블록마다 복제해 여러 서버에 저장, 데이터의 안정성과 가용성 향상

### 데이터 수집 및 전송 기술

#### 3. Chukwa (척와)
대규모 분산 시스템에서 나오는 로그 데이터를 안정적으로 수집하는 아파치 프로젝트다.

- 구조: 데이터를 수집하는 에이전트(Agent), 수집한 데이터를 받아 저장소로 넘기는 컬렉터(Collector)
- 특징: HDFS에 저장하는 것이 기본, 실시간 데이터 분석 및 모니터링 시스템 구축에 사용

#### 4. Sqoop (스쿱)
관계형 데이터베이스(RDBMS)와 하둡(HDFS, Hive 등) 사이에서 대량의 데이터를 효율적으로 옮기는 도구다.

- 주요 기능: Import(RDBMS에서 하둡으로 가져옴), Export(하둡에서 RDBMS로 내보냄)
- 특징: MapReduce 작업을 만들어 병렬로 처리하므로 빠르고 안정적인 전송 가능

#### 5. 스크래피 (Scrapy)
웹 사이트에서 구조화된 데이터를 추출(크롤링)하는 파이썬 기반 오픈 소스 프레임워크다.

- 특징: 비동기 처리 방식으로 매우 빠르게 웹 페이지 수집
- 특징: 데이터 추출 규칙(Spider)을 정의해 원하는 정보만 정확하게 가져옴, 수집 결과는 JSON, CSV 등 다양한 형식으로 저장

### 데이터 분석 및 활용 기술

#### 6. 데이터 마이닝 (Data Mining)
**데이터 마이닝**은 대규모 데이터 속에서 의미 있는 패턴, 규칙, 관계를 찾아내 가치 있는 정보로 만드는 과정이다. 주요 기법은 셋이다.

- **분류(Classification)**: 데이터를 미리 정의된 그룹으로 나눔 (예: 스팸 메일 분류)
- **군집화(Clustering)**: 비슷한 특성의 데이터끼리 그룹을 만듦 (예: 고객 세분화)
- **연관 분석(Association)**: 데이터 항목 사이의 관계를 찾음 (예: '기저귀'와 '맥주'의 연관성)

#### 7. 데이터 웨어하우스 (Data Warehouse)
기업의 의사결정을 지원하려고 여러 시스템의 데이터를 주제 중심으로 통합해 저장하는 데이터베이스다. 4대 특징이 있다.

- **주제 중심(Subject-Oriented)**: 고객, 제품 등 분석 주제별로 데이터 구성
- **통합(Integrated)**: 데이터 형식을 일관되게 변환해 저장
- **시계열(Time-Variant)**: 시간에 따른 변화를 분석할 수 있게 저장
- **비휘발성(Non-Volatile)**: 한 번 저장한 데이터는 삭제·수정하지 않음

#### 8. 데이터 마트 (Data Mart)
데이터 웨어하우스의 축소판으로, 특정 부서나 사용자 그룹의 요구에 맞춘 소규모 데이터 저장소다.

- 특징: 특정 주제에 집중하므로 데이터 웨어하우스보다 빠르고 저렴하게 구축
- 목적: 전사적 분석보다 특정 현업 부서의 분석 요구 충족

### 데이터 관리 기술

#### 9. 메타데이터 (Metadata)
'데이터에 대한 데이터'로, 데이터의 구조, 속성, 이력, 관계 등 모든 정보를 설명한다.

- 중요성: 데이터의 출처, 의미, 형식을 명확히 해 가치를 높이고, 사용자가 데이터를 쉽게 찾고 이해하고 활용하게 도움
- 데이터 거버넌스와 데이터 품질 관리의 핵심 요소

#### 10. 디지털 아카이빙 (Digital Archiving)
장기 보존 가치가 있는 디지털 정보를 체계적으로 수집, 관리, 보존해 미래에 활용할 수 있게 하는 활동이다.

- 특징: 정보의 진본성, 무결성, 신뢰성 보장이 핵심
- 용도: 법적 증거, 역사적 기록, 연구 데이터 등을 안전하게 보존

#### 11. 마이데이터 (MyData)
정보 주체인 개인이 자기 데이터에 대한 통제권을 갖고 직접 관리·활용하는 데이터 패러다임이다.

- 핵심 권리: 개인신용정보 이동권. 금융기관 등에 흩어진 자기 정보를 한곳에 모아 관리하고, 이를 바탕으로 맞춤형 자산관리, 신용관리 등의 서비스를 받음

#### 12. LOD (Linked Open Data)
**LOD**는 'Linked Data + Open Data'의 합성어로, 누구나 자유롭게 쓸 수 있게 공개된 데이터를 표준화된 형식으로 서로 연결한 데이터망이다. 이름을 이루는 두 말부터 풀면 이렇다.

- **Open Data**: 정부·공공기관·기업이 누구나 자유롭게 사용·재배포할 수 있게 공개한 데이터
- **Linked Data**: 데이터 항목마다 고유한 URI를 붙이고 RDF로 데이터 사이의 관계를 표현해, 흩어진 데이터를 하나의 거대한 그래프로 잇는 시맨틱 웹 기술
- **LOD**: 둘을 합친 개념, 공개된 데이터를 서로 연결해 전 세계 데이터를 하나로 묶는 방식

데이터를 얼마나 잘 공개했는지 매기는 등급으로 팀 버너스리(Tim Berners-Lee)가 제안한 5-Star LOD가 있다. 별은 ★1(공개) → ★2(구조화) → ★3(개방 형식) → ★4(URI 식별) → ★5(다른 데이터와 연결) 순서로 올라가고, 많을수록 활용도가 크다.

활용 예로는 DBpedia(위키피디아를 LOD로 만든 것), 공공 데이터 포털, 시맨틱 웹 검색 등이 있다.

#### 13. 다크 데이터 (Dark Data)
**다크 데이터**는 조직이 수집·저장은 했지만 분석·활용하지 않은 채 방치한 비구조화 데이터다.

- 정의: 가트너(Gartner)가 정의한 용어, 빅데이터와 비슷하지만 구조화되어 있지 않고 더는 쓰이지 않는 '죽은' 데이터. 로그, 이메일 첨부파일, CCTV 영상, 백업본 등
- 문제점: 가치는 뽑아내지 못한 채 저장 비용·관리 부담만 발생, 개인정보가 들어 있으면 유출·규제 리스크의 원인
- 대응: 데이터 거버넌스 관점에서 분류·태깅·생명주기 정책을 세워 활용 가능한 데이터로 전환하거나 안전하게 폐기

### 기출에서 이렇게 나왔다
- 22-3: 설명 2개 중 하나(다른 하나는 사회공학) → **다크 데이터**
- 20-4: 분산 컴퓨팅, HDFS, MapReduce → **하둡(Hadoop)**
- 20-2: Linked Data와 Open Data의 합성어 → **LOD**
- 20-1: 대용량 데이터에서 패턴·규칙 발견 → **데이터 마이닝**

### 답 쓸 때
하둡은 Hadoop, LOD는 약어 그대로 쓴다. 여기서 헷갈리기 쉬운 짝이 데이터 마이닝과 데이터 웨어하우스인데, 마이닝은 패턴을 "찾아낸다", 웨어하우스는 데이터를 "모아 둔다"로 가른다. 다크 데이터는 저장은 되어 있어도 "활용 안 됨"이 핵심이다.

### 개념
소프트웨어 신기술은 최신 IT 흐름을 반영한 문제가 나오는 부분이다. 마이크로서비스, 디지털 트윈, 서비스 지향 아키텍처, 사이버-물리 시스템, 메타버스, VR, AR, MR처럼 현대 소프트웨어 개발의 패러다임을 바꾼 근본 기술을 중심으로 외워 두면 된다. 먼저 전체를 표로 보면 이렇다.

| 분류 | 기술 | 핵심 키워드 |
|---|---|---|
| 아키텍처 | 마이크로서비스 아키텍처 (MSA) | 독립적 서비스, API 통신, 장애 격리, DevOps, 클라우드 네이티브 |
| 아키텍처 | 서비스 지향 아키텍처 (SOA) | 서비스 재사용, 웹 서비스(WSDL, SOAP), ESB, 느슨한 결합 |
| 현실-가상 융합 | CPS (사이버-물리 시스템) | 현실-가상 상호작용, 제어, 피드백 루프, IoT의 확장 |
| 현실-가상 융합 | 디지털 트윈 | 가상 모델, 동기화, 시뮬레이션, 예측, 최적화 |
| 현실-가상 융합 | 메타버스 | 3차원 가상 세계, 아바타, 사회/경제/문화 활동 |
| 현실-가상 융합 | VR / AR / MR | 가상현실, 증강현실, 혼합현실, 몰입 경험 |
| 기타 | 매시업 (Mashup) | 웹 정보/서비스 조합, 새로운 소프트웨어/서비스/데이터베이스 생성 |

### SW 패러다임을 바꾸는 3가지 근본 원리
네트워크 신기술의 애드혹 네트워크처럼, 소프트웨어 쪽에도 수많은 기술의 바탕이 되는 핵심 원리가 있다.

| 기술 | 핵심 원리 | 이 기술이 기반이 되는 것들 |
|---|---|---|
| 마이크로서비스 아키텍처 (MSA) | 분해와 자율: 거대 서비스를 작고 독립적인 단위로 분해 | 클라우드 네이티브, DevOps, 컨테이너, 서버리스 |
| CPS & 디지털 트윈 | 연결과 동기화: 현실과 가상 세계를 1:1로 연결 및 동기화 | 스마트 팩토리, 자율주행, 시뮬레이션, 메타버스 |
| 서비스 지향 아키텍처 (SOA) | 재사용과 조합: 기능을 '서비스'로 보고 조합해 개발 | 마이크로서비스, 매시업, API 경제 |

#### 1. 마이크로서비스 아키텍처 (Microservice Architecture, MSA)
**MSA**는 거대한 애플리케이션 하나를, 작고 독립적으로 배포할 수 있는 서비스들의 조합으로 개발하는 방식이다. 각 서비스는 자기만의 데이터베이스를 가질 수 있고, 다른 서비스와는 API로 통신한다. 레고 블록처럼 필요한 기능(블록)을 조합해 하나의 큰 결과물을 만든다고 보면 된다.

- 특징: 서비스마다 독립적으로 개발·배포·확장 가능, 서비스 간 통신은 주로 API, 특정 서비스의 장애가 전체 시스템에 영향 없음
- 장점: 높은 유연성과 확장성, 빠른 배포 속도, 팀의 독립성 보장
- 단점: 전체 시스템 복잡도 증가, 분산 시스템 관리의 어려움, 테스트·디버깅의 복잡성

왜 근본 기술일까? 이 구조 덕분에 빠른 개발 속도, 높은 확장성, 유연한 기술 선택이 가능해졌다. 특정 서비스에 문제가 생겨도 전체 장애로 번지지 않아 장애 격리에도 유리하다. 그래서 클라우드 환경에서 애플리케이션을 개발·운영하는 현대적 방식의 표준이 됐다. SOA(서비스 지향 아키텍처)의 사상을 이어받았지만, 서비스 간 결합도를 더 낮추고(느슨한 결합) 독립성을 극대화한, 더 실용적이고 진보된 형태다.

#### 2. CPS (사이버-물리 시스템) & 디지털 트윈 (Digital Twin)
현실 세계의 물리적 객체와 프로세스를 가상 세계에 그대로 복제하고, 둘이 실시간으로 데이터를 주고받으며 동기화하는 기술이다.

- **CPS**: 현실 세계의 사물(Physical)을 센서로 제어하고, 사이버(Cyber) 공간에서 모은 데이터로 분석·판단해 다시 현실을 제어하는 큰 틀의 시스템
- **디지털 트윈**: CPS를 구현하는 핵심 기술. 현실의 기계·장비·공장 등을 가상 공간에 쌍둥이(Twin)처럼 똑같이 만듦. 현실에서 생긴 데이터가 즉시 가상 모델에 반영되고, 가상 모델의 시뮬레이션 결과를 다시 현실에 적용

현실에서는 할 수 없는 시뮬레이션(예: 공장 전체를 멈추고 하는 테스트)을 가상 세계에서 돌려 미래를 예측하고 최적의 운영 방안을 찾게 해 준다는 점에서 근본 기술이다. 제조업, 건설, 의료, 도시 계획 등 거의 모든 산업의 혁신을 이끈다. 디지털 트윈의 핵심 효과는 셋이다.

- **자산 최적화**: 실제 자산의 성능을 가상 모델에서 분석해 최적 운영 조건 탐색
- **돌발 사고 최소화**: 가상 시뮬레이션으로 잠재적 문제를 미리 예측하고 대응 방안 수립
- **생산성 증가**: 설계부터 제조, 서비스까지 전 과정의 효율 향상

#### 3. 서비스 지향 아키텍처 (Service-Oriented Architecture, SOA)
**SOA**는 기업의 IT 시스템을 재사용 가능한 '서비스' 단위로 만들고, 이 서비스들을 조합(Orchestration)해 비즈니스 프로세스를 구현하는 아키텍처 스타일이다. 각 서비스는 표준화된 인터페이스(주로 웹 서비스)로 자기 기능을 외부에 제공하고, '서비스 버스(ESB)'로 서비스들을 중앙에서 연결·관리하는 경우가 많다.

- **분할된 애플리케이션 조각들**: 큰 애플리케이션 하나를 기능별로 나눠 '서비스' 단위로 분할
- **느슨한 결합**: 서비스 간 의존성을 최소화해 독립적으로 운영
- **완성된 애플리케이션 구현**: 분할된 서비스들을 조합해 완전한 애플리케이션 하나를 구성
- 특징: 웹 서비스(WSDL, SOAP, UDDI) 기술을 주로 사용, ESB(Enterprise Service Bus)로 서비스를 연동하는 중앙집중적 방식인 경우가 많음
- MSA와의 차이: MSA보다 서비스 크기가 크고, ESB를 거쳐 통신해 서비스 간 결합도가 상대적으로 높을 수 있음

'기능을 부품처럼 만들어 재사용한다'는 생각을 소프트웨어 아키텍처에 본격적으로 들여온 것이 SOA다. 이것이 뒤에 마이크로서비스 아키텍처(MSA)와 매시업(Mashup) 같은 기술이 나오는 사상적 바탕이 됐다.

### 기술별 상세 설명

#### 4. 메타버스, VR, AR, MR
사용자가 몰입감을 느끼며 상호작용하는 가상·증강·혼합 현실 기술과 플랫폼이다.

- **VR (Virtual Reality)**: 100% 가상으로 만든 환경에 몰입
- **AR (Augmented Reality)**: 현실 세계에 가상의 정보나 이미지를 덧씌워 보여 줌 (예: 포켓몬 고)
- **MR (Mixed Reality)**: 현실과 가상 객체가 서로 상호작용하며 영향을 줌
- **메타버스**: 이런 기술을 활용해 사회, 경제, 문화 활동이 이루어지는 3차원 가상 세계

메타버스는 1992년 미국 작가 닐 스티븐슨(Neal Stephenson)의 사이버펑크 소설 '스노우 크래쉬(Snow Crash)'에서 처음 소개된 개념으로, 이후 가상현실을 넘어서는 개념으로 발전했다.

#### 5. 안드로이드 (Android)
**안드로이드**는 구글이 주도하는 OHA(Open Handset Alliance)가 개발한 Linux 커널 기반 오픈소스 모바일 OS다. 단순한 OS가 아니라 운영체제(Linux 커널) + 미들웨어 + 사용자 인터페이스 + 기본 응용프로그램(웹 브라우저 등)을 모두 포함한 소프트웨어 스택이다.

- **Linux 커널 기반**: 안정성·이식성·드라이버 생태계를 그대로 활용
- **오픈소스**: AOSP(Android Open Source Project)로 코드 공개, 제조사가 자유롭게 커스터마이징(One UI, MIUI 등)
- **개발 언어**: 공식 언어 Java, 2017년부터 Kotlin 추가 (둘 다 1급 시민)
- **런타임**: 컴파일된 바이트 코드를 실행하는 런타임 라이브러리 제공 (과거 Dalvik VM → 현재 ART, Android Runtime)

iOS와 비교하면, iOS는 애플이 혼자 개발한 폐쇄형이고 Objective-C/Swift를 쓴다. 안드로이드는 오픈소스에 여러 제조사가 참여하고 Java/Kotlin을 쓴다.

#### 6. NUI (Natural User Interface)
**NUI**는 키보드·마우스 같은 별도 입력 장치 없이 음성, 제스처, 표정, 시선 등 사람의 자연스러운 표현 그대로 컴퓨터·기기와 상호작용하는 사용자 인터페이스다. 키워드는 "자연스러운(Natural)"이다. 사람이 평소 남과 의사소통하는 방식, 곧 말하기·손짓·표정을 그대로 컴퓨터 입력으로 쓰는 UI 패러다임이다.

UI 패러다임은 이렇게 진화해 왔다.

| UI | 방식 | 예 |
|---|---|---|
| CLI(Command Line Interface) | 명령어 타이핑 | 터미널 |
| GUI(Graphical User Interface) | 마우스로 그래픽 요소 조작 | 윈도우, macOS |
| NUI(Natural User Interface) | 음성·제스처·표정 | Siri, Alexa, Kinect, Apple Vision Pro |
| OUI(Organic User Interface) | 사물 자체가 인터페이스 | 폴더블, 스마트워치, 종이처럼 휘어지는 디스플레이 |

- 활용: 음성 비서, AR/VR 기기, 모션 인식 게임, 자율주행차 인포테인먼트

#### 7. TrustZone (트러스트존)
**TrustZone**은 ARM사가 자사 프로세서에 적용한 하드웨어 기반 보안 기술로, CPU 하나 안에서 일반 영역과 보안 영역을 물리적으로 분리한다.

- 개념: ARM 프로세서 내부를 Normal World(일반 영역)와 Secure World(보안 영역)로 나눠, 결제·인증·DRM 같은 민감한 처리는 보안 영역에서만 수행하도록 격리. 일반 OS에 침투한 악성코드도 보안 영역의 비밀(키, 지문 등)에는 접근 불가
- 하드웨어 기반 보안의 의미: 소프트웨어 보안(백신·방화벽)과 달리 CPU 수준에서 영역을 분리하므로 OS가 통째로 뚫려도 보안 영역은 살아남음
- 활용: 삼성 Knox, 모바일 결제(삼성페이·구글페이), 지문/Face ID 데이터 보호, DRM, 보안 부팅(Secure Boot)
- 유사 기술: Intel SGX(인텔), Apple Secure Enclave(애플). 모두 같은 사상의 하드웨어 보안 영역

#### 8. Typosquatting (타이포스쿼팅)
22-3에서 TrustZone과 한 문제로 나온 용어라 여기에도 둔다. 자세한 내용은 「보안」 페이지의 웹 공격 묶음과 같다.

- 정의: 사용자가 주소를 잘못 입력하는 실수를 노려 유명 사이트와 철자가 비슷한 도메인을 미리 등록하는 수법, URL 하이재킹이라고도 함
- 예시: gogle.com처럼 유명 도메인의 오타 형태를 선점해 방문자 유인, 광고 노출이나 피싱·악성코드 배포에 악용

#### 9. 매시업 (Mashup)
**매시업**은 웹에서 제공하는 정보와 서비스를 이용해 새로운 소프트웨어나 서비스, 데이터베이스 등을 만드는 기술이다. 여러 웹 서비스의 API를 조합해 기존에 없던 서비스나 애플리케이션을 만든다. 음악에서 여러 곡을 섞어 새 곡을 만들듯, 웹의 여러 서비스를 '섞어서' 새 가치를 만든다.

- **웹 기반**: 웹에서 제공하는 정보와 서비스 활용
- **조합과 재구성**: 기존 서비스들을 새로운 방식으로 조합
- **빠른 개발**: 기존 API를 활용해 비교적 빠르게 새 서비스 개발

활용 예를 보면 감이 온다.

- 지도 API + 부동산 정보 API = 부동산 지도 서비스
- 날씨 API + 교통 정보 API = 날씨별 교통 상황 서비스
- 소셜 미디어 API + 뉴스 API = 소셜 트렌드 뉴스 서비스

SOA의 '서비스 재사용' 개념을 웹 환경에서 실현한 구체적인 기술이 매시업이다.

- 20-2: 리눅스 기반 모바일 OS, 자바·코틀린 → **안드로이드**

### 답 쓸 때
NUI는 영문 약자로 요구된 적이 있다. 헷갈리기 쉬운 짝은 아래 둘이다.

- MSA와 SOA: 둘 다 이름에 "서비스"가 들어감. 작게 쪼개서 **독립 배포** 하면 MSA, **ESB로 통합** 하면 SOA
- AR과 MR: "겹치기만" 하면 AR, "서로 상호작용"하면 MR

## 네트워크 신기술
출제: 24-3, 21-2
형태: 설명 2~3줄 → 용어

### 개념
네트워크 신기술은 실기에서 의외로 꾸준히 나오는 부분이다. Wi-SUN, NFC, 블루투스, SDN, NFV, MEC, IoT, MQTT, 지그비 같은 용어를 정리하고, 애드혹 네트워크가 왜 두 번이나 나왔는지도 짚어 본다. 먼저 주요 용어를 표로 보면 이렇다.

| 용어 | 키워드 |
|---|---|
| MQTT | 발행/구독 모델, 경량 메시징 프로토콜, IoT 표준, IBM 개발, 브로커 |
| SDN | 제어부/데이터부 분리, 중앙 집중 제어, 프로그래머블, OpenFlow |
| NFV | 네트워크 기능 가상화, 범용 하드웨어, 비용 절감, 소프트웨어화 |
| 스마트 그리드 | 지능형 전력망, 양방향 통신, 에너지 효율화, AMI, 원격 검침 |
| IoT | 사물인터넷, 센서, 데이터 수집/처리/제어, 컴퓨터 칩 내장 |
| Wi-SUN | IEEE802.15.4g, 900MHz 대역, 스마트 그리드, HAN/NAN, 원격 검침 |
| AllJoyn | IoT 디바이스 상호작용, 퀄컴 개발, 오픈소스, 서로 다른 제조업체 |
| 비컨(Beacon) | BLE 기반, 70m 통신, 모바일 결제, 위치 인식, 5~10cm 구별 |
| Zing | NFC 기반, 키오스크, 기가급 속도, 초고속 근접 통신, 10cm 이내 |
| 애드혹 네트워크 | 인프라 없는 통신, 자율적 네트워크 구성, 중앙 제어 장치 없음 |

### 애드혹 네트워크는 왜 출제되었을까?
최신 기술이 쏟아지는 가운데 다소 오래돼 보이는 애드혹 네트워크(Ad-hoc Network)가 실기에 나온 이유는 무엇일까? 답은 애드혹 네트워크가 현대 무선 통신의 근간이 되는 핵심 원리이기 때문이다.

- **인프라 없는 통신**: 중앙 제어 장치(AP, 기지국 등) 없이 단말기끼리 직접 통신하며 자율적으로 네트워크 구성
- **현대 기술의 기반**: IoT, 메시 네트워크(Mesh Network), V2X(차량-사물 통신), 재난 통신망 등 수많은 최신 기술에 그대로 적용

예를 들어 수많은 IoT 센서가 서로 통신하며 데이터를 넘기거나, 차량들이 서로의 위치와 상태를 공유하는 것이 모두 애드혹 네트워크의 개념에서 출발한다. 결국 출제자는 최신 유행 기술을 묻는 게 아니라, 새 기술을 이해하는 바탕이 되는 근본 원리를 정확히 아는지 보려 한 것이다. 애드혹 네트워크는 필기에 여러 번 나왔고 실기에도 두 번 나왔다.

### 차세대 기술을 이끄는 3가지 근본 원리
애드혹 네트워크가 다른 기술의 '뿌리'인 것처럼, 지금 네트워크 기술의 패러다임을 바꾸고 있는 핵심 원리가 셋 있다. 시험에서 그 자체로도 중요하지만 다른 신기술을 이해하는 기반이 된다. 이 가운데 SDN과 MQTT는 필기에 나온 적이 있다.

| 기술 | 핵심 원리 | 이 기술이 기반이 되는 것들 |
|---|---|---|
| SDN / NFV | 분리: 제어/데이터, 하드웨어/소프트웨어 분리 | 네트워크 슬라이싱, 클라우드 데이터 센터, 5G 코어망 |
| MQTT | 비동기 메시징: 발행자와 구독자를 브로커로 분리 | 대부분의 IoT 플랫폼, 실시간 채팅 앱, 마이크로서비스 |
| MEC | 분산화: 데이터 처리를 중앙에서 엣지로 이동 | 5G 초저지연 서비스 (자율주행, AR/VR), 실시간 AI 분석 |

#### 1. SDN (소프트웨어 정의 네트워킹) & NFV (네트워크 기능 가상화)
둘 다 '분리(Decoupling)'로 네트워크를 중앙에서 프로그래밍하고 자동화한다.

- **SDN**: 네트워크의 '뇌(제어부)'와 '근육(데이터부)'을 분리. 중앙 컨트롤러가 모든 것을 지시하고 네트워크 장비는 명령대로 데이터를 전달만 함
- **NFV**: 네트워크 장비의 '소프트웨어 기능'을 '하드웨어'에서 분리. 비싼 전용 장비 대신 일반 서버에 방화벽, 라우터 등의 기능을 소프트웨어로 설치해 사용

이 '분리' 덕분에 네트워크 전체를 프로그래밍하고 자동화할 수 있게 됐다. 클라우드 데이터센터, 5G 코어망, 네트워크 슬라이싱 같은 현대 네트워크 기술의 핵심 기반이다.

SDN을 조금 더 보면, 핵심은 제어부(Control Plane)와 데이터부(Data Plane)의 분리다. 중앙의 SDN 컨트롤러가 네트워크 전체를 내려다보고, 라우터나 스위치 같은 장비는 컨트롤러 지시에 따라 패킷을 전달하는 역할만 한다. 그래서 네트워크를 프로그래밍하고 동적으로 제어할 수 있다. NFV는 위에서 본 대로 소프트웨어 기능을 하드웨어에서 떼어 내는 개념이다. 둘 다 현재 활용도가 높아서, 데이터 센터·클라우드 컴퓨팅·대규모 엔터프라이즈 네트워크에서 효율적인 관리와 자동화를 위해 널리 도입되었다.

#### 2. MQTT
**MQTT**는 '발행/구독(Publish/Subscribe)' 모델로 1:N 비동기 통신을 구현한다. 중간에 '우체국(브로커)'을 두는 구조다. 데이터를 보내는 쪽(발행자)은 우체국에 데이터를 맡기고, 받고 싶은 쪽(구독자)은 우체국에 미리 신청해 둔다. 발행자와 구독자가 서로를 알 필요가 없어 느슨한 결합(Loose Coupling)이 유지된다.

- 특징: 메시지 브로커를 거쳐 통신하므로 송신자와 수신자가 직접 연결될 필요 없음
- 특징: TCP 기반이라 신뢰성이 높고, 프로토콜 자체가 매우 가벼워 저사양 기기에 적합
- 현재 활용도: 매우 높음. 페이스북 메신저, 아마존 웹 서비스(AWS) IoT 같은 대규모 시스템부터 소규모 IoT 프로젝트까지 가장 널리 쓰이는 IoT 프로토콜 중 하나

장치 수십억 개가 연결되는 IoT 환경에서는 1:1 통신이 비효율적이고 확장도 어렵다. 발행/구독 모델은 이런 대규모 비동기 통신을 가능하게 하는 핵심 구조라서, 대부분의 IoT 플랫폼과 실시간 메시징 앱의 기반이 된다.

#### 3. MEC (모바일 엣지 컴퓨팅)
데이터 처리의 '중심'을 중앙 클라우드에서 사용자와 가까운 '엣지'로 옮긴다. 모든 데이터를 멀리 있는 중앙 데이터 센터로 보내는 대신, 데이터가 생기는 현장(기지국, 공유기 등)에서 바로 처리한다.

- 특징: 데이터를 중앙 클라우드까지 보내지 않고 엣지에서 처리해 초저지연(Ultra-low latency) 서비스 가능
- 현재 활용도: 높음 (성장 중). 5G 시대의 핵심 기술로 실시간 스트리밍, 클라우드 게임, AR/VR, 스마트 팩토리 등 초저지연이 필수인 서비스에 적용

물리적 거리 때문에 생기는 지연 시간(Latency)을 극복하는 가장 효과적인 방법이라서, 자율주행, AR/VR, 스마트 팩토리 같은 5G 시대 핵심 서비스를 가능하게 하는 기반 기술이다.

### 단거리 무선 통신 (Short-range Wireless)

#### 4. NFC (Near Field Communication)
13.56MHz 주파수 대역을 쓰는 10cm 이내의 초근접 무선 통신 기술이다.

- 특징: 통신 거리가 매우 짧아 보안성이 뛰어나고, 기기 간 설정 없이 간단한 태깅만으로 연결
- 주요 기능: P2P(기기 간 통신), 카드 에뮬레이션(교통카드, 신용카드), 리더/라이터(NFC 태그 정보 읽기/쓰기) 모드
- 현재 활용도: 매우 높음. 삼성페이/애플페이 등 모바일 결제, 교통카드, 스마트 키, 출입 통제 시스템

#### 5. Zing (NFC 기반 모바일 결제 서비스)
NFC 기술을 활용한 모바일 결제 서비스로, 키오스크나 결제 단말기에 스마트폰을 갖다 대면 간편하게 결제할 수 있다.

- 핵심 특징: NFC 기반, 10cm 이내 근접 거리에서 기가급 속도로 데이터를 전송하는 초고속 근접 무선 통신
- 주요 기능: 키오스크나 결제 단말기에 기기를 대면 원하는 데이터(결제 정보, 쿠폰, 멤버십 등)를 바로 가져옴
- 현재 활용도: 중간 (특수 분야). 주로 대형 마트, 편의점, 카페 등에서 NFC 기반 모바일 결제로 활용, 삼성페이·애플페이와 비슷한 기능

#### 6. 블루투스 (Bluetooth), 피코넷 (Piconet), 스캐터넷 (Scatternet)
블루투스는 개인 근거리 무선 통신(PAN)을 위한 표준 기술이다.

- **피코넷**: 마스터(Master) 장치 하나와 최대 7개의 슬레이브(Slave) 장치가 1:7로 통신하는 기본 블루투스 네트워크
- **스캐터넷**: 여러 피코넷이 서로 연결된 더 큰 네트워크, 피코넷 사이의 장치가 브릿지 역할
- 현재 활용도: 매우 높음. 무선 이어폰, 키보드, 마우스, 스피커 등 주변기기 연결에 필수

#### 7. BLE (Bluetooth Low Energy)
이름 그대로 저전력에 초점을 맞춘 블루투스 기술이다.

- 특징: 클래식 블루투스보다 훨씬 적은 전력으로 동작해 작은 배터리로도 수개월~수년간 작동, 작은 데이터를 주기적으로 보내는 데 최적화
- 현재 활용도: 매우 높음. 스마트 워치, 피트니스 밴드 등 웨어러블 기기, 비컨을 이용한 실내 위치 측위, 각종 IoT 센서

#### 8. 비컨 (Beacon)
블루투스 저전력(BLE) 기술을 바탕으로 특정 정보를 주기적으로 송신하는 장치다.

- 핵심 특징: 스마트폰 같은 수신 장치가 비컨 신호를 감지하면 미리 설정된 정보(위치, 할인 쿠폰, 이벤트 정보 등)를 사용자에게 전송
- 주요 기능: 정확한 실내 위치 인식, 개인화된 정보 제공, 모바일 결제 연동
- 현재 활용도: 높음. 매장 내 고객 위치 기반 마케팅, 박물관/미술관 안내, 스마트 오피스 출입 관리, 주차장 안내 등

#### 9. UWB (Ultra-Wideband)
매우 넓은 주파수 대역을 써서 정밀하게 거리와 위치를 재는 기술이다.

- 특징: cm 단위의 정밀 측위 가능, 벽 같은 장애물 투과율이 높고 보안성이 뛰어남
- 현재 활용도: 높음 (빠르게 성장 중). 애플 에어태그(AirTag), 삼성 스마트태그+(SmartTag+) 같은 분실물 추적기, 디지털 키, 실내 내비게이션, 정밀 위치 기반 서비스

#### 10. 애드혹 네트워크 (Ad-hoc Network)
**애드혹 네트워크**는 고정된 기반 시설(라우터, AP) 없이 모바일 노드들이 자율적으로 구성하는 임시 네트워크다.

- 핵심 특징: 인프라 없는 통신. 중앙 제어 장치(AP, 기지국 등) 없이 단말기끼리 직접 통신하며 자율적으로 네트워크 구성
- 현대 기술의 기반: IoT, 메시 네트워크(Mesh Network), V2X(차량-사물 통신), 재난 통신망 등 수많은 최신 기술에 그대로 적용
- 주요 활용: 군사 통신, 재난 구조 통신, 센서 네트워크, 차량 간 통신(VANET) 등 특정 목적의 임시 네트워크
- 현재 활용도: 중간 (특수 분야). 재난 상황이나 임시 모임처럼 인프라 구축이 어려운 환경에서 유용, 현대 무선 통신의 근간이 되는 핵심 원리

#### 11. 지그비 (Zigbee)
저전력, 저속, 저비용이 특징인 무선 통신 기술이다.

- 특징: 메시(Mesh) 네트워크를 지원해 통신 거리를 넓히고 안정성을 높임, 수많은 장치를 한 네트워크에 연결하기 쉬움
- 현재 활용도: 높음. 스마트홈(조명, 스위치, 도어락), 스마트 팩토리, 빌딩 자동화 등 대규모 센서 네트워크·제어 시스템

#### 12. Wi-SUN (Wireless Smart Utility Network)
스마트 그리드 같은 대규모 사물 인터넷을 위한 장거리 무선 통신 표준이다.

- 특징: 수 km에 달하는 넓은 통신 범위, 저전력 동작, 단말 수천 개 연결
- 현재 활용도: 중간 (특수 분야). 주로 스마트 미터링(AMI, 원격 검침), 스마트 그리드, 스마트 시티 인프라(가로등, 주차 관리) 등 공공·산업 분야

#### 13. 스마트 그리드 (Smart Grid)
전기와 정보통신 기술을 활용해 전력망을 지능화·고도화한 지능형 전력망이다.

- 핵심 특징: 양방향 통신으로 전력 공급자와 소비자가 실시간으로 정보를 주고받아 에너지 효율 극대화
- 주요 기술: AMI(Advanced Metering Infrastructure), 실시간 모니터링, 자동화된 제어 시스템, 분산 전원 관리
- 현재 활용도: 높음 (성장 중). 전 세계적으로 전력 인프라의 디지털 전환이 빨라지면서 구축 활발

### IoT (Internet of Things) 통신

#### 14. IoT (Internet of Things)
각종 사물에 센서와 통신 기능을 넣어 인터넷에 연결하는 기술 전반을 말한다.

- 핵심 요소: 센싱(데이터 수집), 네트워킹(연결), 서비스 인터페이스(데이터 처리 및 활용)
- 현재 활용도: 매우 높음. 스마트홈, 스마트 팩토리, 헬스케어, 자율주행차 등 거의 모든 산업 분야의 핵심 패러다임

#### 15. CoAP (Constrained Application Protocol)
자원이 제한된 저사양 기기(Constrained Device)를 위한 프로토콜이다.

- 특징: HTTP를 바탕으로 설계되어 RESTful API 사용 가능, UDP 기반이라 MQTT보다 가볍고 빠르지만 신뢰성은 낮음, M2M(Machine-to-Machine) 통신에 최적화
- 현재 활용도: 중간 (특수 분야). 통신 환경이 매우 열악하거나 극도의 저전력이 필요한 특정 산업용 IoT 분야

#### 16. AllJoyn (IoT 디바이스 상호작용 프레임워크)
퀄컴이 개발한 오픈소스 소프트웨어 프레임워크로, IoT 디바이스 간 상호작용을 위한 통합 플랫폼이다.

- 핵심 특징: 서로 다른 제조업체의 기기들이 함께 작동하도록 연결, 디바이스끼리 통신하고 협업하게 함
- 주요 기능: 디바이스 발견, 서비스 공유, 보안 통신, 플랫폼 독립적 개발 환경
- 현재 상황: Matter로 진화. AllJoyn의 개념은 Matter(구 Thread Group) 표준으로 발전. Matter는 Apple, Google, Amazon, Samsung 등이 함께 만든 통합 스마트홈 표준으로, AllJoyn보다 넓은 업계 지원과 표준화를 달성
- 현재 활용도: 중간 (과도기). AllJoyn 자체는 점차 Matter로 대체, 새 IoT 프로젝트는 Matter 표준을 우선 고려

### 네트워크 가상화 및 차세대 기술

#### 17. 네트워크 슬라이싱 (Network Slicing)
물리적 네트워크 하나를 독립적인 가상 네트워크 여러 개로 나누는 5G의 핵심 기술이다.

- 특징: 각 '슬라이스'가 특정 서비스(예: 초고속 스트리밍, 초저지연 자율주행, 대규모 IoT)의 요구에 맞게 대역폭, 지연 시간 등을 맞춤형으로 할당받음
- 현재 활용도: 높음 (성장 중). 5G 망을 바탕으로 산업별 맞춤형 서비스를 제공하려고 통신사들을 중심으로 활발히 도입

### 개념
클라우드와 가상화 기술은 현대 IT 인프라의 근간이다. 2023년에는 기본 모델인 IaaS, PaaS, SaaS가 출제되었고, 앞으로는 이를 바탕으로 한 심화 기술(멀티 클라우드, 도커, 쿠버네티스, 하이퍼바이저, 서버리스)이 나올 수 있다. 먼저 전체를 표로 보면 이렇다.

| 분류 | 기술 | 핵심 키워드 |
|---|---|---|
| 클라우드 컴퓨팅 유형 | IaaS, PaaS, SaaS, BaaS | 제공 범위(인프라/플랫폼/소프트웨어/블록체인), 제어 수준 |
| 클라우드 확장/연동 | 멀티 클라우드 | 2개 이상 클라우드 사용, 특정 기업 종속 방지(Vendor Lock-in) |
| 클라우드 확장/연동 | 인터클라우드 컴퓨팅 | 클라우드 간 연동/상호운용성, 표준화, 하이브리드 클라우드 |
| 클라우드 확장/연동 | 메타 클라우드 | 여러 클라우드를 하나처럼 관리, 통합 관리 포털 |
| 가상화 기술 | 하이퍼바이저 | 가상 머신(VM) 생성/관리, 하드웨어 가상화, Type 1/2 |
| 가상화 기술 | 도커 (컨테이너) | OS 수준 가상화, 이미지, 격리된 실행 환경, 빠른 배포 |
| 클라우드 네이티브 | 쿠버네티스 | 컨테이너 오케스트레이션, 자동화된 배포/스케일링/관리 |
| 클라우드 네이티브 | 서버리스 컴퓨팅 | FaaS, 이벤트 기반, 서버 관리 불필요, 사용량 기반 과금 |
| 콘텐츠 전송 | N-Screen | 하나의 콘텐츠를 여러 기기에서 연속적으로 소비 |

### IaaS, PaaS, SaaS는 왜 출제되었을까?
클라우드 기술이 쏟아지는 가운데 가장 기본인 IaaS, PaaS, SaaS가 나온 이유는, 이 세 모델이 모든 클라우드 서비스의 근간이 되는 핵심 분류 체계이기 때문이다.

- **서비스의 본질 이해**: 사용자가 클라우드 위에서 무엇을 할 수 있고 어디까지 관리해야 하는지를 정하는 가장 기본적인 약속
- **현대 기술의 기반**: 서버리스(PaaS의 확장), 쿠버네티스(IaaS 위에서 동작), 멀티 클라우드(여러 IaaS/PaaS 조합) 등 모든 신기술이 이 세 모델 위에서 동작하거나 이 모델을 확장한 개념

결국 출제자는 최신 기술 이름을 아는지를 넘어, 클라우드 생태계를 떠받치는 근본 원리와 서비스 모델을 정확히 이해하는지 보려 한 것이다.

### 클라우드 서비스 모델 (IaaS, PaaS, SaaS, BaaS)
클라우드 컴퓨팅의 핵심은 누가 무엇을 관리하느냐에 따라 서비스를 나누는 것이다. 기업이 클라우드를 도입할 때 어느 수준의 제어권을 갖게 될지를 정하는 중요한 기준이 된다.

#### 1. IaaS (Infrastructure as a Service)
서버, 스토리지, 네트워크 같은 **물리적 인프라**를 클라우드로 제공받는 인프라 서비스다.

- 기업이 관리: 운영체제, 런타임, 미들웨어, 애플리케이션, 데이터
- 클라우드 제공업체가 관리: 서버, 스토리지, 네트워크, 가상화
- 특징: 가장 많은 제어권(운영체제부터 애플리케이션까지 모두 직접 관리), 가장 많은 책임(보안, 패치, 업데이트 등), 기존 온프레미스 환경과 가장 비슷한 구조
- 대표 서비스: AWS EC2, Azure Virtual Machines, Google Compute Engine
- 언제 사용하나: 기존 시스템을 그대로 클라우드로 옮기거나 특별한 보안 요구사항이 있을 때

#### 2. PaaS (Platform as a Service)
애플리케이션 개발과 실행에 필요한 **플랫폼 환경**을 클라우드로 제공받는 플랫폼 서비스다.

- 기업이 관리: 애플리케이션, 데이터
- 클라우드 제공업체가 관리: 런타임, 미들웨어, 운영체제, 서버, 스토리지, 네트워크
- 특징: 인프라 관리 부담 없이 개발에만 집중, 자동 스케일링·백업·보안 등 자동 처리, 개발 생산성 크게 향상
- 대표 서비스: AWS Elastic Beanstalk, Azure App Service, Google App Engine
- 언제 사용하나: 새 애플리케이션을 빠르게 개발하고 배포하고 싶을 때

#### 3. SaaS (Software as a Service)
완성된 **소프트웨어 애플리케이션**을 클라우드로 제공받는 소프트웨어 서비스다.

- 기업이 관리: 없음 (사용자 계정 관리 정도)
- 클라우드 제공업체가 관리: 애플리케이션, 데이터, 런타임, 미들웨어, 운영체제, 서버, 스토리지, 네트워크
- 특징: 가장 간단한 사용법(웹 브라우저로 접속해 바로 사용), 가장 적은 제어권(커스터마이징 제한적), 가장 적은 책임(기술적 문제는 제공업체가 해결)
- 대표 서비스: Gmail, Office 365, Salesforce, Netflix
- 언제 사용하나: 비즈니스 기능에만 집중하고 싶을 때, 빠른 도입이 필요할 때

#### 4. 블록체인 (Blockchain)
**블록체인**은 거래 정보를 블록 단위로 묶어 암호학적 해시로 잇고, P2P 네트워크의 모든 참여자가 같은 사본을 나눠 보관하는 분산 원장(DLT) 기술이다. 거래 내역을 일정 시간 단위의 블록(Block)에 담아 체인(Chain)처럼 연결하는데, 각 블록이 이전 블록의 해시를 품고 있어서 한 블록을 변조하면 그 뒤의 모든 블록이 깨진다. 그래서 위·변조가 사실상 불가능하다.

- **분산 원장 기술(DLT, Distributed Ledger Technology)**: 중앙 서버 없이 P2P 네트워크의 모든 노드가 같은 장부 사본을 갖고, 분산 합의(PoW, PoS 등) 알고리즘으로 새 블록 검증
- **무결성**: 해시 체인 + 분산 저장으로 위·변조 불가
- **투명성**: 모든 참여자가 같은 거래 내역 공유
- **탈중앙화**: 신뢰받는 중앙 기관(은행, 정부) 없이도 거래 가능
- 활용: 비트코인·이더리움 등 암호화폐, 스마트 컨트랙트, 공급망 추적, 디지털 신원, NFT, 아래 BaaS의 기반 기술

#### 5. BaaS (Blockchain as a Service)
블록체인 개발 환경을 클라우드로 제공하는 블록체인 서비스다. 복잡한 블록체인 인프라를 감춰 주어 개발자가 블록체인 애플리케이션을 쉽게 만들 수 있다.

- 기업이 관리: 블록체인 애플리케이션, 스마트 컨트랙트, 사용자 데이터
- 클라우드 제공업체가 관리: 블록체인 노드, 네트워크, 합의 알고리즘, 암호화, 스토리지
- 특징: 블록체인 네트워크 구축·운영의 복잡성 제거, 노드 추가/제거가 간단하고 자동화, 다양한 블록체인 플랫폼(이더리움, 하이퍼레저 등) 지원, API로 쉽게 애플리케이션 개발
- 대표 서비스: AWS Managed Blockchain, Azure Blockchain Service, IBM Blockchain Platform
- 언제 사용하나: 블록체인 기반 애플리케이션을 빠르게 만들고 싶을 때, 복잡한 인프라 관리 없이 비즈니스 로직에만 집중하고 싶을 때

네 모델을 비교하면 이렇다.

| 구분 | IaaS | PaaS | SaaS | BaaS |
|---|---|---|---|---|
| 제어 수준 | 높음 | 중간 | 낮음 | 중간 |
| 관리 책임 | 많음 | 중간 | 적음 | 중간 |
| 개발 속도 | 느림 | 빠름 | 즉시 | 빠름 |
| 커스터마이징 | 자유로움 | 제한적 | 매우 제한적 | 제한적 |
| 비용 | 높음 | 중간 | 낮음 | 중간 |
| 보안 책임 | 기업 | 공유 | 제공업체 | 공유 |

### 클라우드 시대를 이끄는 3가지 근본 원리
IaaS, PaaS, SaaS가 서비스의 '종류'를 나눈다면, 지금 클라우드 기술을 이끄는 핵심 '동작 원리'도 셋 있다. 시험에서 그 자체로도 중요하지만 다른 신기술을 이해하는 기반이 된다.

| 기술 | 핵심 원리 | 이 기술이 기반이 되는 것들 |
|---|---|---|
| 하이퍼바이저 & 도커 | 가상화: 물리적 자원을 논리적으로 분할하고 격리 | 클라우드 컴퓨팅의 모든 것, 효율적인 서버 자원 활용 |
| 쿠버네티스 | 오케스트레이션: 수많은 컨테이너를 자동으로 관리/조율 | 마이크로서비스 아키텍처(MSA), 대규모 애플리케이션 배포 |
| 서버리스 컴퓨팅 | 추상화: 인프라를 완전히 감추고 코드 실행에만 집중 | 이벤트 기반 아키텍처, 빠른 개발 및 확장, 비용 효율화 |

#### 가상화 (하이퍼바이저 & 도커)
'격리(Isolation)'로 물리적 시스템 하나에서 여러 운영체제나 애플리케이션을 동시에 돌린다.

- **하이퍼바이저**: 하드웨어를 가상화해 여러 가상 머신(VM)을 만듦. VM마다 독립된 운영체제(Guest OS)를 가짐 (무거운 가상화)
- **도커(컨테이너)**: 운영체제(OS)를 가상화해 여러 컨테이너를 만듦. 모든 컨테이너가 호스트 OS의 커널을 공유 (가벼운 가상화)

가상화 없이는 클라우드 컴퓨팅이 존재할 수 없다. 물리 서버 한 대의 자원을 수십, 수백 개로 나눠 여러 사용자에게 동시에 제공하는 것이 클라우드의 핵심 원리이기 때문이다.

#### 쿠버네티스 (컨테이너 오케스트레이션)
수백, 수천 개의 '컨테이너(배)'를 자동으로 관리하는 '조타수(Kubernetes)' 역할을 한다. 도커 같은 컨테이너 기술이 널리 쓰이면서 수많은 컨테이너를 효율적으로 배포·확장·관리할 필요가 생겼고, 쿠버네티스는 이 과정을 모두 자동화하는 '컨테이너 관리 시스템'이다. 현대의 대규모 애플리케이션(MSA)은 작은 서비스(컨테이너) 여러 개의 조합으로 이루어지는데, 쿠버네티스는 이 복잡한 시스템이 안정적으로 돌아가도록 지휘·조율하는 사실상의 표준 기술이다.

#### 서버리스 컴퓨팅 (Serverless Computing)
개발자가 서버 걱정 없이 '코드'에만 집중하고, 쓴 만큼만 비용을 내게 한다. '서버가 없다'는 뜻이 아니라 개발자가 서버를 직접 관리할 필요가 없다는 뜻이다. 클라우드 제공업체가 서버 프로비저닝, 스케일링, 관리를 모두 맡고, 개발자는 특정 이벤트가 생겼을 때 실행될 함수(Function)만 작성한다(FaaS: Function as a Service). 클라우드 기술의 궁극적인 목표인 '완전한 추상화'를 보여 주는 패러다임으로, 인프라 고민을 줄이고 비즈니스 로직 개발에만 집중하게 해 생산성을 극대화한다.

### 클라우드 확장 및 연동

#### 멀티 클라우드 (Multi Cloud)
2개 이상의 서로 다른 클라우드 제공업체(AWS, Azure, GCP 등)의 서비스를 함께 쓰는 전략이다.

- 특징: 특정 클라우드 기업에 대한 기술·비용 종속 회피(Vendor Lock-in 방지), 서비스마다 장점만 골라 시스템 구성, 재해 복구(DR)와 고가용성 확보에 유리
- 현재 활용도: 매우 높음. 비용 최적화, 위험 분산, 특정 기능 활용 등을 위해 많은 기업이 채택

#### 인터클라우드 컴퓨팅 (Inter-Cloud Computing)
서로 다른 클라우드 서비스 사이의 상호운용성(Interoperability)을 확보하는 기술이다.

- 특징: 서로 다른 클라우드가 표준화된 API나 프로토콜로 하나의 클라우드처럼 원활하게 연동되도록 하는 것이 목표, 하이브리드 클라우드(프라이빗+퍼블릭) 구성의 핵심 요소
- 현재 활용도: 높음. 클라우드 간 데이터 이전, 워크로드 이동, 서비스 연계 등을 위해 계속 발전 중

#### 메타 클라우드 (Meta Cloud)
여러 클라우드 서비스를 통합 인터페이스(포털) 하나로 관리·운영하는 상위 수준의 클라우드다.

- 특징: 멀티 클라우드 환경의 복잡성을 줄이는 것이 주목적, 사용자는 메타 클라우드 포털에서 여러 클라우드의 리소스를 한눈에 보고 제어
- 현재 활용도: 중간 (성장 중). 멀티 클라우드 도입이 늘면서 통합 관리 필요성이 커져 관련 솔루션 등장

### 가상화 기술

#### 하이퍼바이저 (Hypervisor)
가상 머신(VM)을 만들고 실행하는 소프트웨어, 펌웨어 또는 하드웨어다. VMM(Virtual Machine Monitor)이라고도 한다. 종류는 둘이다.

| 종류 | 설치 위치 | 예 | 용도 |
|---|---|---|---|
| Type 1 (네이티브/베어메탈) | 하드웨어 위에 직접 설치 | VMware ESXi, Xen, KVM | 성능이 뛰어나 엔터프라이즈 환경 |
| Type 2 (호스트형) | 일반 운영체제(Windows, macOS) 위에 애플리케이션처럼 설치 | VMware Workstation, VirtualBox | 개발 및 테스트 |

- 현재 활용도: 매우 높음. 모든 IaaS 클라우드의 기반 기술, 서버 가상화의 핵심

#### 도커 (Docker)
애플리케이션을 빠르게 구축, 테스트, 배포할 수 있는 컨테이너 기반 오픈소스 가상화 플랫폼이다.

- 특징: 애플리케이션과 실행에 필요한 모든 것(라이브러리, 종속성 등)을 '이미지' 단위로 패키징, 이 이미지로 어떤 환경에서든 격리된 상태로 일관되게 실행, VM보다 가볍고 빠름
- 현재 활용도: 매우 높음. 현대 애플리케이션 개발·배포의 표준

### 기타

#### N-Screen
하나의 미디어 콘텐츠(영화, 방송 등)를 스마트폰, TV, PC, 태블릿 등 여러 기기에서 이어서 즐길 수 있는 서비스다.

- 특징: 클라우드에 사용자 정보와 콘텐츠 소비 기록을 저장해, 어느 기기로 접속하든 같은 시점부터 이어 보게 하는 것이 핵심
- 현재 활용도: 매우 높음. 넷플릭스, 유튜브 등 대부분의 OTT 서비스가 기본 지원

### 답 쓸 때
IaaS·PaaS·SaaS는 약어 그대로 쓴다. 23-3처럼 세 개를 한꺼번에 구분하는 문제라면 지문의 단어를 보면 된다.

- IaaS: "서버·스토리지"
- PaaS: "개발 환경·플랫폼"
- SaaS: "소프트웨어를 바로 사용"

가상화 쪽은 무엇을 다루느냐로 가른다.

- 하이퍼바이저: VM
- 도커: 컨테이너
- 쿠버네티스: 컨테이너 여러 개의 관리

도커와 쿠버네티스는 둘 다 컨테이너 이야기라 섞이기 쉬운데, 컨테이너 자체냐 그걸 여러 개 관리하느냐의 차이다.
